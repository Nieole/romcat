## 被推翻的判断

**街机不是第二大集合。** 资源站全站有 MAME 12,522 条，我据此说「街机条目数巨大、单位处理成本最低、优先级要往前提」。**这个库里街机只有 265 个文件、3.73 GiB。** 优先级判断作废。

**PSV 是文件数的绝对主导：171,073 个文件，占全库 67%**，但只有 1.64 TiB，且含汉字仅 0.5%。它是目录树转储，海量游戏内部资源文件。这是此前完全没有预料到的形态。

**容量最大的平台是 `pc`（2.72 TiB，792 文件），而 `pc` 不在议定的 27 平台清单里。** 同样 `switch`（223.84 GiB）也不在——它比 PS3 还晚一代。

**中文占比是 15.6% 而非资源站的 9%**，但两者口径不同（这里是文件名含汉字，那里是条目分类）。

## 并发：按介质探出来，不按 CPU 数猜

2026-09-01 实测（详见 `docs/research/scan-concurrency.md`）。测法是**两组不重叠的冷缓存
兄弟目录，一组串行一组并发，按目录/秒归一化后比**——同一组目录跑两次只会量到热缓存。

**同一块盘上，提高并发的效果按区域分，方向相反：**

| 区域 | 串行 目录/秒 | 16 线程 目录/秒 | 提速 |
|---|---|---|---|
| `Game/ps` | 8.7 | 40.9 | **4.71×** |
| `Game`（主库根） | 10.7 | 15.2 | **1.42×** |
| `Game/FC` | 42.7 | 36.0 | 0.84× |
| `Game/SFC` | 125.3 | 21.9 | **0.17×**（慢 5.9 倍） |

规律很干净：**串行就读得快的区域，并发一定亏**——目录项在盘上挨着，16 个线程等于把一次
顺序读拆成 16 股互相打断的随机读。

**主库根上量到 1.42 倍**，那是整趟全库扫描该用的样本。票 01 那个「按 CPU 数取，夹在 2 到 8」
的默认值（这台机器上取到 8）**没有依据**，现在由 `scan::probe` 开扫前量出来。

**表里的提速是实测，具体定几个线程是模型外推**：探测只量 1 线程与 16 线程两个点，「主库根上
4 个线程就够到 16 线程吞吐的九成」是把 1.42 倍代进一个饱和模型算的。**「旧默认 8 与新默认 4
哪个扫得快」这个实验做不成**——一个库只有一份，第二遍必然是热缓存。

## 识别：第一次看到真实命中率（2026-09-01，票 07）

拿 46,444 个变体去撞 395 份 DAT 的 481,106 条文件记录，判据是 **CRC-32 加未压缩大小**。

| | |
|---|---|
| 变体 | **46,444 个** |
| **命中** | **30,024** |
| 未命中 | 11,823 |
| 无判据 | 4,537（这一层拿不到判据，不是「DAT 里没有」） |
| 跳过 | 60（补丁 27 + 没有发行版链接 33） |
| **命中率** | **撞了 DAT 的里面 71.7%**（30,024 / 41,847）；**全部变体里 64.6%** |
| 候选 | 150,959 条，自动通过 136,238 条；**16,004 个变体有不止一条候选** |
| 三层 | 建出**作品** 9,226 个、**发行版** 18,571 个 |

**命中率有两个数，两个都得说。** 分母取「撞了 DAT 的」时它回答「这一层准不准」；
取全部变体时它回答「这个库现在被认出来多少」。**跳过与无判据不进第一个分母**——
把「不该撞 DAT 的」和「拿不到判据的」混进未命中，等于拿别的账压低这一层的准确率。

### 逐芯片的命中一条都不自动通过

MAME 的 software list 撞出 **14,696 条候选、涉及 12,199 个变体，自动通过 0 条**。
一条 `rom` 是**一颗芯片**（`prg` / `chr` 的一个 dataarea），不是一个文件——单芯片卡上它
恰好等于去头哈希，多芯片卡上「对上了一颗芯片」离「这个文件就是那次发行」还差着别的芯片。
所以它是**中置信**：通过但标记，等裁决（ADR-0002 的中置信那一档）。

## 第一次真实识别命中率（2026-09-01，票 07）

**30,024 个变体被 CRC-32 精确认出来。**

| 口径 | 命中率 |
|---|---|
| 有 DAT 弹药可撞的（30,024 / 41,847） | **71.7%** |
| 全部变体（30,024 / 46,444） | **64.6%** |

四类相加正好等于变体总数：命中 30,024 + 未命中 11,823 + 无判据 4,537 + 跳过 60（补丁 27、无发行版链接 33）。**「无判据」与「跳过」不算进未命中**——否则命中率虚低。

建出作品 9,226 个、发行版 18,571 个。候选 150,959 条，自动通过 136,238 条。

**性能**：首趟 832.9 秒，回盘只读 **9.04 GiB（全库的 0.1%）**——零解压读 CRC-32 这条路兑现了。第二趟 **7.9 秒、0 字节**（挂账 D14 说的「增量价值到票 07 才显现」，兑现）。

### 按平台：两个世界

| 平台 | 命中率 |
|---|---|
| GB | **91.5%** |
| FC | **82.8%** |
| SFC | **80.1%** |
| GBA | **5.8%** |
| NDS | **4.4%** |
| GBC | **0%** |

**与 ADR-0008 的预判一分不差**：GBA 与 NDS 是中文玩家存量最大的两个平台，却是汉化版数据覆盖最差的。抽样确认 GBA 的未命中全是宝可梦汉化版。

### 一个结构性事实

**汉化命中 1,064 个全部来自 TOSEC。GoodNES 那 748 条在这一层一条都撞不到——它只记 SHA-1，不记 CRC-32。** 要用上这个数据源，需要一个愿意为小文件付 SHA-1 的层（票 10）。

两套哈希都撞出了东西：含头 141,119 条候选、去头 9,840 条；12,388 条去头口径的记录里有 5,756 条是被含头哈希撞上的。

### 媒体：库里现成的图归得上 647 份

| | |
|---|---|
| 归得上的媒体 | **647 份**（涉及 230 个变体），全部收进来是 **10.04 GiB** |

| 读不动 | 0 份 |

**「同一份媒体只存一份」是内容寻址天然给的**，不是另加的去重步骤：538 条引用落在
516 份内容上，差出来的 22 份就是省下来的。最大的一份是

### 采集缓存：`--refresh` 重采一遍读盘 0 字节

`--refresh` 把 119,322 个「锚点 × 源」全部重采，**4.1 秒、回盘 0 字节**——
539 份媒体的内容哈希从中立库直接取回。重采的是结论，不是重读一遍盘。

### 上限进了输入指纹，调高它那些媒体真的会进来

**上限改变采集的结果，所以它必须进输入指纹。** 实测把 `--max-media-mib` 从 32 提到 64：

| | |
|---|---|
| 新收进来 | **53 份**（另有 2 次算出来发现池里已经有了） |
| 超上限的 | 从 108 份降到 **53 份** |
| 回盘读 | 2.44 GiB / 55 份；**其余 539 份的哈希从中立库直接取回** |
| 跳过的「锚点 × 源」 | 119,322 —— DAT 与文件名那几个源的指纹不含上限，一条都没重采 |

指纹里漏掉上限的话，这一趟会一口咬定「输入没变」而整条跳过，那 55 份永远收不进来，
只有整份 `--refresh` 才逃得掉。反过来调低上限也一样：此前收进来的那些会被挡在外面。

### 那 6,501 个中文名各是哪一档来的

| 类型 | 作品数 | 置信度 |
|---|---|---|
| **译名**（官中版的官方译名） | **54** | 中置信 |
| **汉化组自取的名** | 73 | 中置信 |

官中那 54 条只到中置信，因为两件事要分开：「这个变体是不是那条官中发行版」精确哈希撞上了、
确凿；「这串字是不是官方译名」不确凿——**官方译名不在 DAT 里**（No-Intro 给台版卡带的

**中文名的绝大多数没有任何官中发行版为它背书**，它只是文件名。这不是缺陷，是如实：
库里 46,444 个变体里 16,716 个没挂上作品（DAT 认不出来），而这个库的中文名本来就写在
文件名上——**标题集合里 17,991 条来自文件名，超过全部叫法的一半**。
**照用但标记**（ADR-0002 的低置信那一档）——前端里多 6,374 条中文，同时这 6,374 条
一条不落地进队列等人裁决。文件名里带着的目录编号、分类前缀与地区后缀，只有人看得出来
该不该留：实测队列里就有 `007 - The World Is Not Enough → 「01.動作：007過關」`、
`007 - Everything or Nothing → 「[NGC][0600]詹姆斯邦德007：谁与争锋 James Bond 007
Everything or Nothing（美）」` 这种。

### 世代裂缝两侧都有真东西（ADR-0019）

显示标题取到官中译名的那 54 个作品里（标题集合里的译名一共 65 条）：

两侧的判据是**发行版自己的身份**，不是一张世代表——这个库里没有世代那一列，也不该为它
造一列。**分叉的是归属，不是取字的那口井**：两侧的中文名都只能从盘上那个文件的名字里来。

| 那一侧 | 条数 | 实测长什么样 |
|---|---|---|
| **独立发行版** | **10** | FC / GBC 的台版与大陆版卡带：地区就是 `Taiwan` / `China`，DAT 里独立一条记录、独立哈希 |
| **语言属性** | **44** | PSV 港版与美版：地区是 `Asia` / `USA`，中文写在语言标记组里（`En,Ja,Fr,De,Es,Zh-Hant,Zh-Hans,Ko,Ru`），**同一条记录服务多个地区** |

地区是中国 / 台湾 / 香港，这条发行版就是官中那一条；地区是别的而语言里带 `Zh`，
它是一条多地区共用的记录、中文只是它的一项属性。

## 端到端跑通（2026-09-01，票 16）

| 800 条清单有、卡上一致 | **保持 800 个，207.34 MiB** |
| 30 条清单有、卡上一致、规则不再要它 | **删除 30 个，腾出 120.00 MiB** |

| 10 条清单有、卡上被改过 | **意外「被改过」10 个，既不覆盖也不删** |
| 5 条要、清单没有、卡上却已有东西 | **意外「落点被占」5 个，不覆盖** |
| 3 个手动拷进去的存档 / 金手指 / 截图 | 与上面那 5 个一起算作**清单之外 8 个、96.40 KiB** |

净变化 **+100.72 MiB**，这次要动 117 个文件。**清单之外一条步骤都没有。**

**`(大小, 修改时间)` 这套判据在真机上对得准**：800 条摆进去时记的是从目标上读回来的
戳，再读一遍全部判为「保持」，一条误报都没有。

### 装得下吗：比的是「目标现占 + 净变化」

```
目标现占    398.53 MiB  （其中清单之外 96.40 KiB）
同步之后    499.25 MiB
```

**不是拿子库该有多大去比**：卡上的地方是共用的，手动拷进去的存档、落点被占而这趟
根本传不上去的、被改过因而不删的，全都还占着位置（挂账 D76）。

把上限压到 256 MiB：

```

  58.28 MiB   172.74 MiB  GB/…/PSP模拟器/MasterBoy_CN v2.02.zip
  …
这几个**全砍掉也只腾出 232.56 MiB，还差 10.70 MiB**
```

**922 个一个都没砍**（ADR-0016）。裁剪建议落在**变体**这一层（例外记的是变体的键），
带**累计**一列——「砍到第几个才够」直接读得出来，不够时报告直接说还差多少。

## 光盘序列号：只读几百字节就认出来（2026-09-02，票 09）

第一命中层（CRC-32 加大小）对光盘世代结构性地不够用：**压缩镜像的 CRC-32 算在压缩后的
字节上**、**汉化版改过字节**、**目录树转储压根没有一个整文件可以算哈希**。而这三种东西
都把身份明文写在最前面。这一层去读它。

### NKit：验了 1,967 份，一份都不是

**NKit 是这一层最要紧的那道闸**（Dolphin：它的 CRC32 可能和好转储的相同，即使两个文件
并不完全一样）。判据是**光盘逻辑偏移** `0x200` 处的 `NKIT`。真机结果：

- **验过 1,967 份**（1,939 份未压缩镜像 + 28 份 CSO，那两种交得出逻辑偏移 `0x200`），
  **0 份是 NKit**。
- **另外 4,647 份没验**：WBFS 只交得出 256 字节的 Wii 光盘头、WIA/RVZ 只交得出 `0x80`
  字节，两种都够不到 `0x200`；CHD 与 GCZ 的负载解不开；solid 块太深的那 2,508 条壳都没开；
  `param.sfo` 与 NKit 无关。**没验过就不许自动通过**——这不是保守，是 Dolphin 那句话的
  直接推论。
- **这一层为了 NKit 多花了一笔**：撞上了 CRC 的内容本来不必再探（序列号是第二命中层），
  但「NKit 检测在任何 CRC 匹配之前执行」不许拿 CRC 的结果来决定验不验，所以凡是
  **形态上可能是 GC / Wii 光盘**的一律照探。代价是 1.69 → 1.93 GiB、183.5 → 232.4 秒。

「0 个」是一条结论不是一次落空：这块盘上没有 NKit 处理过的镜像，而闸门本身在 fixture
上有可断言的证据（`tests/disc_serial.rs`）。

### solid 块吃掉了 2,508 条

7z 的一个块里几个条目是连着压的，解压器跳不过中间的字节。真机上 **2,508 条**光盘形态的
内容排在 1.36–3.46 GiB 的东西后面，为它们付那笔解压等于把「只读几百字节」反过来做——
闸设在 64 MiB，超了就放弃并如实报（挂账 D109）。其中 **2,459 条是 PSV 的 `.7z`**，
多半是 DLC 目录里那份 `param.sfo`；本体那一份通常排得浅，所以 PSV 照样跳到了 94.1%。

### Redump 一条序列号都不写

实测：Redump 的官方 DAT 里 `<game>` 只有 `name` 与 `id`、`<rom>` 只有四套哈希。
于是 **PS2 / NGC / WII 三个平台读得出 `SLPS-25604` 与 `GALE01`，却无处可撞**——
它们的序列号弹药分别只有 178 / 58 / 27 条，全来自 No-Intro 的 Non-Redump 附集。
报告因此在平台表上单列「序列号」一列（挂账 D110）。

**序列号写在 `<rom serial>` 属性与 `<game_id>` 子元素上，不在 `<game serial>` 上。**
票 06 的解析器只读后者，于是 Vita 与 PSP 两个平台一条都读不到——补上这两处之后，
395 份 DAT 索引出 **95,022 条**序列号。
