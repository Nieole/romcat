# 领域文档

工程技能探索这个仓库时，怎么消费它的领域文档。

## 动手前先读

- 根目录的 `CONTEXT.md` —— 这个项目的词表
- `docs/adr/` 里与你要动的区域相关的决策记录

**每条 ADR 读到底。** 有些 ADR 末尾带「修订」段，那是后来的调研推翻了开头的判断——只读开头会拿到已经作废的结论去干活。

## 用词表的词

输出里凡是提到领域概念——工单标题、测试名、方案里的名词——用 `CONTEXT.md` 里定的那个词。词表给每个术语列了 `_Avoid_`，那些是要绕开的同义词。

要用的概念词表里没有，这是个信号：要么你在发明这个项目不用的语言（重新想），要么是真缺口（记下来交给 `/domain-modeling`）。

## 与 ADR 冲突就说出来

你的输出与某条 ADR 相悖时，明说：

> _与 ADR-0004（主库只读）相悖，但值得重开，因为……_
