# 工单跟踪器：本地 Markdown

这个仓库的工单与规格（规格也叫 PRD）以 Markdown 文件的形式住在 `.scratch/` 下，**跟代码一起进 git**——票据的历史与代码的历史是同一条。

## 约定

- 一个特性一个目录：`.scratch/<feature-slug>/`
- 规格是 `.scratch/<feature-slug>/spec.md`
- 工单一个文件一张：`.scratch/<feature-slug>/issues/<NN>-<slug>.md`，编号从 `01` 起，按依赖顺序排，被阻塞的排在后面。多张工单塞进一个文件是不行的。
- triage 状态记在文件靠前处的 `Status:` 行，取值见 `triage-labels.md`
- 阻塞关系记在 `Blocked by:` 行，列出它依赖的工单编号；无阻塞则写明可立即开工
- 评论与对话追加在文件末尾的 `## Comments` 标题下

## 技能说「发布到工单跟踪器」时

在 `.scratch/<feature-slug>/` 下新建文件，目录不存在就建。

## 技能说「取相关工单」时

读引用路径指向的文件。用户一般会直接给路径或工单编号。

## 收尾一张票

**收尾由做这张票的人自己完成**——逐条勾上验收框（`- [ ]` → `- [x]`），勾后写清证据（哪条测试、哪个实测数字），并把 `Status:` 改成 `done`。

做的人知道哪条验收对应哪条测试，写证据是顺手的事；交给别人写只是把回报转录一遍。

`Status` 是结论，**勾是逐条证据**。只盖戳不打勾等于说「过了」却不说过在哪，日后没人能复核，也看不出哪条其实是带保留通过的。

**证据不足的条目照勾但要写明保留**，并指向对应的挂账或后续票。留着空框而 `Status` 已是 `done`，是自相矛盾。

**动过令牌（`crates/gui/src/tokens.toml`）的票，收尾时跑一遍设计稿核对脚本**
`python3 .scratch/gui-looks-like-the-design/check_tokens.py`，结果当证据写进票里。
**新立的令牌要么在脚本里写一条核对，要么进脚本的豁免表 `EXEMPT` 并写明设计稿里为什么没有可核的对应物**
（不是「还没顾上核」）——漏一格它就退 1、说出是哪一格。这份脚本不进门禁，只有收尾这一步会跑它；
它核出令牌与设计稿对不上的，不替拿主意的人挑一边改，照实记挂单。

**真库数只住台账 `docs/library-facts.md`。** 代码注释、根 `Cargo.toml` 与编进二进制的 toml 要拿真库的数
给一处取舍作证时，**写量级词、再指一句台账**：「四万多个变体，逐个查就是四万多次查询（见台账
`docs/library-facts.md`）」——量级要保得住原来那句论证，不是把论证删成一句「见台账」。抄过去的具体数会漂，
漂了没有东西报红（台账开头的「记账规矩」）。台账没收的数不硬指台账：写它真正的出处，并记一条挂单
（台账缺的真库数见挂单 `Q1256`，外部数据源的覆盖率算不算真库数见 `Q1257`）。
ADR、`docs/research/` 与 `.scratch/` 里的数是当日证据，不换（挂单 `Q501`）。
代码里还有五十多个文件复述着具体真库数，**不统一改**（票 `gate-and-tests/08`）：收尾时看你这张票改过的文件，
里面还复述着的顺手换掉，没改过的文件不去碰。粗筛用下面这条——那串数抄自挂单 `Q500`，是拿来搜旧抄本的，
不全，漏网的靠读：

```sh
git -C <worktree> diff --name-only -z <基点提交> -- crates xtask Cargo.toml \
  | xargs -0 -r git -C <worktree> grep -nE '46,444|46,428|46,483|9,226|8\.60 TiB|256,128|171,073|2\.50 TiB|21,901|1,016,857|28,529|2,631|30,024|15\.6%|342 张|342 jpg|94\.2%|99\.7%|83\.8%|4,085|216,203|18,571|136,238|38,963|16,420' --
```

编排多张票的人只做轻量核对——提交在不在、工作区干不干净、最吃重那条验收打一个**独立探针**（自己跑一条命令，而不是采信回报）。目的是决定下一张票怎么排，不是替人盖章。

## 挂单托给一张票时

实现时撞上、但没为它停线的东西记在 `.scratch/PARKING-LOT.md`（条目 `Qn`）。那份文件的
「谁来裁」一栏**不许填一张还没开工的票**——试过，失灵了四次：票后来真的来了、真的动了
那一带、没收它，因为**义务记在挂单上，而干活的人只读票**。

所以：**要把一条挂单托给某张票，就当场往那张票的正文里追加一行**

```markdown
收挂单 `Q371`：把「折中立库的路径」与「带着原名开它」收成一个函数。
```

追加不了（那张票还不存在）就别托付，「谁来裁」只剩**拿主意的人**与**收尾**两个选项。

接票时反过来读：**票里出现「收挂单 `Qn`」，那一条就是你这张票的活**，收尾时和验收条目
一起勾，并在挂单那一条上标 `settled`。

## 前沿

**前沿**是当下可以开工的那批工单：阻塞它的工单全部完成。扫 `.scratch/<feature>/issues/`，挑 `Blocked by:` 里列的工单都已完成的，编号小的优先。纯线性依赖时，前沿就是从上往下。
