# romcat-gui

**职责**：这个工具唯一的人机面。打开它看见的是**待确认队列**（`adr-0002`）。

**边界（红线）**：**领域判断一条都不在这里**。排序、筛选、分页在中立库那一层；队列怎么筛、按什么分组、一次裁决说不说得成立在待确认那一层；容量怎么写成人话在体检那一层；置信度那一档叫什么词也是核心挑的。界面只问它要哪一段、把要来的画出来（`adr-0005`、`adr-0024`）。换掉这个 crate 的代价被限制在这一层——那正是把判断按在核心里的理由。

## 顶上那两态

窗口收的不是「一屏」，而是**启动那条路**：定位要开哪份库 → 开出**现场** → 进主窗口。程序入口只剩解析参数与开窗。抬上来是为了**那条路够得着测试**——`main.rs` 里的东西一条测试都碰不到，而它正是人第一次打开这个工具时走的路。

**开场**（六屏之外的那一屏）通常见不到：上次开的那份记着，下次直接进主窗口；只在那一份打不开了（挪走、删了、结构版本对不上）或人主动要换库时才出现。旧库照列不误、当场说清哪个版本对哪个版本——从列表里静静消失才是最难的错。**添加主库**是开场上的三步向导（名字 → 第一个根 → 开始扫描），**按下「开始扫描」之前一个文件都不写**，开库就是建库。

## 六屏与开场

| 屏 | 一句话 |
|---|---|
| 开场 | 这个工作目录里有哪些中立库，挑一份；盘没挂上也看得见 |
| 待确认 | 一级按依据形状、二级按目录或命名规律，每批带共同依据与样本，整批通过或逐条走 |
| 库 | 一组根加三个数据源的状况；加根、扫描、取数据源都排到任务台 |
| 浏览 | 一个作品一行的表、左边的分面与条件组（那就是子库的规则）、右边作品 → 变体 → 文件；**所有元数据编辑收敛在这里** |
| 子库 | 规则与例外、差量预览、从这里触发同步 |
| 任务 | 长活的进度、停止与历史 |
| 设置 | 八节一屏；核心答不上的照实说接不上，不画假开关 |

左栏是主窗口左边那条导航：三组入口各带计数，栏底是已存多少条裁决，收起状态记在版式文件里。

「六步都在界面上答得完」是**自足**的判据（`adr-0023`）：凡是「就在这台机器上、就现在、就这一份库」的动作，界面上都得有落点；「界面做不到、人得回终端」是一条缺陷，不是一次取舍。

## 六屏共用的四样

**弹层**只有一种写法（遮罩、内容区、页脚、四档宽度、Esc 一层层退、开着时底下不接快捷键）。**面板边界**拖得动、有下限也有上限，位置记在工作目录里——不记进中立库，那份整份可再生，界面偏好放进去会被某一次重扫抹掉。**令牌**是颜色、字号、圆角、间距的唯一来源（`tokens.toml`，编进二进制），界面里别处不写一个颜色。**观感基线**把亮暗两套与焦点样式装上去；**颜色不是唯一线索**，每一处上色都跟着核心挑的那个词。

**快捷键全窗口一处**：「这一下算不算快捷键」那三道门（有弹层、有浮层、光标在文本框里）只有一份实现，屏上那张表也只有一份，接一个才列一个——表上不许印按不动的键。

## ADR-0005 那三个风险怎么清的

- **字体**：打包字体子集，不读系统字体。egui 内置字体不只缺汉字，中文标点、假名、`Ⅲ`、`①` 全缺；系统字体各机器覆盖不一致，且 macOS 上躺在哈希命名的路径下。打包等于把「哪些字显示得出来」变成编译期常量。
- **十万行表格**：只画视口里那几十行，开销与总行数无关；它没有排序能力，所以排序、筛选、分页一律下推到 SQLite，内存里只有当前视口。
- **输入法**：自动化验不了（注入的文本不经过输入法），由人在真机上验，两侧都过了。这一层为它留的是两件事——中文输入放在**不虚拟化的详情面板**里而不是表格单元格里，以及退出前先关掉输入法。三屏加起来**每一个文本框都长在不虚拟化的面板上**，有测试钉着。

## 合成数据的边界

`demo` feature 之后的合成数据、演示窗口与那几条实测开关，**默认一个字节都不进交付出去的二进制**：假数据与真库在界面上长得一模一样，看见一屏假名字的第一反应会是「我的库怎么了」，那比起不来更坏。合成数据走的是核心库的公开 API，不是旁路。

## 这一层刻意不做测试的地方

系统模态窗口（选目录）测试驱动不了，那一层只交回一个可空的路径；抽帧走外部 ffmpeg，找不到就退化成占位图标，窗口里一个字节都不解码视频。
