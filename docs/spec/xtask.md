# xtask（门禁跑手）

**职责**：`cargo xtask gate` 那几条的唯一一份定义。不交付、不被另外三个包依赖。

**边界**：它只跑 cargo 与读仓库文件，不碰任何领域逻辑。**门禁只有这一句话**，本地与 CI 调同一句，因此不会出现「我这儿绿的、CI 红的」这种只能靠猜的分歧。

## 七条，按这个顺序

排版 → 词表 → 默认特性编得过 → clippy → 全量测试 → 那几个数 → 文档。

- `fmt` 排在最前，几秒就出结果：「忘了跑 `cargo fmt --all`」这种最常见的红不该罚一整趟冷编译。
- 默认**在第一处红上就停**；`--keep-going` 一趟跑完每一条（CI 上就这么调）。
- 内存吃紧有 `--throttle`：编译期同时活着的 `rustc` 与跑起来之后的测试线程**各管一段**，少一个都不成立。
- **`check` 是唯一一条不带 `--all-features` 的**：它编的是交付出去的那份配置（`demo` 关着）。少了它，「交付的那份还编不编得过」在门禁里一个把门的都没有。

## 词表那一条

从 `CONTEXT.md` **当场读** `_Gate_` 词，这里一个词都不抄——哪些词严到可以报红是领域判断，而它只许有一处实现（`adr-0024`）。只扫**新写的代码**（相对 `main` 的 merge base 以来，含未提交）里的标识符与字符串字面量，不扫注释、不扫存量、不扫 `.scratch/`。拿不到历史时**如实跳过**并印明「一行代码都没扫」——不许假装扫过。它拦不住什么，那份清单也写在它的模块文档里。

## 那几个数

README 里四个带标记的数（票数、测试条数、测试目标数、ADR 份数）由 `--write` 写进去、由门禁那一条 `--check` 核对：过期了当场红并说出对的那个数，人不必自己去数。**所以它们不该在第二处再抄一份**——同一个数住在好几处、而没有东西盯着它们同步，正是它被立起来的原因。
