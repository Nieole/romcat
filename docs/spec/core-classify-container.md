# 内容分类与穿透（`classify` + `container` + `header`）

**职责**：回答「这份文件是什么形态」——**透明容器**、**压缩镜像**、还是**裸文件**——以及容器里面有什么（名字、未压缩大小、可得的校验和）。

**边界**：不判身份。这里给的是拿来做识别的原料（内部哈希、头部魔数），**撞不撞得上 DAT 是 `core-identify` 的事**。`header` 只做按已知偏移看魔数与校验和那一层，刻意不是识别器。

## 三类主线

- **透明容器**只是包装，不改变内容身份，识别要看内部字节（zip / 7z / rar / zst）。分卷的多个分卷合起来才算一个容器。
- **压缩镜像**不是包装，它就是变体本身的形态（`.chd` / `.cso` / `.pbp` / `.rvz`），模拟器直接读它——**绝不当容器去解**。边界看模拟器读不读得了：`.nsz` / `.xcz` 归裸文件。
- **裸文件**：其余直接可读的内容。

另有一条不看扩展名、看**键里的目录段**的归类：这份内容是不是**非游戏资产**。它住在这一层，是因为识别、导出、界面都够得着这一层（`adr-0024`）。

## 两个代价不同的「读不进去」

- **穿不透**：容器好好的，里面就是看不进去（格式不认、要密码、编解码器不支持、缺字典）。
- **不可读**：文件的元数据取不到（`adr-0021`）。
- **还没读过**：压根没试过——zst 要显式开关才读。

三者处置完全不同，混为一谈会让扫描做出错误的判断。**zst 是其中最贵的一个**：它的内部构成只能靠完整解压读出来，代价比 zip/7z 高两个数量级，所以它是唯一有开关的那一种（`ref-zstandard-containers`）。

## 实现上的两条

- rar 与 7z 是手写的读法，为的是避开 UnRAR 的许可；写和读都要过版权这一关（`ref-containers-and-compressed-images`）。
- 容器里的名字有编码问题（老 zip 的 GBK 文件名），因此有一层 charset 归一，免得同一个文件因编码不同而在库里认不出来。
