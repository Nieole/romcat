# 子库（`sublibrary`）

**职责**：从主库挑一部分做成一个派生库——持久实体，带自己的选择集、目标路径、前端格式、转格式规则与容量上限。

**边界**：只管「这一批是哪些」与「落到哪」，不管怎么搬（`core-sync`）、也不管前端格式怎么写（`core-adapter`）。选择集是主库的切片，主库永远不因此被改。

## 选择集 = 规则 + 例外

- **规则**是可重放的那部分：一棵**组**，组里摆着**子句**与更多的组，按平台、语言、中文、合集、收藏、类型、作品、年份、评分、体积、开发商、发行商、简介这些**维度**筛。主库新增的内容自动落进符合条件的规则。浏览屏上的筛选器就是一棵组，筛到满意存成子库，它原样变成那个子库的规则。
- **例外**是手动增删的那部分，**优先于规则**、永久记住。两向都有；界面上写「包含 / 排除」，中立库里存的仍是收入 / 排除。
- 同一层里不许既写「且」又写「或」——要混就套括号。

**一个求值器**：规则、浏览屏的筛选、收藏与合集成员共用同一张表与同一套编译（`core-catalog`）。多一个求值器，屏上筛出来的那批与真正搬过去的那批就会分家。

## 目标与容量

- **目标**：设备路径、前端格式、转格式所用的**能力档案**（`core-capability-convert`）。
- **容量上限**两档：自定义（记着的那个数）与按设备容量（跟着卡走，没读过就不设上限）。本机磁盘不设上限时按剩余空间算。**超限只给删减建议，绝不自动截断**（`adr-0016`）。

## 已知局限

**「评分」这一维立着，但眼下没有源**——中立库里还没有哪个源在写它，写得出规则、筛不出东西（访谈确认）。词表已经把这件事记在维度那一条上，这里记的是它在实现上的样子。
