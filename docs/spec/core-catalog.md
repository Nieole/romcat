# 中立库（`catalog`）

**职责**：工具自己的**事实来源**——能表达所有前端格式并集的那些表，加上围绕它的查询面（浏览、筛选、详情、前端快照、导出取数）。Pegasus 与 ES-DE 的元数据文件只是它的导入源与导出目标（`adr-0001`）。

**边界**：它是持久化枢纽，因此**与几乎每个领域互指是常态**：领域定义类型与判断，这里负责存。它不自己判领域的事——变体怎么成型归 `core-shape`，候选怎么来归 `core-identify`，选中了谁归 `core-sublibrary`。

## 三层内容与附属

作品 → 发行版 → 变体，加合集与收藏的投影（`adr-0011`）。三层各自的判断都在别的规格里，这张表只保证它们并存、可查、可重建。

## 整份可再生

**装的全是工具自己算出来的东西**，所以结构一变就让用户删库重扫（`SCHEMA_VERSION`），省下一整套迁移代码。代价是：**任何不可再生的东西都不许放进来**——裁决、收藏、合集成员、人工纠正住在沉淀库（`core-verdict`），这里只留它们的投影，重扫之后照沉淀库重建。

这条边界一旦破了，「删库重扫」这个便宜买卖就没了，所以它是这一份规格里最硬的一条。

## 键与增量

- 键是**根名 + 相对路径**、NFC（`core-path-fs`）；一个主库可以有好几个根，加根不动已有键。
- 扫描这一趟用一个**扫描代号**：中断续跑沿用同一个，收尾时靠它判断哪些条目「这次没见到」。
- **不可读是第三态**（`adr-0021`、`core-scan`）：表里得留得住这个状态，长度分得清「空」与「不知道」。
- 成型跑在库上、不跑在遍历途中（`adr-0022`）：所以 `scan` 收尾会触发一次成型，而 `shape` 也能就地重来。

## 查询面

浏览（排序/筛选/分页**推到 SQL**，不在内存里筛）、筛选（一棵**组**编译成 `WHERE`）、详情、前端快照与底本。筛选跨平台与征集成员关系共用同一张表——「收藏=是」与「合集=通关过的」不许长出两个求值器，否则屏上筛出来的那批与同步真正搬过去的那批会分家（`core-sublibrary`、`core-sync`）。

## 不在这儿的东西

导入底本（前端原文件副本）与导出取数住在这里，但**写**出去的动作归 `core-adapter`；媒体不在库里，在**媒体池**（`core-scrape`）。
