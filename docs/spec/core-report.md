# 库体检（`report`）

**职责**：把扫描累积的状态整理成可读、可存档的结论——有什么、多少、什么形态、哪些不该在这。同一份结论两种形态：给人看的文本与给界面与后续判断吃的 JSON。

**边界**：**只发现并报告**，不动盘上一个字节。覆盖面大于识别：未纳入管理的目录照样出现，那是人工整理的依据。它一个字节都不读主库——外置盘不在位时照样出报告。

## 报告里有什么

- 每一类内容的占比（透明容器 / 压缩镜像 / 裸文件），回答「识别管线会走哪条路为主」。
- **目录与内容平台不符**：与库体检那几组、平台纠正、识别报告那一栏数的是同一个数（`adr-0024`）。
- **不可读**那一档单独列（`adr-0021`）——既不算已变也不算已删。
- 成型存疑、附属文件落单（`core-shape`）。
- **疑似同一作品**以及其余整理建议（`core-triage`）。
- **重复拷贝**：同名且同大小，同库内或跨库都算；这是近似判据、不读字节，屏上照实写并请人动手前自己看一眼。只列容量最大的前几组，完整明细**单独导出**，不塞进报告——大多数场景用不上它，塞进去只会让报告膨胀。

## 与处置的关系

报告给的是下一步该动哪里的材料；真动手处理走各自的**正门**：成型走人工纠正、平台走平台纠正、重复拷贝人自己去删。报告里不出现「一键修复」这种把两类动作混成一条路的东西（`adr-0004`）。
