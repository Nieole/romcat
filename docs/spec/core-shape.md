# 成型（`shape`）

**职责**：按**成型规则**把磁盘上散落的文件聚成**变体**，并认出多碟同族、报出成型存疑与附属文件落单。

**边界**：跑在中立库上，**不跑在遍历途中**（`adr-0022`）——所以规则改了不必重扫主库，`romcat shape` 就地重来。它不改盘上一个字节：成型是库上的纯函数，变体表整批换。

## 三件事

- **聚成变体**：平台的成型规则说这一堆文件怎么算一个变体，谁当**主文件**（一个变体可以是一整棵目录，比如 `PS3_GAME` 所在的那一层）。
- **多碟同族**：名字末尾的碟片标记剥掉之后完全相同、至少一个真带标记，才合；分在几个目录里的不算。合完之后一个变体只有一个主文件，别的碟的主文件是附属文件，而**能力档案判的是每张碟的主文件**（`core-capability-convert`）。
- **只发现并报告两类毛病**，不自动修：**成型存疑**（多碟没合、或者一个目录被当成了一个变体）与**附属文件落单**（存档与补丁在自己那个目录里找不到同名主文件）。判断只在核心库一处（`adr-0024`），界面不另判。

## 人工纠正与「待生效」

人把这一处**拆开**、合并、改归属，落的是**人工纠正**——住沉淀库、键是路径锚（`core-verdict`）。它**攒着**：每纠正一处先落一条**待生效**记录，屏上累计「N 处待生效」并说清眼下看到的还是旧的成型结构，人按一下「重新成型」才跑一趟全库。

**成完一趟型就生效**：不论是那颗按钮、扫完一遍根，还是命令行 `shape` / `scan`，记录随之清掉。这个「攒着」不是省事，是因为成型是整份条目表的纯函数、没有「只重算这一处」这回事。

## 与其他域的分工

- 走哪条成型规则由平台清单答（`core-platform-filename`）。
- 一个变体是不是多碟、各张碟是哪几份，由这里答；前端用不用得上由适配器答，模拟器吃不吃由能力档案答（`core-sync` 的播放列表三处各答一问）。
