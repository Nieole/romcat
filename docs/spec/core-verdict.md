# 沉淀库（`verdict` + `collection`）

**职责**：**用户亲手定的东西**住的地方——裁决、收藏、合集成员、人工纠正。把文件哈希直接钉到发行版、汉化组与版本上，补的正是 DAT 覆盖不到的中文汉化部分，可导出分享。

**边界**：它是**唯一不可再生的库**，因此与中立库的分工是硬的：中立库删得、这里删不得，走顺序迁移、永不要求删库、认不出比程序更新的库就拒绝打开。它不认识前端格式，也不决定导到哪儿。

## 键分两族，不是一族

- **内容锚**：拿得到内容判据的都走这一族——裁决、收藏、合集成员。换机、改名、挪目录都还认得出，**可导出分享**；两块盘接着同一台机器，裁决一次两边都受益。
- **路径锚**：拿不到内容判据的走这一族，键是**主库标识**加那条键——成型的人工纠正与平台纠正。一整棵目录树没有哪一份字节代表得了它，所以这一族**熬得过删库重扫，熬不过改名与挪目录**，默认不随导出带走。

换个锚点就是换一条结论管多大范围，所以这不是实现细节。

## 里面有什么

- **裁决**：候选之间选定的那一个，或「都不对」。撤销以**一批裁决**为粒度。
- **收藏与合集**：同一套成员关系。一个合集是用户自己起名的一组游戏，收藏就是名字定死的那一组——**一个模型，一套函数**，不许长出两个求值器（否则屏上筛出来的那批与同步搬过去的那批会分家）。它是规则的维度之一（`core-sublibrary`），在中立库里只是投影。
- **人工纠正**：成型那一族（待生效，`core-shape`）与平台纠正（键是主库标识加一对平台）。
- **审计**：收回清单（把设备上被改过的文件重新纳入工具的行为边界）留一笔账：谁、何时、哪几份。

## 不许放进来

**用户状态**不出现在这里，也不出现在任何库里：前端的游玩次数、通关状态、它自己的收藏，只从底本原样搬运，绝不生成、绝不覆盖（`adr-0006`）。词表里那个**收藏**与此同名不同物——它长在沉淀库里，是用户对着这个库做的一次挑选。
