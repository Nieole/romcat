# 识别（`identify`）

**职责**：判定一个变体对应哪个**发行版**，并给出候选、置信度与**依据**。输入是文件本身的字节，不是文件名。

**边界**：只下结论、不落裁决——拿不准的进待确认队列由人裁（`core-triage`）。也**不决定刮削**：识别错了刮削再准也是错的，顺序是死的（`core-scrape`）。

## 分层，一层比一层弱

1. **撞 DAT**：零解压穿透容器算内部哈希，两种口径（带 header / 去 header）各撞一遍；光盘读 ISO9660 与序列号，卡带读内部头（游戏码、CGB 标志），Switch 读 PFS0/HFS0 明文名表撞 TitleID 库。这一层用的是 `core-sources` 的弹药。
2. **序列号与头部**：撞不上 DAT 时按平台标识再试一次，命中一律**降级**，不许自动通过。
3. **文件名 + 中文离线源**：字符层面已经说不出话时，用**正题**做模糊匹配，中文源那一条带交叉校验。
4. **模型推断兜底**：最低一档，**永不自动通过**、置信度永远低、依据里写明这是推断（`adr-0002`）。它是核心库里唯一一处除刮削之外的联网，价钱按 TOML 里的价目算。

## 结论的形状

- **四档结论**：命中 / 未命中 / **无判据** / **跳过**。跳过说的是「这个变体不该撞 DAT」——补丁，以及没有发行版链接的变体（homebrew、同人移植）。把跳过混进未命中会把命中率说低。
- **还没识别**（连跑都没跑过）与**没有候选**（跑过了、一个字都没说）是另外两条轴上的事，两者都不属于那四档（`adr-0024` 的口径：报告与界面读同一处）。
- **自动识别只做到发行版级**（`adr-0008`）：汉化组与第几版靠文件名启发加人工裁决。
- **官中与数字世代**：有独立序列号的世代里官中是一个独立发行版；数字世代（Switch）共用 TitleID，中文只是语言属性（`adr-0019`）。

## 平台的三种说法

目录声明的、识别判定的、人纠正的——三种各有名字、各有用途，不许拿一种顶另一种。回退链只有一处（`platform_of`）：**纠正说了的听纠正，没纠过的看卡带头，都没有才退回目录声明的**。打分、刮削、两份报告按识别判定的平台；导出与同步的落点听纠正、否则听目录；分歧只在库体检里报，不自动搬家（`core-report`）。

## 已知局限

- 模型推断这一档的结论不可复核到字节级，因此它是兜底而不是主力。价目表与开关在 `identify/pricing.toml`，默认档一样不发请求。
