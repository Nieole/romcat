# 扫描（`scan`）

**职责**：只读走完一个主库根，把看见的东西落进中立库，并留下这一趟的**遍历**记录、断点与后续判断要用的聚合（每一类内容的占比、目录与内容平台不符的组）。

**边界**：只碰主库的读面（`core-path-fs`），只写中立库。**成型不在这里发生**——扫描收尾调用一次成型，而成型是库上的纯函数（`adr-0022`）。

## 一趟扫描里成立的事

- **只读**：文件一个字节不改；不 touch 时间戳（`adr-0004`）。
- **分三档不是两种**：读得到、读不到（**不可读**）、这次没见到。第三态不许塌成「已删」，长度不许拿 `0` 充数（`adr-0021`）；删除只在**完整**遍历之后才判。
- **能打断、能续跑**：断点记录这一趟走到哪儿，重跑沿用同一个**扫描代号**。被打断时照旧要收场，留下断点——那是下一趟接着跑的依据（`adr-0015` 的「部分完成」口径）。
- **并发按介质定**：先探一次这块盘是机械、SATA SSD 还是 NVMe，再定并发；同一块盘的不同区域可能落在不同档上。实测的吞吐与并发记在 `ref-library-facts`，这份规格不抄数。
- **顺手做两件便宜的分类**：内容分类（`core-classify-container`）与头部抽样（`header` 只回答「头部解析在真实文件上能不能用」，不做识别）。

## 聚合出来的东西

- 每一类内容各占多少——体检报告「识别管线会走哪条路为主」那一栏的原料。
- **目录与内容平台不符**只有一处判：扩展名、卡带头、GB/GBC 的 CGB 标志三样取并集，有一样说不符就算；扩展名与卡带头说的不一样时记卡带头说的。库体检那一格、平台纠正那几组、识别报告那一栏数的是同一个数（`adr-0024`、`core-report`、`core-identify`）。
- 未纳入管理的目录照样出现在体检里：报告的覆盖面大于识别的覆盖面。

## 入口

`scan::scan` 是这一域的唯一入口，两个调用者：命令行 `romcat scan` 与界面的根那一屏。界面那一侧递的是 `&dyn LibraryFs`，所以测试与预览能喂内存里的假盘。
