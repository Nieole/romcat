# 平台清单与文件名规则（`platform` + `filename`）

**职责**：两份**声明式配置**加两份读它的代码。平台清单说这个工具认识哪些平台、每个平台的目录名、扩展名族、多碟同族规则与成型规则；剥离规则说怎么把一个文件名剥成**正题**加汉化组、版本、噪音词。

**边界**：都不做判断之外的判断。平台清单不决定「这个文件的平台是什么」——目录是**强先验而非权威**，内容可以推翻它（`adr-0011`），回退链在 `core-identify` 一处。剥离规则不决定「这是汉化版还是官中版」——那是 `core-title` 与裁决那一侧的事。

## 平台清单（`platforms.toml`）

- 数据不是代码：加一个平台是改 TOML，不是改 Rust（`adr-0014` 与成型规则同一条路）。
- 每个平台声明：目录名怎么折、扩展名只可能属于谁、多碟同族的碟片标记、成型规则。
- 覆盖范围与「哪些平台还没有调研」以 `ref-platforms` 为准，这份规格不抄那份清单。
- 平台与合集**正交**：SFC 是平台，「我通关过的」是合集（`adr-0011`、`core-verdict`）。

## 剥离规则（`rules.toml`）

剥出来的是**正题**，拿去模糊匹配；同一条规则不许再兼职干第二件事——汉化组与第几版**不从文件名剥**，那是识别不出来时的第三个答案，正是 `adr-0024` 要堵的（`core-title`、`core-triage`）。

## 与识别的分工

目录声明的平台是扫描的输入，中立库原样留着，纠正也不回写它；它是「目录与内容平台不符」的对照物。识别判定的平台另存一列，两列不许互相顶替（`core-identify`）。
