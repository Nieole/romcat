# 同步（`sync`）

**职责**：把子库的目标状态与目标设备的实际状态对齐——**三方对比**：主库该有的 / 清单记录的 / 目标上实际有的。它也是这个工具**唯一往别人盘上写**的地方。

**边界**：只动**清单**记过的那些文件。清单之外的一律不碰，这是工具在目标设备上的行为边界，不是礼貌（`adr-0015`）。主库那一侧仍然只读。

## 计划就是预览

**排出来的计划本身就是差量预览**，不是两份可能分家的东西：屏上看到的就是要执行的那一份，执行那一侧不接受「另排一份」的计划。因此预览里每一档都要说得清工具**不会**做什么。

- 一排五个大数字：**新增**、**删除**、**不动**、**异常**、**放不进目标**，数的是文件数；底下一行补上「更新」那一档（不并进新增）与每类涉及几个**变体**（人认得的单位是变体）。
- **异常五栏**，一栏一类：设备上缺失（默认不补）、被修改过（不覆盖也不删除）、目标位置被占用（清单之外的文件，不碰）、元数据读不到（第三态，既不算在也不算不在）、放不进目标（落点撞车、超单文件上限、文件名不收的字符、路径太长）。五栏的名字与每栏那句「不会做什么」由核心一处答（`adr-0024`），命令行与界面印同一份。
- **落点撞车一个都不放行**：留一个放行等于随排序决定谁赢，下一趟排序变了赢家就换人。

## 播放列表与「没上卡」

多碟变体同步到卡上时旁边生成一份 `.m3u`，前端条目拿它启动；每张碟的主文件各写一条藏起来的条目。三处各答一问：是不是多碟、各张碟是哪几份由成型答（`core-shape`），前端用不用得上由适配器声明，模拟器与卡吃不吃由能力档案答（`core-capability-convert`）。

**主文件放不进目标、卡上又没有播放列表接住的变体算没上卡**：前端元数据里不列它、媒体也不铺；设备上缺失、这一趟又不补的同样算没上卡。差量预览另起一行说「前端里也不列它们。」

## 收场

会写东西的活被叫停时照旧要收完：**清单**是下一趟接着跑的依据，抛错会把它丢掉。所以这一档是**部分完成**——产物与跑完的那份一样，留下了什么由那个长入口自己说。

## 与导出的分工

同步对齐的是子库与那台设备上的实际状态；**导出**到主库那一侧没有目标设备、没有清单，也没有放不放得下这回事，照旧全列（`core-adapter`）。
