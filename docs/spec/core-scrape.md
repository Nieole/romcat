# 刮削（`scrape`）

**职责**：在识别结论之上取标题、简介、年份、开发商、封面等元数据与媒体，并判断这一趟值不值得跑。

**边界**：识别错了刮削再准也是错的——这一层不回头认游戏。它也不挑谁进子库（`core-sublibrary`），只把值存进中立库、媒体存进媒体池。

## 两档采法

- **离线档**：一个网络请求都不发，来源是本地数据源与 DAT（`core-sources`）。默认档。
- **在线档**：赌的是账号与 IP（`adr-0007`），默认限流，未识别的变体一个请求都不发。在线源是**唯一**不可替代地提供图的地方。

**采法是「补缺」与「重采」两档**，它管跑多久、花多少配额，不管显示哪个值：只想换一个值不是重采的理由。

## 输入指纹

一个源对一个**锚点**这一轮的全部输入折成一串字，与上一轮一样就不再采它。所以它**必须盖住一切会改变结果的输入**——漏一样，那一样变了也不会重采。它盖不住的只有一样：源自己的读法变了，那正是重采的出口。

## 锚点与并存

刮削结论挂在**作品名**或**变体的键**上；不同源给出的同一个字段**并存不覆盖**，谁的值更靠前由优先级配置决定（`priorities.toml`，数据不是代码）。作品的简介与封面默认挂作品这一层，不是挂在每个变体上。

## 媒体池

按内容哈希存放全部封面、截图、视频，位于本机；**文件名不是媒体的主键**。导出与同步铺进前端媒体目录时由它铺，优先硬链接、不支持时降级复制（`adr-0009`）。

## 先算账再跑

界面与命令行在同一处取预估：这一趟要发几个请求、大概多久、多大空间。估不出来就说估不出来，不拿一个好看的数糊弄（`adr-0024`）。
