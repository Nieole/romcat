# 适配器（`adapter`）

**职责**：把某一种前端格式与中立库对接的自包含模块——读、写、字段映射，以及两件必须先声明再动手的事：**能力档位**与**结构性损失**。当前两族：Pegasus 与 ES-DE（gamelist.xml，安卓那几家复用同一套）。

**边界**：只写元数据文件、点名要铺时再铺媒体目录，**一个 ROM 都不搬**（`adr-0004`）。导出目录在语义上是主库根的**替身**：元数据里的相对路径相对它自己所在目录解析，所以放进主库根路径直接就对。导出**不是同步**：没有目标设备、没有清单，也没有「放不放得下」这回事。

## 两个声明

- **能力档位**（`adr-0003`）：只读 / 只写 / 双向 / **无损往返**，对用户可见。它答的是「这个格式能不能双向走、写回去一不一样」。
- **结构性损失**：把一个值交给这个格式存一趟，格式**自己**会把它改成什么样，逐条声明出来，导出前才看得见。它挂在格式上，与手上这份库里当下有没有这样的值无关；**清单是空的意思是「还没查过」**，不是「什么都不丢」。

两档分工不同，不许拿一个顶另一个。

## 无损往返怎么做到

导入前端元数据时留下一份**底本**——原文件的完整副本。中立模型表达不了、或者格式会吞掉的部分，导出时从底本还原。这是「读一趟写回去与原文件等价」的机制，不是尽量。

## 收敛

导出时把同一作品的多个变体并成前端里的**一个条目**：一个条目、多个文件、默认启动**首选变体**（汉化 > 官中 > 日版 > 其他，可被裁决覆盖）。整库级、不挑选。这一条与「合并作品」不是一回事——收敛不改库里的归属。
