# 成型跑在中立库上，不跑在遍历途中

**成型规则**要看的是一整棵子树。PSV 的 `app/<TitleID>` 与 `patch/<TitleID>` 是同一个**变体**的两半；`游戏.cue` 与 `游戏 (Track 02).bin` 是同一个变体的两块；三张碟分在三个兄弟目录里，也还是一个变体。

而遍历是多线程、乱序、可中断的（票 01 的队列）：一个工作线程手上只有一层目录，谁也不知道兄弟目录里有什么。把成型塞进遍历，就得让线程之间互相等对方的结果——那正是当初用队列避开的东西。

## 决定

**成型是中立库上的一遍纯计算**：输入是 `entry` 表的键、类型与大小，加上人工纠正表，输出是变体。它由 `shape::plan` 这个纯函数完成，`shape::reshape` 只负责读库、算、整批写回。

- **只在完整扫完一遍之后跑**，理由与「删除只在扫完之后判」同源：半个库上成出来的变体是错的。一份 PSV 转储只扫到 `app/` 就成型，`patch/` 那一半会在下一趟变成第二个变体。
- **`romcat shape` 可以单独重跑**，一个字节都不读主库。改一条成型规则不必重扫 8.6 TiB。
- **变体表整批换掉**，但 `work_id` / `release_id` 与合集成员**保住**：那是裁决攒出来的，改一条规则不该把它们冲掉。

## Consequences

- **成型完全测得动**：它是键的纯函数，单元测试不必碰磁盘，也不必造真实字节。
- **中立库多了五张表**：`work` / `release` / `variant` / `variant_member` / `shaping_override`，外加与平台正交的 `collection` / `collection_variant`。结构版本从 2 升到 3。
- **一条硬闸：变体根绝不上溯到平台目录本身。** 少了它，一个直接躺在 `PSV/` 下的 TitleID 目录会把整个平台吞成一个变体——十几万个文件归到一条记录上，比不成型还糟。
- 报告因此能同时说出「库里有多少文件」与「库里有多少个变体」，两者之比是判断成型规则有没有生效的唯一办法。

## 顺序不交给配置

平台条目里的 `成型` 列表只说**用哪几条**规则，不说先后。先后由成型器定死：**目录树 → 同名成组 → 多碟同族**。

三步之间有真实的依赖：目录树认下的子树里，文件已经是**内部资源**，不该再被同名成组捡一遍；而多碟同族合并的是前两步的产物。把顺序交给配置，只会让人写出跑不通的组合，而错误要到报告里才看得出来。

## 规则里的名字模式不用正则

「TitleID 目录长什么样」「碟片标记长什么样」是随平台变的知识，必须留在配置里（`docs/platforms.md`：平台清单是数据不是代码）。但为它引一个正则引擎太重——真正要表达的只有三件事：一位数字、一位字母、后面随便还有什么。

于是有了 `platform::pattern`：`#` 一位数字、`@` 一位字母、`*` 任意尾巴，其余字面量且大小写不敏感。四十行，测得动，写不出灾难性回溯（`*` 的个数有上限）。

代价是表达力有限。真出现表达不了的规则时，加一个记号比引一个正则引擎便宜——**但要先出现**，不要预先加。
