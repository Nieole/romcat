# 子库的格式转换由设备能力档案驱动

调研确认「原样拷贝」不安全，而且不存在一个「最兼容」的统一格式：RetroArch 不支持 rar；PPSSPP 不支持 ZSO 与 CSO v2（对应 issue 已 closed as not planned）而 PCSX2 反而支持 zso；Dolphin 支持 rvz/wbfs；DuckStation 支持 chd。zip 对卡带类可行，光盘类则没有统一答案。

因此每个子库声明它使用的前端与核心，工具查内置能力矩阵决定每个平台的目标格式（rar→zip、ZSO→CSO v1、cue+bin→chd 等），用户可手动覆盖。差量预览中列出哪些需要转换及预估耗时。

## Consequences

- **能力矩阵会随模拟器更新而过时**，必须维护。维护错误比不转换更糟——用户会以为工具已经处理妥当，直到在掌机上打不开才发现。矩阵应标注数据来源与核实日期。
- **转换产物默认不缓存**，边转边流式写入目标。转换很贵（解压加重压缩，512GB 子库可能数小时），而缓存要再占一份等同空间。多设备共用相同格式时可另开一个可选的转换缓存目录。
- 转换发生在导出侧，主库始终保持原始形态（见 ADR-0004、ADR-0015）。

## 补充：能力档案还须涵盖目标文件系统约束

能力档案不能只描述模拟器支持哪些格式，还必须包含目标存储的限制：

- **FAT32 有 4GB 单文件上限**，PS2 / PSP 的大 ISO 直接放不进去——这类情况必须在差量预览阶段就报出来，而不是传到一半失败。
- exFAT 与 FAT32 均不支持硬链接，媒体一律复制。
- 目标文件系统的文件名字符限制与路径长度限制同样需要检查。
