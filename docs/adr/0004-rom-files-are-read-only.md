# v1 对 ROM 文件只读

识别对汉化版是有损的（见 ADR-0002），而重命名、移动、去 header、重新压缩这些「整理」操作不可逆、作用于 10T 真实数据，且会打断其他设备上前端已记录的路径。拿一个可能错的识别结论去改真实文件，是这个项目里唯一能造成真正损失的动作。因此 v1 只写元数据文件与媒体目录，ROM 文件一个字节都不改。

## Consequences

- 文件名混乱不靠改文件名解决：前端显示什么由元数据里的 `title` 决定，文件叫什么无所谓。整理文件的实际收益远小于直观感受。
- 去重只做「发现并报告」，不做「自动删除」。
- 整理能力不是永久放弃，而是排在识别质量被实际验证之后。放开时必须配套：干跑预览、仅限高置信条目、可撤销日志。

## 修订：查不出主库的根时，守卫退到字节级底线（2026-09-23）

「不许写进任何一份主库」那道守卫要先从中立库里查出每个主库的根，才知道一条输出路径落没落进主库。
中立库住的那个目录**读不动**时，根查不出来。从前这一支**放行**（与「开不动的那几份跳过：宁可少挡一次，
也不能挡错一次」同一个口径）——可那道守卫后面是一次**覆盖写**，放行的极端情况就是把一份 ROM 盖掉。

**因此：查不出根时只放行新建文件，目标已经存在就拒绝，并说明是因为查不出主库的根。**
这条红线的本义是 **ROM 一个字节都不改**，不是「主库里不许多一个文件」：新建一份文件碰不到任何已有的字节，
拒绝覆盖就把两条判据都守住了，而「开不动的那几份跳过」那套口径不用翻（拿主意的人定，挂单 `Q616`）。
