# 工具完全不管理用户状态

收藏、游玩次数、游玩时长、通关状态这类数据是用户在前端里玩出来的历史，覆盖掉就真的没了；而各前端的存放位置极其分散（Pegasus 在 `favorites.txt` 与 `stats.db`，ES 在 gamelist.xml 内，LaunchBox 在库文件里），多设备并用时还存在无解的合并语义。因此工具既不读也不写用户状态，全部交给前端自己管。

## Consequences

- 换前端或重建库时，多年积累的收藏会丢失。这是明确接受的代价。
- **「不碰」在 ES gamelist.xml 上不是省略而是搬运**：`favorite` / `playcount` / `lastplayed` 长在同一个文件里，导出时若省略这些元素等于把它们清零。必须从导入快照里逐条原样搬过去。这再次说明三方合并与快照是必需的，不是可选优化。
