# 媒体存中央池，导出优先硬链接并在不支持时降级复制

各前端的媒体目录互不兼容（Pegasus 用 `media/`，ES-DE 与 Cocoon 用 `downloaded_media/<平台>/<类型>/`，Batocera 用 `images|videos/` 加文件名后缀而非 `media/`，RetroArch 用 `Named_Boxarts/` 加净化后的 label），而且媒体的匹配键在各格式间横跳（ROM 文件名 / 标题 / label），净化函数多对一不可逆。因此媒体一律按内容哈希存进中央池，由中立库记录映射，导出时再按目标格式铺设。

## Consequences

- **文件名不能当媒体的主键**，映射只存在库里。
- 导出必须先**探测目标文件系统**：同卷且支持硬链接就链接（零额外占用），否则降级复制。这不是优化项而是必需项——外置盘常见的 exFAT 既不支持硬链接也不支持符号链接，NTFS 在 macOS 上默认只读，网络盘同样不行。缺了探测与降级，工具在用户的真实磁盘上会直接失效。
- 中立库与媒体池存放在本机而非外置盘上。外置盘不常挂载，库若跟着盘走，盘不在时连浏览和编辑元数据都做不了。扫描是唯一需要盘在位的操作。

## 修订：主库 NTFS 支持硬链接，子库侧必须复制

用户主力机为 Windows，外接硬盘为 NTFS。

- **主库侧链接方案可行**：NTFS 支持同卷硬链接，媒体池导出无需退化为复制。
- **子库侧必须复制**：SD 卡通常格式化为 exFAT 或 FAT32，两者都不支持硬链接。ADR-0009 原本设计的文件系统探测与自动降级在这里正是必需路径。
- **NTFS 的 mtime 精度为 100 纳秒**（exFAT 仅 2 秒），主库的增量扫描依据 `(路径, 大小, mtime)` 是可靠的。
