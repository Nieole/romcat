# 界面自足，命令行是后台入口

ADR-0005 定下「核心必须是独立的库 + CLI」，理由是 10T 规模的扫描迟早要挂后台或扔到别的机器上跑。**那条理由今天仍然成立，但它从来没说过「第一步必须在命令行」**——两件事在实现里被合成了一件，于是界面长成了一个装不下完整流程的壳。

用户的原话：

> 其实 CLI 只是可以方便地挂后台进行扫描，但是对用户来说，更多的操作都是在进行数据的整理，所以我肯定期望可以从 GUI 开始第一步操作。

## 现状：界面离不开命令行

**开不了第一份库。** `Site::open` 在 `catalog.exists()` 那一步就挡下（`crates/core/src/site.rs:68`），报的是「还没有 X 这份中立库。先跑一次 `romcat scan`」。三种给法（主库根 / `--library` / `--catalog`）全都要求库**已经存在**，界面因此没有任何从零开始的路。

**主干七步断三步。** 把流程摆开看：

| 步 | 命令 | 界面 |
|---|---|---|
| 扫描（内部已带成型） | `scan` | ✅ 库屏 |
| 识别 | `identify` | ❌ |
| 刮削 | `scrape` | ✅ 刮削面板 |
| 折标题 | `titles` | ❌ |
| 裁决 | `triage` | ✅ 队列屏 |
| 导出 | `export` | ❌ |

**成型不在断点里**：扫描内部就调了 `shape::reshape`（`crates/core/src/scan/mod.rs:537`），`romcat shape` 只是「改了成型规则之后就地重来」的独立入口。

**界面里有四处硬编码指着命令行**：队列屏三处「先跑一次 `romcat identify`」（`crates/gui/src/queue.rs`），浏览屏一处「它下一趟重折（`romcat titles`）之后……」（`crates/gui/src/browse.rs:988`）。`export` / `import` / `adapters` / `switch` 在 `crates/gui/src/` 里零出现。

## 决定

**界面自足：从第一步起，全程不必开终端。** 命令行保留，定位收窄成两件事——把长活挂后台（扫一趟真库 37.1 分钟），以及在另一台机器上跑批（ADR-0018 的双机工作流）。

**不搬全部命令。** 判据一条：**不做这一步、下一步就没法做的，必须在界面；「看一眼」与「改规则」的，留在命令行。** 按这条，`import`（一次性迁移）、`adapters` / `platforms` / `report`（只读）、`switch` / `names`（低频配置）留在命令行，它们一个都挡不住干活。

反面教材是这个仓库自己踩过的：`.scratch/gui-redesign/spec.md` 诊断旧三屏时写的是「**这三屏是照命令行的命令结构切的**，于是成了三种互不相通的选东西的办法」。把十七个命令一个不落搬成屏，是把那个病按六倍规模重犯一遍。

## 开场：五屏之外的那一屏

**新增一屏，叫开场**，产物是词表里已有的**现场**（中立库 + 沉淀库 + 主库在路径锚里的名字）。它交出 `Site` 之后自己退场。

**为什么是独立一屏，而不是让库屏处理「还没有库」**：`App::new(site, …)` 拿的是一个**已经开好的** `Site`，五屏全建立在「库一定在」这个前提上。让库屏兜住空态，就得把 `Site` 变成 `Option<Site>`，那个 `Option` 会渗进五屏每一处判空——为一个只在冷启动出现一次的状态，让全程都背着它。挡在 `Site` 之前，五屏一行都不用改。

**「新建」走一条龙向导**：起主库名 → 选第一个根 → 开扫。**领域判断一条都不许长在向导里**：加一个根要拦的三种情况（重名、套在一起、圈进工作目录）全在 `catalog::roots::add_root`，向导重画 UI，但必须调同一个函数。这是 ADR-0005 那条红线的直接应用——两套判断只会分叉出两套行为。

**晚落盘**：前两步只在内存里攒，按下「开始扫描」才 `Catalog::open`（它是打开即创建）。中途关窗，磁盘上什么都不留。**重名在第一步就拦**，靠 `workspace::catalog_path()` 折出来的文件在不在，而不是等到最后一步落盘时才发现。

零根的库仍然是合法状态——`Roots::is_empty()` 是公开 API，`library_root` 表的注释特意区分「没扫过就一列都没有」与「扫过但一个条目都没有」——晚落盘不是因为零根非法，是因为**一份零根空库对人没有用处，却会永久占着开场那一行**。

## 主库的名字要落盘

**建库时把主库原名写进 `meta` 一行。** 现在它没有落点：中立库文件名是 `{readable}-{16 位哈希}`，而 `readable()`（`crates/core/src/workspace.rs:157`）会滤掉 `/ \ : * ? " < > |` 与控制字符、**截断到 24 个字符**、全滤光时退成 `library`，哈希那半段更不可逆。名字只活在人敲过的那行命令里，忘了就再也拿不回来。

`meta` 是 key-value 表，加一个 key 是**纯加**——按 `crates/core/src/catalog.rs:99` 定的判据（**改了已有表的列或含义才加 1**），这不构成结构版本加 1，旧库拿新程序打开照样能用，读不到那行就退回从文件名截取。

## 记住上次开的那份

**开场屏不该每次都挡在前面。** 记住上次那份中立库的**完整路径**，下次直接开它进主窗口；开场只在两种时候出现：记的那份打不开了（挪走、删了、结构版本对不上），或人主动要换。

记路径而不记工作目录，是因为 `workspace_of()` 已经存在（`crates/gui/src/site.rs:84`，从 `<工作目录>/catalog/某某.sqlite3` 反推）——记一条，工作目录是白拿的，也不会两样对不上。

这份记忆**不属于任何工作目录**：所有偏好都住在工作目录里（版式偏好是 `<工作目录>/gui/layout.txt`），而「工作目录是哪个」没法住在工作目录里。它是程序级配置，位置固定取 `workspace::default_dir()` 的结果——于是在 Windows 上它落在 `%APPDATA%\romcat\`，**那恰好也是默认工作目录**。同一个目录下住着两种东西，不会出错，但读代码的人会绊一下，注释里要写明白。

## 工序：库屏的第三段

**库屏长出第三段，叫工序**：这个库要走的那几道步骤——识别、折标题、导出各一行。**工序是那道步骤，任务是跑那一趟**；点一道工序的按钮，排一趟任务上台。

**这不是往库屏硬塞东西。** 那一屏的自述是「这个库由什么构成——让识别能干活的**原料**」，设计理由写着「新用户最容易卡的『扫完了怎么没认出来』，在这一屏上一眼看得见」（`crates/gui/src/roots.rs` 开头）。而那个问题的答案有两种：某个数据源是空的（已经画着了），或者**识别根本没跑过**（现在这一屏看不见）。第三段是把它自己许诺过要回答的问题补完。

**每一行显示「还差多少」，不是「上次几点跑的」。** 日志式没解决真正的问题——人要的不是时间戳，是「下一步该干什么」。识别那一行就是「N 个变体连识别都还没跑过」，而**这个数现在就有**：`Queue::not_run()`，队列屏已经用警告色画着它，命令行 `triage list` 印的也是同一份报告（`triage::report::QueueReport`）。折标题与导出的度量要新造；某一支的度量一时造不出，那一行退回显示时刻——比为了整齐把现成的那支也降级好。

**各屏空态给捷径**：队列屏那句「还没跑过识别」旁边直接放按钮。但那是**同一趟活的第二个入口**，调同一个函数、排同一趟任务，不是第二份实现。人是在队列屏发现「没识别」的，让他跑回库屏是多余的一步。

## 导出摆在工序段，不当子库

`romcat export --out <目录>` 是**整库级**，没有任何「只导这一批」的参数；`--out` 的语义是「**主库根的替身**」——元数据文件里的 `file:` 相对它自己所在目录解析，中立库的键相对主库根，所以文件放进主库根路径直接就对。**它只写元数据，一个 ROM 都不搬。**

**不把它做成一个特殊子库**，虽然子库屏那套（差量预览、清单、容量条）看着能复用。词表里子库是「从主库挑选**一部分**导出到某个**目标设备**形成的**派生库**」，而导出三个限定词一个都不满足：不挑选、没有目标设备、不是派生库。硬塞进去，「子库」就从「给掌机的一份派生」稀释成「任何一次往外写」，而**清单**——「工具在目标设备上的行为边界」——在主库根上根本没有边界可划。

导出的配置（格式、输出目录）跟主库名同一处，存 `meta`。

## Consequences

- **界面新增两处落点、核心库新增三样能力**：开场屏与工序段是界面的活；核心库要新增「列出一个工作目录里有哪些中立库」（`crates/core/src/workspace.rs` 现在一个列举函数都没有）、折标题与导出各自的「还差多少」度量、以及 `meta` 里那两组新 key。
- **识别、折标题、导出三个长入口要接上任务台**：办法与已接的那五种一样——核心那侧收一个 `task::Handle`，界面这侧往 `Board` 上排一趟。`task::Product` 因此长出三支。
- **命令行一行都不用改，也不会被弃用。** 它与界面走同一个核心库、同一份现场、同一套路径锚，命令行裁的界面看得见，反过来也一样。
- **四处硬编码的文案要改**：队列屏三处、浏览屏一处，从「先跑一次 `romcat identify`」改成指向工序段的那个按钮。
- **开场屏要面对打不开的库**：结构版本对不上的旧库仍然会列出来，但要当场说清「版本 4，本程序认 7，删掉重扫」，而不是从列表里静静消失——用户机器上现有三份这样的库。
