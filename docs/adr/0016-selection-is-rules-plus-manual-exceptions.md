# 选择集 = 可重放的规则 + 优先于规则的手动例外

主库 7.5 万条目、10T，掌机 SD 卡 512GB。纯手动勾选两千个不现实；纯规则又表达不了「这个我小时候玩过」「这个太占地方先不带」这类个人口味。因此选择集由规则打底、手动例外覆盖，**例外优先于规则且永久记住**。

规则的价值在可重放：主库新增了符合条件的游戏，下次同步自动进，不必重挑一遍。多设备时这个收益乘以设备数。

## Consequences

- **同步前必须预览差量**，且这是硬要求不是优化项。规则一改可能几百个游戏进出——要新增多少个多少 GB、删除多少个腾出多少 GB、净变化多少，全部先摆出来。永远不能「点了同步就开始传」。
- **容量超限不自动截断**。规则选出 800GB 而卡只有 512GB 时，明确报出超出量并给按体积排序的裁剪建议，但由用户决定砍谁。自动截断的结果不可预测——同一套规则在两张不同容量的卡上会得到完全不同的结果，而用户无从得知它砍掉了什么。
