# 一个领域判断只有一处实现

ADR-0005 有半句写着「两处各挑一次迟早挑出两个答案」，可它挂在**界面那条红线**底下
（领域判断不进界面层），没人拿它管核心库内部。于是核心库内部反复长出第二个判据。

**这条 ADR 把那半句提出来，管到全仓：一个领域判断只许有一处实现，谁要用都从那一处取。**

## 这不是假想的病，有账可查

第四轮收口把 68 条仍然成立的长期挂账逐条对着代码核了一遍，**11 条有代码在催**
（判据严格：两侧都给得出文件行号，缺一侧不收）。其中**四条是同一个形状**——
**一个领域判断有了正确的实现，但它住的那一层别的调用方够不着，于是那些调用方各自
长了一个简化版**：

- **`D66`**：「这份内容是不是**非游戏资产**」的判断长在适配器那一层（票 16 加的，真库上
  挑出 11 个），而识别那一层挑**作品**时够不着它。后果是**容器里捎带的一份 BIOS 命中，
  定了整包游戏的作品**。
- **`D142`**：「这是补丁还是附属内容」在识别那一层是一个**结构化的字段**，而导出那道闸
  够不着它，只好去 parse 一句**理由字符串**。词表与 ADR-0013 逐字说它们不该成为前端条目。
- **`D123`**：平台判据在识别那一层早就改成**看内容**了，刮削那一层仍然**听目录声明**。
- **`D64`**：铺**媒体**的能力长在同步那一侧，导出那一侧交空表——**而两者是同一个函数的产物**。

四条都不是「谁写错了」。四次里每一次，写第二个判据的人手上都没有第一个判据可用。

## 规矩

**一个领域判断——「世上这件事是什么」那一类的问题——只许有一处实现。**

判据（沿用 ADR-0005 那条已经在用的）：**这个问题的答案与它在哪一层被问无关**，那它就是
领域判断。「这份内容是不是非游戏资产」「这个变体是什么平台」「这是不是补丁」都是；
「这一格该画多宽」「这句话摆屏上哪儿」不是。

三条推论：

1. **发现第二处判据时，先问「第一处在哪」，再决定动谁。** 默认是**把判断提到两处都够得着
   的那一层**（多半是核心库），两处都改成从那一处取。不是「把正确的那份复制过去」。
2. **提上去的是判断，不是调用方的形状。** 判断收什么、答什么，由**领域**定，不由第一个
   调用方的手头数据定。够不着的那一方要自己补齐输入，而不是让判断迁就它。
3. **判断只有一处，不等于结论只有一处。** 各层照旧可以缓存、可以在库里存一份物化的结果；
   要紧的是**算它的那段代码只有一份**。

## Consequences

- **提判断要连输入一起想。** `D66` 那一条最典型：适配器那侧的判断收的是**变体键**，而识别
  那侧手上是**容器里的一份内容**——提上去的时候要先把「拿什么当输入」这一问答清楚，
  否则提上去的是一个两边都不好用的函数。
- **这条规矩会挡下一些看起来无害的改动**：某一层为了少绕一步，就地写一个「差不多的」判断。
  它下一轮就是一条挂账。
- **这条规矩不管性能上的第二份**：为了不跨层调用而在库里物化一份结果是允许的（推论 3）。
  被禁的是**第二次判断**，不是第二次读。
- **反向的代价**：判断提到核心库之后，调用方要多传一点上下文进去。这是有意的——
  上下文缺失正是第二个判据长出来的原因。

## Considered Options

- **逐条判，不立规矩。** 十一条修完就完事。否掉的理由是：这一批的名字就是「一件事一个
  判据」，而**立不立规矩本身就是这批活最该产出的东西**——十件修完而规矩没立，
  下一轮还会长出第十二件。第四轮之前已经长了四条，没有理由认为第五轮不会。
- **把规矩写进 ADR-0005。** 那条 ADR 叫「Rust 核心 + egui 原生 GUI」，这条规矩管的是核心
  库内部，挂在那儿读的人找不到。ADR-0005 那半句保留，两条互相指。
