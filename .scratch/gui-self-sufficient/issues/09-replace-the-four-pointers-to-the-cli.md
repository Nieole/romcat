# 09 — 四处指向命令行的文案，换成就地的捷径

**What to build:** 界面里眼下有四处硬编码写着去开终端：**待确认队列**屏三处"先跑一次 `romcat identify`"，浏览屏撤销标题压制之后一处"它下一趟重折（`romcat titles`）之后……"。全改成**就地的按钮**——人是在队列屏发现"没识别"的，让他跑回库屏是多余的一步。

**捷径必须是同一趟活的第二个入口**，调同一个函数、排同一趟**任务**，不是第二份实现。两份实现迟早各跑各的。

这一张压在最后，是因为**文案与新入口必须同一趟落地**：留一处旧文案，人就照着去开终端了。

**Blocked by:** 06、07、08

**Status:** done

⚠️ **票面那句「队列屏三处」是错的，实测四处**（挂单 `Q446`）：顶栏、一级分批那张空态、逐条那张表的空态各一处写着同一句话（票面点到的是这三处），**第四处**是「另有 N 个变体连识别都还没跑过」那句警告的悬停里那半句「先跑一趟 `romcat identify` 把它们补上」。加上浏览屏那一处，**一共五处，五处全换掉了**。

- [x] 待确认队列屏那三处指向命令行的话，改成就地能点的按钮
      —— **实为四处，四处全改**（`crates/gui/src/queue.rs`：顶栏 `status`、一级分批空态
      `batches_ui`、逐条那张表的空态 `table`、「还没识别」那句警告旁边）。四处画的是
      同一颗按钮与同一张空态（`queue::identify_shortcut` / `queue::identify_empty_state`）
      ——从前四处也是同一句话，换成四份写法迟早各说各的。
      证据：`crates/gui/tests/roots.rs::队列屏那几处空态不再指向命令行_就地摆着一颗跑识别`
      （一级分批与逐条两档各画一帧，断言屏上没有 `romcat identify`、有一行就是「跑识别」），
      以及 `::队列屏那颗捷径排的是与库屏工序段完全同一趟识别` 末段那三句（警告那一处）。
      数字与票面的出入记在挂单 `Q446`。
- [x] 浏览屏撤销标题压制之后那句话，改成就地的折标题入口
      —— `browse::Screen::lift_title` 不再说「下一趟重折（`romcat titles`）之后」，改说
      「**这一屏不折**，那要走遍全库——点旁边那颗「折标题」排一趟」，那颗按钮就画在这句话
      旁边（`Screen::lift_notice` 单开一格，换一个作品就连按钮一起收掉）。
      证据：`crates/gui/tests/browse.rs::撤掉一条标题压制之后就地摆着折标题的入口_排的是与库屏工序段同一趟`
      第一段（屏上没有 `romcat titles`、有一行就是「折标题」）。
- [x] 捷径排的活与工序段那一行**完全相同**：同一个函数、同一趟任务、同一份产物
      —— 两屏都排不了活（排一趟工序要同时够得着库屏工序段与任务台，而屏与屏之间不该互相
      拿着对方，ADR-0005）。按下去只留一个记号（两屏都是 `asked: Option<Stage>`），由
      `App::route` 取走、交给 `App::start_stage` —— 库屏工序段那三颗按钮走的也是它。
      **断言不看代码长什么样，看谁认领了那一趟**：只有 `Section::start` 排出去的任务号才
      进得了 `Section::running`，也只有它认领得下来（`Section::settle`）。
      证据：两条测试各有一句 —— `roots.rs` 断言库屏工序段报出「识别 跑完了：…」，
      `browse.rs` 断言它报出「折标题 跑完了…」。捷径要是第二份实现，工序段一个字都不会说。
      **同一趟活也不会被排两遍**：`roots.rs::台上已经有一趟识别时再按队列屏那颗捷径_不会排第二趟`
      走的是真的那条路（留记号 → `App::route` → `App::start_stage`），断言台上那一趟的
      任务号没换、队里仍只有一趟 —— 兜底在 `Section::start` 那句「同一道工序已经在跑就
      什么都不做」（捷径不像工序段那一行那样禁得掉：队列屏够不着工序段）。
- [x] 从捷径排的活，在任务台上与从库屏排的看不出区别
      —— 证据：`roots.rs` 那条断言 `app.tasks().history()[0].name == "识别"` 且
      `matches!(record.ending, Ending::Done(_))`；`browse.rs` 那条断言
      `history()[0].name == "折标题"`。那一行的名字就是 `Stage::label()`，
      两个入口共用 `Section::start` 里那一句 `stage.label().to_string()`。
      同一份产物另有三句：识别那一行的数当场刷新到 `Behind::Left(0)`、队列自己重新列过
      （`queue().identified()` 为真）—— 一次「重新列队列」都没点。
- [x] 界面里再没有一处叫人去开终端跑主干工序
      —— 实际跑过的 grep 与它的输出：

      ```
      $ grep -rn 'romcat \(scan\|identify\|scrape\|titles\|export\)' \
          crates/gui/src --include='*.rs' | grep -v ':[0-9]*: *//'
      $ echo $?
      1
      ```

      （无输出。`grep -v` 那一段滤掉的是首个非空字符为 `//` 的行，也就是 `//`、`///`、
      `//!` 三种注释；剩下的才是屏上真会出现的串。）

      ⚠️ **两处保留，写明理由**（挂单 `Q448`）。放宽成全部子命令时还剩两行：

      ```
      $ grep -rn 'romcat [a-z]' crates/gui/src --include='*.rs' | grep -v ':[0-9]*: *//'
      crates/gui/src/sublibrary.rs:1163:  命令行那条路也还在：`romcat sublibrary rule <子库> --remove <序号>`，\
      crates/gui/src/queue.rs:1757:      更早落下的那些在命令行上撤：`romcat triage batches` 看有哪几批，\
      crates/gui/src/queue.rs:1758:      `romcat triage undo --batch <号>` 撤其中一批。"
      ```

      两处说的都**不是「跑一趟工序」**：前者自己就写着「命令行那条路**也**还在」，
      界面上同一件事做得到，是并列不是指路；后者如实说出了一个**界面还没有的能力**
      （界面只撤得掉最后一批），删掉它等于把「这件事界面做不到」一起藏掉。

      ⚠️ **刮削那三处的裁定在这一票里翻过一次**（挂单 `Q447`）：头一版判成「三处都不算
      在内」，被审查的 Spec 那一轴翻掉 —— 第 5 条要的是**那句话别指向终端**，不是每一处
      都得长出一颗按钮。于是劈成两半：**文案算在内，三处全改**（改成「下一趟**刮削**」
      与「浏览屏抬头那颗「刮削选中…」」，一条约束都不碰）；**捷径按钮不算在内，一颗都
      没加**（`Stage::ALL` 只有三支，加第四支与另排一趟都被这张票的硬约束禁着）。
- [x] 命令行那几条命令本身照旧能用——这一张不改命令行
      —— 证据：`git diff d68fcf8 --name-only` 七份文件里 `crates/cli/` 与 `crates/core/`
      一份都没有（`SCHEMA_VERSION` 因此照旧是 7），改的全在 `crates/gui/`。
