# 09 — 四处指向命令行的文案，换成就地的捷径

**What to build:** 界面里眼下有四处硬编码写着去开终端：**待确认队列**屏三处"先跑一次 `romcat identify`"，浏览屏撤销标题压制之后一处"它下一趟重折（`romcat titles`）之后……"。全改成**就地的按钮**——人是在队列屏发现"没识别"的，让他跑回库屏是多余的一步。

**捷径必须是同一趟活的第二个入口**，调同一个函数、排同一趟**任务**，不是第二份实现。两份实现迟早各跑各的。

这一张压在最后，是因为**文案与新入口必须同一趟落地**：留一处旧文案，人就照着去开终端了。

**Blocked by:** 06、07、08

**Status:** done

### Q447 — 刮削那三处：文案算在内、按钮不算，两半的判据不一样

**裁决（第四轮收口，2026-09-09）：活** —— 把刮削按同一个形状收进工序段。`Stage::ALL` 眼下只有识别 / 折标题 / 导出三支，而这张票的硬约束逐字禁掉了「加第四支」与「第二份实现」——所以这一趟只改了文案（三处，指向浏览屏那颗「刮削选中…」）。刮削缺的是「还差多少」那个数，与 `Q426` / `Q436` 是同一类问题。

- **来自：** 票 `gui-self-sufficient/09`
- **类别：** 规格没说
- **在哪：** `crates/gui/src/queue.rs`（匹配裁决那份回执里两句）与
  `crates/gui/src/browse.rs`（刮削字段那一栏的空态一句）。三处从前都写着
  `romcat scrape`。**刮削是主干六步之一**（`CONTEXT.md` 的**工序**条），
  所以验收第 5 条那句「主干工序」逐字读是盖得住它们的。
- **为什么没停线：** 两半都可逆——文案改回去是三句话，将来真要给刮削加捷径是另一张票。
- **这张票实际做了什么：** **劈成两半，两半各按各的判据裁。**
  **① 文案算在内，三处全改。** 验收第 5 条逐字要的是「界面里再没有一处**叫人去开终端**」
  ——它管的是那句话指向哪儿，不是每一处都得长出一颗按钮；规格 Further Notes 那段也写着
  「改成**指向工序段或就地的捷径按钮**」。而刮削在界面上早有自己的入口
  （浏览屏抬头那颗「刮削选中…」），所以三处改成指向它、或者干脆只说「下一趟刮削」，
  是纯文案改动，一条约束都不碰。改后：`queue.rs:2015` →「下一趟**刮削**才改写」
  （连 `crates/gui/tests/queue.rs:1396` 那句断言一起改）、`queue.rs:2050` →
  「再采一趟刮削——浏览屏抬头那颗「刮削选中…」」、`browse.rs:2862` →
  「点抬头那颗「刮削选中…」采一趟」。
  **② 捷径按钮不算在内，一颗都没加。** `Stage::ALL` 只有识别 / 折标题 / 导出三支
  （`crates/core/src/stage.rs:121`），而这张票的硬约束逐字写着「别动工序段本身……
  你加的是第二个入口，不是第四支」。给刮削排一趟活只有两条路：加第四支 `Stage`
  （明令禁止），或者绕开 `App::start_stage` 自己排（那就是**第二份实现**，
  硬约束第一条明令禁止）。何况刮削本来就不缺入口——它缺的是「还差多少」那个数，
  而那是 `Q436` / `Q426` 那一类问题。
  **头一版判成了「三处都不算」，是审查的 Spec 那一轴翻掉的**：它指出第 5 条要的是
  文案不指向终端，而不是每处都长按钮——那一版会让第 5 条名不副实。
- **谁来裁：** 拿主意的人——要不要另开一张票，把刮削按同一个形状收进工序段
  （那会牵出「刮削的『还差多少』怎么算」，与 `Q436` 是同一类问题）。
- **状态：** settled（第四轮收口，2026-09-09）


### Q448 — 验收第 5 条那条 grep 还捞出两处指向命令行的话，都不是主干工序
