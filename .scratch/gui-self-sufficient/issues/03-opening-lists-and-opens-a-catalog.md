# 03 — 开场：列出这个工作目录里的库，开一份进去

**What to build:** 双击图标、一个参数都不给，看见的是**开场**——这个**工作目录**里有哪些**中立库**，一份一行：主库名、多少个**变体**、上次扫描是什么时候。这些数住在中立库里，**盘没挂上照样看得见**。选一行进主窗口，开场交出**现场**之后自己退场，窗口标题写着开的是哪一份。

**结构版本对不上的旧库照列不误**，当场说清"版本 X，本程序认 Y，删掉重扫"——从列表里静静消失才是最难查的那种错。工作目录里一份库都没有时，直说"还没有库，认领一个主库开始"。

开场上能换一个工作目录，换完立刻看见那个目录里的库——不换的话，那些不在默认位置的库一份都开不出来。

核心库这一侧要新增"列出一个工作目录里有哪些中立库"：现在一个列举函数都没有，所有开库的路都是"给我名字或路径，我去折一个出来看在不在"。

**Blocked by:** 01（主库名要从元数据表读）、02（开场是顶层类型的第一态）

### Q388 — 中立库那个目录读不动与它压根不在，列举交出来的是同一样东西

**裁决（第四轮收口，2026-09-09）：活** —— 票 `05` 已经在那一屏上认领新主库了（要往那个目录**写**），而「这个目录写不动」到今天仍然说不出来——`catalogs` 里那句 `let Ok(dir) = read_dir(..) else { return Vec::new() }` 把「读不动」与「不在」压成了同一样东西。条目当初把这两件事托给票 `05` 一起裁，`05` 没裁。

- **来自：** 票 `gui-self-sufficient/03`
- **类别：** 规格没说
- **在哪：** `crates/core/src/workspace.rs` 的 `catalogs`：
  `let Ok(dir) = std::fs::read_dir(...) else { return Vec::new() }`
- **为什么没停线：** 两种情况屏上都说「还没有库，认领一个主库开始」，而这句话在两种情况下
  都不是错的下一步。照 ADR-0023 那条「一份打不开不该让整屏失败」的同一精神，整屏也不该
  因为目录读不动就交不出东西。第二条路是交 `Result`，让开场把「这个目录读不动」如实说出来。
- **这张票实际做了什么：** 读不动就当空的交出去，函数不返回 `Result`。
- **谁来裁：** 票 `gui-self-sufficient/05`（它要在这一屏上认领新主库，那时「目录写不动」
  必须说得出来，两件事一起裁）
- **状态：** settled（第四轮收口，2026-09-09）
