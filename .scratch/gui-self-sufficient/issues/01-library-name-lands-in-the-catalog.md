# 01 — 主库的名字落进中立库

**What to build:** 你给主库起的那个名字，现在只活在你敲过的那行命令里——中立库的文件名是"可读的那一段 + 哈希"，可读那段滤过非法字符、截断到 24 个字符，哈希那半段不可逆，忘了就再也拿不回来。这一张让名字有个落点：建库时写进中立库的元数据表一行，读得回来。**可演示处在命令行**：对着现有的库跑一次报告，看见的是你起的那个名字，而不是一串带哈希后缀的文件名。

元数据表是键值表，加一个键是**纯加**——按仓库既定的判据（改了已有表的列或含义才升结构版本），这不构成升版。旧库拿新程序打开照样能用，读不到那行就退回从文件名截取。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 建库时把主库原名写进中立库的元数据表
      —— `Catalog::open_named` 在「结构版本这一行还不在」（＝这一趟才建出来的库）那个分支
      写 `meta` 表的 `library_name` 键。**眼下唯一建得出中立库的是命令行的 `open_catalog`**
      （`Site::open` 与 `Site::open_file` 都先 `exists()` 才往下走，建不出新库），
      它已经换成 `open_named`；票 `05` 的向导会是第二个建库的地方，记在挂单 `Q371`。
      钉住它的是 `crates/core/tests/library_name.rs::建库时原名落进元数据表再开一次读得回来`。
      **空白不算名字**：`--library ""` 那一行干脆不落，读的时候也退回从文件名截
      （`名字是空白时退回从文件名截而不是留一行空的`）。

      —— `界面与命令行开同一份库读到的是同一个名字` 拿同一份库走两条开库入口：
      `Site::open`（命令行按 `--library` 找）与 `Site::open_file`（界面开开场列出来的那份文件），
      两边读出同一个原名；名字特意挑了 `。、？` 这种折进文件名会变形的，

### Q373 — 门禁放后台跑，回执里那份输出只留尾部几 KB，看起来像压根没跑过

**裁决（第四轮收口，2026-09-09）：活** —— 把「怎么跑门禁」写进 `docs/agents/`：`setsid nohup` 脱出会话、前台分段 `tail --pid` 阻塞等它、**日志写到自己的文件里**。判据一句话：**回执里那份输出不是完整日志，不能拿它的短小当「没跑过」的证据**（实测：同一趟门禁，回执里 42 行 / 3.7 KB，自己的日志 2,233 行 / 145 KB）。这一趟为这个误判白跑了一趟门禁、约十一分钟。

- **来自：** 票 `gui-self-sufficient/01`
- **类别：** 工具缺陷
- **在哪：** Bash 工具的 `run_in_background`（前台上限 600 s，超了自动转后台）与它写的那份
  `tasks/<id>.output`；对照物是 `xtask/src/gate.rs:291` —— 五步都走
  `Command::status()`，**stdio 是继承的**，所以真跑一趟的输出里必然有几十行
  `Running …` 与 `Compiling …`。
- **为什么没停线：** 门禁本身是绿的，卡住的只是「怎么证明它绿过」。
- **这张票实际做了什么：** 第一趟 `cargo xtask gate --keep-going` 撞上 600 s 上限被自动转
  后台，跑完回执说 `exit code 0`，输出文件却只有 **42 行 / 3,753 字节**、零个 `Running`、
  零个 `Compiling`，只剩最后一步 rustdoc 的输出加那张五行汇总表。编排者据此判定
  「它压根没产出、后台 shell 随轮次结束就死了」，要求重跑。
  **于是重跑了一趟，写进磁盘上自己的日志文件**（`setsid nohup` 脱离会话，前台分段
  `timeout 560 tail --pid=… -f /dev/null` 阻塞等它）：**2,233 行 / 145,417 字节，五条全绿。**
- **证据指向的是截断，不是进程死掉**，三条：① 第二趟的 check / clippy / doc 都是 **0 s**
  ——全命中缓存，而缓存只可能是第一趟建的；② 第一趟结束时 `target/debug/deps` 的 mtime
  与那份输出文件的 mtime 同在 04:44；③ 那 42 行**正好是最后一步的输出**，是尾部截断留下的
  形状，不是「什么都没跑」的形状（什么都没跑的话连汇总表都不会有，而汇总表里
  `test 624s` 是 xtask 自己量的墙钟）。
- **另一条路（编排者给的那条）：** 一律前台跑，别放后台。前台单次上限 600 s 挡不住这件事
  ——门禁本身就要 8～11 分钟，一进前台就必然撞上限、必然被转后台。真正做得到的办法是
  上面那套：`setsid nohup` 把它脱出会话，再用分段的 `tail --pid` 在前台阻塞着等。
- **该选哪条：** 走 `setsid nohup` + 分段阻塞，并且**日志写到自己的文件里**，别只靠回执
  那份输出。判据一句话：**回执里的输出文件不是完整日志，不能拿它的短小当「没跑过」的证据。**
  这一趟为这个误判花掉约十一分钟——一趟白重跑的门禁。
