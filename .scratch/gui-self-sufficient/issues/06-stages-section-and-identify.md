# 06 — 工序段与识别这道工序

**What to build:** 库屏长出第三段——**工序**：这个库还差哪几道步骤。这一张立起工序段本身，加上第一道工序：**识别**。

那一行显示的是**还差多少**——"N 个**变体**连识别都还没跑过"——不是"上次几点跑的"。人要的是"下一步该干什么"，时间戳答不了这个问题：加了一块盘重扫之后，那个数自己就涨上去，你不必再自己推理"是不是该重跑识别了"。

**这个数已经有了**：**待确认队列**屏正用警告色画着它，命令行的队列报告印的也是同一份。这一张不另造一份，复用现成的那个。

点那一行的按钮，识别排上**任务台**——报得出跑到哪儿、按得下停下，跑完那一行的数字当场刷新、待确认队列自己重新列过。接任务台的办法与已接的那五种（差量预览、扫描、取数据源、刮削、同步）一模一样：核心那侧收一个任务句柄，界面这侧往台上排一趟；要写库的那几支写在**认领**那一步，因为台上那条线拿的是只读连接。

**这一张同时立起"工序进度"这个新模块**（眼下只含识别一支），07 与 08 各往里加一支。三道工序的度量收在一处，是为了工序段一次问得出全部状态，而不是调三个地方。

## 证据

**新立的两个模块**：`crates/core/src/stage.rs`（**工序进度**，`Stages::survey` 一趟问出全部
工序还差多少）与 `crates/gui/src/stages.rs`（库屏上的**工序段** + 排识别那一趟活的入口）。
核心那一侧的长入口是 `identify::run_task`（收一个 `task::Handle`，与 `scan::scan` 同形）。

逐条：

1. **第三段**——`crates/gui/src/roots.rs::Screen::body` 末尾 `self.stages.ui(...)`；
   `crates/gui/tests/roots.rs::库屏在根与数据源之后长出工序那一段_识别那一行说的是还差多少`
   断言屏上真画出了「工序 · 1 道」与「识别」那一行。
2. **还差多少**——措辞在 `stage.rs::StageRow::render`（领域判断不在界面层，ADR-0005）；
   同一条测试断言屏上那一行逐字是「2 个变体连识别都还没跑过」。
3. **同一个数**——工序段、`triage::Queue::not_run`、`QueueReport::not_run` 三处同取
   `Catalog::not_run_count`，没有第二份算法。`crates/core/tests/stage.rs::识别那一行的数与待确认队列和命令行队列报告印的是同一个`
   （连命令行那份报告 `render_text()` 印出来的数一起断）＋
   `crates/gui/tests/roots.rs::工序段那个数与待确认队列屏上的是同一个`
   （顺带钉住「加了一块盘重扫那个数自己涨上去」，规格 28）。
4. **排上任务台、报得出进度**——`crates/core/tests/task.rs::识别一路报得出算完了几个变体而且跑完记成完成`
   （`task.progress().done` 走到变体总数）＋ 下面第 6 条那条 GUI 测试。
5. **停在半路**——`crates/core/tests/task.rs::识别按停之后在台上记成停在半路而且不说下一趟接着算`
   ＋ `crates/gui/tests/roots.rs::识别跑到一半按停在任务台历史上记成停在半路`。
   两条都断到那半句上：**识别没有断点**，那句话写的是「从头再算一遍」而不是「接着算」。
6. **数字当场刷新** ＋ 7. **队列自己重新列过**——
   `crates/gui/tests/roots.rs::点一下把识别排上任务台_跑完那一行的数字当场刷新_队列自己重新列过`：
   全程一次「重新列队列」都没点，跑完之后 `queue().identified()` 翻成真、`not_run()` 变 0。
   重列那一下在 `crates/gui/src/app.rs::poll_tasks`（只有窗口同时够得着两屏）。
8. **按钮按不下去**——`crates/gui/tests/roots.rs::这一趟正在跑的时候那一行的按钮按不下去`：
   **先拿一趟占位任务占住台**，识别稳稳排在队列里，于是这一条不靠「识别恰好还没跑完」
   那种挂钟彩票（挂单 `Q196` / `Q349`）。断的是屏上真画出了「跑着呢」，加上再按一次
   什么都不发生。
9. **盘不在位照样看得见**——`crates/gui/tests/roots.rs::外置盘不在位的时候工序那几行照样看得见`：
   把 fixture 目录删掉、`reload` 之后那一行的数与屏上那句话都还在（工序段一个字节都不读主库）。

## 挂单

这一趟记下 `Q416`–`Q424` 九条（`.scratch/PARKING-LOT.md`），一条都没停线：

- `Q416` **识别在任务线程里自己开一份连接写库**，与规格那句「要写库的那几支写在认领那一步」
  对不上——照的是扫描与刮削两条已经落地的先例（识别一路往库里写批，攒到认领那一步再写会
  卡住画帧那条线程）。**这一条要拿主意的人裁**：07 / 08 会跟着走同一条路。
- `Q417` 工序那一行的形状（两支的 `Behind` vs 每行都带「数 + 时刻」两格）——票 `07` 裁。
- `Q418` 界面上的识别整层关掉**模型推断**，连库里已经付过钱的答案也不用。
- `Q419` 「跑完自己重新列队列」只做识别这一支，扫描完不重列。
- `Q420` 识别没有断点：按停之后下一趟从头再算一遍（如实说了，没瞒）。
- `Q421` 票 `09` 那三处捷径怎么把按下的那一下递到 `App::start_stage`——留给 `09`。
- `Q422` 「退回上次跑的时刻」那条退路**有形状、没有数据通路**（`at` 眼下恒为 `None`）——
  识别这一支数得出来，不需要它；票 `07` 是第一个真要用退路的，那条通路跟它一起来。
- `Q423` 「没有 DAT 库就当场拒绝」这条守卫票与规格都没要求（不加的话整库会落成
  「未命中」并写进中立库，那是假结论不是失败）。
- `Q424` **没有任何东西在新代码上跑一遍词表**：`job_of` 又撞进**任务**那条的 `_Avoid_`
  里（这一趟改成了 `task_of`）。**与 `Q365` 互相指认**——那一条记的是票与规格上的
  同一个缺口，两条一起裁才划得出「词表要不要有一道门禁」。
