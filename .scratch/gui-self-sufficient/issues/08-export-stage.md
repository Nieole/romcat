# 08 — 导出这道工序

**What to build:** 工序段加第三行：**导出**。点一下把中立库写成前端能读的元数据，铺在主库上。

那一行说得出**上次导出之后库里改了多少条**。这个度量同样没有现成实现，**同一条退路适用**：算不出来就退回显示上次跑的时刻，且不牵连另外两支。

第一次跑之前选一次**前端格式**与输出目录，之后记进中立库的元数据表（与主库名同一处，纯加键、不升结构版本），下一趟一键重导。

**不做成一个特殊子库**，虽然子库屏那套（差量预览、清单、容量条）看着能复用。词表里**子库**是"从主库挑选**一部分**导出到某个**目标设备**形成的**派生库**"，而导出三个限定词一个都不满足：不挑选（整库级、作品级收敛）、没有目标设备、不是派生库。硬塞进去，"子库"就从"给掌机的一份派生"稀释成"任何一次往外写"，而**清单**——工具在目标设备上的行为边界——在主库根上根本没有边界可划。

  **走了退路，度量没做**——量过了，理由与实测代价在挂单 `Q436` 与 `crates/core/src/stage.rs::Stage::Export`：算这个数就是跑一遍这道工序（真机上一趟 `romcat export` **2.7 秒**，`docs/library-facts.md`；合成库 4,000 变体上 `converge::run` **45–49 毫秒**、整趟 `dry_run` 导出 **166–199 毫秒**，线性折算到 46,483 变体是 0.5 秒与 2.0 秒），而 `Stages::survey` 跑在画帧线程上、一帧预算 16 毫秒。那一行画的是**上次导出的时刻**（`Catalog::exported_at`）。
  证据：`crates/core/tests/stage.rs::导出那一支退回上次跑的时刻_而识别那一行照旧报数`（同一条里断言识别报 `Left(4)`、折标题照说自己那一句）、`crates/gui/tests/roots.rs::工序段上导出一行_画的是上次跑的时刻`。
  度量真被认下来时那一行该说的话已经钉住：`导出的度量真做出来时那一行说的是几个条目在上次导出之后变过`。

- [x] 第一次跑之前能选前端格式与输出目录，选完记进中立库的元数据表

  元数据表加两个键：`export_format`、`export_out_dir`（`crates/core/src/catalog/export.rs`）。**纯加、`SCHEMA_VERSION` 一动不动，仍是 7。** 校验在核心里（`ExportSetup::check`，ADR-0005），界面只把话转出来。
  证据：`crates/core/tests/stage.rs::选过一次前端格式与目录_下一趟从库里读得回来`、`格式打错时当场说清眼下带的是哪几个`；`crates/gui/tests/roots.rs::选一次前端格式与目录之后_点一下就重导_而主库里的东西一个字节都没动`（断言 `catalog.export_setup()` 读得回来）。
  ⚠️ 屏上与代码里一律写「**导出目录**」而不是「输出目录」——「输出」在词表**导出**条的 `_Avoid_` 里（挂单 `Q439`）。

- [x] 下一趟不必再选，直接重导

  证据：同上那条 GUI 测试的末段——第二趟只调 `App::start_stage(Stage::Export)`，任务台历史里名为「导出」的记录变成 2 条，一句错都没有。

- [x] 点一下排上任务台，报得出进度、按得下停下

  长入口是 `romcat_core::adapter::transfer::export_task`（三步 + 界面那两步装配，`TASK_STEPS`）；排活走 `App::start_stage(Stage::Export)` → `stages::Section::start`。
  证据：`crates/core/tests/stage.rs::导出这一趟报得出走到第几步`（`steps`/`at`/`step` 三样都断言，`fraction()` 说得出走了几成）、`导出一份都没写就被按停_盘上与中立库都一个字节没动`、`导出写过一份之后被按停_记的是停在半路而且写过的那几份留在盘上`；GUI 那一侧 `crates/gui/tests/roots.rs::导出排着队被撤掉时一份元数据都没写出去`（规格 Testing Decisions 要的「排一趟、当场按停」那一条，从 `App` 进去）。
  **导出有「停在半路」这一档**（与折标题正相反），判据与两档的分界见挂单 `Q438`。

- [x] 外面有人动过那些元数据文件时停下来，不静默覆盖

  界面这一侧 `force` 钉死在关（挂单 `Q441`），核心那一侧照 ADR-0001 修订段逐份点名。撞上时**另起一句红字**说「有 N 份没写——外面有人动过」，与「跑完了」那一句并排画着；而**「跑完了」那一句只数真写出去的那几份**（`ExportedFile::written`），被挡下的一份都不算进去。
  证据：`crates/gui/tests/roots.rs::外面有人动过那些元数据文件时停下来_不静默覆盖`（导一趟 → 手改落点上那份 → 再导一趟 → 断言文件内容**一字不差还是手改的那份**、屏上报了错并说到「动过」、那句「跑完了」说的是「写进 1 份」而不是 2 份）；`crates/core/tests/stage.rs::每一份都撞上外面有人动过_那一趟不打时刻戳`（**一份都没写成就不算导过一趟**——判据统一成「真往盘上写过东西」，与只排计划、按停两档同一条）。

- [x] 只写元数据文件，一个 ROM 都不搬，主库里的 ROM 一个字节不动

  证据：`crates/gui/tests/roots.rs::选一次前端格式与目录之后_点一下就重导_而主库里的东西一个字节都没动`——导出前后各取一份**主库那棵树的逐字节快照**（相对路径 + 内容），逐字节比。比「文件数没变」严：原地改写一个 ROM 也验得出来。

- [x] 不出现在子库屏上，也不占用子库那套选择集与清单

  导出根本不碰 `sublibrary` 那几张表：它写的是元数据文件加中立库里的**底本**与一个时刻戳。
  证据：`crates/gui/tests/roots.rs::导出不出现在子库屏上_也没占用子库那套选择集与清单`——导完一趟之后 `sublibrary.reload()`，那一屏的清单仍然是空的。
