# 06 — 结论的状态在全部候选进来之后再定

**What to build:** 维护者跑完识别看报告，那几个数说的是真话——一个**只有模型候选**的变体
不再被记成「一条候选都没有」。词表**无判据**那一条逐字写着那是「一个字都没说」，
而它说了，只是说的人是模型。

收挂账 `D129`：模型推断的候选不改变结论的状态。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

⚠️ 眼下状态在模型那一层的候选进来**之前**就定死了，于是**同一个候选集合一半算数一半不算**。
改成**一次判断、一个候选集合**。改后一个只有模型候选的变体落进「**有候选但没被自动通过**」那一档。

⚠️ **这一改会让历史库的状态计数跳一次**（重跑一趟识别就对上）。**不升结构版本**，
但要在票面收尾与发布说明里写明白，否则读报告的人会以为库坏了。

⚠️ **测试要连「数会跳」一起验**：改前改后同一份库跑一遍，断言那几个数**确实变了**、
并且变成了对的那个。只断言「现在是对的」会让下一个人以为这一改没有影响面。

- [ ] 一个只有模型候选的变体，状态不再是「一条候选都没有」那一档
- [ ] 它落进「有候选但没被自动通过」那一档
- [ ] 没有模型候选的那些，状态**一个字没变**
- [ ] 有一条测试断言这一改**确实让那几个数变了**，并且变成了对的那个
- [ ] 结构版本没升
