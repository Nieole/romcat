# 06 — 结论的状态在全部候选进来之后再定

**What to build:** 维护者跑完识别看报告，那几个数说的是真话——一个**只有模型候选**的变体
不再被记成「一条候选都没有」。词表**无判据**那一条逐字写着那是「一个字都没说」，
而它说了，只是说的人是模型。

收挂账 `D129`：模型推断的候选不改变结论的状态。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ 眼下状态在模型那一层的候选进来**之前**就定死了，于是**同一个候选集合一半算数一半不算**。
改成**一次判断、一个候选集合**。改后一个只有模型候选的变体落进「**有候选但没被自动通过**」那一档。

⚠️ **这一改会让历史库的状态计数跳一次**（重跑一趟识别就对上）。**不升结构版本**，
但要在票面收尾与发布说明里写明白，否则读报告的人会以为库坏了。

⚠️ **测试要连「数会跳」一起验**：改前改后同一份库跑一遍，断言那几个数**确实变了**、
并且变成了对的那个。只断言「现在是对的」会让下一个人以为这一改没有影响面。

- [x] 一个只有模型候选的变体，状态不再是「一条候选都没有」那一档
  - 证据：`crates/core/tests/model_inference.rs` 的 `状态在模型候选进来之后才定_那句理由一个字不丢`。一份读不进去的 zip 先跑一趟不问模型，是**无判据**；问过之后是**命中**。残渣一问过之后是 `(命中, 无理由)`，从前它是未命中。
  - 定状态只剩一处 `State::of(候选几条, 撞过几份内容)`（`crates/core/src/catalog/identify.rs`）。缓存那条路（识别主循环，模型候选在定状态之前就并进同一个集合）与真问那条路（`Catalog::append_candidates`，追加完照库里那两列重定一次）都调它。
- [x] 它落进「有候选但没被自动通过」那一档
  - 证据：结论的四档里，这一档就是**命中**。`State::of` 的判据是「有候选」，不看自动通过没有，与文件名那一层同一个待遇（`D127`）。模型候选 `accepted` 恒假，由 `这一层的候选永不自动通过而且进了待确认队列` 钉着。
  - 待确认队列默认收非跳过的各档，所以挪进命中的变体照样在队列里。
  - 报告里「只靠名字」那一列（`BLIND_SOURCES`）加上了模型推断，于是「不算那几层的命中率」没有替模型邀功。见挂单 `Q562`。
- [x] 没有模型候选的那些，状态**一个字没变**
  - 证据：`没有模型候选的变体_状态与理由一个字没变`。精确命中的、名字撞得上的、补丁三份，问模型前后状态与理由逐字相等（命中、命中、跳过）。
  - 全量门禁里 `identify`（26 条）、`triage`（43 条）等没动过断言的测试照绿。
  - **保留：** 前面各层落进无判据、又被模型候选挪进命中的那些，理由照留在库里、界面上看得见，但**不再进识别报告的「无判据的理由」表**（那张表仍按状态分）。见挂单 `Q561`，由拿主意的人裁。
- [x] 有一条测试断言这一改**确实让那几个数变了**，并且变成了对的那个
  - 证据：`只有模型候选的变体_状态计数跳一次`。同一份合成库，四档（命中、未命中、无判据、跳过）**改前** `[2, 3, 1, 1]`，这是在 `49dece6` 上实测、写死的常量；**改后** `[6, 0, 0, 1]`。先 `assert_ne!(改前)` 再 `assert_eq!(改后)`。
  - 真问那条路与只用缓存那条路是同一个数。「只靠名字」那一列从 `(1, 0)` 变成 `(5, 1)`，不算那几层的命中率前后都是 20.0%。
  - 这条测试在旧实现上是红的：`left != right` 失败于 `[2, 3, 1, 1]`，日志 `/Users/nicoer/dev/game-wt/logs/slot-4-oc06-slice2-red.log`。
- [x] 结构版本没升
  - 证据：`crates/core/src/catalog.rs` 的 `SCHEMA_VERSION` 仍是 `7`，`git diff 49dece6 -- crates/core/src/catalog.rs` 为空。表与列一个没改，改的是 `identification.state` 那一列怎么填。「无判据」那句理由与候选并存，靠的是 `reason` 本来就是可空的另一列。
