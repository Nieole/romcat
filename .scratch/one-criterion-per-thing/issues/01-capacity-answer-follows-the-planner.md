# 01 — 「装得下吗」以计划器为准

**What to build:** 维护者在**子库**屏上看见的「装得下吗」，与他真按下去同步时算的是**同一件事**
——目标上**已经占着的** ＋ 这一趟的**净变化**。它说装得下，就是真装得下；不会跑到一半才发现盘满了。

收挂账 `D76`：容量账把清单之外的占用也算进去（两处口径不同）。

**Blocked by:** 无 —— 可立即开工

**Status:** done

而真正会发生的是计划器算的那件事——报告答的是一个更好听、但不成立的问题。

### Q591 — 卡不在手边时「装得下吗」如实说算不出，不退回上一趟同步时记下的现占

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `one-criterion-per-thing/01`
- **类别：** 规格没说
- **在哪：** `crates/core/src/sublibrary.rs` 的 `Fit`／`fit`；`crates/core/src/sublibrary/report.rs`「装得下吗」那一节；`crates/gui/src/sublibrary.rs` 卡片上「装不装得下算不出：…」那一句
- **为什么没停线：** 没有哪条 ADR 要求这个数不读卡就给出。ADR-0016 那句「规则选出 800GB 而卡只有 512GB 时，明确报出超出量并给按体积排序的裁剪建议」挂在「同步前必须预览差量」底下，而同步本来就要卡在位——卡插上时这里照报超出量与裁剪建议，一个都不砍；代码注释里挂着的 ADR-0009 说的是主库那块外置盘与媒体池住哪儿，不是 SD 卡。改走另一条是多一种 `Fit` 加一处落库，不拆已有的活
- **这张票实际做了什么：** 目标看不成（不在位、列不开、计划排不出）时交 `Fit::Unknown { why }`，**不给数**；选中容量照印，但明说它答不了装不装得下。测试 `crates/core/tests/sublibrary.rs::目标不在位时装不装得下如实说算不出_不给一个数`
- **没走的那条：** 每趟同步完把目标现占、清单之外连同时刻落进中立库，卡不在手边时退回它，注明「截至某时」。（更近的一条——卡不在手边、光选中容量就超上限时照报「装不下」——也不同底：放不进目标被拦下的、你在掌机上删过不补的都不进计划，选中容量超了不等于同步之后超了，所以没列成候选）
- **建议留：** 现在这条。那份快照说的是一张此刻没人看过的卡——维护者在掌机上删过、拷过的都不在里头，而 ADR-0015 选读卡器的全部理由是「验证目标真实状态、不盲信清单」；「上次同步时装得下」仍是一个与计划器不同底、却标着装得下的数。它还要往中立库加东西（ADR-0001 修订：先问它是不是该住别处）
- **谁来裁：** 拿主意的人
- **状态：** settled（第五轮收口，2026-09-23，见顶上裁决）
### Q592 — 「算一遍容量」每台设备各看一眼目标、各排一遍计划，不是只在差量预览之后才给数

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `one-criterion-per-thing/01`
- **类别：** 规格没说
- **在哪：** `crates/core/src/sublibrary.rs` 的 `survey`（多收 `workspace`，每台设备走 `sublibrary::fit` → `sync::prepare_selected`）；`crates/core/src/sync/prepare.rs` 拆成两半，「看一眼目标」挪到后半截第一步
- **为什么没停线：** 推翻它是 `survey` 里不调 `fit`、一律交 `Fit::Unknown`，改一处
- **这张票实际做了什么：** 折一趟事实全部设备共用，每台再走一遍排计划那八步（卡不在的那台第一步就停下、如实说算不出）；`romcat sublibrary show` 也改走它。进度总步数从「1 + 台数」变成「1 + 台数 × 8」，步名前带着是哪一台
- **没走的那条：** `survey` 保持只问中立库，报告一律 `Unknown`（「排一次差量预览才知道」），装不装得下只在差量预览上出现——`survey` 照旧快，词表**容量条**那句不用改
- **建议留：** 现在这条。票 `gui-looks-like-the-design/20` 要在每台设备的卡上画装不装得下，`/23` 要问「加入之后装不装得下」——后者问的是一份没存进库的选择集，只能对着目标排计划，所以核心里本来就得有「给一份 `Selected` 答装得下吗」这一处（`sublibrary::fit`）；近路那条让「算一遍容量」这个按钮不再回答它名字里那个问题。**代价没量过**：真机量级上每台多一趟期望状态＋铺媒体＋折前端元数据（都读中立库）
- **谁来裁：** 拿主意的人

### Q593 — `romcat sublibrary show --json` 的超出量与裁剪建议收进 `fit`，顶层那两个字段去掉了

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `one-criterion-per-thing/01`
- **类别：** 规格没说
- **在哪：** `crates/core/src/sublibrary/report.rs` 的 `SelectionReport::fit`（原顶层 `over_capacity`／`trim_suggestions`）
- **为什么没停线：** 加回两个顶层字段是纯加；仓内没有第二个读这份 JSON 的（界面读的是结构体，跟着改了）
- **这张票实际做了什么：** JSON 里是 `"fit": {"Known": {…}}` 或 `"fit": {"Unknown": {"why": …}}`；测试断言算不出时顶层没有 `over_capacity`

- **建议留：** 现在这条。顶层一个 `null` 的超出量读起来就是「装得下」，而算不出时它只能是 `null`——那正是这张票的底线换了个出口

### Q594 — 「装得下吗」按同步默认那一趟算，`show` 不收 `--restore`／`--priorities`

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `one-criterion-per-thing/01`
- **类别：** 规格没说
- **在哪：** `crates/core/src/sublibrary.rs` 的 `fit`（`sync::Request::default()`）；`crates/core/src/sublibrary/report.rs`「按同步默认的那一趟算」那一句
- **为什么没停线：** 改走另一条是 `fit` 收一份 `Request`、`show` 加两个旗标，纯加
- **这张票实际做了什么：** 报告里明说按默认那一趟算（不补回你删过的），`--restore` 那一趟指去 `sublibrary plan --restore`。界面上的差量预览与同步本来就只走默认那一趟，所以子库屏那个数与那颗同步按钮同底
- **没走的那条：** `fit` 收 `Request`，`show` 加 `--restore`／`--priorities`，与 `plan`／`sync` 一一对应
- **建议留：** 现在这条。子库屏那个数要对的是界面上那颗同步按钮，而它不补回；命令行 `sync --restore` 是一次明知故犯的选择（ADR-0015），它装不装得下该在 `plan --restore` 那份差量预览上看——那份预览本来就是同步前的硬要求（ADR-0016）。`--priorities` 只动前端元数据那几个字节
