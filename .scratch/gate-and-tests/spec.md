# 门禁说到做到，测试不赌挂钟

**Status:** ready-for-agent
**Opened:** 2026-09-24（`/settle` 第五轮收口 → `/grill-with-docs` → `/to-spec`）
**来源：** 挂单 15 件；已裁定的形状与逐件核查见同目录 `grill.md`

## Problem Statement

门禁绿了，可有好几格其实没盖住；有几条测试靠挂钟与大盘赛跑；有两样事实没有机器替人核。拿主意的人与派出去的 agent 看见的「全绿」因此不总是真的：

- **在维护者自己的机器上门禁就红**：默认 APFS 不分大小写，`sync_run` 那五条真盘测试在 `main` 上就红，得先挂一块分大小写的稀疏盘当 TMPDIR 才绿；忘了挂盘，报错形状还误导。
- **test 那一步在第一个红的测试二进制就停**：CI 用 `--keep-going` 本意是一趟看全，可 test 步内部照停，回执只报第一个红的，后面的一概不跑。
- **在本地合进 `main` 再推的改动，CI 上词表扫描一行都不扫**：它只比「相对 `main` 的 merge base」，站在 `main` 上就只剩未提交的——而这个仓库的流程恰恰是本地合并、不开 PR。
- **「编测试但不开 demo 特性」这一格门禁没编过**：`Q1081` 那一次，`main` 上门禁全绿，这一格却是红的。这是第三次裁这件事。
- **本机的 Rust 不是钉的那一版**，裸跑 `cargo` 与跑门禁互相顶掉编译缓存，每轮白付一两趟约百秒的重编。
- **测试赌挂钟**：「走完向导之后扫描……按得下停下」那一条靠一块三万文件的大盘赌「扫描比进主窗口慢」，加过三次盘都被追上，机器一忙照样红；另有两处等按停的写法各写一个 sleep 循环，没用共享的「占位活」。
- **「界面里没有第二处写死的颜色」没人守**：已经滑了三处写死白色，暗色主题下不跟令牌走。
- **设计稿核对脚本漏核二十多个令牌，漏了还照样报「一致」**。
- **代码注释里复述的真库数**从五十五个文件长到了六十个，其中一处还引错了文件。

## Solution

- **本机门禁变绿**：那五条在不分大小写的盘上如实跳过「分大小写」那一遍，并印「跳过：…」（照测试夹具里已有的做法）；CI 的 ext4 上照跑全量。门禁起手核 TMPDIR 那件事随之作废。
- **`--keep-going` 时 test 步加 `--no-fail-fast`**；默认仍是第一处红就停。`long-jobs.md` 里「手动另跑一遍补」那段删掉。
- **词表扫描加「跟哪个提交比」的开关**，CI 在 push 事件上递上一版（全零时照旧如实跳过）。事后报红——已经在 `main` 上了——但咬得住每一次 push。
- **`check` 那一步加 `--all-targets`**（翻 `Q208` 的「不补」）。
- **本机保留 Homebrew 的 Rust**：只追出裸跑与门禁互顶缓存的那个环境变量，在门禁起子进程时清掉；钉版照旧只管 CI（`long-jobs.md` 已写明）。
- **扫描加一道测试用的闸**：走到第 N 个条目停住等信号（与「占位活」同一规矩），那条向导测试彻底不等时间；另两处 sleep 循环并进共享的「占位活」。
- **一条测试扫界面源码**：见颜色字面量就红，只放行透明与占位色；先把那三处写死的白色换成令牌。
- **设计稿核对脚本**：补齐漏核的存量；加完整性检查——每个令牌要么被某条核对核到、要么列进脚本里的显式豁免表，否则退 1。脚本仍手动跑，设计稿不进门禁。
- **真库数**：先改引错文件的那一处与三份非 `.rs` 文件；其余由下一张碰到那个文件的票顺手换成量级词，并把「写量级词、指向台账」写进约定。
- 刮削「部分完成」那一档不补从工序段入口的测试（已裁）。

## User Stories

1. 作为在默认 APFS 的 Mac 上跑门禁的维护者，我想不挂任何额外的盘门禁就绿，这样绿灯不靠一块我记得挂的盘。
2. 作为在不分大小写的盘上跑门禁的人，我想看得到「跳过：分大小写那一遍」，知道本机没验那一格、而 CI 会验。
3. 作为看 CI 回执的人，我想分大小写那一格在 CI 上照跑，这样它不会因为本机跳过就从此没人验。
4. 作为派 agent 跑门禁的编排者，我想 `--keep-going` 时一趟看到所有红的测试二进制，不用手动再补跑。
5. 作为本地跑门禁的人，我想默认仍是第一处红就停，这样快。
6. 作为在本地合并再推的编排者，我想推到 `main` 的那一趟 CI 照样扫新写的代码撞没撞词表。
7. 作为本地跑词表扫描的人，我想能指定跟哪个提交比，这样合并前也能自己验一遍。
8. 作为看 CI 的人，我想上一版拿不到（新分支、强推）时照旧如实说跳过，不报假红。
9. 作为写测试的人，我想「编测试但不开 demo」那一格进门禁，这样 `Q1081` 那种红不会在 `main` 上活一整张票。
10. 作为在本机跑门禁的人，我想裸跑 `cargo` 与跑门禁不再互相顶掉编译缓存，每轮省一两趟重编。
11. 作为读 `long-jobs.md` 的人，我想知道本机 Rust 不是钉的那一版、为什么，以及 fmt/clippy 与 CI 偶尔说法不同时该先想到这条缝。
12. 作为跑界面测试的人，我想「走完向导之后扫描按得下停下」那一条在机器再忙时也不红，因为它不等时间。
13. 作为写界面测试的人，我想等按停的写法全仓只有一份（占位活），不在两处各写一个 sleep 循环。
14. 作为改界面颜色的人，我想哪儿写死了一个颜色，测试当场红、指出文件与行。
15. 作为用暗色主题的人，我想那三处写死的白色跟着令牌走。
16. 作为画透明底或占位图的人，我想这两种「无颜色」不被那条测试拦。
17. 作为对稿的人，我想设计稿核对脚本漏核一个令牌时退 1，而不是照样说「一致」。
18. 作为新立令牌的人，我想被脚本提醒：要么写一条核对，要么列进豁免表并写明理由。
19. 作为读代码注释的人，我想注释里不再复述会过期的真库数，而是写量级词并指向台账。
20. 作为追溯出处的人，我想那一处引错文件的注释改指台账。
21. 作为下一个碰到那些文件的 agent，我想约定里写明「写量级词、指向台账」，顺手换掉。
22. 作为拿主意的人，我想这一批不改变门禁「从便宜到贵」的次序与步数的叫法。

## Implementation Decisions

- **门禁（xtask）**：test 步的参数跟着 `--keep-going` 走；check 步加 `--all-targets`（仍排在 clippy 之前，本机 16 GiB 的编译峰值由已有的限流管）；起子进程时清掉追出来的那个互顶缓存的环境变量，并在注释里写明它是什么、为什么。
- **词表扫描**：加一个环境变量形式的「比哪个提交」覆盖口，给了就用它、没给照旧 merge base；CI 工作流在 push 事件上递 `github.event.before`，全零时照旧跳过。
- **五条真盘测试**：照测试夹具里「先问盘分不分大小写、摆不出就印跳过」的做法改；不改测试想验的东西。`long-jobs.md` 里「怎么处置还没裁，见 Q479」那一句改成裁定。
- **扫描的闸**：给扫描那条路递一个可注入的文件系统或等待点（与已有的「占位活」同一规矩），只在测试里用；生产路径不变。
- **颜色扫描测试**：逐个读界面源码（剔除测试模块与令牌装配那一处），见颜色字面量或具名颜色常量就红；白名单只放透明与占位色。三处写死白色先换成已有令牌（强色底上的字那一格），换不了的新立令牌。
- **设计稿核对脚本**：存量补核对；加完整性检查与显式豁免表。
- **真库数**：只改引错文件那一处（改指台账）与根 `Cargo.toml`、两份内嵌 toml；`long-jobs.md` 或 `CLAUDE.md` 指向的约定里加一句。
- 不改的：刮削「部分完成」从工序段入口的测试（`Q556`，已裁不补）；门禁起手核 TMPDIR（`Q947`，作废）。

## Testing Decisions

- 门禁自己的改动接在门禁那份测试上：断言它要跑的命令与参数（`--keep-going` 时 test 步带 `--no-fail-fast`、check 步带 `--all-targets`、清掉那个环境变量），**不在测试里真跑全量门禁**。每张票收尾时照 `long-jobs.md` 跑一趟真门禁当证据。
- 词表扫描：接在它已有的测试上——给一个覆盖提交，扫的是它之后的改动；覆盖口为全零时如实跳过。
- 五条真盘测试：在不分大小写的盘上跑 → 印「跳过」且不红；在分大小写的盘上（CI，或本机稀疏盘）→ 照跑。
- 扫描加闸：那条向导测试本身就是验收——把机器压满（并排跑整份测试）连跑多趟都绿；另两处换成占位活后原测试照旧绿。
- 颜色扫描：它自己是测试；再验一次它会红——临时写一个颜色字面量，看它指出文件与行（变异实测写进票的证据）。
- 设计稿核对脚本：拿一份故意漏核一个令牌的令牌文件跑，退 1 且说出是哪一个；正常那份跑通。
- 每一件先写一条在今天 `main` 上红的测试（或先演示今天的错）再修。

## Out of Scope

- 本机装 rustup、让钉版在本机生效——已裁保留 Homebrew。
- 设计稿核对脚本进门禁——已裁仍手动跑。
- 改成开 PR 合并——与现行本地合并的编排冲突。
- 一次统一改掉六十个文件里的真库数、或加一道扫真库数的机器检查——已裁顺手换。
- 刮削「部分完成」从工序段入口的测试——已裁不补。
- ego-browser 对稿的约定（`Q948`）——那是编排者记忆里的事，不动仓库，编排者直接补。

## Further Notes

- 改门禁那三件（test 步参数、check 步参数、清环境变量）都动门禁那一个文件，**串着做**。
- `--all-targets` 会让 check 从约 8 秒涨到接近 clippy 的量级，门禁总时长跟着涨，是预期。
- 颜色扫描那条一旦合进，别的 effort（尤其 `gui-draws-the-rest-of-the-design`）新写的颜色字面量会当场红——那正是它要的效果；那边新立的颜色一律走令牌。
- 扫描加闸会碰到库屏扫描那条路，与 `gui-draws-the-rest-of-the-design/11`（库屏工序段）在同一带，派活时错开。
