## Problem Statement

维护者手上这套工具已经能扫、能识别、能刮削、能导出、能同步子库了。但**它对自己说的话
还不算数**：

1. **「门禁」是一句口头约定。** 仓库里没有 `.github/`、没有 git hook、没有任何机器执行
   门禁的地方。四条命令只写在 `README.md` 的「开发」一节里，漏跑了没有人拦。README 上
   写的测试条数（1,581）已经比实际少 50 条，而门禁第四条 `cargo doc` **从来没有绿过**
   ——68 条 rustdoc 告警，其中 `romcat-core` 独占 56 条。更远一层：没有任何东西钉住是
   哪一版 `rustfmt`，换一台机器跑 `cargo fmt --all`，提交里就会多出一大片与手上这件事
   无关的重排。

2. **同一趟活在两屏上说两套话。** 一趟同步被按停、但已经往卡上写进去了东西：子库屏
   如实说「⚠️ 这一趟被你按停了」，任务屏的历史却记成「完成」。界面刮削那一趟按了停，
   任务台把它记成**失败**——因为它交出去的那句话与核心库定的那句差着字。中文离线源那
   435 MB 下载按了 Ctrl-C 要等它下完才生效。任务屏上只有「已用 X」，没有「预计剩余」
   ——而扫描真机上要跑 37 分钟。

3. **落点闸有两格没验、有一格是空的。** 同步执行层那道「落点被占就不写」的闸，在
   大小写不敏感的目标上验不了（开发机造不出那种挂载点），在列不开的目录底下整个失效，
   而 `AlreadyExists` 那道豁免比「落点被占」宽——卡上有个文件叫 `gb`（不是目录）时，
   整个平台目录下每一条新增都会以同一句话失败，而放弃计数一次都不涨。

4. **翻库时人认的是作品，可作品这条线到处漏。** 变体表里那一列作品名排不了序也筛不了；
   重跑识别会造出两行同名的作品，还会把作品锚点里的那个 id 换掉；一部作品的显示标题被
   裁成非中文之后，报告数出来的「有中文标题的作品」与详情面板摆出来的各说一套。

5. **界面在真库量级上有三处会卡或会截断。** 「全选 46,483 行 → ★ 收藏」在画帧那条
   线程上跑 6.7 秒；差量预览的步骤表列满 2,000 条就打住；队列那一屏的表点表头不换排序。

6. **合成数据与测试夹具跟不上真库的形状。** `--bench-browse` 与七个界面测试还在
   二十个作品上；合成数据里只有两个变体有 `entry` 行，于是 `--demo` 打开的队列里**每一条**
   详情都写着「裁决钉在：路径——只在本机成立」；两份界面测试各搭了一份几乎逐字相同的小库夹具。

7. **一个新起的词还没进词表，一个格式的结构性损失清单还是空的。** `StructuralLoss`
   是票 `queue-followups/02` 新起的概念，`CONTEXT.md` 里没有它；ES gamelist 的结构性
   损失没人查过；Pegasus 还有一族没声明（值里那一行 `.`、多值字段里的换行与空串、
   以及值**末尾**的空白）。

## Solution

按九组收掉这 26 条。每一组都是一条从核心库穿到界面（或穿到仓库工具链）的完整路径，
做完就能验。

**先立两根桩，其余各组挂上去：**

- **门禁真的会拦人。** 门禁四条写进仓库里一个真实可跑的子命令，GitHub Actions 只调它
  ——本地与 CI 永远跑同一套，不会漂。工具链钉住，`cargo doc` 清到零并敲成硬红。
  这一组**最先做、单独跑完**：它一动就是全仓面的（钉工具链可能让 `cargo fmt` 产出整体
  位移，修 68 条文档链接要动几十个文件），而眼下没有任何在飞的活。

- **任务台把「这一趟怎么收场」说全。** 核心库那对枚举（`Ending` / `Done<T>`）现在
  只认「跑完 / 被按停 / 出错」三种，说不出**「被按停，但留下了可用的产物」**这第四种；
  `Progress` 报得出走了几成，但任务台没拿它算剩余时间。这一组是三簇活（「停下」一致、
  落点闸收尾、表格与批量代价）共同的前置，**一次改到位**，其余三组各自 `Blocked by` 它。

**然后是七组实质活：**

| 组 | 收掉 | 一句话 |
|---|---|---|
| 「停下」从核心到任务台一致 | Q150 Q151 Q153 Q54 | 按停的话对得上、留了产物的说得出、下载停得掉、剩余时间算得出就给 |
| 落点闸收尾 | Q135 Q136 Q142 | 给执行层加一道可注入的目标侧接缝，把三格空白一次补齐 |
| 表格与批量代价 | D153 D158 Q119 | 队列表能排序、步骤表不截断、整批收藏离开画帧线程 |
| 作品名这条线 | D161 D162 Q193 | 变体表按作品名排得了序、重跑识别不再造同名两行、作品锚点指得中 |
| 标题口径 | D163 D157 | 中文覆盖率数的是标题集合、删掉的错译名不会自己回来 |
| 结构性损失清单补齐 | Q159 Q160 Q161 Q163 | 词表收下这个词、Pegasus 那一族补齐、gamelist 先量再声明 |
| 夹具与合成数据 | Q156 Q168 Q177 Q192 | 合成数据长成真库的形状、两份夹具并成一份、卡片补一句悬停 |

## User Stories

### 门禁与工具链

1. 作为维护者，我想要门禁四条写成仓库里一个真实可跑的子命令，这样我和接票的 agent 只要记一句话，而不是四句加一串开关。
2. 作为维护者，我想要推上去就自动跑门禁，这样漏跑的那一次不会等到下一个人接票时才炸出来。
3. 作为维护者，我想要 CI 与本地跑的是同一套定义，这样不会出现「我这儿绿的、CI 红的」这种只能靠猜的分歧。
4. 作为维护者，我想要 CI 上不带我这台 15 GB 机器的内存约束（`-j 1` / `--test-threads=2`），这样 CI 跑得比本地快，而本地那套限流仍然留着能用。
5. 作为维护者，我想要仓库钉住 `rustfmt` 的版本，这样换一台机器提交时不会多出一大片与我这件事无关的重排。
6. 作为维护者，我想要知道钉工具链的副作用（rustup 每次进目录可能触发一次下载），这样我是认了这个代价才落的，不是被它绊到才发现。
7. 作为维护者，我想要 `cargo doc` 那 68 条告警清到零，这样文档里的断链在写的当场就红，而不是攒到没人敢碰。
8. 作为维护者，我想要 `cargo doc` 那条门禁带上 `--all-features`，这样它盖的范围与另外三条一致，不会漏掉 `demo` 后面那一整块。
9. 作为维护者，我想要 rustdoc 告警敲成硬红（`-Dwarnings`），这样它与 clippy 那条「零警告」的口径对齐，不再是四条里唯一一条没写过标准的。
10. 作为维护者，我想要 README 上那个测试条数是当下的真数，这样我拿它当基线核对时不会一开始就差 50 条。

### 任务台把结局说全

11. 作为维护者，我想要任务台能说出「被按停，但留下了可用的产物」这第四种收场，这样同一趟活不会在两屏上说两套话。
12. 作为维护者，我想要按停一趟已经写过东西的同步之后，任务屏历史那一行如实写着「停了，留下了 N 步的成果」，这样我知道下一趟是接着做还是重来。
13. 作为维护者，我想要按停的判据不是「那句话正好是某一句」，这样界面上任何一处措辞改动都不会把「停了」悄悄变成「失败」。
14. 作为维护者，我想要在长活跑着的时候看见「约剩 X」，这样我能决定是等它还是去干别的。
15. 作为维护者，我想要在工具算不出剩余时间的时候它就不显示，而不是给我一个跳来跳去的数，这样我不会被一个假的数字骗着等。
16. 作为维护者，我想要「已用 X」在剩余时间出现之后仍然留着，这样我看得出这一趟到底跑了多久。

### 「停下」从核心到任务台一致

17. 作为维护者，我想要界面上按「停下」之后那一趟显示成「停了」而不是「失败」，这样我不会以为自己按坏了什么。
18. 作为维护者，我想要中文离线源那 435 MB 下载按得停，这样我不用为一个按错的动作等上几分钟。
19. 作为维护者，我想要停下之后留下的东西被明确交代，这样我知道中立库里现在是什么状态。
20. 作为维护者，我想要子库屏那句回执与任务屏历史那一行说的是同一件事，这样我不用比对两屏才敢下结论。

### 落点闸收尾

21. 作为维护者，我想要「落点被占就不写」这道闸在大小写不敏感的目标（FAT32 / exFAT 的卡）上有测试钉着，这样我不是靠推理相信它，而是靠实测。
22. 作为维护者，我想要这道闸在列不开的目录底下也生效，这样不会在维护者那份文件旁边多写一份只差大小写的。
23. 作为维护者，我想要「该建目录的位置上躺着一个文件」这种情况被闸挡下来并计入放弃计数，这样整个平台目录下的每一条新增不会把同一句错误印上几百遍。
24. 作为维护者，我想要落点判定与目录列举在一次 `place()` 之内共享一份缓存，这样常数减半，而 TOCTOU 那道缝不会因此变宽。

### 表格与批量代价

25. 作为维护者，我想要队列那一屏的表点表头就换排序，这样在 16,656 条待确认里我能按容量或按结论找到该先动的那几条。
26. 作为维护者，我想要差量预览的步骤表把全部步骤都列得出来，这样我要确认第 5,000 步是什么时不用转去命令行。
27. 作为维护者，我想要「全选整个库 → ★ 收藏」不把窗口冻住，这样即使我做了一件没什么意义的事，界面也还应我。
28. 作为维护者，我想要整批操作跑在任务台上，这样它跟别的长活一样看得见进度、按得停。
29. 作为维护者，我想要批量取判据只走一趟查询，这样队列那 18,241 条填判据时不是一条四次查库。
30. 作为维护者，我想要批量取判据与单条那一份是同一个说法，这样收藏与裁决不会钉在不同的东西上。

### 作品名这条线

31. 作为维护者，我想要变体表里那一列作品名点表头就排序，这样翻库时我认的那个东西也是我能排的那个东西。
32. 作为维护者，我想要按作品名筛，这样我不用退回「键里含」那个框去凑。

### 标题口径

37. 作为维护者，我想要「中文覆盖率」这个数说的是**刮削到底采到了多少中文**，这样它回答的是「源好不好用」，不被「我用哪个当显示名」这个后续选择抹掉。

## Implementation Decisions

### 门禁

- **门禁四条落成一个仓库子命令。** 定义只有一份，人与 CI 都调它。工作区加一个只在
  开发时用的成员承载它，**不进交付出去的二进制**。子命令要能在受限内存的机器上退回
  限流模式（并发与测试线程可调），默认按机器给的资源跑。
- **GitHub Actions 只调那个子命令，不重复列命令。** 远端已经是 `github.com/Nieole/romcat`。
  workflow 要缓存 `~/.cargo` 与 `target/`，否则每趟重编全部依赖。
- **`rust-toolchain.toml` 落在仓库根。** 钉住具体版本（当下实测的是
  `rustfmt 1.9.0-stable`），并在文件里写清副作用：rustup 从此为每个人拉这一版，
  第一次进目录可能触发一次下载。`Cargo.toml` 的 `rust-version = "1.95"` 是 MSRV 声明，
  与它并存、互不替代。
- **`cargo doc` 那条补 `--all-features`，并把 68 条清到零。** 四类：多余的显式链接目标、
  解析不了的 intra-doc 链接、「既是函数又是模块」的歧义（`sync::prepare`、`observe`
  两处要用消歧前缀）、公开文档链到私有条目。清完之后用 `RUSTDOCFLAGS=-Dwarnings` 钉死。
- **README 的门禁块同步真数**：测试条数改成当下的实测值，并写明这个数会随票涨、
  以门禁输出为准。

### 任务台的「结局」

- **核心库那对枚举合流成一条轴。** 现在 `Ending`（`Done` / `Stopped` / `Failed`）与
  `Done<T>`（`Product(T)` / `Stopped` / `Failed`）是同一件事的两个说法，只差「带不带产物」。
  合成一条之后要能表达**四**种收场，`Stopped` 那一支带上「停之前留下了什么」：

  ```
  跑完了            → 有产物
  停了，什么都没留下 → 干净，可以当没跑过
  停了，留下了产物   → 有产物，且明说它是半截的
  出错了            → 停在哪一步、为什么
  ```

  （这个形状是从 `sync::execute::run` 与 `scan::scan` 两条真实路径上折出来的：
  两者都在被叫停时返回 `Ok` 并把 `interrupted` 记在账上——ADR-0015 要求写过东西的活
  留下续跑的依据才停得干净，抛错会把清单丢掉。）

- **判据不再是字符串比对。** 任务台现在靠「那句话正是 `Halted` 交出来的那一句」分
  「停了」与「失败」，差一个字就记成失败。改成由类型说话，界面那一侧不再需要凑话。
- **`Progress` 补上算剩余时间要的东西，折算放在核心库。** 剩余 = 已用时间 ÷ 已完成
  比例 − 已用时间，且只在已完成比例说得出来（现有 `fraction()` 给 `Some`）时才有值。
  界面拿到 `None` 就一格都不画，与「说不出走了几成时画一条动着的条」是同一套诚实口径
  （ADR-0005：折算是领域逻辑，不进界面）。
- **这一组是前置票**，「停下」一致、落点闸收尾、表格与批量代价三组各自 `Blocked by` 它。

### 「停下」一致

- **界面刮削那四处交出去的错误改成由类型转换得来**，不再手写「按停了」。
- **中文离线源的下载接上中断信号。** 取数那个接缝现在整个不收中断；要么让它按块读、
  每块看一眼，要么把「取数」这一步本身排上任务台。与挂单 `Q62`（三条取数入口都停不下来）
  是同一件事，本轮只收中文离线源这一条，另两条如实记着。
- **同步与扫描被叫停时仍然返回「有产物」**，但走的是新的「停了，留下了产物」那一支；
  子库屏那句回执与任务屏历史从此说同一件事。

### 落点闸

- **给执行层加一道可注入的目标侧接缝。** 现在它直接吃 `std::fs`，所以「大小写不敏感的
  目标上行为一致」在开发机上造不出来。加了这道接缝之后，三条落点占用的测试可以在
  两种折叠语义下各跑一遍，而真机行为不变。这道接缝是本轮**唯一新增的接缝**，
  加在最高点：执行层对外那一个入口，不下沉到每一次文件操作。
- **「列不开的目录」与「列开了没找到」分成两态**，从目录读取一路带到落点判定。
  ADR-0021 已经为「读不动是第三态」立过规矩，这里照它办。
- **落点被占的判据收紧**：认「这一步是被那道闸挡下来的」，不认 `io::ErrorKind`。
  `AlreadyExists` 那道豁免现在会把「该建目录的位置上躺着一个文件」也放过去，
  导致连续失败计数一次都不涨、放弃机制永不触发。
- **一次 `place()` 之内共享一份目录缓存**（落点判定建、占用查询复用）。作用域收在
  单次调用之内，不按整趟缓存——后者会把 TOCTOU 那道缝重新打开。

### 表格与批量代价

- **队列那一屏在内存里排序。** 它的条目本来就在内存里（几千条），与变体表那种下推到
  `ORDER BY` 的路子不同；不为它改查询。
- **差量预览的步骤表改成虚拟化的。** 计划整份本来就已经在界面状态里，表格组件也本来
  就支持——去掉那个 2,000 条的上限，四行汇总照旧留着。
- **整批收藏排上任务台。** 它要一份落在磁盘上的库（内存库分不出第二份连接），
  所以这条路要么在内存库上退回同步、要么把这一下限制在磁盘库上——**如实说出走了哪条**。
- **给识别那一层加一个批量取判据的入口**（一趟几条查询取回整批），单条那份改成它的
  特例，两者不会漂开。队列填判据那一路跟着受益。

### 作品与标题

- **不给 `work.name` 补 `UNIQUE`。** `work` 是跨平台、跨地区的**游戏概念**（平台在
  发行版那一层），同名异作是真实存在的；裸约束会把它们强行并成一部。改成**识别重跑时
  按名字复用现成的那一行**，且**裁决来源的优先**——重跑识别本来就只清「识别自己造的」
  那些行，复用之后 `work.id` 不再被换掉，作品锚点跟着稳住。
- **变体表那一列作品名下推到查询里**（浏览专用的行类型，与「变体表的一行」分开），
  排序与筛选一律下推到中立库（ADR-0005）。
- **「中文覆盖率」数的是「标题集合里有中文的作品」**，不是「显示标题是中文的作品」。
  它回答的是刮削采到了多少，不该被后续的显示选择抹掉。报告改口径，详情面板不动。
- **删标题保持「都能删」，但删掉的要压得住。** 现在重折时会把非裁决来源的整批重建，
  于是删掉的下次刮削又回来。要在标题那一层记下「这条被压掉了」，重折时尊重它。

### 结构性损失

- **词表收下这个词。** `CONTEXT.md` 现有的**能力档位**四个词（只读、只写、双向、无损往返）
  答不了「把值交给这个格式存一趟会变成什么样」，词条那一句已经窄了半格——新词条要与
  能力档位并列，说清两者的分界。
- **Pegasus 补齐三条**：值末尾的空白、值里恰为 `.` 的一行、多值字段里的换行与空串。
  照既有做法：**先量，再声明**，行为一个字不改。
- **ES gamelist 先量再声明。** 空清单在文档与报告里定成「还没查过」，不是「什么都不丢」
  ——这条口径已经有测试钉着，量完之后不许弱化它。

### 夹具与合成数据

- **合成数据那条能按形状造的路子推广到 `--bench-browse` 与那七个界面测试**，
  它们各自钉的东西（帧率、面板、媒体、版式）跟着重定基线。
- **合成数据里每个变体都补 `entry` 行。** 补完之后别的屏上「钉在内容上的多少条」
  那个数会从 0 变成一万多——**那是对的**，跟着改断言。
- **两份界面测试的小库夹具搬进共用模块**，一次改两处。
- **批次卡片补一句悬停**，折算那一对核心库里已经备好了。

## Testing Decisions

**什么算一条好测试。** 只断外部行为，不断实现细节。这个仓库有两条既有接缝，本轮**优先
用它们**，只新加一道：

### 接缝一：核心库的集成测试（`crates/core/tests/`）

对着一份真造出来的中立库跑，断的是「库里读回来的是什么」「报告印出来的是什么」。
本轮用它验：门禁子命令的行为、结局那条轴的四种收场、落点闸的三格、批量取判据与单条
那份给出同一个说法、识别重跑之后作品行没有多、中文覆盖率数的是哪一批、结构性损失
清单的内容与「空清单不许印一句假保证」。

**既有范本**：`works.rs::一行底下只要还剩一个变体没跑过识别这一行就说还没识别`
（同一件事的两种折法，把错的那种换回来当场红）；`sync_run.rs` 那三条落点占用；
`pegasus.rs` 里按关键字找声明、不断言清单长度的写法。

### 接缝二：界面测试的「画出来的字」（`crates/gui/tests/`）

从一帧的输出里收集所有文本，**一段一行**。「屏上摆得出来」「屏上写的是同一个词」
「屏上没了」这三类断言只有看这个才算数——查数据结构里有没有这条是在测别的东西。
本轮用它验：任务屏那一行写着「停了，留下了…」而不是「完成」、剩余时间那一格在算不出
时**一个字都不画**、队列表点表头之后第一行换了、步骤表第 5,000 行摆得出来、
变体表按作品名排序之后的次序、批次卡片悬停那句话。

**既有范本**：`queue.rs` 里「屏头不许出现『还没识别 0』」那条（断的是**没有**）；
`browse.rs` 里「一条顶到闸上的简介收成一行画得下的那一截」（靠一段一行这个粒度）。

### 接缝三（新增）：执行层的目标侧

落点闸那三格里有两格在开发机上造不出来（要一个大小写不敏感的挂载点、要一个列不开的
目录）。加一道**可注入的目标侧接缝**，加在执行层对外那一个入口上，不下沉到每次文件操作。
注入之后，同一批落点占用的测试在两种折叠语义下各跑一遍。

**这是本轮唯一的新接缝**，而且它同时解掉 `Q135`（不敏感盘验不了）与 `Q136`（列不开的
目录那一格）——两条都因为「没有能塞进一个假文件系统的地方」而被挂了两轮。

### 门禁这一组怎么验

- 门禁子命令自己要有测试：给它一份故意不 fmt-clean 的输入，它得红。
- CI 那份配置**不写测试**——它只调子命令，验它的方式是推一次看它跑。
- 68 条 rustdoc 告警清零之后，硬红那个开关本身就是回归测试：再断一条链接当场红。

### 不为它们写测试的

- `rust-toolchain.toml` 落地（是一份声明，验的方式是 `rustfmt --version`）。
- README 里的数字（由门禁输出对照，不另立断言——那会变成两处要同步的数）。
