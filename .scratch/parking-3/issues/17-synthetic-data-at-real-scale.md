# 17 — 合成数据长成真库的形状

**What to build:** 维护者跑界面实测量出来的帧率，是他**真会遇到**的那个；`--demo` 打开的
队列里，详情不再**每一条**都写着「裁决钉在：路径——只在本机成立」。（挂单 `Q156` `Q168`）

眼下：`--bench-browse` 与七个界面测试还跑在二十个作品上（真库主列表是 10,978 行，
那份合成数据只收出 3,596 行）；合成数据里**只有两个变体有内容锚那一行**，别的一万六千多条
折不出内容锚，于是全都退到路径锚。

**Blocked by:** 16（夹具已经并成一份，这张票只改一处）

**Status:** ready-for-agent

- [ ] `--bench-browse` 与那七个界面测试换到**按形状造**的那条路子上，跑真库量级。
- [ ] 它们各自钉的东西（帧率、面板、媒体、版式）跟着**重定基线**——新旧数字并排写进报告，说清每一条为什么变。
- [ ] 合成数据里**每个**变体都补上内容锚那一行，折得出内容锚。
- [ ] 补完之后别的屏上「钉在内容上的多少条」那个数会从 0 变成一万多——**那是对的**，跟着改断言，别为了保住旧数字回避。
- [ ] `--demo` 打开的队列里，详情不再每一条都说「钉在路径」。有一条界面测试钉着这一点。
- [ ] 合成数据那几处注释改准——现在写着「钉在内容上」却一条内容锚都没有。
- [ ] 挂单 `Q156` `Q168` 标 `settled` 并分别迁回票 `gui-redesign/13` 与 `queue-followups/06`。
