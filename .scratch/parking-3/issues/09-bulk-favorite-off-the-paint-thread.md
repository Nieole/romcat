# 09 — 整批收藏离开画帧线程

**What to build:** 维护者按下「全选 46,483 行 → ★ 收藏」，窗口不冻住——它像别的长活一样
排上任务台，看得见进度、按得停。实测眼下这一下在画帧那条线程上跑 **6.7 秒**。（挂单 `Q119`）

那 6.7 秒里的大头是：判据折算**一个变体问四次库**（成员、容器构成、容器状态、算过的哈希）。
真库上队列有 18,241 条要各算一次，所以这条不只是「全选」那一下的事。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 识别那一层加一个**批量取判据**的入口：一趟几条查询取回整批，不是一条四次。
- [ ] 单条那份改成批量那份的**特例**，两者共用同一个说法。**不许另写一遍**——那一层是「谁代表这个变体」的唯一说法，写两遍迟早漂开，而漂开的后果是同一个变体上的收藏与裁决钉在不同的东西上。
- [ ] 队列填判据那一路改走批量入口，实测数字写进报告。
- [ ] 整批收藏排上任务台，跑完了按号认领——与差量预览一模一样的形状。
- [ ] 它要一份**落在磁盘上的库**（内存库分不出第二份连接）。内存库上走哪条路（退回同步 / 直接拒绝并说清楚）由实现者挑一条，**在挂单里写明走了哪条**。
- [ ] 有一条界面测试断：这一下跑着的时候屏上有进度、有「停下」。
- [ ] 实测重跑一遍（dev profile，同一份合成数据），新数字与 6.7 秒并排写进报告。
- [ ] 挂单 `Q119` 标 `settled` 并迁回票 `gui-redesign/06`。

## 别顺手做的

- 增量投影与整份重建走**同一个展开**这条正确性修复不许退回去——它当初买回来 1.5 秒是有理由的：同一份内容存了两处时，不这么做屏上这一下与下一趟识别会给出两种样子。
