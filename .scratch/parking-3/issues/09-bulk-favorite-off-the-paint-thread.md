# 09 — 整批收藏离开画帧线程

**What to build:** 维护者按下「全选 46,483 行 → ★ 收藏」，窗口不冻住——它像别的长活一样
排上任务台，看得见进度、按得停。实测眼下这一下在画帧那条线程上跑 **6.7 秒**。（挂单 `Q119`）

那 6.7 秒里的大头是：判据折算**一个变体问四次库**（成员、容器构成、容器状态、算过的哈希）。
真库上队列有 18,241 条要各算一次，所以这条不只是「全选」那一下的事。

> **收尾更正（两处）：** ① 收藏那一路每个变体其实是 **5–6 次**——上面那四次之外，
> `collection::apply` 自己还要一次 `Catalog::variant`，`landed` 的路径锚那一支再一次。
> ② 「大头是查询」这个判断在实测上不成立：批掉那些查询只省下不到 2 秒，其余是
> `identify::collect` 的纯 CPU。两条都记在挂单 `Q274`。

- **`--all-features` 没省**，`--keep-going` 也带了：66 个目标、1,656 条，数对得上。
  `main` 上那一份是 1,681 条 / 66 个目标——本分支从 `4ab25c1` 切出，中间 `main` 又合进了
  六张票，少的那 25 条是它们带来的，不是这一票丢的。
- **那条挂钟彩票（`任务六秒都没跑完`，挂单 `Q349`）这一趟没红**：机器是空的。
- **`cargo doc` 那条是软的**：66 条既有 rustdoc 告警。头一趟跑出来是 66（`romcat-core`
  58 + `romcat-gui` 8），比既有的多两条——**都出在本票新写的那一段文档上**
  （`identify::content_prints` 的文档链到了私有的 `KEYS_PER_QUERY` 与 `Bulk`）。
  当场改成不带链接的代码体，`cargo doc` 重跑：**56 + 8 = 64**，与既有基线一致，
  **本票一条新告警都没添**。那 64 条是票 `parking-3/02` 的活，没顺手去清。
- 那一处改的是**一行文档注释**，所以改完只重跑了 `fmt`（干净）、`clippy`（绿）、
  `doc`（64 条，全绿）；`test` 那条的结果原样成立——一行注释改不动它。
