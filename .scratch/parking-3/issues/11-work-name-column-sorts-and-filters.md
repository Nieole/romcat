# 11 — 变体表那一列作品名排得了序

**What to build:** 维护者翻库时认的是**作品**（不是那些各路来源攒出来的文件名），
所以变体表里有一列作品名——但它排不了序也筛不了，因为它是从一张整份读进来的小表
（真库 9,226 条）里查的，不在查询的排序与筛选里。想按作品找就只能退回「键里含」那个框。
（挂账 `D161`）

**Blocked by:** 10（作品行的形状在 `10` 里刚动过）

**Status:** ready-for-agent

- [ ] 作品名**下推到页查询里**——排序与筛选一律下推到中立库（ADR-0005），不在内存里补。
- [ ] 另立一个**浏览专用的行类型**，与「变体表的一行」分开——后者被十几处构造着，直接给它加字段会波及一大片。
- [ ] 点表头按作品名排序；筛选器里作品名也用得上。
- [ ] 有测试断：按作品名排序之后屏上画出来的次序对。
- [ ] 有测试断：没有作品的那些变体（作品那一格是空的）排序时的位置是确定的，不是随机漂。
- [ ] 帧率不塌：真库量级（10,978 行）上翻行的代价与总行数无关，实测数字写进报告。
- [ ] 挂账 `D161` 标 `settled` 并迁回票 `rom-metadata-automation/25`。

## 说明

「按标题排」是另一件事——那要的是标题选取的结果，SQL 里算不出来。这张票**只做按作品名排**，
标题那条路不在范围内，如实记在挂单里。
