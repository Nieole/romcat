# 03 — 任务台说得出「停了，留下了产物」

**What to build:** 维护者按停一趟已经往卡上写进去东西的同步，子库屏说「⚠️ 这一趟被你按停了」，
任务屏历史那一行**也**这么说——而不是记成「完成」。同一趟活不再在两屏上说两套话。

眼下核心库那对枚举只认三种收场（跑完 / 被按停 / 出错），说不出**「被按停，但留下了
可用的产物」**这第四种；扫描与同步被叫停时都返回「成功」，于是任务屏历史里那一行是
「完成」。（挂单 `Q153`）

**这是本轮的前置票**——票 `04` `05` `06` `09` 都要动它定下来的形状。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 核心库那对近乎重复的收场枚举合流成**一条轴**，能表达四种收场：

  ```
  跑完了              → 有产物
  停了，什么都没留下   → 干净，可以当没跑过
  停了，留下了产物     → 有产物，且明说它是半截的
  出错了              → 停在哪一步、为什么
  ```

  （这个形状是从 `sync::execute::run` 与 `scan::scan` 两条真实路径上折出来的：两者都在
  被叫停时返回「成功」并把「被打断了」记在账上——ADR-0015 要求写过东西的活留下续跑的
  依据才停得干净，抛错会把清单丢掉。）

- [x] 同步与扫描被叫停时走**第三支**，不再折成「跑完了」。
- [x] 任务屏历史那一行如实画出这四种的区别，「停了，留下了产物」那一行说得出留下了什么（走了几步 / 落了几件）。
- [x] 子库屏那句回执与任务屏历史说的是**同一件事**——有测试对着「画出来的字」钉着两屏的措辞不打架。
- [x] 每一种收场都有测试：核心库那一侧断返回的是哪一支，界面那一侧断屏上画出来的是哪一句。
- [x] 挂单 `Q153` 标 `settled` 并迁回票 `gui-redesign/15`。

## 硬约束

- **不许抛错代替返回。** 写过东西的活抛出去等于把清单丢掉，下一趟会把这次放上去的东西当成「清单之外」，于是碰都不敢碰（ADR-0015）。
- 「剩余时间」不归这张票，归票 `04`；「按停之后措辞对不对得上」不归这张票，归票 `05`。这张票只把**轴**定下来。

## 收尾（2026-09-07）

**这条轴长什么样**（后面四张票接的就是它）：

```rust
pub enum Ending<T> {          // crates/core/src/task.rs
    Done(T),                  // 跑完了，产物在这儿
    Stopped,                  // 停了，什么都没留下——干净，可以当没跑过
    Halfway { product: T, left_behind: String },  // 停在半路：没走完就收了场，可交出了产物
    Failed { step: String, why: String },         // 出错了
}
```

`Done<T>` 没了，`Finished::ended` 是 `Ending<T>`，`Record::ending` 是
`Ending<()>`（`Ending::forget` 折的：产物归认领它的那一屏，历史只留账）。
**走哪一档、以及那句「留下了什么」整句，都由长入口自己说**——`Handle::halfway(…)`，
任务台在 `Board::settle` 里 `Ok(product)` 那一支问一次（那个 getter 不对外）。
`Ending::render` 折出来是「停在半路：{留下了什么}」——**「为什么收的手」不写死在这一层**，
因为下一批候选（连着失败太多次主动停了、刮削撞上配额）不是被按停的（`Q216` `Q217` `Q221`）。
分「停了」与「失败」的那道字符串比对**原样没动**（票 `05` 的活）。

### 逐条证据

- **合流成一条轴，四种收场** —— `crates/core/src/task.rs::Ending<T>`。
  测试：`task::tests::四种收场各画各的话`（四句去重之后仍是 4 条）、
  `task::tests::被按停却交出了产物的那一趟记成停在半路而不是完成`。
- **同步与扫描走第三支** —— `sync::execute::run` 在 `out.interrupted` 时报
  `task.halfway(留下了什么(out.touched()))`；`scan::scan` 在 `interrupted` 时报
  「走过 N 个条目，断点写下了」。界面那一层 `roots.rs` 里那道
  `Ok(outcome) if outcome.interrupted => Err(Halted.to_string())` **拿掉了**
  ——那份半份体检报告不再被丢掉（挂单 `Q214`）。
  测试（四条都**把活丢上任务台跑完再断它记成了哪一支**，断的不是那个侧信道）：
  `crates/core/tests/task.rs::同步按停时已经落下东西的那一趟在台上记成停在半路而且说得出落了几件`
  （用一份只读视图把那一下钉死在「读到第几个文件」上，不靠抢时间；断的是
  `Ending::Halfway`、`interrupted`、`touched() > 0`，以及那句话里的件数与 `touched()`
  **对得上**——不写死某个数）、
  `同步按停时一件都没落的那一趟也记成停在半路留下的只有清单`、
  `扫描被叫停时在台上记成停在半路而且说得出断点写下了`、
  `没设断点的那一趟被叫停时不许说断点写下了`（后两条断的是「断点写下了」/「没设断点」
  整半句——只断「断点」两个字的话，两支文案互换了照样绿）。
- **历史那一行画得出四种的区别、说得出留下了什么** ——
  `crates/gui/tests/task.rs::四种收场在任务屏历史里各画各的话`：对着**画出来的字**
  逐行断四句，其中那一行整整齐齐是
  「停在半路：按停时落了 1 件，清单记着到这儿为止目标上真实有什么」，
  而屏上「完成」只出现一次（四趟里只有一趟是真跑完的）。
- **两屏措辞不打架** ——
  `crates/gui/tests/sublibrary.rs::按停一趟同步之后子库屏与任务屏说的是同一件事`：
  真按「同步」再按「停下」，子库屏那句回执与任务屏历史都出现「按停」，
  任务屏那一趟自己那一行写着「停在半路」、**不含「完成」**。
  **保留一处**：这条测试里那一趟停在第一步之前（`touched() == 0`），
  屏上那句是「一件都没落，只重折了那份清单」——「落了 N 件」那半句的实测由核心那条
  `同步按停时已经落下东西的那一趟说得出落了几件` 钉着（它用一份只读视图把那一下
  钉死在「读到第几个文件」上，不靠抢时间）。
- **每一种收场都有测试** —— 核心：上面三条 + 既有的
  `被叫停时停在两步之间`（`Stopped`）、`失败的那一趟说得出哪一步为什么`（`Failed`）、
  `就地跑的那趟账照样进任务台`（`Done`）。界面：`四种收场在任务屏历史里各画各的话`
  一条覆盖四句，另有 `crates/gui/tests/roots.rs::界面上按停一趟扫描_…` 断扫描那一趟
  是 `Ending::Halfway` 且那句话里说得出「断点写下了」。

  `.scratch/gui-redesign/issues/15-sublibrary-long-runs-onto-the-board.md`

### 词表

`CONTEXT.md` 的「工具自己的状态」一节新增两条：**收场**（一条轴四档）与
**停在半路**。「停在半路」这个名字不是新起的——`Q153` 当年写下的代价那一段里
就是这么叫的（「停在半路，但留下了可用的产物」），刮削屏上也早就在这么说
（那句「这一趟停在半路：{配额用完 / 被封 / 断网}」）。词表把它收下、**写成理由无关的**
（`Q221`），并划清与「不留半截状态」的界：那说的是**那一步**干不干净，
半路说的是**整趟**只走了一段。

### 顺手收掉的一处

库屏那句回执原先把「停在半路」与「还排着队就被撤掉」并成同一句
「……断点已经写下，再按「重扫」从那儿接着跑」。改之前两档长得一样，那句话只能这么写；
轴分开之后它对**撤掉**那一种就是骗人的（压根没开跑，哪来的断点）。
`crates/gui/src/roots.rs::Screen::settle` 里那两支**拆开**了，撤掉那一趟改说
「还没轮到就被撤掉了。中立库与那块盘一个字节都没动」。
