### Q306 — 中文那几栏的子项跟着换了口径，不是只换总数

- **来自：** 票 `parking-3/12`
- **类别：** 规格没说

  显示标题口径）能少改几行，但要在报告里再写一段话解释这两组数为什么不是一件事。
  **顺带修好一处旧的少数**：`rival_works` 从前被 `chosen.language == 中文` 挡着，
  显示标题不是中文的作品即使有两个中文叫法也不计——而报告正文印的是「{} 个作品有不止
  一个中文叫法」（`report.rs:288`），两者本来就对不上。换口径之后它等价于
  `chinese_names > 1`，与那句话终于说的是同一件事。

### Q307 — 口径变了，字段名与 JSON 键没变

- **来自：** 票 `parking-3/12`
- **类别：** 规格没说
- **在哪：** `crates/core/src/title/report.rs:82`（`TitleReport::chinese_works`），
  `crates/cli/tests/titles.rs:93` 断言的就是这个 JSON 键
- **为什么没停线：** 名字没变不影响任何一条验收，而改名会漫出这张票。
- **这张票实际做了什么：** 留着 `chinese_works` 这个名字，只把它的文档与报告正文改成
  说「标题集合里有中文叫法的作品」。理由：`--json` 那份是**对外契约**，谁在读它这边
  看不见；名字本身也不带「显示」二字，改口径之后照样读得通。另一条路是改成
  `chinese_covered_works` 并在 JSON 里同时留一段时间的旧键，代价是给一个只有一个已知
  读者（CLI 测试）的键立兼容期。
  **同一条口径下还有一个键**：`TitleExample::display`（`report.rs:39`）在
  `official_examples` / `queue_examples` 这两组里装的现在是**那条中文叫法**，
  不再是显示标题，而键名照旧叫 `display`。理由同上——它在别的几节里装的仍是显示标题，
  改名要么给它起个两边都别扭的名字，要么把这个结构拆成两个。文档已经写明
  「中文那几节里它是**中文那一档的第一名**，不一定是显示标题」。
- **谁来裁：** 收尾
- **状态：** settled —— 第三轮收口 2026-09-08，走 **A（已经做完，收口只是销号）**
- **收尾裁决（第三轮收口，2026-09-08）：** **A** —— 口径变了、字段名与 JSON 键没变。理由：`--json` 那份是对外契约，名字本身也不带「显示」二字、改口径之后照样读得通；改名要给一个只有一个已知读者的键立兼容期。同一条口径下 `TitleExample::display` 也一样，文档写明了它在中文那几节里装的是什么。
