# 10 — 重跑识别复用同名的现成行

**What to build:** 维护者重跑一趟识别，库里**不会**多出两行同名的作品，挂在作品上的
收藏与媒体**不会**集体失联，之前裁决过的结果**不会**被抹掉。

眼下重跑识别会清掉「识别自己造的」那些作品行再重建，于是：既可能造出两行同名的
（作品锚点是按名字攒的，两边归组的键不一样时那两行会被数成两个作品，代表变体也可能挑到
计划没挑的那一个），又把作品行的 id 换掉（挂在旧 id 上的东西集体失联）。
（挂账 `D162`、挂单 `Q193`）

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] **不给作品名补 `UNIQUE`。** 作品是**跨平台、跨地区的游戏概念**（平台在发行版那一层），同名异作是真实存在的（1988 与 2004 两部 Ninja Gaiden 是两部作品）；裸约束会把它们强行并成一部。
- [ ] 重跑识别时**按名字找现成的那一行复用**，找不到才新建。**裁决来源的优先**——重跑识别本来就只清「识别自己造的」那些行。
- [ ] 有测试钉着：连跑两趟识别，作品行数不涨、id 不变。
- [ ] 有测试钉着：裁决造的那一行在重跑识别之后原样还在，且识别这一趟认领的是它、不是新建一行。
- [ ] 有测试钉着：作品锚点在重跑识别之后仍然指得中——挂在上面的收藏与媒体一条不丢。
- [ ] 有测试钉着：真的同名异作（两条不同的发行版线）仍然分得开，不被并成一部。
- [ ] 中立库结构若有变动，**升 `SCHEMA_VERSION` 重建**，不写迁移（中立库可再生）。沉淀库若要动，走顺序迁移、只追加、不要求删库。
- [ ] 挂账 `D162` 标 `settled` 迁回票 `rom-metadata-automation/25`；挂单 `Q193` 标 `settled` 迁回票 `gui-redesign/03`。
