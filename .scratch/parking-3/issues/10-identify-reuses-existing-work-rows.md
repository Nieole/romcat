# 10 — 重跑识别复用同名的现成行

**What to build:** 维护者重跑一趟识别，库里**不会**多出两行同名的作品，挂在作品上的
收藏与媒体**不会**集体失联，之前裁决过的结果**不会**被抹掉。

眼下重跑识别会清掉「识别自己造的」那些作品行再重建，于是：既可能造出两行同名的
（作品锚点是按名字攒的，两边归组的键不一样时那两行会被数成两个作品，代表变体也可能挑到
计划没挑的那一个），又把作品行的 id 换掉（挂在旧 id 上的东西集体失联）。
（挂账 `D162`、挂单 `Q193`）

**Blocked by:** None — can start immediately

**Status:** done

- [x] **不给作品名补 `UNIQUE`。** 作品是**跨平台、跨地区的游戏概念**（平台在发行版那一层），
  同名异作是真实存在的（1988 与 2004 两部 Ninja Gaiden）；裸约束会把它们强行并成一部。

  一个字都没往 `work` 表上加约束。表注释里写清了这是**有意的**，以及「同一部作品只该有
  一行」这件事**由复用那条路保证、不由约束保证**（`crates/core/src/catalog/content.rs`）。
  测试 `同名异作插得进两行而重跑识别不抹掉裁决造的那一行` 当场插两行同名的进去，
  库里没有拦它的东西。这与挂账 `D53`（`resolved —— 维持原样`）同一条口径。

- [x] 重跑识别时**按名字找现成的那一行复用**，找不到才新建。**裁决来源的优先**——
  重跑识别本来就只清「识别自己造的」那些行。

  四处改动：`clear_identifications` 不再 `DELETE FROM work`、也不再整列摘空
  `variant.work_id`（发行版照旧整批重建）；`work_named` 的 `ORDER BY` 换成
  `(origin = '裁决') DESC, id`；`Projector::work` 复用现成那一行时来路**只升不降**；
  `write_identifications` 改成**逐条覆盖**变体身上那两条链接（认不出来时写的是空）。
  收尾那一遍 `drop_unheld_identified_works` 只收 `origin = 识别`、且只在**跑完整一趟**
  之后跑。顺手给 `work(name)` 补了索引——复用之后那张表一开始就是满的，实测 9,226 行上
  9,226 次 `work_named` **13.52 秒 → 0.639 秒**（debug、内存库）。

  **后两处是审查抓出来的**（`Q288` 记着审查本身跑错地方那件事）：来路无条件重写会在
  「识别与裁决在同一趟里各认领一次、而中断落在两次之间」时把裁决那一行永久写成「识别」；
  整列摘空 `work_id` 会让「被叫停之后接着重扫」把整库的作品连同 `origin = 裁决` 的那些
  一起扫光。两条都另有测试钉着。

- [x] 有测试钉着：连跑两趟识别，作品行数不涨、id 不变。

  `crates/core/tests/identify.rs::连跑两趟识别作品行不涨也不换一批_id`。它不止跑两趟：
  第三趟先让库里**多出一部作品**（一条裁决点名一个新名字）——删了重建那条老路子在这一步
  会按变体次序重新发号，插进来的那一行**后面**的作品全体换号。改之前实测
  「Super Mario Bros.」从 2 号变成 3 号，当场红。

- [x] 有测试钉着：裁决造的那一行在重跑识别之后原样还在，且识别这一趟认领的是它、
  不是新建一行。

  `重跑识别认领裁决造的那一行而不是新建一行`：一条裁决把汉化版那份钉到原版那部作品上，
  重跑之后两个变体挂在**同一行**、而且是原来那一行（改之前实测 `Some(2)` → `Some(1)`，
  当场红）；再跑一趟仍然是它。`同名异作插得进两行而重跑识别不抹掉裁决造的那一行`
  另钉一条：同名有两行时复用挑的是 `origin = 裁决` 那一行，而识别自己造的、如今没人
  指着的那一行跟着这一趟收掉。

- [x] 有测试钉着：作品锚点在重跑识别之后仍然指得中——挂在上面的收藏与媒体一条不丢。

  两条。`被叫停之后重扫再跑一趟作品锚点照样指得中`：起手就被按停的一趟识别之后立刻重扫
  （常规动作），作品行一个都不该被重新成型收掉，再跑一整趟之后锚点还是原来那个。
  把 `UPDATE variant SET work_id = NULL` 那句加回去当场红。

  `作品锚点在重跑识别之后仍然指得中`：拿到 `WorkAnchor::Work(id)`，往作品锚点上挂一条
  刮削值与一份媒体、往沉淀库里落一条**收藏**，然后**删掉库里另一部作品**（这一步会让
  老路子整体换号）、重扫、再跑一趟识别；同一个锚点仍然 `work_detail` 得出同一部作品，
  年份、媒体与收藏一条不丢。改之前实测锚点指到了「Some SFC Game」，当场红。

- [x] 有测试钉着：真的同名异作（两条不同的发行版线）仍然分得开，不被并成一部。
  **（框文与兑现的东西不是一件事，照勾但改口 —— 见 `Q284`）**

  **兑现的是：两条发行版线分得开；作品那一层共用一行，那是挂账 `D53` 已裁的口径。**
  原框文（连同规格 story 35「工具不会替我把两个游戏并成一个」）读起来像是作品层也分得开

  **保留：** 分得开的那一层是**发行版**；在**作品**那一层它们仍旧共用一行。工具手上只有
  名字，而「作品名就是作品的身份」是挂账 `D53` 早已裁过的口径（`resolved —— 维持原样`），

  （上一条那个测试钉着）。记在挂单 **`Q284`**。

### Q284 — 同名异作在**作品**那一层仍旧只有一行

- **来自：** 票 `parking-3/10`
- **类别：** 两份东西矛盾
- **在哪：** `crates/core/src/identify.rs` 的 `Projector::work`、
  `crates/core/src/catalog/content.rs` 的 `work` 表注释；票 `parking-3/10` 验收第 6 条
  「真的同名异作…不被并成一部」
- **为什么没停线：** 票自己那个括号（「两条不同的发行版线」）就是这条路；而挂账 **D53**
  （`deferred.md:331`）早已把这件事裁过一遍，状态 `resolved —— 维持原样`，原话是
  「同名在中立库里本来就已经是同一个作品了，锚点只是跟着它；真要分开，该分的是识别
  那一层的去重键」。翻它不是这张票的事。
- **这张票实际做了什么：** 走 D53 那条已裁的口径——**作品名就是作品的身份**。复用按名字
  来，同名的两部真作品在**作品**那一层共用一行；**分得开落在发行版那一层**，两条发行版线
  各自成行（测试 `同名的两条发行版线不会被并成一条`：一个作品、两条 `release`、
  FC 与 SFC 各一，重跑一趟也不多攒出第三条）。`work.name` 上**没有补 `UNIQUE`**，
  门留着：人工给其中一部改个名（一条裁决就够）之后两行并存，而重跑识别既不把它们并成
  一行、也不抹掉裁决那一行（测试 `同名异作插得进两行而重跑识别不抹掉裁决造的那一行`）。
  另一条路是给作品加消歧键（年份 / 平台世代），要同时改刮削锚点、`converge`、
  浏览行的分组与筛选四处——远超这张票，也正是 D53 说的「该分的是识别那一层的去重键」。

### Q285 — 被叫停的那一趟识别不收「没人再指着」的作品行

- **来自：** 票 `parking-3/10`
- **类别：** 规格没说
- **在哪：** `crates/core/src/identify.rs` 的 `run()` 末尾那句 `if !interrupted`；
  `Catalog::drop_unheld_identified_works`
- **为什么没停线：** 两条路都留下一个说得清的窗口，选的这条窗口更小、而且不会把这张票
  刚治好的病重新引进来。
- **这张票实际做了什么：** 收尾那一遍**只在跑完整一趟之后**跑。被叫停时不收——那时还有
  变体没轮到，收了等于把它们的作品连 `id` 一起扔掉，正是本票要治的那件事。
  **审查在这儿抓到一个洞，一并补了**：起初的写法是「重新成型那一遍是安全网」，
  而它其实是漏洞——`clear_identifications` 起手把 `variant.work_id` 整列摘空，
  于是被叫停之后接着重扫（常规动作），`drop_unheld_works`（判据「还有没有人指着」、
  **不看来路**）会把整库的作品连同 `origin = 裁决` 的那些一起扫掉。补法是**不再整列摘空**：
  变体身上那两条链接改由 `write_identifications` **逐条覆盖**（认不出来时写的是空），
  于是「这一趟认不出来了」与「这一趟还没轮到它」在库里分得开。
  钉着它的测试：`crates/core/tests/identify.rs::被叫停之后重扫再跑一趟作品锚点照样指得中`
  （把那句 `UPDATE variant SET work_id = NULL` 加回去当场红）。
  **剩下的代价**：叫停之后到下一趟跑完之前，库里可能留着已经没人指着的作品行，报告里
  「识别建出来的作品数」在那个窗口里偏高。
- **谁来裁：** 下一个动识别中断路径的人
- **状态：** settled —— 第三轮收口 2026-09-08，走 **A（已经做完，收口只是销号）**
- **收尾裁决（第三轮收口，2026-09-08）：** **A** —— 被叫停的那一趟识别不收「没人再指着」的作品行——收了等于把还没轮到的变体的作品连 `id` 一起扔掉，正是本票要治的那件事。**审查在这儿抓到一个洞并补掉了**：起初 `clear_identifications` 整列摘空，于是被叫停后重扫会把整库作品（连同 `origin = 裁决` 的）一起扫光；改成逐条覆盖，测试 `被叫停之后重扫再跑一趟作品锚点照样指得中` 钉着。剩下的窗口是明写认下的代价。

### Q286 — `origin = 裁决` 的作品行，识别这一趟一行都不收

- **来自：** 票 `parking-3/10`
- **类别：** 规格没说
- **在哪：** `Catalog::drop_unheld_identified_works` 里那句 `WHERE origin = ?1`
- **为什么没停线：** 票自己写着「重跑识别本来就只清『识别自己造的』那些行」。
- **这张票实际做了什么：** 收尾只收 `origin = 识别`，而且**来路这一列只升不降**
  （`Projector::work`：识别认领到一行 `origin = 裁决` 时一个字都不动它）。
  **只升不降那一半是审查抓出来的**：起初的写法是「这一趟头一次认领就照本趟重写来路」，
  而识别与裁决在同一趟里各认领一次，**中断正好可以落在两次之间**——那一行会永久停在
  「识别」，下一趟跑完就被收掉，`Q286` 承诺的东西在那条路上失效。顺带也省掉真库上
  9,226 次「写的还是原值」的 `UPDATE`。
  **代价**：一条裁决从沉淀库里删掉之后，它投影出来的那一行会一直挂着「裁决」这个来路
  （报告里「识别建出来的作品数」因此少数一个），而且识别一趟都收不掉它，直到下一次
  **重新成型**（`drop_unheld_works`，判据「还有没有人指着」、不看来路）把它收掉。
  审查核过这条的下游：刮削 subject 与导出收敛都从变体反查作品名，幽灵行不会烧配额、
  也不会长出浏览行，只有 `crate::title` 会给它开一个空标题集合。
  走这条的理由是「识别不替沉淀库做主」；反过来（识别也收裁决那一行）会让 `Q284` 说的
  那扇门在下一趟识别里自动关上。
