# 04 — 任务屏给出「约剩 X」

**What to build:** 维护者看着一趟长活（真机上扫描要 37 分钟）跑，屏上除了「已用 X」
还有「约剩 X」，能据此决定是等它还是去干别的。工具算不出来的时候**一个字都不画**——
不给一个跳来跳去的假数字。（挂单 `Q54`）

**Blocked by:** 03（进度那一层的形状在 `03` 里刚动过）

**Status:** done

- [x] 剩余时间的折算落在**核心库**，不在界面（ADR-0005：折算是领域逻辑）。口径：已用时间 ÷ 已完成比例 − 已用时间。
      —— `crates/core/src/task.rs::Progress::remaining(elapsed)` 一句
      `elapsed / fraction - elapsed`；`Live::remaining()` 只做「把这一趟的表配这一趟的
      进度」。界面那一侧（`crates/gui/src/task.rs::running_ui`）一次除法都没有，
      只有一句 `format!`。核对：`走了几成说得出时约剩多久是照眼下这个速度直推出来的`
      （四步走完一步＝两成五，跑了 30 秒 → 还要 90 秒）。
- [x] 只在「走了几成」说得出来时才有值。说不出来时给「没有」，而不是 0 或一个猜的数。
      —— **两条路走到「没有」**：`fraction()` 本身是 `None`（总步数还没报），
      以及 `fraction()` 说得出、可它是 `Some(0.0)`（已用除以零成折不出一个数）。
      后者是真机上 `sources::refetch` 取 DAT 与取 Switch **整趟下载**停着的那一档
      （一共一步、一次 `tick` 都不叫）。全函数没有一个 `unwrap_or`、没有占位常量。
      核对：`说不出走了几成时约剩多久是没有而不是零`（两档都断）。
      **溢出也走同一个出口**：`Duration::try_from_secs_f64(left).ok()` —— 那一句在
      画帧线程上，`from_secs_f64` 的第四种 panic（有限但超过 `u64::MAX` 秒）
      `is_finite()` 拦不住（`/code-review` 报的）。
- [x] 界面拿到「没有」就**一格都不画**——与既有那条「说不出走了几成时画一条来回跑的条、
      而不是一条停在 0% 的条」是同一套诚实口径。
      —— `running_ui` 里是裸的 `if let Some(left) = live.remaining()`，**没有 `else`**：
      不画占位、不画「未知」、不画 `约剩 --`。
      **保留**：票里引用的那条「既有口径」其实只兑现了一半——`fraction()` 在
      「报了总步数、走了零成」时答的是 `Some(0.0)`，于是屏上画的正是一条停在 0% 不动的
      条，恰恰是那句注释自己说「看着像卡住了」的样子。不去动 `fraction`（那是既有签名），
      记在挂单 `Q226`。
- [x] 「已用 X」照旧留着，两个数并排。
      —— `crates/gui/src/task.rs:181` 那行一个字没动，新那一行插在它后面同一个
      `ui.horizontal` 里。核对：`走了一半时屏上那一句写着约剩多少` 从**画出来的字**里
      各取一行，两句都得在。
- [x] 有一条界面测试断：在算不出剩余时间的那一帧里，屏上画出来的字**没有**任何剩余时间的字样。
      —— `crates/gui/tests/task.rs::算不出还剩多久的那一帧屏上一个剩余时间的字都没有`：
      断的是 `!屏上.contains("剩")`（整帧禁字，照票那句「没有任何剩余时间的字样」的
      最忠实读法）。**并排验两档**（`fraction` 是 `None` / 是 `Some(0.0)`），
      每一档先断 `live.remaining().is_none()` 当**防恒绿的守卫**——夹具哪天不再造得出
      那一档，先炸的是守卫，而不是让底下那条负面断言静静变成恒真。
      再断「已用」那一行还在，不然整行没画出来也能让负面断言过。
      **真的验到了，是用变异证的**：把界面那一句改成 `unwrap_or(兜底值)` 这条**当场红**，
      改回来又绿。
- [x] 有一条界面测试断：走了一半时屏上那一句写着约剩多少。
      —— `crates/gui/tests/task.rs::走了一半时屏上那一句写着约剩多少`：夹具报
      `steps(2)` ＋ 走两步，先断 `fraction() == Some(0.5)`，再从画出来的字里取
      「约剩」与「已用」两段，断**它们印出来是同一串字**——走了一半时口径自己说了算
      （已用 ÷ 0.5 − 已用 = 已用），于是这一条不看挂钟却钉住了界面画的确实是核心折出来
      的那个数。**变异证过**：把「约剩」乘 2，这条当场红。
      （原先只断 `starts_with("约剩")`，`/code-review` 指出那样换个常数照样绿。）
- [x] 挂单 `Q54` 标 `settled` 并迁回票 `gui-redesign/15`。
      —— 那份文件第 100 行 `open → settled`，加一句指向末尾；末尾

## 挂单

号段 `Q224`–`Q233`，用掉四条，`Q228`–`Q233` **留空不复用**：

- `Q224` — 真机上那趟 37 分钟的扫描，「约剩」照四步平均折出来，一路只涨不落。
  **这是本票最重要的产出**：立票的理由就是那趟扫描，而它恰恰是唯一一趟报不出分母的活
  （`scan/mod.rs:473` 报 `tick(done, 0)`），于是整 37 分钟 `fraction` 恒等于 0.25、
  「约剩」恒等于 3 × 已用。**本票做完之后，立它的那个场景仍然拿不到一个有用的「约剩」。**
- `Q225` — 「约剩」只落在任务屏，子库屏顶栏那句回执还是只有「已用」。
- `Q226` — 「走了零成」在进度条那儿是 `Some(0.0)`，在「约剩」这儿是「没有」。
- `Q227` — 按字节报进度的那两趟（中文离线源、刮削），开头几秒的「约剩」会大得离谱；
  明写出来，免得下一个人以为是漏了平滑。
