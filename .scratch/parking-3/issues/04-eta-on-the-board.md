# 04 — 任务屏给出「约剩 X」

**What to build:** 维护者看着一趟长活（真机上扫描要 37 分钟）跑，屏上除了「已用 X」
还有「约剩 X」，能据此决定是等它还是去干别的。工具算不出来的时候**一个字都不画**——
不给一个跳来跳去的假数字。（挂单 `Q54`）

**Blocked by:** 03（进度那一层的形状在 `03` 里刚动过）

**Status:** ready-for-agent

- [ ] 剩余时间的折算落在**核心库**，不在界面（ADR-0005：折算是领域逻辑）。口径：已用时间 ÷ 已完成比例 − 已用时间。
- [ ] 只在「走了几成」说得出来时才有值。说不出来时给「没有」，而不是 0 或一个猜的数。
- [ ] 界面拿到「没有」就**一格都不画**——与既有那条「说不出走了几成时画一条来回跑的条、而不是一条停在 0% 的条」是同一套诚实口径。
- [ ] 「已用 X」照旧留着，两个数并排。
- [ ] 有一条界面测试断：在算不出剩余时间的那一帧里，屏上画出来的字**没有**任何剩余时间的字样。
- [ ] 有一条界面测试断：走了一半时屏上那一句写着约剩多少。
- [ ] 挂单 `Q54` 标 `settled` 并迁回票 `gui-redesign/15`。

## 别顺手做的

- 不为它引入平滑、滑动窗口或任何一种「更聪明的估法」。线性外推 + 算不出就不画，是这张票要的全部。真需要更好的估法时，那要的是各步自己知道的东西（还剩几个文件、还剩几个请求），不是任务台猜得出来的。
