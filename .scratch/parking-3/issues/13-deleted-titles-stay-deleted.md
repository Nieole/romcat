# 13 — 删掉的标题压得住

**What to build:** 维护者在详情面板上删掉一条明显错的中文译名，它**不会**在下次刮削
之后自己回来。「删」这个动作从此是算数的。

眼下每条叫法旁边都有「删」，刮削来的也能删——但重折时会把非裁决来源的整批重建，
于是删掉的下次刮削又回来了，而界面没解释为什么。（挂账 `D157`）

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 保持「**都能删**」——删一条明显错的中文名是当下就想做的事，把按钮灰掉反而要解释一整套来源规则。
- [ ] 「这条被压掉了」记在**沉淀库**（人的动作不可再生），走**顺序迁移、只追加**，**不要求删库**。
- [ ] 标题重折时尊重压制记录：被压掉的那条不再回来。
- [ ] 界面上分得出「压掉了」与「没采到」——两者对维护者是不同的意思。
- [ ] 有测试钉着：删一条 → 重折 → 它没回来；而同一批里没删的那些照旧回来。
- [ ] 有测试钉着：压制记录在中立库重建（升 `SCHEMA_VERSION`）之后**仍然在**——它在沉淀库里。
- [ ] 挂账 `D157` 标 `settled` 并迁回票 `rom-metadata-automation/25`。

## 硬约束

- 沉淀库**不可再生**。这张票要动它，就走顺序迁移，只追加，绝不要求维护者删库重来。
