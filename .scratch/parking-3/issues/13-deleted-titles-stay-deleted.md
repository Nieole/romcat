# 13 — 删掉的标题压得住

**What to build:** 维护者在详情面板上删掉一条明显错的中文译名，它**不会**在下次刮削
之后自己回来。「删」这个动作从此是算数的。

眼下每条叫法旁边都有「删」，刮削来的也能删——但重折时会把非裁决来源的整批重建，
于是删掉的下次刮削又回来了，而界面没解释为什么。（挂账 `D157`）

**Blocked by:** None — can start immediately

**Status:** done

- [x] 保持「**都能删**」——删一条明显错的中文名是当下就想做的事，把按钮灰掉反而要解释一整套来源规则。
      `crates/gui/src/browse.rs::Screen::titles_ui` 里那颗「删」**一个条件都没加**：
      刮削来的、裁决来的一样按得下去。变的只是按下去之后走哪条路——从
      `Catalog::remove_title`（只删中立库那一行）换成

### Q314 — 压制的键取「那条叫法的五样」，不是「这个作品 + 那串字」

- **来自：** 票 `parking-3/13`
- **类别：** 规格没说
- **在哪：** `crates/core/src/verdict.rs` 第 5 条迁移（`title_suppression` 那张表的唯一索引）、
  `crates/core/src/title.rs::suppression_key`
- **为什么没停线：** 两条路都压得住票里那条验收（删一条 → 重折 → 它没回来），差别只在
  「换个源折回来的同名叫法算不算同一条」，而那不是这张票要答的问题。
- **这张票实际做了什么：** 走**窄键**——作品、语言、类型、源、值五样，与
  `catalog::title` 那张表的主键、与面板上那个「删」删掉的那一行**逐字一致**。理由：
  压制记的是**人做过的那一下**，人删的就是屏上那一行；宽键（作品 + 那串字）会把别的源
  给的同名叫法一并压掉，而 `Catalog::remove_title` 的文档早就写着「少给一样就会连坐」。
  代价说清楚：同一串字下一趟由**别的源**折回来时会再冒出来，人得再删一次。
  钉着它的测试：`verdict.rs::压制的键是那条叫法的五样_少一样都不连坐`。

- **收尾裁决（第三轮收口，2026-09-08）：** **A** —— 压制走**窄键**（作品、语言、类型、源、值五样），与 `catalog::title` 那张表的主键、与面板上那个「删」删掉的那一行逐字一致。理由：压制记的是**人做过的那一下**；宽键会连坐别的源给的同名叫法。代价（同一串字下一趟由别的源折回来时会再冒出来）说清了，测试 `压制的键是那条叫法的五样_少一样都不连坐` 钉着。
