# 13 — 删掉的标题压得住

**What to build:** 维护者在详情面板上删掉一条明显错的中文译名，它**不会**在下次刮削
之后自己回来。「删」这个动作从此是算数的。

眼下每条叫法旁边都有「删」，刮削来的也能删——但重折时会把非裁决来源的整批重建，
于是删掉的下次刮削又回来了，而界面没解释为什么。（挂账 `D157`）

**Blocked by:** None — can start immediately

**Status:** done

- [x] 保持「**都能删**」——删一条明显错的中文名是当下就想做的事，把按钮灰掉反而要解释一整套来源规则。
      `crates/gui/src/browse.rs::Screen::titles_ui` 里那颗「删」**一个条件都没加**：
      刮削来的、裁决来的一样按得下去。变的只是按下去之后走哪条路——从
      `Catalog::remove_title`（只删中立库那一行）换成
      `title::suppress`（删那一行，再往**沉淀库**记一条**压制**）。
- [x] 「这条被压掉了」记在**沉淀库**（人的动作不可再生），走**顺序迁移、只追加**，**不要求删库**。
      `crates/core/src/verdict.rs` 的 `MIGRATIONS` **追加第 5 条**（前四条一个字没动），
      建 `title_suppression` 表：`work / language / kind / source / value` 五列是那条叫法的
      去重键，加 `note` / `suppressed_at` / `lifted_at`。`schema_version()` 自动从 4 变 5
      （它就是 `MIGRATIONS.len()`）。**没有任何一处要求删库**——那条「往后拒绝、绝不提议
      删掉」的错误信息（`VerdictError::Ahead`）照旧是唯一的出口。
      钉着它的测试：`verdict.rs::第四版的老库带着裁决合集升上来_压制那张表是空的`
      （照仓库里「每加一条迁移就照这个形状补一条」的成规写的）。
- [x] 标题重折时尊重压制记录：被压掉的那条不再回来。
      `crates/core/src/title.rs::refold` 现在收 `&Store`，折完之后照
      `store.title_suppressions()` 筛一遍再写库。**筛在写库这一层**（不在挑显示标题那一层）
      ——写完之后详情面板、导出、报告与搜索读的是同一张表，各自不必再记得筛一遍。
      `title::run` 与 `scrape::zh::judge` 两条重折路径都走它；`romcat titles`
      （`crates/cli/src/main.rs`）跟着开一份沉淀库，**打不开就停下**，不降级成「没人压过」。
      核过一遍：全仓 `INSERT INTO title` 只有 `Catalog::put_titles` 一处，它的调用方只剩
      `title::refold`（已筛）、界面上那个「加进集合」（写 `裁决`，本来就不经过折）、
      合成数据与测试——**没有绕得过压制的路**。
- [x] 界面上分得出「压掉了」与「没采到」——两者对维护者是不同的意思。
      `Screen::suppressed_ui`：标题集合底下多一栏「压掉的叫法 · N 条——是你删的，
      **重折不会把它折回来**。记在**沉淀库**里：中立库删掉重扫也不丢。」，一条一行，
      每行一颗「恢复」。集合为空时那句话按这一栏在不在分两种写法：一条压制都没有时是
      「一条叫法都没有——**一条都没采到**」，有时是「集合里一条叫法都没有：底下那 N 条是
      **你压掉的**，不是没采到」。
      **实测**（`crates/gui/tests/browse.rs::删掉一条刮削来的叫法之后屏上分得出压掉了与没采到`）：
      断言看的是**这一帧真的画在屏上的字**（`元数据栏滚一趟` 收 galley），屏上有
      「压掉的叫法」，也有被压掉那条叫法的原文。
- [x] 有测试钉着：删一条 → 重折 → 它没回来；而同一批里没删的那些照旧回来。
      `crates/core/tests/titles.rs::压掉一条叫法之后重折不把它折回来而同批没压的照旧回来`。
      **实测数**：先跑一遍完整管线（识别 → 刮削 → 折标题），Contra 的标题集合里
      「魂斗罗」（台版官中那条中文译名）与「魂斗罗 中文版」（汉化组自取的名）都在；
      压掉「魂斗罗」→ `removed = true`、`recorded = true`，当场不在了；
      **再跑一整趟管线**（刮削那一侧的值一个字没动，旧行为下它必然回来）之后
      「魂斗罗」**没回来**，而「魂斗罗 中文版」**照旧回来了**，
      `choose()` 挑出来的显示标题也不再是它。先红（`title::suppress` 不存在，编译不过）后绿。
      配套两条：`撤掉压制之后那条叫法下一趟重折就回来`（这一下是可逆的）、
      `裁决来源的叫法删掉就是删掉_不为它记压制`（见挂单 `Q317`）。
- [x] 有测试钉着：压制记录在中立库重建（升 `SCHEMA_VERSION`）之后**仍然在**——它在沉淀库里。
      `crates/core/tests/titles.rs::压制记在沉淀库里_中立库整份重建之后它照旧压着`：
      压掉「魂斗罗」之后**把中立库整份换成一份空的、从头扫一遍、再跑一整趟管线**，
      沉淀库不跟着换。结果：别的叫法（「魂斗罗 中文版」）都折回来了——证明这一趟确实重折过
      ——而「魂斗罗」没有，`store.title_suppressions()` 里那条记号还在（1 条）。
      **保留**：测试走的是「换一份空的中立库」，不是真的把 `catalog::SCHEMA_VERSION` 加一
      再触发删库重建——那两者对沉淀库是同一件事（中立库整份可再生，删掉重扫就是全部动作），
      而在测试里改一个编译期常量做不到。

      `.scratch/rom-metadata-automation/deferred.md` 的 `D157` 状态改成

**`/code-review` 抓到的两条真缺陷，都已改**：

1. **两份库的写次序反了。** 原先先删中立库那一行、再往沉淀库记压制；沉淀库写不动时
   （命令行与界面同时开着撞写锁要等满十秒，`BUSY_TIMEOUT_MS` 的注释自己写着）那一行
   **已经没了而没有人记得**——下一趟重折它原样折回来，正是这张票要消灭的那个状态。
   已改成**先记号、后删行**：记号写不动时一个字都没动，「压不掉」是实话；行删不动时
   记号在、行还在，下一趟重折自己收干净。界面那一侧跟着改：不论成没成都重读一遍面板
   （那一步中间撕得开一次），出错那句从「删不掉这条叫法」改成「这条叫法压不掉」。
2. **「恢复」的回执里有半句是假的。** 原先写着「下一趟重折（`romcat titles`，或者
   界面上跑完一趟刮削）」——而 `crates/gui/src/` 里没有任何一处调 `title::run` / `refold`，
   `scrape::run` 也不写 `title` 表（这正是挂单 `Q315` 记的那件事）。那半句已删掉。

另外照审查改了三处：认不出语言码 / 类型的压制记录**整行丢掉**而不是回退成 `und` / `别名`
（回退出来的键会精确命中**别人**那一条同码同类的叫法，把它压掉，`verdict.rs::read_suppression_row`）；
「压掉的叫法」那一栏比一次作品名再画（换作品那一帧缓着的还是上一个作品的，而那一栏
每行挂着一颗「恢复」，`Screen::suppressed_of`）；`Screen::remove_title` 改名
`Screen::suppress_title`（它现在删行 + 记压制，与只删行的 `Catalog::remove_title` 隔一层同名不同义）。
`refold` 里那本压制账改成借着比、不克隆（真库上折出来的行是万级）。
