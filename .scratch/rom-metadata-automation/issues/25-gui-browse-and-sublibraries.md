# 25 — 界面：库浏览与子库管理

**What to build:** 维护者能在界面里浏览整个主库、按平台与合集筛选、查看与编辑条目元数据，并管理**子库**——编辑选择集的规则与例外、查看**差量预览**、触发同步。

所有元数据编辑收敛在这里完成，主库的元数据文件不再是编辑入口。

**Blocked by:** 21, 24

**Status:** done

- [x] 能浏览主库并按平台、合集、语言、识别状态筛选

  五个维度（多一个**中文**，见下）一律下推到中立库的 `WHERE`
  （`catalog::browse::VariantQuery::where_clause`），可选值走一次 `GROUP BY`
  （`Catalog::facets`）。`crates/gui/tests/library.rs::四个维度筛得动而且筛选下推到中立库`
  钉两件事：界面上那个总数与另一条独立查出来的相等；筛完之后内存里还是那一扇窗
  （≤ 512 行）。`五个维度都有得选而且各自带着条数` 钉每一维都非空、合集名不与平台重名
  （ADR-0011 的正交）、「还没识别」是独立的一档。
  实测（release，合成数据照真机 46,483 个变体）：**列一次筛选面板 36.3 ms**
  （平台 17 个、合集 4 个、语言 6 个、中文 2 个，连表里那列作品名靠的小表），
  **换一次筛选 1.3 ms**（平台=NDS，剩 2,735 行），每帧中位 **0.62 ms**，
  滚一整趟读库 6 次、内存里始终 431 行。十万行时是 88.9 / 1.4 ms、每帧 0.92 ms、507 行。

  **超出票面加了一维「中文」**：汉化版是**变体**，它基于的发行版多半是日版，语言那一列
  上一个中文字都没有（ADR-0012）——只按语言筛的话，这个库最要紧的那批一条都不出现。
  `汉化版按中文这一维筛得出来而按语言筛不出来` 钉住它。

- [x] 能查看与编辑条目的元数据，含标题集合与首选变体

  详情面板由 `Catalog::variant_detail` 一次折齐（作品、发行版、合集、语言、识别结论、
  文件成员、**标题集合**、显示/排序标题、**首选变体**、媒体），实测**点开一条 3.05 ms**。
  编辑三样：加/删一条叫法（来源记作**裁决**，`加一条叫法当场进标题集合而且来源是裁决`）、
  裁/撤**首选变体**（`首选变体裁得动撤得掉而中文标题的来源一个字不变`）、写下/撤掉
  **刮削字段值**（年份、发行商、开发商、类型、简介、汉化组、标题，
  `刮削来的元数据看得见也改得动`）。三样都走**裁决**来源，而优先级表把裁决排在每个
  字段的最前——写下之后导出真会用它，不是「记下了但不生效」。

  ADR-0012 那条**首选变体与标题来源解耦**：`chinese_title()` 走
  `title::best_chinese`（`title::choose` 那把排序键原样用在中文那一档上），面板上把
  「中文标题取的是哪一条、与首选无关」写成一行摆出来；测试断言换过首选之后那一条的
  值、来源、类型一个字不变。

- [x] 能创建与编辑子库，含规则与例外

  `crates/gui/tests/sublibrary.rs::建得出子库也写得进规则与例外`：建子库、加规则、
  **写坏的规则当场拦下且不入库**、记一条带说明的**排除例外**。规则怎么读走
  `Rule::parse`，例外走 `Catalog::set_exception` / `clear_exception`，
  一条领域判断都不在 `crates/gui` 里。

- [x] 差量预览在界面中呈现，同步从这里触发

  排计划那条十来步的线搬进核心 `sync::prepare`，命令行与界面调同一个函数、印同一份
  `concerns()`——「预览说的」与「同步会做的」在构造上是同一个值。
  `差量预览摆得出新增与净变化` 钉账目与「清单之外的文件不进计划」；
  `没排过差量预览就同步不了` 钉 ADR-0016 那条硬要求（没预览时目标目录上一个新文件都
  没出现）；`改过规则那份预览当场作废` 钉「不拿旧差量骗人」；
  `同步从这里触发而且只碰清单里记录过的文件` 走完整条路——落到 fixture 目录、
  维护者自己拷进去的存档连修改时间都没动、清单落回中立库、回执说得出新增/更新/删除。
  同步跑在后台线程上，带一个真按得动的「停下」；中断、放弃、有步骤失败三样都印出来。
  实测：**排一次差量预览 405 ms**（8,203 个变体、8,206 个新增、16.26 GiB）。

  **保留**：排差量预览仍跑在画帧那条线程上（405 ms 的僵住），挂在 **D156**。

- [x] 容量超限时在界面上给出裁剪建议

  超出量与按体积排序的建议都由核心算（`sublibrary::over_capacity` /
  `trim_suggestions`，两处画法收在 `trim_ui` 一处），每行旁边一个「排除」按钮——
  点它记一条**排除例外**，**一个都不自动砍**。
  `容量超限时给裁剪建议但一个都不自动砍掉` 断言建议按体积降序、累计值往上加、
  而且三个变体一个不少地全在计划里。实测：4 GiB 上限下超出 15.79 GiB，给 10 条建议。
  另加一条「求值选择集」：只问中立库，**卡不在手边也算得出选中多少与超限多少**
  （ADR-0009，`卡不在手边也算得出选中多少与超限多少`）。

- [x] 媒体资源在界面中可见，能确认某条目缺哪些媒体

  媒体一条条列出来：类型、挂在作品还是变体、哪个源、**它在媒体池里的落点**、依据
  （`媒体一条条列得出来而不只是一个数`）。缺哪些走 `VariantDetail::missing_media()`，
  `点开一条看得见作品发行版标题集合首选变体与媒体` 断言合成数据里缺视频。
  「**没查池子**」与「查了、没有」分成两态（同 ADR-0021 的道理）：媒体池不在工作目录里
  时那一栏留空并直说，而不是报一句「一张都没有」把人赶去重跑刮削。

  **保留**：只列不画图——egui 自身不解码图片，画缩略图要引一个图像解码器进来。
  挂在 **D160**。

### D162 — `work.name` 要不要补 `UNIQUE`

- **裁决：settled，走 A（不补）。** 由票 `parking-3/10` 落地。
- **为什么不补：** 作品是**跨平台、跨地区的游戏概念**（平台在发行版那一层），同名异作是
  真实存在的（1988 与 2004 两部 Ninja Gaiden）。裸约束会把它们强行并成一部，还会把
  「日后人工给其中一部改个名就分得开」那扇门一起堵死。这与挂账 **D53**
  （`resolved —— 维持原样`）是同一条口径：同名在中立库里本来就已经是同一部作品，
  真要分开，该分的是识别那一层的去重键，不是给这张表加约束。
- **条目里那半句「重跑识别可能造出两行同名的作品」怎么解的：** 不靠约束，靠**复用**。
  重跑识别从此**按名字找现成的那一行**（`Catalog::work_named`，同名有好几行时
  **裁决造的优先**），找不到才新建；`clear_identifications` 不再整张清 `work`，
  收尾才收「识别自己造的、如今没人再指着的」那些
  （`Catalog::drop_unheld_identified_works`）。于是 `work.id` 跨识别重跑不换，
  同名两行也攒不出来。
- **钉着它的测试**（`crates/core/tests/identify.rs`）：
  `连跑两趟识别作品行不涨也不换一批_id`、`重跑识别认领裁决造的那一行而不是新建一行`、
  `同名的两条发行版线不会被并成一条`、`同名异作插得进两行而重跑识别不抹掉裁决造的那一行`。
- **留下的那半格**：同名异作在**作品**那一层仍旧只有一行（分得开落在发行版那一层），
  记在挂单 `Q284`。

### D163 — 显示标题不再是中文时，报告口径与详情面板各说一套

- **裁决：settled，走 A（报告改成数「标题集合里有中文的作品」）。** 由票 `parking-3/12`
  落地。
- **为什么对齐到标题集合那一侧：** 「中文覆盖」这个数要回答的是**刮削到底采到了多少
  中文**。显示标题是**后一步**的选择——裁决可以把它定成英文名，回退链里「那条条目还
  叫什么」也会把一串拉丁字顶上去（`title.rs` 的 `best_chinese` 文档列的两种情形）——
  让那一步去抹掉前一步的产出，等于用「我拿哪个当显示名」去回答「我采到了多少中文」。
  选项 B（详情面板改成印显示标题以外的中文名）解不了这条：面板**本来印的就是**
  `title::best_chinese`，也就是标题集合里中文那一档的第一名；要动的从来是报告那一侧。
- **落地的样子：** `TitleReport::chinese_works` 的判据从 `chosen.language == 中文`
  换成 `best_chinese(set, priorities).is_some()`——**与详情面板同一个判据**。中文那几栏
  （按类型 / 按置信度 / 官方译名的来路 / 低置信那一档 / 例子）跟着一起换，好与总数对得上
  （挂单 `Q306`）。新加 `chinese_not_displayed`：那 N 个里显示标题不是中文的有几个——
  报告里「中文覆盖」与「显示标题的回退链」两个数本来就不相等，差的正是它，
  不说出来看报告的人会以为其中一处是 bug。
- **详情面板一个字都没动**（票明写它是对的）。
- **钉着它的测试**（`crates/core/tests/titles.rs`）：
  `显示标题被裁成英文之后中文覆盖照旧算它`（人裁一个英文显示标题，报告照旧算它、
  `chinese_not_displayed` 涨到 1、`VariantDetail::chinese_title()` 仍是「魂斗罗」）、
  `一条中文叫法都没采到的作品不算进中文覆盖`（报告不算它、面板也说没有）。
- **留下的那半格**：真库上改口径之后那个数是多少没量过（真库不在开发机上），
  `docs/library-facts.md` 里 2026-09-01 实测的 6,501 原样留着，记在挂单 `Q304`。
