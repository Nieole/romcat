# 23 — Windows 真机中文输入法验证（人工）

**What to build:** 在 Windows 真机上人工验证中文输入法的实际表现。**这一项自动化无法完成**——界面自动化在应用层注入事件，而输入法位于操作系统与应用之间，注入的文本根本不经过输入法。

它是一道闸门：如果验证失败，界面层需要更换，那就不应该在验证之前把队列界面盖起来。

**Blocked by:** 22

**Status:** ready-for-human

## 风险已经降了一档：维护者只用系统原生输入法

维护者确认**各平台一律只用系统原生输入法**，不装第三方输入法。这改变了风险构成：

- **最重的那条开放风险不适用了。** 调研里分量最大的未决项是**搜狗候选窗定位**——winit 上一个开了三年、且**与修复者实测结论互相冲突**的 issue，没人能断定谁对。用不上搜狗，这条整个出局。
- **要用的两个环境恰好是修复者亲测过的。** 中文输入最致命的两个 bug（回车上屏在多行输入里多插换行、组字时退格误删已有文字）2026-03-24 修复、随 **0.35.0** 发布；修复者在 PR 里贴的实测矩阵包含 **Windows 11 内置中文输入法**与 **macOS 内置中日韩**——正是这两个。

**仍然要真机验，因为剩下三条与输入法品牌无关：**

- **Windows 上默认仍走旧输入法通路**（winit 因给韩语 IME 报错误光标位置而保守），与用哪个输入法无关。
- **macOS 中文标点方向**（winit#3814）。
- **macOS 的字符检视器插不进 `★` `♪` `Ⅲ`**（winit#3342 / egui#2359，三年未修）——这些符号在游戏标题里真实存在。仅影响手动输入这些字符，不影响显示与刮削。

## 验收

- [ ] 在 Windows 真机上用**系统内置中文输入法**测试单行与多行输入
- [ ] 验证候选窗定位是否跟随光标
- [ ] 验证组字过程中滚动表格是否丢字
- [ ] 验证回车上屏不多插换行、组字中退格不误删已有文字
- [ ] 验证中文标点（，。、《》）输入正常
- [ ] 顺带在 macOS 上试一遍——那一侧的已知问题是中文标点方向与字符检视器插不进特殊符号
- [ ] 若验证失败，评估更换界面层的目标：**降级目标是 Slint**（真内联预编辑、官方承诺行数实际无上限、其搜狗定位 issue 已关闭、另有 Qt 后端作第二通路）。**不要换 iced**——`iced_winit` 走的是同一条 winit 通路，且额外背着一个 Linux 拼音连打三字直接 panic 的未修 bug
