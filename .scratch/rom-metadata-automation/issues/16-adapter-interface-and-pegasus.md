# 16 — 适配器接口与 Pegasus 无损往返

**What to build:** 格式互转的地基。每个前端格式是一个自包含的**适配器**，显式声明自己的**能力档位**：只读、只写、双向、无损往返。第一个适配器是 Pegasus，做到无损往返档。

首要交付是**无损导入维护者多年手工维护的元数据**——未知键、扩展键、注释、字段顺序全部原样留存，否则一次往返就会蒸发这份心血。

「无损往返」不可能靠格式本身达成（Pegasus 自己就会静默丢弃数据），只能靠导入时保存的原文件快照。

**Blocked by:** 05, 15

**Status:** done

- [x] 适配器是一个统一接口，能力档位对使用者可见
      —— `adapter::Adapter` 三个方法（`read` / `write` / `ceiling`），`adapter::Capability`
      四档。`romcat adapters` 列得出来；CLI 测试 `能力档位对用户可见` 盯着它。
      接口**不含任何 Pegasus 的形状**：`Parsed` 只装字节与 `Preserved` 计数，
      各家在自己的 `write` 里把那串字节重新拆开（票 17 的 ES gamelist 因此不必改这层）。
- [x] 导入保留中立模型表达不了的一切：未知键、扩展键、注释、字段顺序
      —— `pegasus::Snapshot` 逐行拆到零件（缩进、键的原始大小写、键与冒号之间的空白、
      冒号与值之间的空白、值、值后的空白、行尾 LF/CRLF、BOM）。
      单元测试 `未知键与扩展键与注释一样不少地留了下来`、`字段顺序原样留着`；
      集成测试 `导出以快照为基线_注释未知键与排版一字不动`。
      **真机**：一份手改过的元数据（注释 ×3、未知键 `我自己加的键`、维护者自己的
      `tag: 我通关了`、`x-通关`、`sort-by  :   …   ` 那样不齐整的排版、改过的标题）
      导入再导出，**逐字节相同**。
- [x] 导入时保存原文件快照，导出时以快照为基线还原表达不了的部分
      —— `catalog::frontend` 的 `frontend_snapshot` 表存原文**字节**（BLOB，读不动的
      编码也存得住）。`pegasus::merge_block` 只重写「库里真的有值而且变了」的那几行，
      其余照搬；基线里有而库里没有的**整段原样留着**（`基线里有而新文档没有的段照搬不删`）。
      主键带 `origin`，于是**导出永远顶不掉维护者的原件**
      （`导出不顶掉维护者的原件`、`导出之后维护者的原件在库里一个字节都没少`）。
- [x] 往返测试通过即认定为无损往返档，未通过则自动降档——档位是断言不是声明
      —— `adapter::assert_capability` 读进来、以自己为基线写回去、逐字节比；
      过了记 `ceiling`，没过记 `ceiling.downgraded()` 并指出第一处分岔在第几行。
      导入每份文件跑一次，导出对自己写出来的每份文件也跑一次。
      **真机**：22 份文件 22 份逐字节相同，实测档位**无损往返**。
- [x] 导出时避开会被静默丢弃的写法：评分的百分号、人数区间、日期精度
      —— `format_rating` 永远带 `%` 或写 `0.xx`（`85` 两条正则都不匹配，会被静默丢弃）；
      `format_players` 只写上界，**下界走 `x-romcat-players` 保真通道，读得回来**
      （`人数的下界走扩展键_写得出去也读得回来`）；`format_release` 有几位精度写几位，
      绝不凭空写出一个不知道的 1 月 1 日。导入侧还把格式自己会吞掉的写法按
      **整条丢弃 / 削平 / 补足**三档逐条点名。
      **保留**：三样里只有日期真的从中立库流到导出——`scrape::Field` 还没有评分与人数
      这两个字段，没有源产得出它们，产品路径上它们只走得到「基线里有就原样保留」那一支。
      挂在 **D68**。
- [x] 导出遵循作品级收敛：一个条目、多个文件、默认启动首选变体
      —— `adapter::converge`。**真机**：46,444 个变体收敛成 **28,529 个条目**
      （作品级 11,844、还没认出作品的 16,685），其中 **6,357 个条目装着不止一个变体**。
      首选变体写在 `files:` 列表第一条（这个格式没有「默认文件」这个键）。
      **保留**：收敛是按**作品 × 平台**而不是纯作品级——一个合集一个文件是 Pegasus
      「game 加进此前定义过的所有 collection」那条语义逼出来的。真机上 2,314 个作品
      横跨多个平台，挂在 **D63**。
- [x] 首选变体规则为汉化优先于官中优先于日版，可被裁决覆盖
      —— `converge::preference_of`，裁决落在 `preferred_variant` 表（**沉淀**，
      不随重跑识别或重新成型消失），`romcat export --prefer <变体的键>` 记得进。
      单元测试 `首选变体是汉化优先于官中优先于日版`、`裁决压过全部规则`；
      集成测试 `作品级收敛_一个条目多个文件_首选变体排在最前`、`裁决压过首选变体规则`。
      **真机**：汉化 360、官中 112、日版 5,094、其他 22,963；`--prefer` 实测把指名的
      那个变体挪到了 `files:` 第一条。
      标题来源与首选变体**解耦**这一条由票 15 保证，这一层一个字都不碰。
- [x] 检测到主库元数据被外部修改时警告维护者，不静默覆盖
      —— `transfer::external_change`：盘上那份的内容哈希不是我们**对齐过的任何一份**
      （导入的原件、导出的产物都算）就停下来，命令行以失败收场。
      从没见过的文件同样停（它可能就是维护者的原件）。`--force` 压得过这一停但
      压不过「说出来」——照写了哪几份、丢掉的是什么，逐条列进报告的 `forced` 那一列。
      测试 `外部改动不被静默覆盖`、`落点上有一份从没见过的文件时先停下来`、
      `把导出产物换回原件不算外部改动`，以及 CLI 的
      `导出写得出文件_再导一次检测到外部改动就以失败收场`。
- [x] 附属内容与非游戏资产入库但不导出为前端条目
      —— `converge::excluded` 三类：附属内容（主文件身份是附属内容的变体）、
      非游戏资产（路径里有一段是 `bios`）、补丁（识别那一趟判过、落在
      `identification.reason` 里，这里读回来）。
      **真机**：非游戏资产 11 个、补丁 27 个被挡下；另有 **10,976 个附属内容成员**
      （PSV 的 `addcont/`）入库而一个都没导出。
      集成测试 `非游戏资产与补丁不导出为前端条目`。
      **保留**：真库里有 17 个「作品」其实是 BIOS（压缩包里捎带的 BIOS 撞上了 DAT，
      把 42 个不相干的游戏拽进了同一个作品）。病根在识别不在导出，挡不住也不该在这一层
      按名字挡——挂在 **D66**。

## 真机实测（2026-09-01，`/Volumes/新加卷/Game`，主库只读、一个字节都没写）

| 事 | 数 |
|---|---|
| 导出条目 | **28,529** 个，写进 22 份文件、14 MiB，用时 2.7 秒 |
| 进了条目的变体 | 46,406 / 46,444 |
| 收敛真的起了作用的条目 | 6,357 个装着不止一个变体 |
| 往返 | **22 / 22 逐字节相同**（导出 → 手改一份 → 导入 → 再导出） |
| 导入落库 | 28,529 个条目全部对上库里的变体（对不上 0 条），45,304 条字段值，源写作 `Pegasus` |
| 实测档位 | **无损往返** |

**库里没有维护者既有的 `metadata.pegasus.txt`**：281,292 个条目里一份都没有
（只有 PSV 一个游戏内部的 `global-metadata.dat`，与前端无关）。所以「对着真数据验无损导入」
用的是**导出产物加手工改动**——注释、未知键、他自己的 `tag:`、`x-` 扩展键、不齐整的排版、
改过的标题，外加 `rating: 85` 与 `players: 1-2` 这两行 Pegasus 自己会吞掉的写法。

## 挂账裁决

这一票开出：**D63**（收敛按作品 × 平台）、**D64**（不写 `launch:`、不铺媒体）、
**D65**（导入进来的标题落成别名 / 低置信）、**D66**（容器里捎带的 BIOS 把整包游戏
拽进同一个作品，病根在票 07/12）、**D67**（中文身份走 `x-` 而不是 `tag:`）、
**D68**（评分与人数在中立库里还没有源）。
- **D63 收敛按「作品 × 平台」** — 维持，不做纯作品级。用户按标题搜索仍然一次全找到。
