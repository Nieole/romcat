# 02 — 中立库与增量扫描

**What to build:** 扫描结果持久化到本机的中立库，第二次之后的扫描按路径、大小与修改时间跳过未变文件，几分钟内完成而不是几小时。维护者不必为了看一眼库的状态而重跑整夜。

中立库位于本机而非外置盘——外置盘不常挂载，库若跟着盘走，盘不在时连浏览元数据都做不到。

**Blocked by:** 01

**修改时间这一侧已经实测过了，不用再验**（`docs/research/ntfs-mtime-precision.md`）：NTFS 的 100 纳秒刻度完整透出（4,577 个采样 100.00% 是 100 ns 整数倍），APFS 是 1 纳秒，Rust 的 `Metadata::modified()` 与系统调用逐位相同（400/400），**且不存在时区偏差**（用回收站 `$I` 文件里的原始 FILETIME 作参照，12/12 吻合，0 例 ±8 小时）。库里异常时间戳 **0 条**。

**三元组能用——但要防的是路径那一侧，不是时间那一侧。**

**Status:** done

**收尾（2026-08-31）**：工头三条探针全过（提交在、工作区干净、NFC 键在**真盘上**复核）。134 个测试全绿。九条验收逐条见下，**一处保留**：票据正文说的「第二次之后几分钟内完成而不是几小时」只兑现了出报告那一半——扫描本身没提速，真机 A/B 三次对比增量 2.70/2.75/2.70 秒对 `--full` 2.87/2.79/2.65 秒，分不开，因为两者都得 `readdir` 每个目录并 `stat` 每个文件。增量接缝的价值要到票 07（7.84 TiB 的 CRC-32）才显现。挂在 D14。

code-review 抓到一个严重缺陷：**列不开的目录整棵子树被当成已删除**——第三态原本只做在文件粒度。真机 `chmod 000` 复现过，已修并有三条回归测试。

- [x] 中立库落在本机，外置盘不在位时仍可读取已有内容 —— 测试 `中立库落在本机重启后仍读得出来`、端到端 `主库不在位时报告照样出得来`（真把主库目录删掉再出报告）
- [x] 扫描结果持久化，重启工具后不丢 —— 同上；新增子命令 `report` 一个字节都不读主库
- [x] 再次扫描时按三元组跳过未变文件 —— 测试 `第二次扫描按三元组跳过未变的文件`、`未变的文件不再打开一次`；真机「街机」265/265 判为未变
- [x] 增量扫描能正确识别新增、删除与内容变化 —— 测试 `增量认得出新增删除与内容变化`，「大小一样只改修改时间」单独验；真机四步序列走通
- [x] 体检报告改为从中立库生成 —— 真机 `report` 0.01 秒 对 全量扫描 27 分钟
- [x] **路径以 NFC 规范化后才作为键**（ADR-0020）。读盘用系统给的原始形式，入库与比较用 NFC——两者不能混用。不做这一步，盘在 macOS 与 Windows 之间接一次就有约 5,100 个文件被判为新文件 —— 测试 `键是_nfc_而读盘用的仍是原始形式` 加 `path.rs` 四条；**工头真盘复核**：3ds 目录实有 64 个 NFD 文件名，扫入中立库后 100 条键里分解形 0 条、含组合浊音符 0 条
- [x] **不可读是第三态**（ADR-0021）：既不判为已变（否则 4,085 个文件永远重扫），也不判为已删（否则会从库里消失）。报告里单独计数 —— 测试 `元数据读不到的文件既不算已变也不算已删`、`列不开的目录下面那些记录不算已删除`、`主库根都列不开时一条记录都不删`、`上次读不到这次读到了算已变`；真机 Wii 两次扫描稳定在「未变 1,489／这次读不到 115／已删除 0」
- [x] **大小未知不等于大小为零**——库里有 4,317 个真正的空文件，两者混淆会让空文件被当成读不到 —— 测试 `大小未知不等于大小为零`、`大小未知的文件不参与重复检测`；真机 Wii 的 115 个不可读与 2 个真空文件分得干净
- [x] `read_dir` 的实现处写明**禁止改用 `getattrlistbulk`** 及其理由（ADR-0021）：它不列出那 4,085 个文件，一次提速改动会让它们被静默判为已删除 —— 禁令写在 `crates/core/src/fs/real.rs` 的 `read_dir` 文档段里


## 挂账裁决（2026-08-31 逐条确认）

- **D14 增量没让扫描提速** — 等**票 07** 自然显现（那时每文件的活是 7.84 TiB 的 CRC-32，跳过未变省下的是几小时）。**不按目录 mtime 跳整棵子树**——目录 mtime 在文件内容原地改写时不变，那等于放弃「内容变化」这一态，而它是本票明确要认出的三种情况之一。
- **D15 SQLite 绑定** — `rusqlite` 开 `bundled`。主力机 Windows 没有系统 SQLite。
- **D16 换挂载点就找不到中立库** — 加 **`--library` 给主库起名**，中立库跟名字走。已出票 29。
- **D17 基线整份读进内存** — 维持。SQLite 连接不能跨线程共享，逐条查库比 30 MB 贵。到千万级再换分批。
- **D18 键的构成** — 键 = **相对根 + `/` + NFC** 三件事，已补进 ADR-0020 的决定段。
- **D19 「基线」「扫描代号」「遍历」不在词表** — 已补进 `CONTEXT.md`。
- **D20 `--full` 票据没要** — 保留。凡是缓存都得有一条不信任它的路，而且「增量确实跳过了活」本身要靠它做 A/B 才证得出来。
