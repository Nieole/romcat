# 02 — 中立库与增量扫描

**What to build:** 扫描结果持久化到本机的中立库，第二次之后的扫描按路径、大小与修改时间跳过未变文件，几分钟内完成而不是几小时。维护者不必为了看一眼库的状态而重跑整夜。

中立库位于本机而非外置盘——外置盘不常挂载，库若跟着盘走，盘不在时连浏览元数据都做不到。

**Blocked by:** 01

**修改时间这一侧已经实测过了，不用再验**（`docs/research/ntfs-mtime-precision.md`）：NTFS 的 100 纳秒刻度完整透出（4,577 个采样 100.00% 是 100 ns 整数倍），APFS 是 1 纳秒，Rust 的 `Metadata::modified()` 与系统调用逐位相同（400/400），**且不存在时区偏差**（用回收站 `$I` 文件里的原始 FILETIME 作参照，12/12 吻合，0 例 ±8 小时）。库里异常时间戳 **0 条**。

**三元组能用——但要防的是路径那一侧，不是时间那一侧。**

**Status:** ready-for-agent

- [ ] 中立库落在本机，外置盘不在位时仍可读取已有内容
- [ ] 扫描结果持久化，重启工具后不丢
- [ ] 再次扫描时按路径、大小、修改时间跳过未变文件
- [ ] 增量扫描能正确识别新增、删除与内容变化三种情况
- [ ] 体检报告改为从中立库生成，不必每次重新遍历
- [ ] **路径以 NFC 规范化后才作为键**（ADR-0020）。读盘用系统给的原始形式，入库与比较用 NFC——两者不能混用。不做这一步，盘在 macOS 与 Windows 之间接一次就有约 5,100 个文件被判为新文件
- [ ] **不可读是第三态**（ADR-0021）：既不判为已变（否则 4,085 个文件永远重扫），也不判为已删（否则会从库里消失）。报告里单独计数
- [ ] **大小未知不等于大小为零**——库里有 4,317 个真正的空文件，两者混淆会让空文件被当成读不到
- [ ] `read_dir` 的实现处写明**禁止改用 `getattrlistbulk`** 及其理由（ADR-0021）：它不列出那 4,085 个文件，一次提速改动会让它们被静默判为已删除
