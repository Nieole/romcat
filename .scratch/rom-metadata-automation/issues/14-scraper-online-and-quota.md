# 14 — 刮削器在线档与配额守护

**What to build:** 在线策略档案，维护者可手动切换。它主要用于补媒体资源——离线数据源不含图片。

在线档对这个库有结构性风险：主流刮削源有专门的「当日未识别 ROM 配额超限」错误，配额同时按账号与 IP 计，多账号轮换会导致永久封禁——而汉化版在这些源眼里正是未识别 ROM。因此在线档必须默认限流，并把配额超限当作硬停止而非重试信号。

**Status:** done

      报告把这几个数全印出来——在线档赌的是用户的账号与 IP，限到多少必须在跑之前看得见。
      测试 `请求之间真的隔着那么久`（实测三发之间真的隔了两个间隔）、
      `服务端说没配额了就不发`、`在线档默认限流_并发与频率有明确上限`。

- [x] 配额超限被识别为硬停止，不重试、不换账号
      —— `online::classify` 是一个**纯函数**，照 Recalbox 的实现抄（调研 §11.4）：
      430 / 431 → `Verdict::Quota`（**停**），400/401/403/423/426 → `Fatal`（停），
      429 → `Backoff`（**有次数上限**，退避到头也停），404 → `NotFound`（一条结论），
      5xx → 退避，**没见过的码一律停**。正文里的配额话术（`Votre quota de scrape est`、
      `Faite du tri dans vos fichiers roms`）另兜一道。
      「不换账号」在类型上就做不出来：**一趟一个 `Net`，一个 `Net` 一套凭据**，
      没有第二处能装凭据；`Credentials::from_env` 只读一套，读不到就整档不启动
      （**绝不匿名试探**）。
      真机证据：9,226 个作品锚点的计划下，假服务器回 431，**一共只发出去 1 个请求**
      就停了。测试 `配额超限判成硬停止而不是重试`、`停了之后一个请求都不再发`
      （断言 `asked().len() == 1`）、`配额超限是硬停止_不重试也不换账号`、
      `退避有次数上限_到头就停`、`退避重发也吃自设的请求上限`。

- [x] 只对已确认的条目发起在线请求，未识别的变体不消耗配额
      —— `ScreenScraper::probe` 只在 **作品锚点 + 有自动通过的候选 + 拿得出判据**
      三条同时成立时才说话。判据（CRC-32 + 字节数）取自 `Catalog::accepted_hash`，
      取的是**候选记着的那一套**（含头 / 去头），取错一套就是白扣一份 431 的配额。
      **一部作品只查一次**（挂账 D55）：真机 9,226 次而不是按变体的 29,728 次。
      真机证据：**16,716 个未确认的变体，一个请求都没有为它们发出去**；
      9,226 个作品锚点全都拿得出判据。报告把这两个数印在「在线那一侧的账」里。
      测试 `只对已确认的条目发请求`（未确认、变体层各断言一次无话可说）、
      `只对已确认的条目发请求_未识别的变体不消耗配额`（断言请求里不含那两个未识别变体
      的名字，且哈希与文件大小同发）。

- [x] 请求结果进入同一份持久化缓存
      —— 在线源就是一个 `Source`，走的是票 13 那套 `scrape_probe` / `scrape_value` /
      `media_ref`，**一张新表都没为它加**。在线媒体进的是同一个**媒体池**，
      同一份内容与本地媒体**只存一份**（内容寻址天然给的）。
      新增的只有 `media_remote`（URL → 内容哈希），而它**必须与 `media_blob` 分开**：
      后者由扫描按「主库里还有没有这个键」整行扫掉，而在线 URL 在主库里永远不存在，
      混在一起等于每次扫描都把下过的图作废一遍。
      真机证据：跑一趟 5 个请求（全 404）之后再跑一趟，头 5 个**整条跳过**——第二趟的
      第一个请求换成了另一个 CRC。测试 `在线结果进同一份持久化缓存_重跑不再问一遍`、
      `在线媒体进同一个媒体池且与本地媒体只存一份`（引用 +1 而内容份数不变、
      `deduped == 1`，且第二趟连那张图都不再取）。

- [x] 网络失败不影响已完成的部分，可续跑
      —— **停下来不是错误**：`scrape::run` 撞上配额时先把手里那批写进中立库、照常出报告，
      再在 `Outcome::halted` 里说清为什么。做成 `Err` 的话，跑到 80% 撞上配额就会把
      那 80% 一起丢掉——而配额是每天才回一次的东西。
      「没问到」与「无话可说」**分成两件事**（`Failure::Skip` vs `probe() == None`）：
      前者**一个字都不写库**（写了下一趟就整条跳过，那条结论永远缺着），后者才清掉
      上一轮的结论。连着 5 次网络错才认定网断了。
      退出码分档：**4 = 自己收的手**（`--online-budget` 用完，立刻重跑就接着采），
      **3 = 对面不让了**（配额 / 凭据 / 拉黑 / 网断，重跑没用，配额那条今天都别再来）。
      测试 `网络失败不影响已完成的部分_可续跑`：第一趟对着一个什么都答不上来的服务器，
      在线那一对记成「没采成」而**离线七个源照常落库、本地媒体照收**；换个通了的服务器
      再跑，那一对接着采成。

## 带保留的一条

**真实凭据下的端到端没有跑过。** ScreenScraper 的 devid 要在它的论坛人工审批，而按
指示**不去申请、也不拿用户的账号与 IP 做实验**。上面每一条验收都是对着一个可复现的
**假服务器**（`CannedFetcher`）跑的——它与真的走同一个 `Fetcher` 接缝、同一道
`dat::guard` 闸门、同一套 `require_ok` 状态码处置，差别只在字节从哪儿来。

因此**验不了的只有一件**：ScreenScraper 实际回的 JSON 是哪一种形状。代码**两种都读**
（数组 `{type, url, …}` 与扁平键 `media_box2d`），认不出的形状是**采不到**而不是**采错**。
挂在 **D59**，那里写明了拿到 devid 之后该跑什么来收掉这条保留。

## code-review 处置

两轴各跑一遍（fixed point `d1eefeb`）。

**采纳并改掉：**

1. **上限没在下载之前判**（spec 轴，真 bug）。`ingest_all` 从没把 `claim.bytes` 传进
   `ingest_online`，于是 `--max-media-mib` 是在**整份下回来之后**才判的——而我自己的
   文档写着「上限在下载之前判」。真库里最大的一份预览媒体 662 MiB，先下回来再嫌它大，
   配额与带宽都已经花掉了。改成源自报的大小与上一趟记下的大小谁说得出算谁的，
   下回来之后再兜一道。
2. **ADR-0021 的第三态被挪用**（标准轴）。「闸门不许下」与「服务端说没有」都被塞进了
   `Ingested::Unreadable`，而那一档的定义是「条目在库里、字节取不到」——报告会指着一块
   好好的盘说它读不动。拆成 `Refused` / `Missing` 两个变体，各自分开数；闸门那个数
   只记在 `Net` 一处（此前 CLI 会为同一件事报两遍）。
3. **`charge()` 在重试循环外面**：一次 429 退避三次是**四发只记一发**，自设上限当场
   漏掉三个——而那个上限存在的全部理由就是「别打太多」。挪进循环，加两条测试。
4. **退避与限流的 `sleep` 看不见 `CancelToken`**：Ctrl-C 最多要干等 15 秒，而这一档
   正是最可能让人想中途叫停的那一档（它在花配额）。切成 100ms 一段，按下就走。
   `Limits::backoff` 因此可调——一条要睡 15 秒才走得完的分支等于没有测试。
5. **`--online-interval-ms 0` 没有下限**（spec 轴）：默认值挡不住它，而「频率有明确
   上限」说的正是挡得住。命令行这一层加 200ms 下限（库那一层仍允许 0，测试要跑得动）。
6. **自设上限与配额超限共用退出码**：脚本分不出「立刻重跑就接着采」与「今天都别再来」，
   而这两件事在 ScreenScraper 上的代价差得很远。拆成 4 与 3。
7. **词表**：`{源} 的分类` 里的「分类」是 **合集** 的 `_Avoid_` 词，全库统一用「类型」。
8. **`RomHash` / `Subject.rom` 拿 `ROM` 当领域名词**——那是 **发行版** 与 **变体** 的
   `_Avoid_` 词。改名 `Basis`（**判据**，`identify::fingerprint` 用的就是这个词），
   只有 `rom_name` 保留 `rom`：它指的是 Logiqx schema 里那个 `<rom>` 记录的名字，
   也是 ScreenScraper `romnom` 参数要的东西。
9. **零使用的公开面**：`Net::limits()`、`MediaFrom::cache_key()` 全删；
   `Server::max_threads` 写而不读——改成报出来（「服务端允许 4，我们照样只开一个」
   该是看得见的事实）。
10. **`pool::store` 与 `pool::ingest` 的后半段逐行同形**，而文档说的是「共用」。
    抽出 `adopt_into`（定扩展名、改名、记库）与 `temp_path`，两条路真的共用。
11. **参数表纪律**（仓库在 `RunContext` 与 `pool::Claim` 两处明文写过）：`ingest_all`
    7 个参数、`ingest_online` 7 个。立 `Ingesting`（主库视图 + 池 + 选项 + 网络句柄），
    降到 4 与 5。
12. **`check_url` 是个中间人**：删掉，直接调 `dat::guard::check`，并写明为什么这里查
    一遍、`Net::request` 里还要再查一遍（一个是「拦下之后怎么办」，一个是「一个字节
    都不许发到禁区去」）。
13. **`Net` 上的 `endpoint` 只赋过一个值**（Speculative Generality），而 `ScreenScraper`
    靠 `self.net.endpoint` + `self.net.credentials.query()` 造 URL（消息链 + Feature
    Envy）。URL 构造搬到 `Credentials::game_info_url`——这条 URL 一半是身份、一半是判据，
    而身份只在那里。
14. **媒体 404 也被算进「未识别 ROM」**：431 惩罚的是「拿一堆我不认识的 ROM 来问」，
    一张封面没有不是那回事。加 `Ask::{Query, Media}`，只有查询的没命中才计数。
15. `quota_phrase` 把每一份正文（**包括一张张封面**）整个 UTF-8-lossy 一遍。改成只看
    开头 4 KiB——配额那句话在最前面。

**另外自己发现并改掉的两处**（不在两份报告里）：

16. **真库上的性能回归**：`accepted_hashes` 起初是一条
    `candidate LEFT JOIN content_hash LEFT JOIN container_entry` 的大 JOIN，
    **实测 151 秒**（离线档一趟从 3 秒涨到 151 秒）——136,238 条自动通过的候选各自去
