# 09 — 光盘序列号识别与 NKit 前置检测

**What to build:** 光盘类变体的识别不再依赖读完整个镜像——只读镜像前部的几百字节取出内部序列号。识别一个 8GB 的 ISO 不需要读 8GB。

同时插入 NKit 检测，且必须卡在任何 CRC 匹配之前：NKit 文件的 CRC-32 可能与完好转储相同而内容并不一样，漏掉这一步会把 NKit 误认成完好转储。

**Blocked by:** 05, 07

**Status:** ready-for-agent

- [ ] 从 ISO 中读取 PS1 与 PS2 的启动配置取得序列号
- [ ] 从 PSP 与 PS3 的参数文件取得光盘标识与标题标识
- [ ] 从 PSV 变体内的 `param.sfo` 取得 TitleID、标题与版本（库体检实测全库 809 个，明文）
- [ ] PSV 目录名里直接写着的 TitleID（`AIME00001(...)` 这类）作为一条独立依据
- [ ] 压缩镜像被当作变体本身的形态处理，不被当作容器解包
- [ ] 从 PBP、CSO、CHD、RVZ、WBFS 的固定偏移处读取明文结构取得标识，不完整解压
- [ ] NKit 检测在任何 CRC 匹配之前执行，判据为光盘逻辑偏移处的标记
- [ ] 检出的 NKit 文件被明确标记，不参与精确哈希命中
- [ ] 序列号命中的候选置信度等同于精确哈希命中
