# 22 — 界面骨架：字体子集与十万行表格

**What to build:** 界面层跑起来，并且一次性清掉两个已知风险：中文与特殊符号的显示、以及十万行规模的表格性能。

字体必须打包子集而非读取系统字体——内置字体不只缺汉字，中文标点、假名、罗马数字、带圈数字全都缺；而系统字体路径不可硬编码，且实测各机器的字形覆盖并不一致。

排序、筛选、分页一律下推到数据库层，内存里永远只有当前视口的内容。

**Blocked by:** 12

**Status:** done

- [x] 界面库版本不低于修复了中文输入两个致命缺陷的那一版
      —— `egui` / `eframe` / `egui_extras` 钉 **0.36.1**（`Cargo.lock`），下限是 0.35，
      而 0.36.1 正是 `docs/research/egui-viability.md` 逐条核实过的那一版；
      `winit` 随之为 0.30.13，与调研一致。工作区 `rust-version` 因此提到 1.95。
- [x] 字体以子集形式打包，覆盖简体、繁体、假名，以及游戏标题中常见的特殊符号
      —— `tools/font-subset.py` 从 `NotoSansSC[wght].ttf`（17,772,300 字节）裁出
      **7,670,804 字节 / 22,534 个码位**（GBK + Big5 + 中日韩标点 + 假名 +
      U+2100–27BF 符号区 + 拉丁扩展，字重固定 400），`crates/gui/assets/` 下随 OFL 副本
      一起提交，`font::SUBSET` 用 `include_bytes!` 嵌进二进制。**同样的输入产出同样的
      字节**（脚本头部记了两份 SHA-256，重跑一遍即可核对）。体积上界由
      `tests/font.rs::子集体积在预算内` 钉住。
- [x] 界面上不出现豆腐块，含中文标点、罗马数字、带圈数字、音符与星号
      —— `tests/font.rs` 四条：必备 27 字、整张字体样张九行、反证（不装子集时
      `简繁龍あカ，。《・Ⅲ①②♥→※Ⓡ` 逐个都是豆腐块）。`romcat-gui --font-check`
      实跑通过。肉眼证据：开窗截图，样张九行（含 `★ ☆ ♪ ♥ Ⅰ–Ⅹ ① ② ③ Ⓡ → ∀ ※ ・ 〜`
      与繁简、假名、拉丁扩展）无一方框。
      **保留**：子集之外的字（CJK 扩展 B、谚文）仍画不出来，界面运行时不提示——
      事前可用 `romcat-gui --font-check --catalog <中立库>` 把全部变体的键过一遍
      （`tests/font_check.rs` 两条，正反各一）；运行时提示挂在 **D151**。
- [x] 十万行表格虚拟滚动流畅，可用合成数据验证
      —— release 实测（`romcat-gui --bench`，合成数据 `demo::synthetic`）：
      **十万行一趟甩到底**每帧中位 **2.12 ms（471 fps）**、最慢 3.91 ms，且这是最坏情况
      （每帧都跨出窗口、每帧都读库）；**常态滚动**（每帧 3 行）中位 **0.26 ms**。
      一百万行的一趟甩到底是 14.81 ms（68 fps），成本在 `OFFSET` 上，记在 **D147**。
      结构断言在 `crates/gui/tests/table.rs` 四条。
- [x] 排序、筛选、分页在数据库层完成，内存占用与总行数无关
      —— `catalog::browse` 的 `variant_total` / `variant_page`：`WHERE key LIKE …`、
      `ORDER BY <列> <向>, key <向>`、`LIMIT`+`OFFSET`，列名来自闭集合 `VariantOrder`。
      `crates/core/tests/browse.rs` 七条（分页翻完等于一次全取、排序是全序不是页内序、
      筛选框里的通配符是普通字符、`limit` 夹在 `MAX_PAGE`…）。
      内存：`table::Window` 只留 512 行，`tests/table.rs::内存里的行数与总行数无关`
      与 `滚完十万行内存里也只有一扇窗` 钉住；实测状态栏「内存里 512 行」在一千行、
      十万行、一百万行三档同值。为让翻页不卡，`variant` 上加了四条复合索引
      （按容量翻到第九万行 **96 ms → 2 ms**），写入代价记在 **D149**。
- [x] 退出前正确关闭输入法状态，避免组字过程中关窗导致崩溃
      —— `app::App::handle_close` 的两拍：第一帧 `CancelClose` + `stop_text_input` +
      `IMEAllowed(false)`，第二帧才 `Close`。`crates/gui/tests/close.rs` 逐帧核对命令
      的**次序**（`IMEAllowed(false)` 必须先于 `Close`）。
      **保留**：验的是命令次序，不是输入法本身——那只能 Windows 真机人工做（票 23）。

## Comments

### code-review 处置（fixed point `d8bc0e1`）

**采纳 16 条：**

1. 收尾没做（两个轴都提）——本节即是。
2. 词表：`table.rs` 里「数据库层」改「中立库那一层」。
3. 词表误用：`demo.rs` 拿**透明容器**当**成型规则**——改成真有的
   `SINGLE_FILE_RULE` / `SPLIT_VOLUME_RULE`。
4. 词表：合成数据里的「游戏 00001」改成作品名；`font.rs` 与脚本里的「游戏标题」改「标题」。
5. 重复：`table::bytes_text` 与 `report::human_bytes` 是同一份且精度还不一样
   （`1.5 GiB` vs `1.50 GiB`）——删掉，调核心库那份。
6. 重复：「跑一帧 + 认领纹理增量」在四处各写一遍——收进 `gui::headless`。
   那个 `.clear()` 漏一处就 panic，正是该收的东西。
7. Feature Envy / Data Clump：`app.rs` 两次「读出查询→改两个字段→写回去」，
   外加 `Sorted` 是 `VariantQuery` 两个字段的副本——改成 `App` 持有唯一一份
   `VariantQuery`，`Table` 拿 `&mut` 直接改，`Sorted` 删掉。
8. 吞错：`variant_platforms().unwrap_or_default()` 把读库失败和「库里没平台」
   显示成同一样——随第 10 条一并消失。
9. 取了不用 + 容量是下界：`unreadable` 读了不显示，界面把下界画成确数——
   有不可读成员时容量列画成 `≥ 1.25 GiB`（ADR-0021）。
10. Scope creep：平台下拉筛选与 `PlatformFilter` / `variant_platforms` 是票 25 的活
    （「能浏览主库并按平台…筛选」），而且眼下的界面入口只有它自己——整套删掉。
    保留的筛选是键的子串，那一条足以证明「筛选下推」。
11. Scope creep：详情面板的 20 个符号按钮删掉——ADR 再修订段已把 macOS 字符检视器
    那件事降级为边缘问题，而详情面板的内容是票 24 的活。符号本身留在**字体样张**里
    （那是验收第 3 条的证据）。
12. 实现错了：`tools/font-subset.py` 的 `--recalc-timestamp=0` 被 fontTools 静默解成
    「**要**重算时间戳」，正好反了，instancer 那步也没关——「同样的输入产出同样的字节」
    这句当时不成立。改成两步都 `--no-recalc-timestamp`，重新生成，连跑两次对 SHA-256
    确认逐字节一致，并把两份哈希写进脚本头部。
13. 实现错了：`Window::fill` 出错时清空行但不动 `first`，`holds()` 恒假，于是**每帧
    都重试一次**读库——与「常态滚动不是每帧都读库」相反。改成用 `error` 当闸门：
    读不动就不再敲门，换筛选或换排序时才清掉。**这条没有自动化测试**——中立库这一层
    没有注错的入口，造不出「读库失败」这个现场。
14. 「这个 crate 里没有一行领域逻辑」自证不成立（`demo` 造变体、`bytes_text` 是第二份
    格式化逻辑）——第 5 条修掉一半，模块文档改成说得准的话。
15. 许可：字体嵌进二进制而 OFL 副本没有，`font.rs` 又称它是「可以随便拷的单文件」——
    `font::LICENSE` 用 `include_str!` 一并嵌入，界面的字体样张里可展开看到。
16. 豆腐块只对硬编码字符串成立，真库里子集之外的字没有任何提示——加
    `romcat-gui --font-check --catalog <中立库>`，把全部变体的键过一遍（分页读，
    不把全库拉进内存），`tests/font_check.rs` 正反各一条；残留风险记 **D151**。
