# 18 — 子库与选择集

**What to build:** **子库**成为持久实体：每台目标设备一个定义，带目标路径、前端格式、容量上限，以及由**规则**加**例外**组成的**选择集**。

规则的价值在可重放——写下「所有某平台的汉化版」之后，主库新增符合条件的内容下次自动进入，不必重挑。例外处理规则表达不了的个人口味，且**优先于规则、永久记住**。

**Blocked by:** 16

**Status:** done

- [x] 子库是持久实体，配置一次可反复使用
  - 中立库里三张新表（`sublibrary` / `sublibrary_rule` / `sublibrary_exception`，
    `crates/core/src/catalog/sublibrary.rs`）。**纯加表**，`SCHEMA_VERSION` 仍是 4。
  - `crates/core/tests/sublibrary.rs::子库是持久实体_配一次反复使用`、
    `crates/cli/tests/sublibrary.rs::子库配一次反复使用_列得出来也删得掉`（另起进程读回来）。
  - 真机：`romcat sublibrary set 掌机 --target … --capacity 512GB` 建了一个，
    此后每次 `show` 都从库里读回同一份。
- [x] 规则可按平台、语言、评分、年份、体积、标签等条件描述
  - 九个维度：`平台` `语言` `中文` `合集` `类型` `作品` `年份` `评分` `体积`
    （`crates/core/src/sublibrary/rule.rs::Dimension`）。运算符 `= != ~ <= < >= >`，
    一条规则里多个子句用 ` 且 ` 连成交集，多条规则之间是并集。
  - `crates/core/tests/sublibrary.rs::事实从三层内容层级与刮削结论折出来` 用六条规则
    分别打中同一个变体，证明六个维度都真的从中立库折得出来。
  - **保留两处**：`评分` 眼下**没有源**（`scrape::Field` 里没有这个字段，
    挂账 **D71**，病根在 **D68**）；票据里的「标签」落成词表的**合集**（挂账 **D72**），
    而合集**眼下没有任何建的办法**（挂账 **D74**，病根在票 05）。两者都写得出规则、
    选不出东西，报告会点名说「这一维在这份中立库里一条数据都没有」，
    `rule` 的帮助里也直接写着合集建不出来。
- [x] 主库新增符合规则的内容后，该内容自动落入对应子库的选择集
  - 规则**存原文不存结果**，每次求值拿当下的中立库现算，因此这不是一个要触发的动作。
  - `crates/core/tests/sublibrary.rs::主库新增符合规则的内容自动落进选择集`
    （重跑一次成型多出一个变体，规则一个字没改，选中数 2 → 3）；
    `crates/core/src/sublibrary.rs` 的单元测试 `主库新增符合规则的内容下次自动进入`。
- [x] 手动增删的例外优先于规则，且不会被规则重算覆盖
  - `select()` 里例外**先看且看完就定**，规则算出什么都不改变这一步的结论。
  - `crates/core/tests/sublibrary.rs::例外优先于规则且不被规则重算覆盖`
    （规则整个换掉，例外一条不动）、`crates/core/src/sublibrary.rs::例外不随规则重算被覆盖`
    （三套规则轮着换）、`crates/cli/tests/sublibrary.rs::例外优先于规则_并记得住为什么`。
  - 例外**不给变体挂外键**（同 `collection_variant`），于是盘没插、目录改了名时
    照旧记着：`指向库里没有的变体的例外照旧记着` 与 `库里没有的变体照样记得下例外`。
- [x] 一个主库可同时存在多个子库，互不干扰
  - `crates/core/tests/sublibrary.rs::一个主库上多个子库互不干扰`、
    `crates/cli/tests/sublibrary.rs::多个子库互不干扰`。
  - 真机上同时建过 `掌机`（3 条规则、1 条例外）与 `备用卡`（1 条规则、0 条例外），
    `sublibrary list` 分得清清楚楚，删掉一个不碰另一个。
- [x] 能查看某个子库当前选中了多少条、多少容量
  - `romcat sublibrary show <子库>`：选中的变体数 / 库里总数 / 作品 × 平台组数 /
    容量合计 / 按平台拆开 / 逐条规则各命中多少 / 例外起没起作用 / 装不装得下。
    `--json` 出机器可读的同一份（票 19 的输入）。
  - **真机数字**：`平台=FC,SFC,GB,GBC,GBA,MD 且 中文=汉化` 一条规则选出
    **922 个变体、508.01 MiB**（225 个作品 × 平台组），求值 0.9 秒；
    再加两条之后合计 **1,094 个变体、18.68 GiB**。详见 `docs/library-facts.md`。
  - 容量上限压到 8 GiB 时报出「超出 10.68 GiB」与按体积排序的前十个裁剪建议，
    **不自动截断**（ADR-0016）：`报告数得出选中多少条与多少容量_并报出超限`。

## Comments

**不做的三件事**（留给票 19 / 20 / 21）：同步计划器与**差量预览**、同步执行与媒体导出、
**能力档案**与格式转换。票 19 的「计划器是纯函数」这道缝在这里就备好了——
`sublibrary::select()` 只吃选择集与一批 `VariantFacts`，不碰中立库、不碰磁盘、不看时钟；
把库折成事实的 `sublibrary::facts()` 是单独一个函数。
