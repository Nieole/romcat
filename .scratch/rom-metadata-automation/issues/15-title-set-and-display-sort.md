# 15 — 标题集合与显示、排序标题

**What to build:** 中立库中标题永远是**标题集合**——每条带语言、地区、来源与类型，而不是一个单值字段。导出时按优先级选出**显示标题**：中文译名、官方英文名、日文原名、文件名。

两条容易做错的地方：**显示标题的来源与首选变体解耦**——即使默认启动的是汉化版，中文标题仍取**官中版**的官方译名，绝不用汉化版文件名里的名字；以及**排序标题**必须独立生成，中文标题按码位排等于乱排。

**Blocked by:** 13

**Status:** done

- [x] 标题以集合形式存储，每条带语言、地区、来源、类型
      —— 中立库多一张 `title` 表（`catalog::title`），主键就是去重键
      `(作品, 语言, 类型, 来源, 值)`，另带 `region`、`variant_key`、`confidence`、
      `seam`、`evidence`、`seen`。**锚点是作品名而不是行号**，与 `scrape_value` 同一条
      理由：重跑识别会把作品与发行版整批换掉，挂在行号上不是留下孤儿而是
      `DELETE FROM work` 当场被外键挡住。**显示标题与排序标题不落库**——它们是集合的
      纯函数（`title::choose`），换一份优先级表就该跟着变。
      语言由**字形加发行版地区**判（`title::language_of`）：No-Intro 的日版条目名是
      罗马字，字形上与英文名一模一样，只有那条发行版的地区说得出它是日文原名。
      真机：**9,226 个作品、28,872 条叫法**，按语言 中文 9,761 / 日文 4,061 /
      英文 15,033 / 认不出 17（`docs/library-facts.md`）。
      测试 `标题以集合形式落库每条带语言地区来源与类型`、
      `一个作品的多个叫法并存而不是互相覆盖`、`一条叫法的四个维度都存得住也读得回来`、
      `日版条目名是日文原名而不是官方英文名`。

- [x] 显示标题按中文、官方英文、日文、文件名的顺序回退
      —— `title::choose` 的回退链：中文（译名 > 官方名 > 别名 > 汉化组自取的名）>
      官方英文名 > 日文原名 > 文件名兜底 > 作品名。**一个叫法都没有的作品也有显示
      标题**，退回作品名——否则前端里是一片空白。
      真机：中文 **6,501**、英文 2,471、日文 254，退回作品名的 **0 个**。
      测试 `显示标题按中文英文日文文件名回退`（逐档拆掉验回退）、
      `显示标题按中文英文日文的顺序回退`（端到端）。

- [x] 中文标题优先取官中版的官方译名，而非汉化版文件名
      —— **这两条链路在类型上就是分开的**：`choose` 拿到的只有标题集合，
      **它连变体是不是首选都看不到**（首选变体那条规则是票 16 的活，这个模块里
      一个字都没有）。汉化版的名字照样入集合，类型是**汉化组自取的名**，排在中文
      那一档的最后一位——ADR-0012 明说别拿它当标题。
      测试 `中文标题取官中的官方译名而不是汉化版文件名`：同一部作品下官中版与汉化版
      并存，汉化版在盘上有 40 份、官中版只有 1 份，**数量压不过类型**；再把官中那条
      拿掉，汉化组自取的名才轮得上（证明它没被扔掉，只是排在后面）。
      端到端那条另建了一个真形状的现场（台版官中卡带 + TOSEC 的 `[tr zh dwt_so]`
      汉化条目），断言挑出来的是「魂斗罗」不是「魂斗罗 中文版」。
      **世代裂缝两侧都走得通**（ADR-0019）：判据是**发行版自己的身份**——地区是
      中国 / 台湾 / 香港，它就是官中那一条（`Seam::OwnRelease`）；地区是别的而语言里
      带 `Zh`，中文只是这条多地区共用记录的一项属性（`Seam::LanguageField`）。
      **分叉的是归属，不是取字的那口井**：两侧的中文名都只能从盘上那个文件的名字里来，
      因为 **DAT 里根本没有中文**（No-Intro 给台版卡带的条目名是拉丁字母的
      `Pokemon 4-in-1 (China) (En,Zh) (Pirate)`）。
      真机两侧都有真东西：**独立发行版 10**（FC / GBC 的台版与大陆版卡带）、
      **语言属性 44**（PSV 港版与美版共用的那些记录）。
      测试 `世代裂缝两侧都走得通`（断言数字世代那两个变体的 `release_id` **是同一个**）、
      `世代裂缝两侧分得开`、`汉化记号压过底版的中文语言标记`。

- [x] 排序标题独立生成，中文条目排序结果符合预期
      —— `title::sort_title` 与显示标题分开生成：显示标题排得动（没有汉字与假名）就用
      它，排不动就另取集合里的拉丁标题，再不行用作品名。**中文显示标题一个都没有进
      排序标题。**
      真机：**集合里的拉丁标题 6,477、显示标题本身 2,725、作品名兜底 24，
      一个拉丁标题都没有的 0 个**。
      测试 `排序标题独立生成中文条目排得对`：先断言按显示标题的码位排是
      `Zelda < 盖亚 < 魂斗罗`，再断言按排序标题排是 `魂斗罗 < 盖亚 < Zelda`
      （Contra < Gaia < Zelda）——**两个顺序不一样，这就是「按码位排等于乱排」**。
      单元测试 `排序标题独立生成而不是拿中文标题去排` 用 `三國志` / `爆破彗星` 验同一件事，
      `一个拉丁标题都没有时排序标题报得出来` 验那一档会被点名而不是悄悄排掉。
      **保留**：`CONTEXT.md` 给的另一个办法是拼音首字母，这一票没做——真机上
      「一个拉丁标题都没有」是 0 个，够用；挂在 **D60**。冠词不搬，挂在 **D61**。

- [x] 同一作品存在多个中文译名时有确定的选定规则
      —— `title::choose` 的文档是这条规则的**唯一出处**，报告与 `library-facts` 都从
      那里抄。六层：**人工裁决 > 语言与类型的档位 > 置信度 > 优先级表里的源名次 >
      有几个变体这么叫 > 字典序**。源名次**排在数量之前**：`priorities.toml` 说
      No-Intro 的条目名最整齐，那就不该被「同一个 TOSEC 写法在盘上重复了三十遍」压过去。
      真机：**2,043 个作品有不止一个中文叫法**，报告逐条列出落选的是哪些、凭什么选中。
      实测 `1942` 同时有三个中文名，两个是汉化组自取的名，于是第三个胜出。
      测试 `同一档里有好几个时的选定规则是确定的`（多数派胜出、置信度压过数量、
      **源名次压过数量**、全平手时按字典序且换个顺序喂进去结果一样）、`裁决压过一切`。

- [x] 中文名的匹配结论带置信度，低置信度可进入队列
      —— 每条叫法带**置信度**与**依据**。三档的含义分得清：**高置信**留给**裁决**
      （人看过一眼才叫确凿）；**中置信**是来源确凿、字面没人确认过——官中那 54 条
      落在这里，因为「这个变体是不是那条官中发行版」精确哈希撞上了，而「这串字是不是
      官方译名」不确凿（官方译名不在 DAT 里，中文名只写在用户起的文件名上）；
      **低置信**是谁也没背书、只是盘上那个文件叫这个。
      真机：中置信 127、**低置信 6,374**，报告把这 6,374 条单列一节，逐条带**依据**
      与它来自哪个变体（`TitleExample.variant`，机器读得动的那一半，裁决要靠它跳到文件）。
      测试 `中文名带置信度低的那些进得了队列`：往库里放一个「盘上叫这个名字、但没有
      任何官中发行版背书」的变体，断言队列数涨了、那条是别名 + 低置信、**而且它没有
      把官中的译名挤掉**。
      **保留**：**待确认队列本身是票 08**（`docs/agents/triage-labels.md` 与 ADR-0002
      说的那个界面），这一票只把队列的**输入**备齐——置信度落库、报告点名、依据可复核。
      另有一条挂在 **D62**：要不要给导出加一道置信门槛，把低置信的中文名挡在前端外面
      （本票的做法是**照用但标记**，与识别那一侧的中低置信候选同一条纪律）。

## 这张票挂出去的账

- **D60** 排序标题用官方英文名，没上拼音首字母（真机覆盖 100%，拼音要内嵌一张几千字的表）
- **D61** 排序标题不搬冠词（搬不搬是前端的口味，更该归适配器那一层）
- **D62** 「中文显示标题」的置信门槛没做成开关（本票照用但标记）

## 给票 16 的前瞻

- **显示标题与排序标题不落库**，导出时调 `title::choose(&TitleSet, &Priorities)` 现挑。
  换一份优先级表就该重挑一次，而不必重折标题集合、更不必重采。
- `Catalog::titles_of(作品名)` 是按作品读集合的那一口；`title::work_titles(&catalog)`
  一次读全库（真机 9,226 个作品、28,872 条，2 秒出头）。
- **裁决定下来的叫法**在 `title` 表里以 `source = '裁决'` 存着，重折一行都不碰。
  导出时它排在每条链的第一位，压过语言那一档——人指名要哪个标题就是哪个。
