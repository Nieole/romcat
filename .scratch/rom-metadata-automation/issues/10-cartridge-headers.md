# 10 — 卡带内部头解析

**What to build:** 哈希未命中时，从卡带 ROM 的内部头取得发行版级的识别结论。汉化补丁通常不改动这些字段，因此即使一个汉化版对不上任何数据库，工具仍能认出「这是哪个游戏」——缺的只是「谁汉化的第几版」。

同时区分**官中版**与**汉化版**。注意 ADR-0019 定下的世代裂缝：**这票覆盖的全是卡带世代，官中在这里确实是独立发行版**（有独立序列号、DAT 里独立一条），走精确哈希直接过；汉化版是变体，改过字节。数字世代那套（中文是语言属性）不适用于这票。

**Blocked by:** 07

**排序依据的更正**：这票原本写的是「按库体检的文件数排序」。那是错的——**任务重不重取决于要识别多少个变体，不是要遍历多少个文件**。正确的数字由票 05 的成型规则产出，而 05 → 07 → 10 的依赖顺序保证了排到这票时它已经存在。库体检的文件数只能当粗略的上界信号。

**Status:** ready-for-agent

- [ ] 解析各卡带平台的内部头字段，字段偏移与长度有据可查
- [ ] **按成型后的变体数排序开工，不是按文件数。** 变体数由票 05 产出，届时已经存在。文件数是错的依据——PSV 有 171,073 个文件却远不到那么多游戏，FC 的 21,739 个文件里 94.2% 是透明容器，一个归档可能是一个 ROM 也可能是一整个合集，目录里还混着模拟器与 HACK 合集
- [ ] 字节序与拷贝机头部在解析前完成归一化
- [ ] 内部头命中产出发行版级候选，置信度低于精确哈希但高于文件名
- [ ] 官中版被识别为发行版，汉化版被识别为变体
- [ ] 内部头与目录声明的平台冲突时记录冲突
- [ ] 头部解析器的测试用真实 ROM 的头部字节，不用手工编造的字节
