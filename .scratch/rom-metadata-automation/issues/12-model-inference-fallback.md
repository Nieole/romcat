# 12 — 模型推断兜底

**What to build:** 前面所有层都认不出的残渣交给模型推断。它是最后一档，处理的是命名奇怪、纯拼音、缩写、乱码的那一批。

两条硬约束：批量打包提问，一次给若干条让模型排序，逐条提问在几千条规模下成本与耗时都不可接受；以及模型的输出永远进队列、永不自动通过——否则库里会混入无法与真实数据分辨的编造内容。

**Status:** done

- [x] 只处理前面各层全部落空的变体

- [x] 批量打包提问，不逐条调用

      让模型对每一条给出**排好序**的猜测。真机 8,218 条打成 **411 个请求**。
      **这件事只能对着请求正文验**：发了几个请求分不出打包没打包，一个正文里装着
      几条才分得出——所以 `CannedFetcher` 加了 `posted()`，测试
      `一个请求装一整批而不是一条一发`（三个变体、`asked().len() == 1`、正文里
      「一共 3 条，编号 1 到 3」）与 `打包大小说了算_三条分两批` 各钉一头。
      编号**按批次算**（每批都是 1..=n），于是一批答坏了不连累别批。

- [x] 提问时附带文件名、已解析出的头部字段、同目录其他文件等上下文
      —— `model::Question` 五样：变体自己 / 独占目录 / 容器里那个文件的**名字**（连出处）、
      **已经解析出来的头部字段**（`model::head_fields`：光盘标识、盘里写的标题、
      卡带游戏码、卡带头里的标题、发行商代码、地区码）、**包里装着**的内部条目名、
      **同目录还有**、以及平台（**内容说的与目录声明的分开给**，打架时两句都说出来）。
      同目录那一栏取的是**紧挨着它的邻居**，不是目录的头几个（`identify::Neighbours`
      ——code-review 的规格轴点出原来那版退化成「本目录头几个」）。
      真机样本（`--model-plan` 直接印出来给人眼核对，拼错了一眼看得出）：

      ```text
      ### 第 1 条

      - 平台：3DS（目录声明的，没读出内部头）

      - 大小：7911187 字节
      ```

      单元测试 `上下文里三样都在`、接缝测试的正文断言。

- [x] 输出一律进入待确认队列，任何情况下都不自动通过
      —— `model::candidates_of` 产出的候选 `accepted` **恒为假**、置信度恒为
      `model::CEILING`（**低置信**，比文件名那一层还低一档：那一层至少撞上了一份

      那条新通道另有一道 `debug_assert!` 与一道 `if candidate.accepted { continue }`
      挡着，并在文档里写明「真要有自动通过的东西得走 `write_identifications`」。
      接缝测试 `这一层的候选永不自动通过而且进了待确认队列` 直接跑 `triage::survey`，
      断言它在队列里、而精确命中的那一份不在。
      **它也不改变结论的状态**（与文件名那一层故意不同，理由见 D129 与
      `identify::model` 的模块文档）：测试
      `结论的状态与那句_为什么没定下来_一个字都没被猜测覆盖` 跑两趟比对那两列。

- [x] 候选的依据明确标注来源为模型推断
      —— 依据的**第一句**就是 `**这一条是模型推断的**（<模型名>）`，后面接：
      在同一批里排第几（一共几个）、模型自己给的那句依据、**提问时给了它哪几样上下文**、
      「**一个字节的内容都没有看过**，也没有撞任何数据库」、以及
      「前面每一层对这个变体全部落空才轮到这一层，**它永不自动通过**（ADR-0002）」。

      code-review 的规格轴点出原来那版回放时印的是**请求的**那一个，同一条候选两趟

      `依据里说得出提问时给了哪几样上下文`、`缓存按变体加提问指纹存取`。

- [x] 调用量与花费可预估、可设上限
      —— **可预估**：`model::Plan` 在**第一个请求发出去之前**就摆出来
      （`Guessing::announce`，不是跑完之后才印）：待问多少个变体、打成几个请求、
      上限卡下来真发几个、输入多少 token、花费的**下界与上界**，外加**第一条问题的
      原样一段**。上界是**硬的**——一个响应的输出不可能超过 `max_tokens`。
      `--model-plan` 只算不发，不要凭据。真机全量：**8,218 个变体 / 411 个请求 /
      估 37.04 到 90.47 美元**；默认那道 40 个请求的上限下是 3.61 到 8.81 美元。

      按响应里 `usage` 的**真数字**一笔一笔加，加到头就停，因此最多超出**一个请求的顶**
      ——那个顶在计划里印得出来）、`--model-max-tokens`、`--model-interval-ms`
      （下限 200ms）。**退避重发的那几发也吃请求上限**（一次 429 退避三次是四发，
      不记账就当场漏掉三个）。
      **价目表是数据不是代码**（`identify/pricing.toml`，带核实日期与出处，
      `--model-pricing` 换、`--model-dump-pricing` 导底稿）：**表里没有那个模型就
      整层不启动**——不知道 token 值多少钱，「花费上限」就是一句空话。
      测试：`net::` 六条（`请求个数的上限挡得住`、`花费的上限挡得住`、
      `退避有次数上限_到头就停`、`退避重发也吃自设的请求上限`、`账按响应里的真数字记`、
      `请求之间真的隔着那么久`）、`计划在发第一个请求之前就说得出问多少花多少`、
      `请求上限先把计划卡下来_不算那些不会发的批次`、`算钱的单位一步都没跳`，
      命令行那一层另有四条。

## 带保留的一条

**真实凭据下的端到端没有跑过。** 按指示**不去申请凭据、不拿用户的账号与 IP 做实验**，
所以这一层从来没有真的对着 `api.anthropic.com` 发过一个请求。上面每一条验收都是对着
一个可复现的**假服务器**（`CannedFetcher`）跑的——它与真的走**同一个 `Fetcher` 接缝、
同一道 `dat::guard` 闸门、同一套 `require_ok` 状态码处置**，差别只在字节从哪儿来。
（假服务器那一侧不查闸门，于是 `HttpFetcher::post` 漏掉 `guard::check` 它测不出来——
所以另加一条 `真的那个_post_也过闸门`，它一个字节都不上网。）

**验不了的只有一件：请求的形状**——`output_config` 里 `format`（`json_schema`）与
`effort` 这一对在 `claude-opus-5` 上是不是真的一起收得下。形状照官方文档写，
而 400 被 `model::classify` 判成**硬停止**、报错里**点名了这两个嫌疑**，
于是第一发就停、不会连着错几百遍。挂在 **D130**，那里写明了拿到凭据之后跑什么来收掉它。

## code-review 处置

两轴各跑一遍（fixed point `298388b`）。

**采纳并改掉（12 条）：**

1. **缓存回放时印的是「请求的」模型名，不是真答话的那个**（规格轴，真 bug）。
   `model_answer.model` 存的是 `answered_by`，而 `model_answers()` 只 SELECT 三列，
   回放走 `guessing.model`——同一条候选两趟印出两个模型名，撞 ADR-0002
   「每条识别结论都要持久化它的**依据**」。改成整行读回来，`Answers` 里模型名跟着答案走。
2. **「同目录其他文件」退化成「本目录头几个」**（规格轴）。原来每个目录只留键序前 9 个，
   于是同目录所有残渣拿到**同一组**兄弟名。改成取**紧挨着它的邻居**
   （`identify::Neighbours`）。顺带发现并修掉一处**真机性能回归**：`position()` 现找
   下标是线性扫描，`3ds/3DSCH/` 那种几千条的目录让整趟识别从 38 秒涨到 **91 秒**；
   把下标与名单捏进同一个类型，回到 **36.0 秒**。
3. **`--model --model-plan` 同给时照发不误**（规格轴）——而 `--model-plan` 的帮助文本
   写着「一个请求都不发」。改成**计划赢**，并明说一句。
4. **计划只在跑完之后才印**（规格轴）：「花费**可预估**」的意思不是「跑完之后报告里
   有个数」，那时钱已经花了。加 `Guessing::announce`，在**第一个请求发出去之前**摆出来；
   收尾不再印第二遍。接缝测试断言它正好摆一次（全命中缓存那一趟一次都不摆）。
5. **花费数字一个字都进不了 JSON**（规格轴）：`--json` 只写 `outcome.report`。
   把 `ModelCount` 挂进 `IdentifyReport`——只在标准错误上说一句的话，跑完就没了。
6. **词表：`理由` 顶了「依据」**（标准轴，硬违规）。`CONTEXT.md`：**依据** _Avoid_:
   来源、理由、evidence。JSON schema 的键、`Guess.why`、系统提示里那条规矩、
   测试里那几句，全部改成「依据」。
7. **词表：`游戏` 顶了「作品」**（标准轴，硬违规）。系统提示是这一层唯一定义
   「猜什么」的地方，改成「它最可能是哪一部**作品**」。
8. **参数表纪律：三处裸元组**（标准轴，硬违规）。`model_answers()` / `put_model_answers`
   的四元组 → `ModelAnswerRow`（与 `DiscFactRow` / `CartFactRow` 同一个形状）；
   `model_pending` 的二元组 → `model::Asking`。
9. **`PROMPT_VERSION` 的纪律盖不住半份提示词**（标准轴）：提示词里「头部字段」那几句

**驳回：**

- **「缓存表 + 提问指纹 + `PROMPT_VERSION`、`model_call` 账本、外置价目表、退出码 3/4、
  `estimate_skew` 都超出票面」**（规格轴 (b)）—— 驳回全部五项，理由是同一条：
  票面第六条写着「调用量与花费**可预估、可设上限**」，而这五样各自是那句话的一半。
  缓存是「**不重复花钱**」（第一条验收）在时间维度上的那一半——没有它，重跑一趟识别
  就是再付三十几美元，而识别是一件要反复跑几十次的事；账本回答的是「这个库上一共
  烧了多少」，那正是决定下一趟设多少上限的那个数；价目表外置是因为**价目会过时**，
  而一张过时的表是这一层唯一会**安静地算错钱**的地方（同 ADR-0017 对能力矩阵的要求）；
  退出码分档是「上限到了」在脚本那一侧的落点（票 14 立的先例）；`estimate_skew` 是
  让**下一趟的计划可信**的唯一办法——估算是个启发式，不把偏差说出来它永远校准不了。

- **「`--model-plan` 之外还该有别的看法」**（无人提，但顺带说明）—— 不做。

  那就只剩「睡多久」还共用了，要么让两边共用一张不对的表。
