# 08 — 待确认队列与批量裁决（命令行）

**What to build:** 置信度不足的候选进入**待确认队列**，维护者能在命令行上列出队列、查看每条的依据、并按目录、按候选作品、按命名规律**批量裁决**。每条裁决沉淀进**沉淀库**，把文件哈希直接钉到发行版上——裁决一次，重装、换机、日后再次拷入同一文件时直接精确命中。

先做命令行版本，因为队列的逻辑在这里就能跑通并测试；界面是后面的一层壳。

**Blocked by:** 07

**Status:** done

- [x] 队列能列出待裁决的变体及其全部候选与依据

  `romcat triage list` / `show`（`crates/core/src/triage.rs` 的 `survey`，报告在 `triage/report.rs`）。
  队列成员的判据是**没有一条自动通过的候选，而且沉淀库还没说过话**。**真机 16,656 条**
  ＝ 未命中 11,823 ＋ 无判据 4,537 ＋ 命中但一条都没自动通过 296；折出来用 1.3 秒，
  一个字节都不读主库。每条印出结论、理由（「为什么没定下来」）、容量、裁决会钉在什么上，
  以及全部候选连各自的**依据**。测试：`crates/core/tests/triage.rs` 的
  `队列列出待裁决的变体连它的全部候选与依据`、`命中但一条都没自动通过的照样进队列`，
  以及 `crates/cli/tests/triage.rs` 的 `队列列得出来并说清一条命令覆盖多少`。

- [x] 支持按目录、按候选作品、按命名规律批量裁决

  `Filter` 的 `under` / `candidate_work` / `name_contains` 三个轴，各配任何一种裁决。
  **报告把每个轴上「一条命令覆盖多少」直接印出来**——ADR-0002 说队列在几千条规模下
  只能逐条点等于没有，所以「从哪一批下手」是报告的正文。真机实测一条命令的覆盖面：
  `--under GoodNES3.1` **1,543 条**（全是内容锚）、`--name 汉化` **1,986 条**、
  `--under gba/【全部汉化】` **852 条**；按命名规律那张表在真机上折出 3,391 组记号，
  其中 `[ACG汉化组]` 129 条、`[CG汉化组]` 54 条、`[巴士汉化组]` 33 条——正是 ADR-0002
  点名的「按汉化组命名规律一次套用几百条」。测试：`按目录一次裁一批`、
  `按候选作品一次裁一批`、`按命名规律一次裁一批`、`报告说得出按各个轴一次能覆盖多少`。
  **保留**：只补汉化组、不说作品的那种批量（129 个文件 129 部游戏）表达不了，见挂账 D105。

- [x] 维护者能判定「都不对」并手工指定，候选集不构成天花板

  「都不对」分**两种**明说：`--no-release`（它没有发行版：同人移植、homebrew）与
  `--unknown`（看过了，认不出）。手工指定走 `--work`，不需要任何候选——**真机队列里
  16,360 条（98.2%）一条候选都没有**，所以这是主路径不是备用路径。测试：
  `判定都不对之后手工指定候选集不构成天花板`、`确认没有发行版是一条明说的记录`、
  `认不出那一档记下来就不再问第二遍`。

- [x] 裁决结果写入沉淀库，键为文件哈希

  `crates/core/src/verdict.rs`。锚是 **CRC-32 加未压缩大小**（第一命中层的口径，
  容器里零解压就有、裸文件上一趟识别算过就存着，于是裁决零成本、当场生效）。
  **与 ADR-0008 字面上的「SHA-1 →」不一致，已在 ADR-0008 补一段修订说明白，
  并挂账 D98**：`sha1` 那一列建好了、导出格式里也有它，一条都没算。
  拿不到内容判据的（无判据那一档）退成**路径锚**并如实说出口，导出时默认不带。
  测试：`裁决钉在文件哈希上下一趟直接命中不再进队列`、
  `拿不到内容判据时退到路径锚并如实说出来`。

- [x] 沉淀库能导出为可分享的格式

  `romcat triage export --out <文件>`，JSON（`format` / `version` / `verdicts`），
  CRC-32 写成八位十六进制。**默认不带路径锚**——它对别人没用，还顺带交出自己的目录结构。
  配套的 `romcat triage import` 收得回来。测试：`导出再导入是同一份`（核心）、
  `导出再收回来是同一份`（命令行，含「分享出去的那份不带路径」）。

- [x] 已沉淀的哈希在下次识别时直接命中，不再进队列

  `identify::run` 收一份 `verdict::Index`，**在撞 DAT 之前**查它；命中就直接产出一条
  高置信、自动通过的候选（数据源写作「沉淀库」，与 No-Intro 平级地出现在报告里）。
  真机实测：裁 5 条之后重跑一遍完整识别（46,444 个变体）**用了 11.3 秒、回盘读 0 字节**，
  报出「7 个变体的结论直接来自沉淀库（4 条裁决）」——**多出来的 3 个是库里别处的同一份
  字节**，正是内容锚该有的样子；队列从 16,656 降到 16,649。测试：同名核心测试，
  外加 `换一份中立库换一个路径同一个文件照样直接命中`（换目录、换文件名、换中立库）
  与命令行的 `沉淀库不跟中立库走删掉中立库重扫也不丢裁决`。

- [x] 裁决时能补充汉化组与版本信息

  `--team` / `--version`，连同 `--set-platform` / `--region` / `--serial` / `--languages`
  / `--chinese` 一起走 `triage::Overrides`，**`--pick` 也吃它们**（「就是这条候选，
  另外汉化组是某某」）。配 `--no-release` / `--unknown` 时**当场报错**而不是静默丢掉。
  测试：`按命名规律一次裁一批`（验汉化组与版本真的落库）、
  `采用候选时人补的那几样盖过候选自己带的`、命令行的
  `说不成立的话当场说不成立而不是静默丢掉`。


## 从挂账转来的前瞻

- **中立库的结构迁移必须在这票之前重新评估（原 D26）**：票 03 把结构版本从 1 提到 2 时没写迁移，理由是「还没有值得迁的真实库」。**这票开始积累沉淀库——用户的裁决结果——之后，删库重扫就不再是可接受的答案。** 动这票之前先决定迁移策略。

  **已决定并落实。** 结论不是「给中立库写迁移」，而是**「别把不可再生的东西放进中立库」**：

  1. **沉淀库单独一份文件**（`workspace::verdict_store_path` → `工作目录/verdict/verdict.sqlite3`），
     与 **DAT 库**、**媒体池**同构，理由也同源——一条裁决说的是「世上这份内容是什么」，
     与它躺在哪块盘上无关（键是内容哈希不是路径）。两块盘接同一台机器，裁决一次两边都受益。
  2. **它自带顺序迁移**：`MIGRATIONS` 是一串只增不改的语句，`PRAGMA user_version` 记着跑到
     第几条，打开时把没跑过的接着跑完。**库比程序新时如实拒绝并说清，绝不提议删库**
     （`VerdictError::Ahead` 的原话：「这份库里装着裁决，删不得」）。趁库还空着把框架立起来最便宜。
  3. **中立库照旧走「版本对不上就删库重扫」**，而且这条现在有了正当理由：库里每一条都可再生，
     `origin = 裁决` 的那几行是沉淀库的**投影**，`clear_identifications` 清掉再照沉淀库重放一遍
     结果一模一样（真机验过：删掉 864 MB 的中立库重扫重识别，裁决活着）。`SCHEMA_VERSION`
     的文档把这套论证写在了它该在的地方。

  测试：`verdict.rs` 的 `新建的库跑到最新一版迁移`、`库比程序新时如实拒绝而不是叫人删库`，
  以及命令行的 `沉淀库不跟中立库走删掉中立库重扫也不丢裁决`。
  **保留**：中立库里还剩几样不完全可再生的东西（成型的人工纠正、子库定义与**清单**、
  导入的前端快照），它们不是这张票产生的，挂账 D97。


## 顺手治掉的一条真机 bug（票据之外）

`identify::scope` 会对**穿不透**的容器说「名字里写着补丁，里面也没有可运行的内容」——
而空名单在那里的意思是「没看见」，不是「里面没有」（`CONTEXT.md` 的「穿不透」条）。
真机上 **39 个 `.tar.zst`** 因此被误判成补丁跳过，`怪物猎人4G[ACG汉化组]+最终汉化补丁.tar.zst`
之流是游戏**加**补丁，不是补丁。scope 自己的文档写着「错跳一个的代价是一个本来认得出来的
变体永远不进识别管线」，而这正是队列该收的那 39 条。判据改成只在**看得进去**时才下，
「读出来了、里面确实空」照旧算看过（三态分开，ADR-0021 的道理）。
测试：`看不进去的包不许被说成里面没有可运行的内容`。

## 挂账裁决（2026-09-03 清理挂账队列）

- **D98 沉淀库的锚是 CRC-32 加大小** — 维持，`sha1` 列留空。本机自用不受影响；哪天要与以 SHA-1 为键的外部库互通，那是导出格式的事。
- **D99 裁决记的平台走 `--set-platform`** — 维持。放错目录那份内容显式给参数即可。
- **D100 一个变体只取一份代表内容当锚** — 维持。真机上多文件变体占少数。
- **D102 `triage undo` 不回滚中立库那一半** — 维持。命令的输出已经把这句话说出口了。
