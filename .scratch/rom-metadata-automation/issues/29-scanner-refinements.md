**Blocked by:** 02

**Status:** done

## 一 · 并发按介质自适应（挂账 D9）

默认并发是「按 CPU 数取，夹在 2 到 8」——**那是按 CPU 密集型工作设计的**。真机实测扫 NTFS 外置盘时 CPU 占用只有 **2.7%**，线程绝大部分时间在等文件系统驱动返回，是**高延迟 I/O 密集型**。两者的最优并发差一个数量级。

改成先探测几次目录读取的延迟，据此定并发。这个探测顺带能分辨两种相反的情况：**磁头寻道受限**（提高并发会造成寻道风暴、更慢）与**驱动软件开销受限**（提高并发能掩盖延迟、更快）。

- [x] 开扫前探测目录读取延迟，据此定默认并发；`-j` 仍可手动覆盖
  — `crates/core/src/scan/probe.rs`，`ScanOptions.jobs` 从 `usize` 改成 `Jobs::{Adaptive, Fixed}`，默认 `Adaptive`。真机验证：`romcat scan /Volumes/新加卷/Game/SS` 打出「串行 7 个目录 0.18 秒（39.0 目录/秒），并发 7 档 0.12 秒（57.8 目录/秒），提速 1.48 倍 → 软件开销受限，并发定为 3 个」。测试 `目录太少时不下判断而是回到按_cpu_数取`、`一层不够就往下走且读开过的那几个不再当样本`、`中断时不下判断`。
- [x] 探测本身要能分辨寻道受限与软件开销受限两种情况
  — 判据是从两个点解出的 `k`（每多一个在飞的请求，延迟涨多少）：`k ≥ 1` 是寻道受限，`k < 1` 是软件开销受限。**真机上两种都量到了**：`Game/ps` 提速 4.71 倍（k = 0.16），`Game/SFC` 提速 0.17 倍即**慢 5.9 倍**（k = 6.21）。测试 `并发没帮上忙就是寻道受限`、`并发叠得起来就取收益拐点` 直接拿这几个实测值当输入。
- [x] **改默认值之前必须有一次干净的实测** —— **勾上但带保留**
  — 8 处实测，每处都是**两组不重叠的、都还没被读过的兄弟目录**（按下标奇偶交错分组，第 0 个当热身丢掉），一组串行一组并发，按目录/秒归一化。**每个目录只读一次**，缓存不可能在两组之间传递。票据要求的那条方法学逐字对得上。
  **保留在哪：实测的是「1 线程对 16 线程的比值」，不是「4 个线程比 8 个线程快」。** 中间那些线程数没量过，是把实测的比值代进一个写明了的饱和模型算出来的。而「旧默认 8 与新默认 4 哪个扫得快」这个实验**做不成**——一个库只有一份，第二遍必然是热缓存，全库遍历没法像目录那样劈成两组互不重叠的样本。这正是把测量单位定在「一组给定的目录」的原因。诚实的说法：**旧默认没有依据这件事是实测证实的，新默认的具体数字是实测加一个写明了的模型。** 文档里两列已分开标注「实测」与「模型」。
- [x] 实测数字写进 `docs/library-facts.md` 或专门的调研文档
  — 全文 `docs/research/scan-concurrency.md`（含测法、8 处读数、`k` 的推导、上一次为什么测砸、两条限制），头条数字进 `docs/library-facts.md` 的「并发」一节。

## 二 · `--library` 给主库起名（挂账 D16）

中立库的文件名现在按主库**绝对路径**的哈希取。可 macOS 重挂一次盘就可能从 `/Volumes/新加卷` 变成 `/Volumes/新加卷 1`，Windows 上盘符也会变——**换了挂载点就找不到原来那份中立库，全库白扫一遍**。而 ADR-0018 定的工作方式正是盘在两台机器之间来回接，所以这事会反复发生。

中立库里的键已经是相对路径了（ADR-0020），偏偏定位那份库的文件名还是按绝对路径取的。

- [x] 加 `--library <名字>`，中立库跟名字走而不跟绝对路径走
  — `workspace::Slug::{Named, AtPath}`，`scan` 与 `report` 都收 `--library`。`report` 的主库根随之变成可选：只给名字就出得来报告（测试 `按名字就出得来报告而不必报出主库在哪`）。名字里的非法字符与 Windows 保留设备名都折得掉（测试 `名字里的非法字符造不出非法文件名`）。
- [x] 不给 `--library` 时维持现有行为（按绝对路径哈希），不破坏已有的库
  — 测试 `不给名字时维持老行为` 把旧算法的输出钉死成 `Game-3a0183855885f3a5`；测试 `不给名字时换个路径还是从头扫` 从命令行验老行为没变；测试 `票_29_之前建的中立库照样打得开` 验没有 `library_root` 那条 meta 的老库不会被当成「另一个主库」拦下。
- [x] 同一个名字在不同路径下能找到同一份中立库（本地 fixture 验，没碰用户的盘）
  — `crates/cli/tests/library_name.rs::起了名字之后换个路径判为全部未变而不是全部新增`：建 fixture 主库 → 扫（全新增）→ `fs::rename` 挪到另一个临时目录 → 用同一个 `--library` 名字再扫 → 新增 0、已删 0、未变等于第一次的新增数。核心库那侧 `同一份中立库换个挂载点判为全部未变` 用 MemFs 做同一件事。**用户那块 8.6 TiB 的盘全程只读遍历，没有卸载重挂。**
- [x] 两个不同的主库用同一个名字时要报错而不是混表
  — 判据是顶层条目的重合比例（`SAME_LIBRARY_OVERLAP = 0.5`），低于半数就报 `ScanError::DifferentLibrary` 并给出该怎么办。测试 `两个不同的主库共用一份中立库时报错而不是混表`（核心库 + 命令行各一条）、`顶层还对得上就认成同一个主库`（增删几个平台目录不会误伤）。

## 三 · 清掉「快照」残留（挂账 D19 / D27）

`CONTEXT.md` 里**快照**是**清单**词条明列的 `_Avoid_` 词。票 03 已经把生产代码里的 `Snapshot` 改成 `Recorded`，但票 01 留下的测试辅助函数还在用。

- [x] `crates/core/tests/fixture_library.rs` 里的 `快照()` 与 `Snapshot` 改用词表允许的词
  — 改成 `记下基线()` 与 `盘上基线`。选**基线**是因为词表给它的定义正是「记下的那份三元组，判断拿它作比」，而这个辅助函数记的就是 `(路径, 大小, 修改时间)` 加内容指纹。文档注释里写明了为什么不叫快照。
- [x] 全仓再搜一遍，确认没有别的 `_Avoid_` 词残留在代码或文案里 —— **勾上但带保留**
  — 从 `CONTEXT.md` 抽出 110 个中文 `_Avoid_` 词逐个扫。**代码（`crates/**/*.rs`）干净**：命中的绝大多数是这些词的**日常义**而不是术语义（「目录」指文件系统目录、「记录」指数据库行、「解压」指真的解压、「版本」指结构版本号）；`快照` 在代码里只剩一处，就是解释为什么不用它的那句注释。
  **文档那一半没清干净，三处指向挂账**：

  - 报告里「未归类」那一栏与词表给 **内部资源** 列的 `_Avoid_` 词同名，但两者判据不同（前者是「没有探针」）→ **挂账 D28**。
  - 「扫描」是 **遍历** 的 `_Avoid_` 词，可子命令、模块与词表正文都在用它 → **挂账 D31**。

## code-review 处置（fixed point `c81ed9a`）

**采纳 8 条：**

1. **`--library` 的名字没做 NFC 规范化**（Standards，近 hard，ADR-0020 + ADR-0018）—— 名字里带假名浊音或拉丁重音符时，macOS 与 Windows 会折出两份中立库，正是这票要治的病。已改：`Slug::Named` 先过 `path::nfc` 再取哈希，新增测试 `名字的两种规范化形式折出同一份中立库`。
2. **把路径那条的可读过滤从 `is_ascii_alphanumeric` 放宽成 `is_alphanumeric`，破坏了已有的库**（Spec，**这条最严重**）—— 末级目录名不含 ASCII 字母数字的老库（如 `/Volumes/新加卷/漫画`）升级后会找不到。已改回：路径那条照旧只留 ASCII，名字那条才放汉字过去；新增两条钉死老算法输出的回归测试，并**用一份独立实现交叉验算过**那两串哈希。
3. **判据与文档打架**（Spec）—— 文档说「`k ≥ 1` 是寻道受限」，但代码另有 `NO_GAIN = 1.05` 一道闸，而表里 `Game/pc`（k = 0.98）判成了寻道受限。已在代码与调研文档里写明是**两道判据**，并说清为什么噪声线优先于模型。
4. **实测与模型外推混在一起**（Spec）—— 已在调研文档与 `library-facts.md` 里把两列分开标注，并写明「旧默认 8 对新默认 4」那个实验做不成的原因。
5. **词表残留只清了代码那一半**（Spec）—— 已把文档那一半的三处如实写进上面的验收框，并出挂账 D28 / D31 / D32。
6. **探测引入的新词没进词表也没记成缺口**（Standards）—— 出挂账 D30。
7. **`建库于()` 与 `建库()` 逐行重抄**（Duplicated Code）—— `建库()` 改成 `建库于("/lib")`。
8. **`MAX_ARM` / `MIN_ARM` / `ARM_BUDGET` 名字读不出是什么**、**生产代码里的中文局部变量 `说法`**（Mysterious Name / 风格偏离）—— 改成 `MAX_DIRS_PER_ARM` / `MIN_DIRS_PER_ARM` / `ARM_TIME_BUDGET` 与 `located_by`。另删掉只剩自己测试在调的 `pub fn slug` 与两个包着公开变体的构造器 `Slug::named` / `at_path`（Middle Man）。

**驳回 4 条：**

1. **「`report --library` 与主库根变可选是范围外」** —— 驳回。不做这一半，`report` 仍然要报出那个可能已经变了的绝对路径，这票要治的病只治好一半；ADR-0009 也明确要求盘不在位时报告出得来。
2. **「同库守卫对没起名字的库也生效，超出票据」** —— 驳回。按路径取名时中立库的文件名本来就跟着绝对路径走，于是库里记的根**必然等于**这次的根，守卫在第一个 `if` 就返回，一次磁盘都不碰。为它加一个开关是给核心库加一个没有行为差异的参数。
3. **「`Medium::Fast` 是票只点名的两种之外的第三种判断」** —— 驳回。它不是为测试造的：本机的 APFS 上一次目录读取不到一毫秒，**没有等待可叠**，那个比值全是线程调度噪声。硬把噪声解释成「寻道受限」或「软件开销受限」才是拿猜测当依据。
4. **「`scan/mod.rs` 与 `main.rs` 为三件不相干的事各改一遍」（Divergent Change）** —— 驳回。这张票本身就是「三件互不依赖、可一并做」的活，票据抬头写着。为此拆模块是让票据的形状去改代码的形状。

## 两条已知限制

1. **探测只量目录读取**，不量 CRC-32 与 7z 解块那些 CPU 活。并发下限因此留在 2 而不是 1。
2. **「同一个名字换了另一个主库」的判据是顶层条目重合过半**，认不出「两个主库恰好有过半同名顶层目录」这种刻意造出来的巧合。真撞上了还有换个 `--library` 名字这条路。
