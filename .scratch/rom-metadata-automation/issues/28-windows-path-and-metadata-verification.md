# 28 — Windows 真机核对路径形式与元数据（人工）

**What to build:** 在 Windows 真机上核对同一块盘的路径 Unicode 形式与元数据，确认 ADR-0020 与 ADR-0021 的假设在主力平台上成立。

**这一项自动化替代不了**：macOS 侧只能看见 fskit 驱动加工过的结果，Windows 侧看见的是什么，只有在 Windows 上读才知道。

已经在 macOS 侧实测确定的（不必重测）：修改时间精度 100 纳秒完整透出、无时区偏差、异常时间戳 0 条。**待验的是路径形式与那 4,085 个读不到元数据的文件。**

**Blocked by:** 02

**Status:** ready-for-human

- [ ] macOS 侧先导出一份基线：路径、大小、修改时间（纳秒）、文件 ID
- [ ] Windows 侧对同一批文件导出同样的字段
- [ ] 核对修改时间是否逐位相同
- [ ] 核对路径的 Unicode 形式——**Windows 侧给的是 NFC 还是别的**？两侧各自规范化为 NFC 后集合是否相等？
- [ ] 核对大小是否一致
- [ ] 核对文件 ID（低 48 位）是否可用作跨平台稳定标识
- [ ] 核对那 4,085 个在 macOS 上读不到元数据的文件：**在 Windows 上是否正常**？是否带 NTFS `Compressed` 属性？
- [ ] 核对大小写语义的差异
- [ ] 若两侧路径形式不同，把结论写回 ADR-0020，并确认票 02 的规范化方向是否需要调整

**注**：调研结论是这一项**不阻塞票 02 的实现**——建议的四个条件在两种验证结果下都成立。它是确认而非前提。
