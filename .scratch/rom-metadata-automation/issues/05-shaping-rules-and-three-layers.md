# 05 — 成型规则与三层内容模型

**What to build:** 扫描产出**变体**而不是裸文件。每个平台声明自己的成型规则，把散落的文件聚成一个变体：`cue` 与它引用的 `bin`、整个 `PS3_GAME` 目录、`(Disc N)` 同族文件。中立库开始承载**作品**、**发行版**、**变体**三层内容层级。

平台由目录给出，但目录只是强先验——文件内容可以推翻它，而这类冲突正是**库体检**最该报的东西之一。

**PSV 是这票最吃重的地方，库体检数据出来后才看清。** 它占全库 **67% 的文件（171,073 个）**，绝大部分是**内部资源**（`at9` 音频 39,360 个、`psarc`、`cpk`、`pck`、`awb`）——库体检里那 56.4% 的「未归类」主要就是它们。**成型规则若没把整个目录树吞成一个变体，库里会炸出十几万条垃圾条目。**

PSV 的安装形态还不止一种：TitleID 直接写在目录名里（`AIME00001(...)`）、`param.sfo` 躺在目录内（全库 809 个）、`.vpk` 安装包、以及被 `.7z` / `.tar.zst` 裹着的。成型规则要认得这几种形态都是「一个变体」。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 平台清单与成型规则是声明式配置，新增一个平台不需要改代码
- [ ] `cue` 加 `bin`、`PS3_GAME` 目录、多碟同族各自正确聚成一个变体
- [ ] 变体的平台属性可空，认不出平台的内容照常入库
- [ ] 目录声明的平台与文件内容不一致时被记录为冲突并出现在报告中
- [ ] 维护者能手工纠正成型结果，指定「这几个文件其实是一个变体」
- [ ] 中立库中平台与**合集**是正交的两个概念，不共用同一张表或同一个字段
- [ ] 报告从统计文件数改为统计变体数
- [ ] PSV 的目录树转储整体成型为一个变体，内部的 `at9` / `psarc` / `cpk` 等**内部资源**被吞进变体，不各自成条目
- [ ] PSV 的多种安装形态（TitleID 目录名、含 `param.sfo` 的目录、`.vpk`、归档裹着的）都能正确成型
- [ ] 成型后的变体数与库体检报告的文件数之比是可解释的——PSV 这类平台应当从十几万文件收敛到几百个变体
