# 24 — 界面：待确认队列

**What to build:** **待确认队列**成为工具的主界面。维护者打开工具就知道该做什么：哪些变体等着裁决、每条的候选与依据是什么、能不能一次处理掉几百条。

中文输入放在详情面板而不是表格单元格——表格虚拟化会让正在组字的那一行滚出视口时控件消失。

**Blocked by:** 23

**Status:** done

- [x] 队列是打开工具后的默认界面

  `app::View::Queue` 是 `#[default]`，`App::new` 建好就 `queue.reload(site)`——打开就已经列好，
  不必再点一次。原料全在**中立库**与**沉淀库**里，**一个字节都不读主库**（ADR-0001）：
  外置盘没挂上照样列得出、裁得动。测试：`crates/gui/tests/queue.rs::队列是打开工具后的默认界面`。
  实测（合成数据，形状照真机来）：**列出 16,656 条待裁决**，列一次 **41 ms**。

- [x] 每条待裁决项展示全部候选、置信度与依据

  底下那块面板的左半：变体的键、结论、平台、容量、「为什么没定下来」（无判据/跳过的理由），
  以及**全部候选**逐条印出序号、**置信度**、数据源、条目名、中文记号与**依据**那一句；
  再加一行「这条裁决钉在**内容**上（换台机器也认得出，可导出分享）还是只钉得住**路径**」
  ——那是人按下去之前该知道的事，由 `Queue::detail` 按需补算（一万六千条不该在列一眼时整份算）。
  测试：`每条待裁决项都带着结论理由与候选`（无判据必有理由、候选必有依据且都没自动通过、
  没候选的占 98% 以上——真机的形状）。

- [x] 支持按目录、按候选作品、按命名规律批量裁决

  左边三张分组表，**每一行就是一次批量裁决能覆盖多少**，点一下就变成选择器。
  判据在核心库的 `triage::Axis` 里：**一个轴同时说「怎么分组」与「点中之后选择器长什么样」**，
  于是「表上写 852 条」与「点下去选中 852 条」出自同一个函数（原先报告与选择器各写一遍）。
  实测（合成数据按真机比例造）：`--under gba/【全部汉化】` **852**、`--under GoodNES3.1` **1,543**、
  `--name 汉化` **1,986**、`--name ACG汉化组` **129**——与票 08 的真机数一致。
  测试：`crates/gui/tests/queue.rs::三个轴各能一次盖住一批`（那四个数是断言）、
  `crates/core/tests/triage.rs::分组表上那一行照着抄成选择器选中的就是那么多条`（三个轴逐组往返）。
  **保留**：队列那一屏的表格不能按列排序（变体表那一屏可以），见挂账 **D153**。

- [x] 支持判定「都不对」并手工指定

  裁决表单四选一：采用候选（第 N 条）／**手工指定作品**（默认，因为真机 98.2% 一条候选都没有）／
  **没有发行版**（同人移植、homebrew）／**认不出**。人补的事实——**汉化组**、版本、平台、地区、
  序列号、语言、中文身份——`--pick` 也吃（「就是这条候选，另外汉化组是某某」）。
  说不成立的话**当场说不成立**：判据是核心库的 `triage::Draft`，命令行与界面共用一份，
  界面上按钮灰掉并把话印在旁边。粒度两种都有：整批，或勾「只裁选中的这一条」
  （`--pick` 天生是逐条的动作——同一批里各人的候选不是同一部游戏）。
  测试：`都不对可以手工指定也可以说它没有发行版`、`只裁选中的这一条也做得到`、
  `说它不成其为一次发行就当场说不成立`。

- [x] 中文搜索与文本编辑位于详情面板，不在表格单元格内

  队列那一屏**顶栏与表格里一个 `TextEdit` 都没有**——连三个选择器的搜索框都在底下那块
  不虚拟化的面板里。ADR-0005 的理由是控件会随虚拟化消失；这里推到底的额外理由是 Windows
  的输入法还没实机验过（票 23），把会碰到输入法的控件收进同一块面板，风险面最小。
  变体表那一屏同办（筛选框从顶栏挪进详情面板）。
  测试：`表格里画多少行文本输入框都是那几个`——**不看代码看结果**：egui 每画一个 `TextEdit`
  就在 `ctx.data()` 里留一份 `TextEditState`，队列从 200 条涨到 16,656 条、还滚一整趟，
  这个数一个都不变。退出前先关输入法沿用票 22 的两拍（`tests/close.rs` 未动，照旧通过）。

- [x] 裁决结果即时写入沉淀库并从队列移除

  「预览这一批」先出**计划**（要落几条、内容锚几条、路径锚几条、盖掉已有的几条、
  落不下去的各是什么原因），模态框里点「落下」才动手——与同步那一侧的差量预览同源。
  落下时 `Queue::apply` 一次做完三件事：写**沉淀库**、当场在中立库里兑现（转成命中／跳过）、
  把裁完的**从队列里去掉**（留着的话人会被同一条问第二遍）。
  测试：`裁决即时写进沉淀库并从队列移除`（129 条一批：沉淀库 129 条、汉化组 129 条落库、
  中立库 129 条转命中、队列少 129 条、那一批的键一条不剩）、
  `crates/core/tests/triage.rs::裁完的当场从队列里消失`。
  实测：3,000 条一批，排计划 **68 ms**、落下 **127 ms**。

## 实测数字（release，`romcat-gui --bench-queue`，合成数据按真机比例造）

```
待确认队列 16,656 条；选中 16,656 条
列一次队列      41 ms
点一行分组表    8.4 ms（--under SFC，选中 3,000 条，一次都不读库）
每帧            中位 0.44 ms（2,288 fps），最慢 0.71 ms，共 238 帧
排一次计划      68 ms（3,000 条）
落下            127 ms；队列还剩 13,656 条
```

票 22 的两条回归未退化：变体表十万行一趟甩到底中位 **2.35 ms**、常态滚动 **0.34 ms**；
`--font-check` **没有豆腐块**。

**保留**：本机没有真库（工作目录是空的，`romcat scan` 要 8.6 TiB 的盘加几小时），
上面的数出自 `demo::queue` 造的合成数据——条数、目录分布、命名规律的组数与那四个覆盖面
都按票 08 的真机实测比例造，队列逻辑本身与命令行是同一份代码。真机复跑一条命令即可：
`romcat-gui --library <名字>`。

### code-review 处置（fixed point `e01dd2f`）

**采纳 15 条：**

1. `capacity_text` 在 `gui::table` 与 `gui::queue` 各写一份，而「≥ 是下界」（ADR-0021）是
   领域判断——提到核心库 `report::capacity`，两处都调它。（这正是票 22 review 第 5 条删过
   一次的同一个重复。）
2. `gui::site::Site` 与命令行的 `TriageSite` 整套重复（同三个字段、同一句文档、同一条
   `catalog_path`/`verdict_store_path`/`slug.text()` 算法）——提到核心库 `core::site::Site`，
   命令行与界面共用。ADR-0004 那道「中立库不许落进主库」的闸口顺带也收进去了，于是界面
   也有了（原先只有命令行有）。
3. **Bug：「（主库根）」那一组既默认高亮又点不动。** 空框的意思是「这个轴不筛」，而主库根
   那一组的标签正好是空串。界面上用哨兵 `/` 写它（`Filter::under` 会把末尾的 `/` 剥掉，
   落到核心库就是空前缀）。测试：`主库根那一组点得动而且不默认高亮`（界面）、
   `根那一层写成斜杠还是空串都是同一批`（核心）。
4. **Bug：`--bench-queue` 会往真的沉淀库里落假裁决。** 它最后一步真的落一批下去。
   现在给了 `--catalog` / `--library` / 主库根就当场拦下并说清。
5. **Bug（显示）：** 详情面板里 `format!("**{}**…")` 交给 `ui.label`——egui 不解析 markdown，
   屏幕上是字面的星号。改掉。
6. **Bug：** `Form::pick` 默认 0 而序号从 1 数起，靠 `draft()` 里 `.max(1)` 兜住——
   界面显示 0、落库当 1。改成 `Default` 里就是 1。
7. **Bug：** 勾上「跳过」之后状态栏会出现「队列 16,656 条待裁决；选中 18,xxx 条」。
   `Queue::total` 拆成 `pending()`（待裁决，默认三档）与 `skipped()`，状态栏说
   「队列 N 条待裁决，另有 M 条跳过；选中 K 条」。
8. **逐条裁决做不到**（只能整批）——「采用第 N 条候选」天生是逐条的动作。加「只裁选中的
   这一条」，落成 `Filter::keys`。测试：`只裁选中的这一条也做得到`。
9. `Form::serial` 有字段、`Overrides` 有它、命令行有 `--serial`，界面上没那一行——补上。
10. `Queue::len()` / `is_empty()` 说的是「选中几条」而不是队列有多长——删掉，
    调用处一律 `selected().len()`。
11. `Queue::groups` 的 `.position(..).unwrap_or(0)` 会悄悄退回第一个轴——改成
    `Axis::index()` 的穷尽匹配，那条不存在的分支就不存在了。
12. 界面上弹命令行文案：`Draft` 的报错里写着 `--pick <序号>`、`--no-release`，而界面上
    没有开关——改成两边都读得通的说法（命令行测试断言的关键短语不变）；三个选择器框的
    提示改成人话，开关名挪进悬停提示（照着抄一条命令这件事仍然做得到）。
13. `--bench-queue` 每帧换两次选择器（先按轴筛再收口「只这一条」），一万六千条上那是
    每帧两次重新分区加六次重新分组——改成一帧只换一次。
14. 测试 `表格里画多少行文本输入框都是那几个` 里 `total * 24.0 * step / 24.0` 乘完又除同一个
    字面量（应是 `ROW_HEIGHT`），16,656 条那趟每帧都被夹到底部，滚动没真扫——修掉。
15. 「队列整份留在内存里」与 ADR-0005 的「排序下推到 SQLite / 绝不把全库载入内存」相左，
    模块文档论证了但没进 ADR——**补一段 ADR-0005 修订**（票 08 对 ADR-0008 就是这么做的）。

**驳回 3 条：**

  敲中文去筛）。票 23 在 Windows 上的靶子因此更多而不是更少。
