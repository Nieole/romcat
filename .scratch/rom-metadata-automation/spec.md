# ROM 元数据自动化

Status: ready-for-agent

## Problem Statement

我有一批约 10TB、跨 27 个平台（FC 到 PS3/PSV/WiiU/XBOX360）的模拟器资源，以 Pegasus 方式手工维护元数据。手工维护已经撑不住了：

- **认不出游戏**。我收集的大量资源是各种汉化版，文件名是「幻想传说汉化完美版」这类中文名加噪音词，跟任何官方数据库都对不上。光看文件名根本确定不了这是哪个游戏。
- **元数据被锁死在一种格式里**。我在多台设备上用不同前端（PC 上的 Pegasus、掌机上的 Cocoon / iiSU / Daijishō），每换一个前端就要重来一遍；别人分享的现成元数据包也吃不进来。
- **我从不在主库上玩**。真正被玩的是我挑一批导到掌机 SD 卡上的子集。每次挑选、拷贝、更新都是手工活，而且我不知道卡上现在到底有什么、跟我想要的差在哪。

## Solution

一个跨平台的桌面工具，把主库当作只读仓储，围绕它做三件事：

1. **识别与刮削**：从 ROM 的字节本身（容器元数据里的 CRC-32、光盘内部序列号、卡带内部头）而不是文件名认出游戏，产出带**置信度**和**依据**的**候选**；置信度不足的进**待确认队列**，由我批量**裁决**。每条裁决沉淀进**沉淀库**，一次裁决永久受益。
2. **格式互转**：一个能表达所有前端字段并集的**中立库**作为事实来源，各前端格式做成**适配器**，每个适配器显式声明自己的**能力档位**。
3. **子库同步**：用**规则**加**例外**定义**选择集**，按目标设备的**能力档案**转换格式，同步前给出**差量预览**，同步时只碰**清单**里记录过的文件。

## Implementation Decisions

### 模块划分

- **扫描器** — 平台无关的遍历与归类，按平台声明的**成型规则**把文件聚成**变体**。平台由目录给出（用户已按平台分目录），但目录只是强先验，文件内容可以推翻它。平台清单与成型规则是**声明式配置而非代码**，加平台不改代码。
- **容器读取层** — 对**透明容器**提供两级能力：零解压读取内部文件的 CRC-32、未压缩大小、文件名；以及流式部分解压读取内部文件前 N 字节。必须按 solid block 分组、一块一趟流式喂多个 hasher，避免朴素实现的约 100 倍放大。RAR 的头部解析自行实现，不引入许可传染的第三方解压库。
- **压缩镜像读取层** — 对**压缩镜像**提供「读取文件前部固定偏移处的明文结构」的能力。压缩镜像不被当作容器解包，它就是变体本身的形态。
- **识别管线** — 分层递进：归一化（字节序、拷贝机头部）→ CRC-32 加大小匹配 DAT → 光盘内部序列号 → 卡带内部头 → 文件名规则解析 → 中文离线数据源模糊匹配 → 模型推断。每层产出带置信度与**依据**的**候选**。NKit 检测前置于一切 CRC 匹配。
- **DAT 仓库** — 本地维护多个数据源的镜像与索引。No-Intro 走 GitHub 每日镜像且绝不直连 datomatic；Redump 走新域名而非那个镜像（镜像硬编码了已冻结的旧域名）；另含 MAME 哈希、TOSEC、GoodNES。从 GitHub 拉取清单时避开会在 1000 条处静默截断的 contents API。
- **中立库** — 事实来源，位于本机而非外置盘。按所有前端格式字段的**并集**建模，即使当前只有两个**适配器**用得上。承载三层内容层级（**作品** / **发行版** / **变体**）、**标题集合**、**候选**、**依据**、**待确认队列**、**沉淀库**。Platform 与**合集**保持正交。
- **刮削器** — 策略档案（离线优先 / 在线优先）加字段级多源优先级加持久化缓存。**识别**与**刮削**是两个阶段，识别错了刮削再准也是错的。
- **媒体池** — 按内容哈希存放全部媒体，文件名不是媒体的主键。
- **适配器** — 一个 trait，N 个实现，每个显式声明**能力档位**。「**无损往返**」靠导入时保存的原文件快照实现，因为没有一个格式本身能做到（Pegasus 自身就会静默丢弃数据）。
- **子库** — 持久实体，含**选择集**（**规则** + **例外**）、目标路径、前端格式、**能力档案**、容量上限、上次导出的**清单**。
- **同步计划器** — 纯函数，输入选择集、清单、目标实际状态，输出操作计划即**差量预览**。
- **CLI 与 GUI** — 核心是独立的库加 CLI；GUI 是它的一层壳。

### 技术决策

- Rust 核心，egui 作为 GUI 层，版本下限 0.35（更早版本的中文输入有回车多插换行与退格误删两个致命缺陷）。
- 字体打包 GBK+Big5 子集并显式包含假名与常用符号区段，不读系统字体（系统字体路径不可硬编码且各机器覆盖不一致）。
- 中文输入放详情面板而非表格单元格（表格虚拟化会让正在组字的行滚出视口时控件消失）。
- 排序、筛选、分页下推到数据库层。
- 跨平台是第一天的约束：主力平台 Windows（外接硬盘 NTFS），开发环境 macOS（NTFS 只读，恰好够库体检使用）。Windows 侧须处理 MAX_PATH 260 限制。

### 收敛与首选

- 导出时**作品级收敛**：一个前端条目、多个文件。
- **首选变体**规则为 汉化 > 官中 > 日版 > 其他，可被裁决覆盖。
- **首选变体与标题来源解耦**：即使首选启动的是**汉化版**，**显示标题**仍取**官中版**的官方译名。
- **附属内容**（真正的追加内容）与**非游戏资产**（MAME 的 BIOS 与 device set）都入库但不导出为前端条目。判定依据是能否独立运行，不是目录名。

## Testing Decisions

好的测试只断言外部行为，不断言实现细节。本项目的核心逻辑天然是「给定输入状态，算出结论」，因此 IO 挤到边缘、纯函数承载密集逻辑，测试挂在纯函数上。这是一个原则落在三处，不是三个各自为政的选择。文件系统通过 trait 抽象，让前两个接缝能完全在内存中测试。

本项目为全新代码库，没有既有测试可作先例。这三个接缝即是先例本身。

### 接缝一 — 识别

输入是变体的字节流与已加载的 DAT 集合，输出是带置信度与依据的候选列表。不碰文件系统、不联网。

用真实的小体积 ROM 头部字节加迷你 DAT 构造用例，断言候选、置信度与依据。它覆盖最密集的逻辑：各平台头部解析、去头与含头双轨哈希匹配、NKit 前置检测、官中与汉化的区分、平台声明与文件内容的冲突检测。

### 接缝二 — 适配器

输入输出是中立模型与格式字节的双向转换。测试形式是往返加黄金文件。

**往返测试就是「无损往返」能力档位的定义本身**——通过即为该档位，未通过则自动降档。这让能力档位成为一条可执行的断言而非文档里的一句话。

### 接缝三 — 同步计划器

纯函数，零 IO，输入选择集、清单与目标实际状态，输出操作计划。

**产品要求的差量预览就是这个函数的返回值**，产品需求与测试点是同一个东西。它也是唯一能守住「只碰清单里记录过的文件」这条硬约束的地方——在这里它是一条可断言的性质，而不是靠实现时记得。

### 端到端

中立库的公开 API 是所有子系统的组合点，端到端测试挂在这里。密集逻辑不压到这一层，否则一个头部偏移算错会以「导出的元数据少了一条」的形式报出来。

## Out of Scope

- **用户状态**（收藏、游玩次数、时长、通关状态）完全不管理。导出 ES gamelist 时从快照原样搬运已有值，但绝不生成、绝不覆盖。
- **修改主库的 ROM 文件**。v1 对主库只读，不重命名、不移动、不去头、不重新压缩、不自动删除重复。格式转换只发生在导出到子库的路径上，产物是新文件。
- **Beacon 前端**。闭源付费、无官网、无仓库、无公开文档、无社区逆向说明，前置条件是真机逆向。
- **N-Gage 的专门识别器**。数据源仅有个位数条目且早已停更，归入「其他掌机」兜底桶。
- **结构指纹与模糊哈希**。ROM 领域无既有实践，且常用模糊哈希算法在文件扩容超过两倍时失效，而汉化版扩容很常见。
- **MTP 与网络传输**。目标设备只支持挂载为普通文件系统的连接方式。
- **多用户与云同步**。单人单机。

## Further Notes

### 必须实机验证的一项

egui 在 Windows 上的中文输入法行为。winit 在 Windows 上默认走 legacy 路径，且搜狗候选窗定位有一个长期未决、与修复者实测结论冲突的问题。**自动化无法验证这一项**——UI 自动化在应用层注入事件，而输入法位于操作系统与应用之间。必须人工在 Windows 真机上验证。若失败，降级目标是 Slint 而非 iced（后者走同一条底层通路）。核心是独立的库，换 GUI 层的代价被限制在一层内。

### 优先级依赖库体检

所有关于「先做哪几个平台」的排序目前都基于外部资源站的全站分布，而非用户库的实际构成。用户库是多年积累的，构成大概率不同。**库体检必须先跑，平台实现类工作应声明对它的阻塞依赖。**

### 会过时的东西

模拟器的格式支持矩阵会随版本更新而变化。矩阵条目应标注数据来源与核实日期。矩阵错误比不转换更糟——用户会以为工具已处理妥当，直到在掌机上打不开才发现。
