## 停线——只有这三条

停线很贵：拿主意的人得把整个上下文重新装回脑子。门槛：

1. **接着做会写出一个错的东西，而且撤销它要伸到这张票之外。**
   典型：票里的指示与上游一条仍然生效的决定（ADR、词表、规格）相悖。
2. **动作不可逆，而且不止一个方向站得住。**
   典型：删掉或改名一个被很多处引用的东西——一个 id、一个字段、一份文件。
3. **前提根本不在，票做不下去。**
   典型：「在 X 上面盖 Y」，而 X 不存在。

其余一律：记在这儿，挑最站得住的那条路走，接着做。这包括：票里的数字与你实测的对不上、
验收条目读着含糊、票没想到的第三种情况、路过看见的无关缺陷、以及你确实拿不准的单条。

> ⚠️ **绕过去要留痕。** 条目记的是**你走了哪条路**，不是「有两条路」。
> 说不出自己做了什么的条目，不算一条条目。

### 三档

| 档 | 意思 | 收口时怎么落 |
|---|---|---|
| **A** | 已经做完只是没销 —— 条目记的是一次已经落地的取舍或一件已经做掉的事，代价写清了、有测试或实测钉着，**没有人再欠一个动作** | `settled`，裁决迁回原票末尾 |
| **B** | 不成立了 —— 条目当初的前提在今天已经不成立 | `settled`，裁决迁回原票末尾 |
| **C** | 仍然成立要开票 —— 今天仍有一处代码、文档或测试是错的、缺的、或会咬人的，而且**有人还欠一个动作**，它不会自己消失 | `settled`（有了主人），裁决迁回原票末尾，同时进第四轮的规格材料 |

⚠️ **A 与 C 的分界线不是「条目说的那句话今天还成不成立」**，是**「今天还有没有人欠一个动作」**。
「不动，理由是这样才对」是 A；「不动，理由是不在这张票的范围内」是 C。

任何票」这一轮**照抄不得**——照抄会把 40 条真待办说成 0 条。

**一、C 有 40 条，是 A 的一半——上一轮结论照抄不得。**

### 票面错误的族谱 —— 这一批最值钱的产出

十七张票每一张都报了「票哪里写错了」。逐条核实之后按**成因**归成七类。它回答的是
**「票为什么会写成这样」**，而不是「这张票哪里错了」——所以它是冲 `/to-tickets` 与
`/wayfinder` 的信号，不是冲这份挂单的。

| # | 类型 | 例 | 实测 |
|---|---|---|---|
| 1 | **病因诊断错，而做法是照那个诊断开的** | 票 `09`（`Q274` `Q277`） | 票说 6.7 秒的大头是「一个变体问四次库」；实测批掉那些查询只省下不到 2 秒，其余 3.75 秒是 `identify::collect` 的纯 CPU。**方子没白开**（往返少三个数量级），但**真正的大头一个字没动** |

### Q373 — 门禁放后台跑，回执里那份输出只留尾部几 KB，看起来像压根没跑过

- **来自：** 票 `gui-self-sufficient/01`
- **类别：** 工具缺陷
- **在哪：** Bash 工具的 `run_in_background`（前台上限 600 s，超了自动转后台）与它写的那份
  `tasks/<id>.output`；对照物是 `xtask/src/gate.rs:291` —— 五步都走
  `Command::status()`，**stdio 是继承的**，所以真跑一趟的输出里必然有几十行
  `Running …` 与 `Compiling …`。
- **为什么没停线：** 门禁本身是绿的，卡住的只是「怎么证明它绿过」。
- **这张票实际做了什么：** 第一趟 `cargo xtask gate --keep-going` 撞上 600 s 上限被自动转
  后台，跑完回执说 `exit code 0`，输出文件却只有 **42 行 / 3,753 字节**、零个 `Running`、
  零个 `Compiling`，只剩最后一步 rustdoc 的输出加那张五行汇总表。编排者据此判定
  「它压根没产出、后台 shell 随轮次结束就死了」，要求重跑。
  **于是重跑了一趟，写进磁盘上自己的日志文件**（`setsid nohup` 脱离会话，前台分段
  `timeout 560 tail --pid=… -f /dev/null` 阻塞等它）：**2,233 行 / 145,417 字节，五条全绿。**
- **证据指向的是截断，不是进程死掉**，三条：① 第二趟的 check / clippy / doc 都是 **0 s**
  ——全命中缓存，而缓存只可能是第一趟建的；② 第一趟结束时 `target/debug/deps` 的 mtime
  与那份输出文件的 mtime 同在 04:44；③ 那 42 行**正好是最后一步的输出**，是尾部截断留下的
  形状，不是「什么都没跑」的形状（什么都没跑的话连汇总表都不会有，而汇总表里
  `test 624s` 是 xtask 自己量的墙钟）。
- **另一条路（编排者给的那条）：** 一律前台跑，别放后台。前台单次上限 600 s 挡不住这件事
  ——门禁本身就要 8～11 分钟，一进前台就必然撞上限、必然被转后台。真正做得到的办法是
  上面那套：`setsid nohup` 把它脱出会话，再用分段的 `tail --pid` 在前台阻塞着等。
- **该选哪条：** 走 `setsid nohup` + 分段阻塞，并且**日志写到自己的文件里**，别只靠回执
  那份输出。判据一句话：**回执里的输出文件不是完整日志，不能拿它的短小当「没跑过」的证据。**
  这一趟为这个误判花掉约十一分钟——一趟白重跑的门禁。
- **谁来裁：** 拿主意的人
- **状态：** open
