## 这份文件是什么

接票实现时总会撞上票没预见到、或者票写错了的东西。**这里面几乎没有一件该停下整条队列。**
它们落在这儿：**记下来、绕过去、接着走、收尾时一起裁。**

它不是项目的长期缺口清单（那是 `.scratch/rom-metadata-automation/deferred.md`，编号 `Dn`，全局连续）：

| | 挂账 `deferred.md` | 这份挂单 |
|---|---|---|
| 装的是 | **产品**里的取舍 | **执行**里冒出来的问题——票写错了、规格没说、两份东西互相矛盾 |
| 寿命 | 活得比这轮队列长 | **收尾时清空**——每条要么就地裁掉、要么升进 `deferred.md`、要么开成新票 |
| 谁读 | 下一个动这块产品的人 | 收尾那一步，和拿主意的人 |

**编号分两套，别混：** 这里用 `Q1、Q2…`；`deferred.md` 用 `D1、D2…`。
一条从这里升进 `deferred.md` 时才拿 `Dn` 号，且这边的 `Qn` 留着不复用。

## 停线——只有这三条

停线很贵：拿主意的人得把整个上下文重新装回脑子。门槛：

1. **接着做会写出一个错的东西，而且撤销它要伸到这张票之外。**
   典型：票里的指示与上游一条仍然生效的决定（ADR、词表、规格）相悖。
2. **动作不可逆，而且不止一个方向站得住。**
   典型：删掉或改名一个被很多处引用的东西——一个 id、一个字段、一份文件。
3. **前提根本不在，票做不下去。**
   典型：「在 X 上面盖 Y」，而 X 不存在。

其余一律：记在这儿，挑最站得住的那条路走，接着做。这包括：票里的数字与你实测的对不上、
验收条目读着含糊、票没想到的第三种情况、路过看见的无关缺陷、以及你确实拿不准的单条。

> ⚠️ **绕过去要留痕。** 条目记的是**你走了哪条路**，不是「有两条路」。
> 说不出自己做了什么的条目，不算一条条目。

### Q135 — 「不敏感的卡上行为一致」这一半，开发机上造不出来

- **来自：** 票 `queue-followups/01`
- **类别：** 规格没说
- **在哪：** `crates/core/tests/sync_run.rs`（三条落点占用的测试）；
  `crates/core/src/sync/execute.rs` 的 `place` / `landing` / `occupied_by`
- **为什么没停线：** 两边判的现在是**同一个** `path::fold`，敏感那一边实测挡得住，
  不敏感那一边只会更容易挡住（`real_path` 直接拼那一下就开得了别人那份）。
- **这张票实际做了什么：** 照勾那一条验收，并写明保留。敏感的盘（这台是 ext4）
  由三条新测试实测；不敏感那一边要一个不敏感的挂载点才造得出来，而 `execute` 这一层
  直接吃 `std::fs` 与 `fs::RealFs`，没有能塞进一个假文件系统的接缝——加那道接缝是
  改这一层的形状，超出这一票。走的是「照勾 + 写明保留 + 开这一条」这条路，
  没有为它加接缝、也没有把验收条目改小。
- **谁来裁：** 拿主意的人（真卡上跑一趟，或者决定给 `execute` 加一道可注入的目标侧接缝）
- **状态：** open

### Q136 — 列不开的目录底下，折起来那半边闸整个失效

- **来自：** 票 `queue-followups/01`（`/code-review` 报的第 5 条）
- **类别：** 规格没说
- **在哪：** `crates/core/src/sync/execute.rs` 的 `folded_children`；
  模块文档七与 `sync::TargetState::unlistable_dirs`
- **为什么没停线：** 漏的那一格窄，而且**不丢数据**——逐字那半边不受影响
  （`real_path` 直接拼那一下在列不开的目录里照样开得了文件），于是大小写不敏感的目标
  上照样挡得住；剩下的只有「敏感的盘 + 列不开的目录 + 只差大小写的占用」，后果是在
  维护者那份**旁边**多写一份（敏感盘上两份本来就能并存），不是顶掉它。
- **这张票实际做了什么：** 走「**把洞写进文档、不补**」这条路。原先那句理由
  （「列不开的目录底下写不进去东西」）是错的——Unix 上 `0300` 的目录列不开却写得进
  ——已改掉，换成把这一格说清楚。没补，是因为补它要把「列不开」与「列开了没找到」
  分成两态从 `read_dir` 一路带到 `place`，那是改这一层形状的活；而模块文档七偏偏点名
  `unlistable_dirs` 是执行层这道闸的头号理由，所以这条得有人裁，不能只留在注释里。
- **谁来裁：** 拿主意的人（值不值得为这一格加一层「读不动是第三态」，ADR-0021 的口径）
- **状态：** open

### Q151 — 界面刮削那一趟把「按停了」折成一句对不上的话，任务台会把它记成失败

- **来自：** 票 `queue-followups/03`
- **类别：** 路过发现，不在范围内
- **在哪：** `crates/gui/src/scrape.rs` 四处 `task.step("…").map_err(|_| "按停了".to_string())`

- **为什么没停线：** 早在这张票之前就是这样，与「中文索引重建这条路」无关。

### Q153 — 被按停却留下了产物的那一趟，任务台历史里记成「完成」

- **来自：** 票 `gui-redesign/15`
- **类别：** 路过发现，不在范围内
- **在哪：** `crates/core/src/task.rs::Board::settle`（`Ok(product)` 一律折成
  `Ending::Done`）；撞上它的两条是 `sync::execute::run` 与 `scan::scan`
- **为什么没停线：** 这不是这一票**弄坏**的：扫描早就这样——它被叫停时那几处写的是
  `let _ = task.step(…)`，照旧把断点写完、返回 `Ok(ScanOutcome { interrupted: true })`，
  于是任务台历史里那一行是「完成」。
- **这张票实际做了什么：** **照扫描那条走**：同步被叫停时也返回 `Ok`，把
  `interrupted` 记在账上。**不能抛 `Halted`**——写过东西的活得留下续跑的依据才停得干净，
  而同步那份依据就是**清单**（ADR-0015）：抛出去的话清单丢了，下一趟会把这次放上去的
  东西当成「清单之外」，于是碰都不敢碰。子库屏那句回执照旧把
  「⚠️ 这一趟被你按停了」说出口（`sync_notice`），所以人不会以为它整趟传完了。
- **代价说清楚：** **同一趟活在两屏上说两套话**——子库屏说「被你按停了」，任务屏的历史
  说「完成」。要收掉得在核心那一层立一种新收场（「停在半路，但留下了可用的产物」），
  那是 `Done<T>` 与 `Ending` 两个枚举一起动，扫描、刮削、取数据源几屏跟着改。
- **谁来裁：** 拿主意的人 / 下一张动任务台那一层的票
- **状态：** open
