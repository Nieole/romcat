# 04 — 筛选器：嵌套分组与两个新运算符

**What to build:** 在浏览屏上用**可嵌套的条件组**筛库：每组选「全部满足 / 任一满足 / 都不满足」，组里可以再套组。筛到满意按「存成子库」，条件原样变成那个子库的**规则**。

**筛选器就是规则语言**，同一套东西两处用。这一票要做的是把它补齐：

- 新增两个运算符：`^ 以…开始`、`$ 以…结束`
- 子句之间从平铺的「且」改为**可嵌套的组**，三种连接
- 维度补上**收藏**，以及元数据齐了之后的开发商、发行商、简介

**旧的平铺规则要原样解析**——它等价于一个「全部满足」的顶层组，已存的子库不该因为这一票失效。

收掉挂账 D154（五个筛选之间只能「且」）。

- [x] 三种连接（全部 / 任一 / 都不满足）各自成立，且组可以嵌套至少两层

      写法是 ` 且 ` / ` 或 ` / `都不(…)`，连接词两侧要有空白（值里出现「且」「或」
      不当分隔符），同一层不许混用——要混就套括号。
      核心：`crates/core/src/sublibrary/rule.rs::tests::三种连接各自成立而且组嵌得下去`、
      `嵌到第三层还是读得懂`（`depth() == 3`）、`都不套一个全部满足组否掉的是那一整条`。

      界面：`crates/gui/tests/library.rs::三种连接在筛选器上各自成立而且组嵌得动`。

- [x] `^以…开始` 与 `$以…结束` 各自成立

      `crates/core/tests/filter.rs::以开始与以结束各自成立`：`开发商^Game` 选中 2 个、
      `开发商^Systems` 选中 0 个（而 `开发商~Systems` 选得中）——`^` 真的只认开头。
      大小写按 ASCII 折（`开发商^game` 与 `开发商^Game` 同一批），两个求值器同一条口径。
      数值维度上这两个用不了：`年份^199` 报 `BadOperator`。
      界面：`crates/gui/tests/library.rs::以开始与以结束在筛选器上筛得动`。
