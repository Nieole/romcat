# 09 — 待确认屏：批分组、下钻、样本、整批操作

**What to build:** 打开待确认屏，看见的不是一万八千行的表，而是**工具已经分好的几十批**。每批写着条数与**那句共同依据**，展开有随机样本，看完一键整批通过。

**设计前提是算出来的**：待裁决 18,241 个变体，按 5 秒一条算是 **25 小时**，逐条不是可行路径。但其中 **14,657 条（80.4%）只有一个候选**——那不是「选哪个」，是「对不对」，而「对不对」可以按批回答。

**二级分组：**
- **一级按依据形状**（源 / DAT / 置信度 / 哈希口径 / 候选数）。这一层分得动，是因为它就是「工具凭什么这么认为」——而整批通过时你验证的正是那句话。实测前 5 批盖住 12,223 条。
- **二级按目录或命名规律**。坏的那几条往往集中在某一个目录里，随机抽样未必抽得到，所以要能下钻。既有的三个轴（按目录 / 按候选作品 / 按命名规律）作为二级的可选分法。

**每一层都能整批过或整批拒**，用户自己决定下钻到多细。屏上常驻三样：**条数、共同依据、随机样本**（可换一组）。

**识别**与**刮削**产生的待确认在**同一条队列**里——真库里那 4,723 条中文离线源的候选本来就和 DAT 的候选同表。

多候选那 3,584 条（2–3 个 2,750、4–10 个 688、10 个以上 146）走逐条键盘流兜底。
