# 02 — 主库变成一组根

**What to build:** 在**库**屏上按「添加目录」加进第二块盘，按扫描，在任务台里看着它跑完——两个根的变体落进**同一份中立库**，从此一起管理。

**主库**不再是一个目录，是**一组根**。每个根有自己的名字、路径、上次扫描的时刻与结果。**变体的键**因此变成「根名 + 相对根 + 路径」。

库屏这一半还要摆出**数据源**：DAT 仓库、中文离线源、Switch 数据库各有多少条记录、上次什么时候取的、一键重取。根与数据源同屏，是因为它们是同一件事——**让识别能干活的原料**。新用户最容易卡的「扫完了怎么没认出来」，在这一屏上一眼看得见：某个源那一行是空的。

**这是唯一动数据模型、也是唯一要求重扫的一票。** 路径锚会全部失效（**内容锚不受影响**）。真库现在 0 条裁决、0 条人工纠正，这是它最便宜的一刻。

## Comments

**真机验收没做。** 规格的「真机验收」那一节要在用户那份真库上跑一遍并报数（两个根扫进同一份
中立库、扫描中途取消再续跑），数字进 `docs/library-facts.md`。这张票没有那块盘，也不许去动
任何真实设备（`CLAUDE.md`）。留给拿主意的人在真机上跑。

**`/code-review high` 报了 10 条，九条当场收掉、一条并进 `Q62`**，逐条记在挂单 `Q63`。
最重的那条（`remove_root` 只删条目不删变体）在审查报回来之前我自己也发现并补上了，
两边对上了同一处。

**这一票撞上的取舍记在挂单 `Q55`–`Q63`**：根名进键的第一段而不是加一列（`Q55`）、
沉淀库旧路径锚的处置（`Q56`）、子库落点与前端 `file:` 剥根名（`Q57`）、
`--under` 与 `--library-root` 的口径变化（`Q58`）、加根只有输入框没有目录选择器（`Q59`）、
扫描时两个写者对着同一个中立库文件（`Q60`）、界面模块叫 `roots` 而不是 `library`（`Q61`）、
数据源重取没有细粒度进度（`Q62`）。
