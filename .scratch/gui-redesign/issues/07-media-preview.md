# 07 — 详情面板的媒体预览

**What to build:** 详情面板里**直接看得见封面与截图**，不必照着路径去文件管理器里开。视频显示成一张抽出来的首帧加一个播放标，点一下用**系统默认播放器**打开。

真库的媒体池现在 9.5 GB：342 张 jpg、98 张 png、**178 个 mp4**。视频是真需求。

**不在窗口里解码播放。** 那要 ffmpeg 绑定，依赖涨一大截且 Windows 构建麻烦（用户的主力机）。抽首帧走**外部 ffmpeg**，**找不到就退化成占位图标**——不当硬依赖，不新增 Rust 依赖。

抽出来的首帧按内容哈希缓存进**媒体池**，不重复抽。

收掉挂账 D160（详情面板列得出媒体，但不显示图）。

      **但测试没有靠这个事实**：靠它写出来的测试在装了 ffmpeg 的机器上就不测那条路了，

      另有 `抽首帧这条路在装没装ffmpeg的机器上都不崩` 用**默认那个程序名**真跑一趟，

      面板上那句提示**只说一遍**（`Gallery::lacks_ffmpeg`）：178 个视频各摆一句是噪音。
      测法与各条各盖住哪一角，写在挂单 **Q125**。
- [x] 抽出来的首帧缓存进媒体池，第二次打开不重抽
      —— 首帧按**内容哈希**入池（ADR-0009），映射记在新表 `media_frame`
      （键是视频自己的内容哈希；**没涨结构版本**，判据与理由记在挂单 **Q124**）。
      **落盘那一半在后台线程做**（纯文件系统，`MediaPool::take_bytes`），
      **记库那一半回画帧线程**——中立库全程只有一个写者。
      端到端：`crates/core/tests/preview.rs::抽出来的首帧落进池里再交回来等着记库`

      `crates/gui/tests/media.rs::任务在跑时首帧先攒着不去跟别人抢写锁`（抽 → 落池 → 记库
      整条走完）。「不重抽」在两层各钉一遍：
      `首帧记进中立库之后第二次打开一个进程都不拉` 与
      `抽过的首帧第二次打开一个进程都不拉`——**抽帧那个程序名故意给一个不存在的**，

      还有一条兜底：`记着抽过但池里那个文件没了就重来一遍`（人手动清过池之后不该永久占位）。
- [x] 媒体读不动时说清是哪一件、为什么，不静默留空
