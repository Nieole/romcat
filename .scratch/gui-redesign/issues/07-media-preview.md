# 07 — 详情面板的媒体预览

**What to build:** 详情面板里**直接看得见封面与截图**，不必照着路径去文件管理器里开。视频显示成一张抽出来的首帧加一个播放标，点一下用**系统默认播放器**打开。

真库的媒体池现在 9.5 GB：342 张 jpg、98 张 png、**178 个 mp4**。视频是真需求。

**不在窗口里解码播放。** 那要 ffmpeg 绑定，依赖涨一大截且 Windows 构建麻烦（用户的主力机）。抽首帧走**外部 ffmpeg**，**找不到就退化成占位图标**——不当硬依赖，不新增 Rust 依赖。

抽出来的首帧按内容哈希缓存进**媒体池**，不重复抽。

### Q121 — 「不新增 Rust 依赖」与「jpg 与 png 内嵌显示」不可兼得，走的是**加 `image`**

- **来自：** 票 `gui-redesign/07`
- **类别：** 票的两条要求互相矛盾，选了一条
- **矛盾在哪：** 票据写「不新增 Rust 依赖」，验收第一条写「jpg 与 png 在详情面板里内嵌
  显示」。**egui 自己不解码图片**（挂账 D160 开头那句就是这么写的）：`ColorImage` 要的是
  一片 RGBA，而 jpg 与 png 的字节变不成 RGBA 就画不出来。两条同时满足只剩一条路——
  自己写解码器。
- **走的是：** 在 workspace 加 `image = { version = "0.25", default-features = false,
  features = ["png", "jpeg"] }`，`romcat-core` 直接依赖它。
- **为什么是这条：**
  1. **票据那句「不新增 Rust 依赖」的语境是 ffmpeg。** 它与规格第六节里的那句一字不差，
     两处都紧跟在「抽帧走外部 ffmpeg，找不到就退化成占位图标」后面——说的是
     **不引 ffmpeg 的 Rust 绑定**。ffmpeg 那条一步没让：抽帧调的是外部进程，
     没装照常可用。
  2. **`image` 本来就在编译图里。** `eframe` 的剪贴板（`arboard`）要它读图，而且已经开着
     `png` 那一半——PNG 解码器一行都不多编。多开的只有 `jpeg`，代价是 `zune-jpeg` 与
     `zune-core` 两个纯 Rust 小 crate（无 C、不联网）。这条推理与 workspace 里选 `ring`
     而不是 `sha2` 那条注释一模一样。
  3. **自己写 JPEG 解码器是经典的自伤**，与 workspace 里 `quick-xml` 那条注释同一个道理
     ——霍夫曼表、量化表、反 DCT、色度上采样、重启标记、渐进式扫描。而真库里图片的大头
     正是 jpg（342 张，`docs/library-facts.md`）。PNG 那一半靠已有的 `flate2` 手写得出来，
     JPEG 这一半写不出、也不该写。
- **没走的两条：** 自己写两个解码器（上面第 3 条）｜只做 png、jpg 显示成占位
  （真库里 jpg 是多数，那等于把这条验收做掉一半）。
- **顺带收窄的：** **只开 `png` 与 `jpeg`**。gif 与 webp 各要再拉一个解码器，而真库的
  媒体池里一张都没有；`bmp` / `tga` 虽然零额外 crate，库里同样没有。认不出的格式如实说
  「这一版不解这个格式，用系统看图工具打开吧」（`Missing::UnknownFormat`）——那是工具的
  **能力边界**，与「这份文件坏了」分成两档。
- **撤起来多大：** 删 workspace 与 `crates/core/Cargo.toml` 各一行、`scrape/preview.rs`
  里 `decode` / `fit` 两个函数换实现。不伸到这张票之外。
- **谁来裁：** 收尾（要么认下这条依赖，要么把「内嵌显示」这条验收改掉）
- **状态：** open
- **收尾裁决：** **settled** —— 这条的决定已经落进代码，并有测试钉着。

### Q122 — `egui_extras` 那个图片 loader 没用，理由是它在**画帧那条线程**上解码

- **来自：** 票 `gui-redesign/07`
- **类别：** 一条看着更省事、但过不了验收的路
- **那条路是：** `egui_extras = { features = ["image", "file"] }` 之后

- **为什么没走：**
  1. **它在画帧那条线程上解码。** 头一次画到某张图的那一帧要等它解完——真库那些封面

  3. **ADR-0005**：解码、抽帧、缓存都是领域侧的账，该在核心库。走它等于把这三件事
     搬进界面。
- **于是走的是：** `romcat_core::scrape::preview::Loader`——一条后台线程，界面每帧问一次
  「好了没」，好了传上显卡、没好画占位并请下一帧。`crates/gui/tests/media.rs::切换选中那一帧不解码`
  钉着这条（头一帧 `ready() == 0` 且 `busy() > 0`）。

- **状态：** open
- **收尾裁决：** **noted** —— 核对过、不用改，留作记录。

### Q123 — 预览加载器**没有排进任务台**，另起了一条线程

- **来自：** 票 `gui-redesign/07`
- **类别：** 与票 01 立的那套基础设施的边界
- **在哪：** `romcat_core::scrape::preview::Loader`（自己一条线程）对
  `romcat_core::task::Board`（票 01 立的任务台）
- **为什么另起：** 任务台的文档写着「**一次只跑一趟**，不是线程池」，理由是那些活
  （扫描、刮削、同步）都在读同一份中立库、写同一块盘，同时跑两趟只会互相抢。
  而预览是**几十件几毫秒的小活**：排进那条队列会把「停下扫描」那颗按钮挤到一百张
  缩略图后面去，任务历史也会被一屏缩略图淹掉。
- **两者不打架的地方：** 预览那条线程**不写中立库**。抽出来的首帧落盘那一半在后台做
  （纯文件系统），记库那一半交回画帧线程——**全程只有一个写者**，与
  `Catalog::read_only` 的头一条同一条纪律。
- **要是将来想合：** 任务台得先长出「小活不占正在跑的那个位子」这一档，那是另一张票。
- **谁来裁：** 收尾（要么认下两条线程，要么开票把任务台改成两档）
- **状态：** open
- **收尾裁决：** **noted** —— 核对过、不用改，留作记录。

### Q124 — 「首帧抽出来存哪儿」新加了一张表 `media_frame`，**没涨结构版本**

- **来自：** 票 `gui-redesign/07`
- **类别：** 这一票新引入的东西
- **在哪：** `crates/core/src/catalog/scrape.rs` 的 `SCRAPE_SCHEMA`，
  `media_frame(video, frame, at)`，键是**视频自己的内容哈希**。
- **为什么不涨版本：** 照 `SCHEMA_VERSION` 那段文档立的判据——「加 1 的判据是**旧数据会
  不会被读错**，不是文件里多了点东西」。这是**纯加表**：已有的表一列没动、一条语义没改，
  `CREATE TABLE IF NOT EXISTS` 在打开时就补上，旧库照样打得开，拿旧版程序打开也照样能用。
  为它逼用户删库重扫 37.1 分钟换不到任何东西（同挂账 D50）。中立库结构版本仍是 **6**。
- **为什么不并进 `media_blob` 或 `media_remote`：** 那两张表分开的理由是**作废的方式相反**
  （扫描按「主库里还有没有这个键」清 `media_blob`，而在线 URL 在主库里永远不存在）。
  `media_frame` 是第三种：它只在池里那份视频没了才失效，而扫描扫的是主库、动不着它。
  混进任何一张，扫描都会把抽过的帧每趟清一遍——那要重拉一百多个 ffmpeg 进程。
- **谁来裁：** 不必裁，记下这张表为什么独立
- **状态：** open
- **收尾裁决：** **noted** —— 核对过、不用改，留作记录。

### Q125 — 这台机器上**没有 ffmpeg**，验收第三条那条路是怎么测的

- **来自：** 票 `gui-redesign/07`
- **类别：** 测试怎么写的
- **事实：** 写这张票的机器上 `which ffmpeg` 与 `which ffprobe` 都是空的（退出码 1）。
- **没有靠这个事实写测试。** 「这台机器碰巧没装」写出来的测试，在装了 ffmpeg 的机器上
  就不测那条路了——而验收要的正是**那条退化路走得通**。
- **怎么测的：** 抽帧那个程序名是**收进来的参数**
  （`preview::extract_frame(program, …)`、`Loader::set_program`），测试传
  `preview::NO_SUCH_PROGRAM`（一个不可能存在的名字）。于是：
  - `crates/core/tests/preview.rs::ffmpeg不在的机器上视频是占位而不是报错`
  - `crates/gui/tests/media.rs::ffmpeg不在时视频那一格是占位而不是报错`

  这两条**在装没装 ffmpeg 的机器上都测得到**。
- **另外三条各盖一角：**
  - `抽首帧这条路在装没装ffmpeg的机器上都不崩` 用**默认那个程序名**真跑一趟，
    两种结局都算通过（抽出来了、或者是 `NoFfmpeg` / `FrameFailed`）——它盯的是「不 panic、
    不返回错误」。

### Q128 — `/code-review high` 报的十一条，十一条当场收掉

- **来自：** 票 `gui-redesign/07`
- **类别：** 审查发现
- **它先替我确认了两件事：** `media_frame` 不涨结构版本这条判断成立（`Catalog::prepare`
  每次 `open` 都跑一遍 `CREATE TABLE IF NOT EXISTS`，老库开一次就补上；全仓库没有
  `DELETE FROM media`，那两条外键不会在 `clear_scraped` / 移除根上炸）；
  「先 `put_media` 再 `put_media_frame`」的顺序正确（外键确实开着，
  `libsqlite3-sys` 的 bundled 构建带 `SQLITE_DEFAULT_FOREIGN_KEYS=1`）。
- **十一条与各自的处置：**
  1. **高 · `Drop` 里那句 `join()` 会无限期等** —— `quit` 旗子在 `run()` 里一个字都不看，
     而 `extract_frame` 用的是 `Command::output()`，没超时也没 kill。后台正卡在 ffmpeg 上
     （慢盘、网络盘、畸形 mp4）时关窗口或换池子，**整个画帧线程冻在 join 上**。
     **收法是撒手不等**：立旗子、换掉递活那一头，然后 `drop(worker.take())`。
     安全靠三条构造上的事实（都写在 `Drop` 的注释里）：它不碰中立库、往池里落文件走的是
     「先写 tmp 再 `rename`」（原子，最坏留一个 `.part`）、交结果那一头断了就自己收工。
  2. **中高 · 记首帧那一下会跟扫描抢写锁，最长堵住画帧线程十秒** —— 这是**这一票新引入的
     性质**：以前 UI 线程只在人按下裁决时写库，现在选中一行就自动写；而扫描在后台另拿着
     一份写得动的连接，`busy_timeout = 10000`。**收法是任务台上有活在跑就先不写**
     （`Gallery::sync` 的 `writable` 参数，由 `Board::busy()` 给），首帧攒在
     `Gallery::pending` 里下一帧再试——**攒着比丢掉要紧**，池里那个文件已经落下去了。
     `crates/gui/tests/media.rs::任务在跑时首帧先攒着不去跟别人抢写锁` 钉着
     （`#[cfg(unix)]`，用一个冒充 ffmpeg 的脚本走完整条路）。
  3. **中 · 缓存永不淘汰** —— 按真库翻一遍是 440 张图加 178 段视频的首帧全解过一遍，
     `Loader::cache` 与 `Gallery::textures` 各躺着六百来份 RGBA（单份最大 1 MiB），
     内存与显存各几百兆且永不回落。**收法是 `Loader::trim` 与 `Gallery` 那段 `retain`**：
     超过 `KEEP = 64` 份就只留还看得见的那几份，**上限之内一份不动**（来回切两个变体
     不该每次重解）。`crates/core/tests/preview.rs::缓存攒过头就只留还看得见的那几份` 钉着。
  4. **中 · `error` 一旦置上就永远留着** —— 上一帧撞锁失败、这一帧成功了，面板底下那行
     红字还挂着，说的是一件已经不存在的事。**收法是让它跟 `pending` 一起活**：
     记进去了就清掉，没记进去就留着。
  5. **中 · `media_frame` 里那份首帧从池里没了就永久占位** —— 人手动清过一次池之后，
     那几段视频永远显示「媒体池里没有 &lt;某个哈希&gt;.png」，而那个哈希在界面上别处
     一次都不出现，人拿它什么也查不出；**视频本身好好地在池里，重抽一次就能修好**。
     **收法在 `Loader::want`**：给了首帧先问一句池里在不在，不在就当没抽过、走回抽帧那条路。
     `crates/core/tests/preview.rs::记着抽过但池里那个文件没了就重来一遍` 钉着。
  6. **中低 · 没选中变体时 `drain` 根本不跑** —— 点开一段视频、抽到一半切走，那份**已经
     落进池里**的首帧卡在管子里：`busy()` 一直大于零却不再有 `request_repaint`，
     退出前没收账的话池里多一个孤儿文件，两张表里一行都没有，下次打开照样重抽。
     **收法是 `sync_media` 不再早退**：没选中就拿一份空的 `items` 照跑，收账那一步与
     「这一屏正摆着什么」无关。`crates/gui/tests/media.rs::没选中变体时后台跑完的那几件照样收得回来` 钉着。
  7. **中低 · `decodable` 判在 `is_file` 前面** —— 一条 `.webp` 的**悬空引用**会被报成
     「这一版不解 webp，用系统看图工具打开吧」，人照这句话去开，那个文件压根不在池里；
     而 `cell` 那道警告色边框只认 `NotInPool`，于是一条真正的悬空引用连黄边都没有。
     **收法是把两句判断换个个儿**：「东西没了」比「这一版不认得」更要紧，先说它。
  8. **低中 · 点池里没有的那一格也报「打开了」** —— `open_externally` 走的是 `spawn`，
     `xdg-open` / `start` 这个进程照样起得来、照样返回成功，而什么都没打开；反过来
     `at` 为 `None`（没查池子）时点击**完全静默**。**收法是 `Clicked` 这个枚举**：
     `Open(路径)` 与 `Nothing(为什么)` 两档，后者在面板上说一句。
     `crates/gui/src/media.rs` 三条单元测试钉着那段判定（`clicked_on`）。
  9. **低 · 每帧对正在抽帧的视频白查一次 `media_frame`** —— 抽一帧几百毫秒，这期间
     每秒六十次 SQLite 查询跑在画帧线程上，而 `want` 拿到之后因为 `inflight` 命中直接丢掉；
     这些查询同样要跟别处的写者抢 `busy_timeout`（同第 2 条）。
     **收法是 `Loader::inflight`**：已经排出去的就别再问一遍。
  10. **低 · `decode` 没设 `Limits`** —— `fit` 是先整张解开再缩，峰值内存与 `EDGE` 无关；
      一张声明 20000×20000 的 PNG（在线源刮来的，或者损坏的）要 1.6 GB，分配不下就是
      abort，整个窗口跟着走。**收法是 `ImageReader` 加上限**：边长 16384（常见显卡的纹理
      上限）、单次分配 256 MiB（装得下 8192×8192 的 RGBA），真库那些封面最大不过四千像素。
  11. **吹毛求疵 · `format!` 里一个多余的具名参数** —— 删掉。
- **审查没有异议的：** `image` 这笔依赖（Q121）；`work()` 那个 LIFO 队列不会饿死；
  `Command::output()` 同时读 stdout 与 stderr、不会管道死锁。
- **状态：** resolved（十一条全部收在这一票里）
- **收尾裁决：** 已在队列进行中裁决过（见本条原有的状态行）。
