# 14 — 读不懂的子库规则要有一条界面上的处置路

**What to build:** 一条读不回来的子库规则，眼下在界面上**改不动也删不掉**——只能去命令行。给它一条界面上的路。

**怎么来的（挂单 Q86）：** 票 25 那版子库屏每条规则旁边有个「删」。票 11 把选择集整个改成**只读**（票的原话：「规则增删、例外记撤的控件要**搬走**」），规则从此在浏览屏的筛选器里改。而**读不懂的那几条搬不去浏览屏**：筛选器摆的是一棵读得懂的树，一条读不回来的原文在那儿没有位置。于是它们卡在中间——子库卡上照旧摆出来（红的，连它错在哪），可一个动它的办法都没有。

票 12 只补了半件事：卡上现在写明「读不懂的这 N 条**界面上改不动**：按序号去命令行删（`romcat sublibrary rule <子库> --remove <序号>`）」。**说清了下一步，但那一步还在命令行上。**

**为什么不能顺手加回一颗「删」：** 那会推翻票 11 立的「这一屏不选内容」。选择集在子库屏只读，是那一票把八个概念降到三个的做法本身；开一个口子，规则增删就会一条条回来。

**几条能走的路**（不预先定死）：

- 让**筛选器**摆得下一条读不回来的原文：一个「读不懂的原文」节点，只显示与删除，不参与求值。那样「改选择」这条路就完整了——去程带过去、回程原样带回或者被人删掉。
- 或者在子库卡上只给**删**这一个动作（不给改），并把它与「改选择」在屏上分开写清：一个是「换掉读得懂的那几条」，一个是「把这条坏的扔掉」。
- 或者给**浏览屏的筛选器**一个「这个子库还有 N 条读不懂的规则」的横幅，点进去处置。

**不许动的：** `replace_rules` 只换**读得懂**的那几条这条口径（`crates/core/tests/sublibrary.rs::换掉规则时读不懂的那几条原样留着` 钉着）——顺手把读不懂的一起删了，等于拿一次「改选择」悄悄清掉用户还没来得及修的东西。**例外是永久记住的**（ADR-0016），一并不许被顺手清掉。

**Blocked by:** 无 —— 可立即开工

### Q143 — 读不懂的规则给的是「扔掉」这一个动作，不是「改对它」

- **来自：** 票 `gui-redesign/14`
- **类别：** 票给了三条路，选了第三条（理由在下面）
- **在哪：** `crates/gui/src/browse.rs::Screen::broken_rules_ui` /
  `::discard_broken_rule`、`crates/core/src/catalog/sublibrary.rs::discard_broken_rule`
- **走的是哪条路：** 票给的第三条——**浏览屏筛选栏顶上那条横幅**。「正在改子库「X」的
  选择集」那条横幅本来就印在那儿，读不懂的那几条跟着「改选择」整条带过去，摆在它底下、
  各给一颗「扔掉这条」。
- **有没有在「这一屏不选内容」上开口子：** **没有。** 子库屏一行写的代码都没加——
  卡上那几条照旧只读地摆着（红的、连它错在哪），改的只是末尾那句指路：从
  「界面上改不动，去命令行删」改成「按上面『改选择』跳去浏览屏，横幅里逐条扔得掉」。
  票 `11` 立的「规则增删、例外记撤的控件要搬走」一个字没动。
- **另外两条路为什么没走：**
  1. **给筛选器加一个「读不懂的原文」节点**（票给的第一条）——那棵树是
     「**读得懂**」这件事的具象：`Filter` 每个节点都是一条 `Clause`，`WorkQuery::to_rule`
     把整棵树折成一条规则带回子库。塞一个不参与求值、也折不进 `to_rule` 的异类进去，
     「屏上筛出来的 ＝ 子库选出来的」（票 `11` 验收第 3 条）与「规则原样带回」
     （第 4 条）两条口径都要各开一个洞，而它们各自钉着一条测试。
  2. **在子库卡上只给「删」**（票给的第二条）——它正是票正文点名警告的那一颗：
     开一个口子，规则增删会一条条回来。而且那一屏上删完之后人还得再跳一趟浏览屏
     去补一条对的，路反而更长。
- **为什么只给「扔掉」不给「改对它」：** 改一条读不回来的原文，要的是一个**规则语言的
  文本框**——那正是这一版界面拆掉的东西（票 `11` 把八个概念降到三个）。改对了的那一条
  走上面的筛选器重筛一遍、按「更新到子库」带回去，那条路本来就通。
  **代价：** 一条写了一半、只差一个括号的规则，眼下只能扔掉重筛，原文捡不回来
  （屏上印着它，人能照着抄）。真库上眼下一条这样的规则都没有
  （`add_rule` 只收读通了的 `Rule`）。
- **那道闸落在核心里而不是界面上：** `Catalog::discard_broken_rule` **先读一遍再决定
  删不删**，读得懂的那几条它拒绝（`Discarded::Readable`）。界面只递一个序号过去
  （ADR-0005）——不然一次「扔掉读不懂的」就能删掉一条好的，而屏上写的是另一回事。
- **谁来裁：** 收尾
- **状态：** open
- **收尾裁决（第二轮）：** **settled** —— 这条的决定已经落进代码，并有测试钉着。

### Q144 — 扔掉一条读不懂的规则会把子库屏缓着的差量与容量账一起丢掉，而它并不改变选出什么

- **来自：** 票 `gui-redesign/14` 的收尾审查（`/code-review high` 报的三条之一，medium）
- **类别：** 有意的保守，代价记下来
- **在哪：** `crates/gui/src/browse.rs::Screen::discard_broken_rule` 的 `self.touched`
  → `crates/gui/src/app.rs::App::route` → `crates/gui/src/sublibrary.rs::Screen::forget`
  → `::open` → `::invalidate`
- **是什么：** 扔掉一条**读不懂**的规则不改变这个子库选出什么（它本来就没参与求值），
  可它留下的那个记号是**通用**的那一根：`forget` 会把这一台缓着的差量预览与容量账
  一起丢掉。于是「排完一趟预览 → 跳去浏览屏扔掉一条坏规则 → 回来」要重排一趟，
  而大库上那一趟是走一遍全库折事实（343 ms 起，挂单 `Q87`）。
- **这张票实际做了什么：** **留成这样，没另开一根「只重读、不作废」的轻通道。**
  理由是severity不对称：那根通道挡的是票 `11` 收尾审查报的那一条（挂单 `Q91` 第 2 条）
  ——浏览屏一按就落库、子库屏还攥着旧差量，而「同步」认的正是它，按下去会把刚排除掉的
  那个传上卡。多一根轻通道就多一个「真改过选择却没作废」的入口，而那一类的代价是
  **把过期的计划传上卡**，比重排一趟贵得多。真库上眼下一条读不懂的规则都没有，
  这条路一年也走不了一次。
- **要收的话怎么收：** 子库屏那边分出 `reread`（只重读 `rules` / `broken` / `exceptions`，
  不碰 `prepared` / `evaluated`），浏览屏这边分出第二个记号；两根通道各自钉一条测试，
  并在 `forget` 的文档里写死「哪些改动只准走轻的那根」。
- **谁来裁：** 票 `gui-redesign/15`（子库屏那两条长活搬上任务台的那一票——差量重排的
  代价正是那一票在算的东西）
- **状态：** open
- **收尾裁决（第二轮）：** **settled** —— 这条的决定已经落进代码，并有测试钉着。
