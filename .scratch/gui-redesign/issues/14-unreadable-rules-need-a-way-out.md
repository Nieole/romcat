# 14 — 读不懂的子库规则要有一条界面上的处置路

**What to build:** 一条读不回来的子库规则，眼下在界面上**改不动也删不掉**——只能去命令行。给它一条界面上的路。

**怎么来的（挂单 Q86）：** 票 25 那版子库屏每条规则旁边有个「删」。票 11 把选择集整个改成**只读**（票的原话：「规则增删、例外记撤的控件要**搬走**」），规则从此在浏览屏的筛选器里改。而**读不懂的那几条搬不去浏览屏**：筛选器摆的是一棵读得懂的树，一条读不回来的原文在那儿没有位置。于是它们卡在中间——子库卡上照旧摆出来（红的，连它错在哪），可一个动它的办法都没有。

票 12 只补了半件事：卡上现在写明「读不懂的这 N 条**界面上改不动**：按序号去命令行删（`romcat sublibrary rule <子库> --remove <序号>`）」。**说清了下一步，但那一步还在命令行上。**

**为什么不能顺手加回一颗「删」：** 那会推翻票 11 立的「这一屏不选内容」。选择集在子库屏只读，是那一票把八个概念降到三个的做法本身；开一个口子，规则增删就会一条条回来。

**几条能走的路**（不预先定死）：

- 让**筛选器**摆得下一条读不回来的原文：一个「读不懂的原文」节点，只显示与删除，不参与求值。那样「改选择」这条路就完整了——去程带过去、回程原样带回或者被人删掉。
- 或者在子库卡上只给**删**这一个动作（不给改），并把它与「改选择」在屏上分开写清：一个是「换掉读得懂的那几条」，一个是「把这条坏的扔掉」。
- 或者给**浏览屏的筛选器**一个「这个子库还有 N 条读不懂的规则」的横幅，点进去处置。

**不许动的：** `replace_rules` 只换**读得懂**的那几条这条口径（`crates/core/tests/sublibrary.rs::换掉规则时读不懂的那几条原样留着` 钉着）——顺手把读不懂的一起删了，等于拿一次「改选择」悄悄清掉用户还没来得及修的东西。**例外是永久记住的**（ADR-0016），一并不许被顺手清掉。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

- [ ] 一条读不懂的规则在界面上处置得掉（删掉，或者改对）
- [ ] 处置它**不碰**同一个子库里读得懂的那几条与例外
- [ ] 「改选择」那条路照旧只换读得懂的那几条（原有那条核心测试仍绿）
- [ ] 子库屏照旧不输入规则与例外（票 11 立的「这一屏不选内容」不破）
- [ ] headless 测试钉住：卡上摆着一条读不懂的，走完界面上那条路之后它没了，别的没动
- [ ] 挂单 Q86 标为 resolved，写清走了哪条路
- [ ] 门禁命令全绿（带 `--all-features`）

### Q86 — 读不懂的规则在界面上删不掉了

- **来自：** 票 `gui-redesign/11`
- **类别：** 票没预见到的第三种情况
- **在哪：** `crates/gui/src/sublibrary.rs::selection_ui`、
  `crates/core/src/catalog/sublibrary.rs::replace_rules`
- **为什么没停线：** 上一版子库屏每条规则旁边有个「删」，这一票把选择集整个改成只读
  （票的原话：「规则增删、例外记撤的控件要**搬走**」）。而**读不懂的那几条搬不去
  浏览屏**——筛选器摆的是一棵读得懂的树，一条读不回来的原文在那儿没有位置。
- **这张票实际做了什么：** 读不懂的那几条在卡上**照旧摆出来**（红的，连它错在哪），
  并且写明「它没参与求值，『改选择』也不会碰它」。`replace_rules` 只换**读得懂**的
  那几条：顺手把读不懂的一起删了，等于拿一次「改选择」悄悄清掉用户还没来得及修的
  东西；而留着它们不改变这个子库选出什么（`LoadedSelection::from_stored` 早把它们
  挑出来另放了，`select` 根本看不见）。核对在
  `crates/core/tests/sublibrary.rs::换掉规则时读不懂的那几条原样留着` 与
  `crates/gui/tests/sublibrary.rs::选择集在这一屏上只读摆得出规则与例外`。
- **删它的路还在，只是在命令行上：** `romcat sublibrary rule rm <子库> <序号>`，
  而卡上印着的正是那个序号。
- **正常路径上长不出这种规则**：`add_rule` 只收已经读通了的 `Rule`。它们的来路是
  「人打开过那个 SQLite 文件」或者「换了一版程序、删掉了一个维度」
  （`LoadedSelection::from_stored` 的文档）——真库上眼下一条都没有。
- **谁来裁：** 票 `12`（版式与一致性收尾）——要么在卡上给这几条单独留一个「删掉这条」，
  要么就明确写成「走命令行」
- **票 `12` 裁定：屏上那一半做掉，界面上删得掉那一半升成新票 `gui-redesign/14`。**
  加回一颗「删」会推翻票 11 立的「这一屏不选内容」——那一票把八个概念降到三个靠的就是它，
  开一个口子，规则增删会一条条回来。而这张票的硬约束里点名写着**票 11 的「选择集只读」
  不许顺手改形状**。
- **屏上眼下多了一句**：「读不懂的这 N 条**界面上改不动**：按序号去命令行删
  （`romcat sublibrary rule <子库> --remove <序号>`），或者改对了再 `--add` 一条。」
  ——**看不出下一步**是这条挂单里最贵的那一半，它当场没了；而「那一步还在命令行上」
  由新票 14 收。
- **状态：** open（屏上说清已做；界面上处置得掉转 票 `gui-redesign/14`）
- **收尾裁决：** **由本票接着做** —— 它就是从这条挂单立起来的。
