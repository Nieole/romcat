# 10 — 刮削面板与估算

**What to build:** 在浏览屏筛出一批，按「刮削选中…」，面板上四个旋钮定清楚要干什么，**按下去之前就看得见会发多少网络请求、大概多久**。

四个旋钮，两条轴分得清清楚楚：

| 旋钮 | 答的是 |
|---|---|
| **范围** | 对谁 —— 筛出来的这批，带条数，不可就地编辑（要改回筛选器改） |
| **字段** | **我要什么** —— 简介 / 类型 / 开发商 / 发行商 / 年份 / 媒体 |
| **源** | **花多少代价** —— 默认只勾本地源；勾联网源弹配额提醒 |
| **采法** | 跑多久 —— **补缺**（只采一个源都没给过值的）/ **重采**（绕过输入指纹全部重来） |

面板底部实时估算**请求数与耗时**，并常驻一句：**裁决与你手工维护的元数据不会被动。**

**要纠正的心智模型：** 刮削结果按「锚点 × 字段 × 源」三元组**并存**，没有「覆盖」这回事。「有值了但我想换一个」**不该靠重刮**——那是**优先级**的事，改一次排序、零成本、不重跑。面板上要让这件事说得出口。

按下去之后任务走**任务台**。

- [x] 补缺与重采各自成立，行为与命令行一致

  `crates/core/tests/scrape.rs::估算的请求数与在线档实际发出去的一致` 一条钉三态：
  第一趟发 N 个请求；**补缺**的第二趟估算与实际都是 0（判据没变、指纹没变）；
  **重采**的第三趟估算与实际都回到 N。界面与命令行 `--refresh` 之间只有一处映射
  （`scrape::Gather::apply` 写 `Options::refresh`），命令行的 `--refresh` 帮助文本
  也改成用这两个词。

  **重采是「不看那道输入指纹」，不是「先把库清空再重来」**（收尾审查改的，挂单 Q103
  第 2、5 条）：清空跑在采集之前，中途按停下或者撞上配额就只剩一个空壳，而且它无条件
  删掉的 `media_ref` 在「这趟不收媒体」那一档根本写不回来。三条测试各钉一面：
  `重采不收媒体时上一趟收进来的媒体引用还在`、`重采半路被按停也不会把没走到的锚点清空`、
  `范围之外的变体这一趟一个字都不动`。

- [x] **只勾本地源时估算的请求数为 0**

  两处各钉一遍：核心 `crates/core/tests/scrape.rs::只勾本地源时估算的请求数为零`，
  界面 `crates/gui/tests/library.rs::只勾本地源时面板上估的请求数是零`。
  **这不是「大概是 0」**：离线档只收自报本地的源，混进一个联网源会当场被拒
  （`scrape::sources` 那道闸门），估算那一侧照同一条判据直接返回 0。

- [x] 估算的请求数与实际发出的**一致**（有测试钉住）

  `crates/core/tests/scrape.rs::估算的请求数与在线档实际发出去的一致`：
  `estimate.requests == outcome.online.requests`，用 `CannedFetcher` 真跑一趟对上。
  一致靠的是**三处共用同一段代码**而不是照着抄：代表变体的挑法
  （`Catalog::work_representatives` 的 `MIN(key)` ＝ `Plan::build` 按键遍历挑中的第一个）、
  判据（两边都调 `Catalog::accepted_hash`）、指纹（两边都调
  `online::query_fingerprint`）。另有 `范围里一个已确认的作品都没有时在线档也不发请求`
  钉住「未识别 ROM 一个请求都不发」（ADR-0007）。

  **真库整库那一档算得出来**：`work_representatives` 给每个键各绑一个 SQL 参数，
  46,444 个会撞穿 SQLite 的绑定变量上限（挂单 **Q103** 第 1 条），改成分批问，
  `crates/core/src/catalog/scrape.rs::作品代表变体这一问吃得下四万多个键` 钉着。
  **账算不出来时「加入任务队列」按不动**（Q103 第 3 条）——不知道要发多少请求就不该发。

  **保留：** 这个数是**查询**那一半。收媒体时每采到一份图还要各下一次，而图有几份要
  查过才知道——源不说，谁也算不出来。面板上照实写（连同「图与查询共用这一趟自设的
  N 个请求的上限」，Q103 第 4 条），另一条测试 `估算说得出媒体那一段是下界`
  钉住「实际 > 估算」。见挂单 **Q96**。
  真机上的偏差没量（这台机器上没有那份真库），见挂单 **Q100**。

- [x] 面板上常驻「裁决与手工维护的元数据不会被动」，且行为确实如此

  那句话是 `scrape::UNTOUCHED`，`Panel::account_ui` 每帧都画（不随旋钮变）。
  **行为上也成立，而且这一票是把它修成立的**：`clear_scraped` 原先是一句光秃秃的
  `DELETE FROM scrape_value`，`--refresh` 会把人手写的元数据一起删掉（挂单 **Q93**）。
  眼下更硬一档——**重采这一趟一个 `DELETE` 都不发**，只走 `put_scraped_within`，
  而它只在这一趟点名的字段之内替换。三条测试各钉一面：
  `crates/core/src/catalog/scrape.rs::整份清掉刮削结论时裁决一条都不删`、
  `crates/core/tests/scrape.rs::重采不碰裁决与手工维护的元数据`、
  `crates/gui/tests/library.rs::刮削走任务台而且裁决与手工写的元数据一个字都没动`。
  另外「字段选窄了不抹掉上一趟采到的别的字段」也是同一条纪律的一半。

  面板上还常驻 `scrape::NOT_BY_RESCRAPE`——「有值了但我想换一个」不该靠重采，
  那是**优先级**的事：改一次排序，零成本、不重跑。它印在「采法」那一栏底下，
  正好在人要去按「重采」的地方。

- [x] 任务走任务台：带进度、能停、期间别的屏照常用

  `crates/gui/tests/library.rs::刮削走任务台而且裁决与手工写的元数据一个字都没动`：
  按下去之后拿到一个任务号，跑完之后台上留着一条带耗时的历史，面板销号。
  进度：`scrape::run` 的进度回调桥到 `Handle::tick`；能停：`task.cancel()` 交下去，
  `run` 每个锚点看一眼，停在两个锚点之间（采完的那部分留在中立库里，
  `Panel::settle` 的 `Done::Stopped` 那一支照实说）。

  **保留：** 真库走 `Board::queue`（后台线程，与扫描那一趟同一个套路），
  合成数据只活在内存里、分不出第二份连接，走 `Board::run_here` 就地跑完——
  与子库屏排差量预览同一条退路。因此「期间别的屏照常用」这一条由票 01 的
  `crates/gui/tests/task.rs::任务跑着的时候别的屏照常画得出来` 钉着，
  刮削这一票没另钉一遍（它排的是同一张台上的同一种活）。

- [x] 估算逻辑在核心库里

  `crates/core/src/scrape/estimate.rs`（ADR-0005）。界面那一层只调它、把结果画出来。
  它不走「把计划立起来数一遍」那条最准的路——那要读全库的变体、候选与文件表，
  是好几秒的活，而这块面板每动一下旋钮都要重算一次。理由与代价见挂单 **Q92**。

  界面那一层留下的只有**装配**（哪份优先级表、哪份中文索引、哪份裁决），
  与命令行摆的是同一副；凡是会让两条路得出**不同结论**的（剥离规则、平台清单、
  匹配参数、中文索引打不开时怎么办）这一票都并成一条查法了，见挂单 **Q102**。
