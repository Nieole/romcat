# 06 — 收藏与合集

**What to build:** 在主列表里多选或全选一批游戏，一下子全部收藏或取消收藏；之后用 `收藏=是` 把它们筛出来。

收藏走**合集**那套机制，界面上就是一颗星。于是同一套东西顺带给出自建合集（「通关过的」「送朋友的」），按 `合集=某某` 筛。这收掉挂账 D74——**合集** 这个维度立了很久却一直没有任何建的办法，界面上始终显示「合集 0 个」。

**收藏是用户亲手点的，不可再生**，所以它住**沉淀库**不住中立库（中立库整份可再生，某次重扫就没了）。锚用**内容锚**，于是重扫、改名、挪目录、以及票 02 那次换键形状，收藏都不丢。

**诚实的限制**：**无判据**的那些变体（真库里 2,631 个）拿不到内容锚，只能退**路径锚**——挪了位置收藏会飘。与裁决同一个限制，界面上要标出来。

## 挂账裁决

- **D74**（合集没有任何建的办法）—— resolved，走的是当初推荐的 **A**：这一票就是那张
  单独的票。建法是**浏览屏上多选或全选一批、给它起个名字**；合集不另立一张表，
  一个合集就是它那些成员关系，成员一条不剩它就没了（挂单 Q110）。
  命令行仍然没有 `romcat collection` 子命令，那是有意的（挂单 Q112）。

## 与 ADR 的关系

**与 ADR-0006（用户状态不在范围内）的字面相悖，但与它的理由不相悖**，所以给它加了一段
修订收窄适用范围，而不是推翻它（挂单 Q116）。ADR-0006 的三条理由——数据长在前端各家
自己的文件里、那是**在前端里玩出来的历史**、多设备并用时合并语义无解——对 romcat 自己
这颗星一条都不成立：它长在沉淀库里、键是内容锚（两台机器上同一份内容天然是同一条）、
也不是运行时累加出来的历史，而是**用户对着这个库做的一次挑选**，与裁决、人工纠正同类。
`adapter::gamelist` 与 `adapter::pegasus` 对前端那份用户状态的原样搬运**一个字都没动**。
