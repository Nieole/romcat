# 06 — 收藏与合集

**What to build:** 在主列表里多选或全选一批游戏，一下子全部收藏或取消收藏；之后用 `收藏=是` 把它们筛出来。

收藏走**合集**那套机制，界面上就是一颗星。于是同一套东西顺带给出自建合集（「通关过的」「送朋友的」），按 `合集=某某` 筛。这收掉挂账 D74——**合集** 这个维度立了很久却一直没有任何建的办法，界面上始终显示「合集 0 个」。

**收藏是用户亲手点的，不可再生**，所以它住**沉淀库**不住中立库（中立库整份可再生，某次重扫就没了）。锚用**内容锚**，于是重扫、改名、挪目录、以及票 02 那次换键形状，收藏都不丢。

**诚实的限制**：**无判据**的那些变体（真库里 2,631 个）拿不到内容锚，只能退**路径锚**——挪了位置收藏会飘。与裁决同一个限制，界面上要标出来。

- **D74**（合集没有任何建的办法）—— resolved，走的是当初推荐的 **A**：这一票就是那张

## 与 ADR 的关系

**与 ADR-0006（用户状态不在范围内）的字面相悖，但与它的理由不相悖**，所以给它加了一段
修订收窄适用范围，而不是推翻它（挂单 Q116）。ADR-0006 的三条理由——数据长在前端各家
自己的文件里、那是**在前端里玩出来的历史**、多设备并用时合并语义无解——对 romcat 自己
这颗星一条都不成立：它长在沉淀库里、键是内容锚（两台机器上同一份内容天然是同一条）、
也不是运行时累加出来的历史，而是**用户对着这个库做的一次挑选**，与裁决、人工纠正同类。
`adapter::gamelist` 与 `adapter::pegasus` 对前端那份用户状态的原样搬运**一个字都没动**。

### Q110 — **合集不另立一张表**：一个合集就是它那些成员关系，成员一条不剩它就没了

- **来自：** 票 `gui-redesign/06`
- **类别：** 数据模型取舍（票只说「收藏走合集那套机制」，没说合集本身怎么存）
- **在哪：** `crates/core/src/verdict.rs` 的第 4 条迁移（`collection_member` 一张表）
- **两条路：** A 一张 `collection_member`（名字 + 锚），合集由 `SELECT DISTINCT name`
  折出来｜B 再立一张 `collection`（id + 名字），成员关系引它 —— 那样**建得出空合集**
- **走的是哪条路：** **A，一张表。** 理由不是省一张表，是**空合集本身是个坏东西**：
  这一票的正题恰恰是把「合集 0 个」那句话收掉（挂账 D74），而 B 让屏上「合集 3 个」
  里可以有两个一件东西都选不出来。而且落地的建法根本用不上空壳——**先勾一批再起名**
  （`Catalog::scoped_variants`，票 03 的口径），不是先建壳再往里挑。D74 当初推荐
  「留给单独一张票」时说的就是这句话：难题是「怎么把几百个变体放进去」，不是「建一个空的」。
- **代价写明白：** 想先建一个空合集、日后慢慢往里加的人，得先随便放一个进去。
  真要支持空合集，加第 5 条迁移即可——**迁移只许往后追加，这条路是通的**。
- **谁来裁：** 收尾
- **状态：** open
- **收尾裁决：** **settled** —— 这条的决定已经落进代码，并有测试钉着。

### Q120 — `/code-review high` 报的五条，五条当场收掉

- **来自：** 票 `gui-redesign/06`
- **类别：** 审查发现
- **五条与各自的处置：**
  1. **中 · 增量投影与整份重建对同一条成员关系给出两种展开** ——
     `collection::apply` 只点亮人勾的那几个键，而**内容锚钉的是「世上这份内容」**：
     同一份内容在本机存了两处（两块盘各一份）时，一条成员关系落在**两个**变体上。
     于是取消收藏会把共享的那条从沉淀库里删掉，而屏上另一处还亮着，直到下一趟识别
     才悄悄熄掉——**沉淀库不可再生，而这次丢失用户全程看不见**。
     **收法是把展开提成一处** `collection::landed`，`project` 与 `apply` 共用它；
     `crates/core/tests/collection.rs::同一份内容存了两处_一处点星两处一起亮_而且重扫之后还是这个样子`
     钉着（点一个两个一起亮、重扫之后样子不变、取消也一起熄）。
     代价见 Q119 那张表最后一列。
  2. **中低 · `project` 的「先清后写」不在一个事务里** —— 中途出错或进程被杀，投影就停在
     空的或半份的样子：`收藏=是`、筛选栏那一维、子库的选择集上所有的星一起消失，
     要等下一趟识别才回来——而这一票的正题恰恰是「重扫之后还在」。
     **收法是 `Catalog::replace_collections`**（清 + 写一个事务），与本仓库同类
     「先删后写」的写法一致（`catalog/sublibrary.rs`、`catalog/identify.rs`）。
  3. **低 · 告警串里一段 17 个空格** —— 断行的续行 `\` 掉了，合集名带逗号时屏上那句话
     中间会裂开一大段空白。补回去。
  4. **低 · join 那一支无条件先 `add_collection`** —— 整批键在中立库里都已经不在时

### Q119 — 「全选 46,483 行 → ★ 收藏」在画帧那条线程上跑，实测 **6.7 秒**（dev）

  1. **识别那一层有了批量取判据的入口** `identify::content_prints`。

     `variant_members_of` / `container_files_of` / `container_status_of` /
     `entry_facts_of` / `content_hashes_of`），**原来那几条单键版全部改成它们

     取消收藏与自建合集那两下一并搬上去（`Q282`）。
