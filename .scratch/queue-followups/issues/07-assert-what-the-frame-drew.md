# 07 — 界面那条验收改成断言这一帧画出来的字

**What to build:** 「库里有一条顶到闸上的简介时列表照样滚得动」这条验收现在断言的是一个**纯函数**的输出，没有一条断言真看着那一行被画出来。这一票把它改成断言**这一帧真画出来的字**。

egui 每画一段文字就留下一个 `Galley`，它带着原文。待确认屏与版式那两处测试已经是这个写法，照抄。

**「屏上看得见」这类验收若断言的是「数据在不在库里」，那是在测别的东西**——这一轮出过一次，被审查抓了回来。

**Blocked by:** 无 —— 可立即开工

**Status:** done

- [x] 那条验收断言的是这一帧画出来的文字，不是纯函数的返回值
      —— `crates/gui/tests/browse.rs` 的 `一条顶到闸上的简介收成一行画得下的那一截`：
      它现在读的是 `元数据栏滚一趟` 交回来的**这一路上真的画出来的字**（每个 `Galley`
      一段），拿 `简介 · 变体` / `简介 · 作品` 这两个开头找出屏上那两行。
      验它不是恒真的废话：把那一趟的滚动步数改成 0 再跑，它当场红——
      「滚下来画出的 167 段字里没有以「简介 · 变体」开头的那一段」，那正是挂单 Q20
      记着的「headless 的一帧里够不着它」。剩下 `browse::one_line(…) == None` 一条
      仍在函数那一侧：屏上画的是同一串字，中间换没换过一份字符串出去，看那一帧看不出来
      （挂单 Q172）。
- [x] 超长简介那一行真的被画出来，且被收成画得下的那一截
      —— 同一条测试：往中立库里摆一条 4,000 字（`scrape::zh::DESCRIPTION_LIMIT`）的简介，
      断言屏上那一行**值那一段**（最后一个 `｜` 之后那一截）`ends_with('…')` 且画出来的
      **不到 80 个字**（实际 61 个：60 个字加省略号）。换行那一半也搬到了帧上：作品那一层
      摆一条带换行的简介，断言屏上那一段既以全角空格起头、又以换行之后那半句收尾——
      值里若留着换行，那一段就断在换行处，后半句根本跟不上来。
- [x] 列表在有超长简介时仍然滚得动
      —— `库里有一条顶到闸上的简介时列表照样滚得动` 一个字没动：它钉的本来就是**表**那一侧
      （`bench::scroll` 滚 240 行只读 2 次库、内存里仍是一扇窗），不是纯函数。票开头把
      两条验收记混了，记在挂单 Q171。
- [x] 门禁全绿（`--all-features`）
      —— clippy 干净；一趟全量 `cargo test --workspace --all-features -j 1 -- --test-threads=2`：
      **58 个 `test result: ok`、1,571 条通过、0 失败**，与基线一模一样——这一票没新增测试，
      只把一条重写了。

### Q20 — 界面那条验收钉在 `one_line` 上，钉不到画出来的那一帧上

- **来自：** 票 `offline-chinese-fields/03`
- **类别：** 工具缺陷（egui 的，不是这个仓库的）
- **在哪：** `crates/gui/src/browse.rs` 的 `one_line` 与 `values_ui`、
  `crates/gui/tests/browse.rs` 的两条测试
- **为什么没停线：** 票要「带一条超长简介的库，界面上的列表仍然滚得动」。真正会被
  撑坏的是详情面板右栏那份**刮削来的元数据**清单——它画在一条 `ui.horizontal` 里，
  而**横排不折行**：4,000 个汉字排出来就是四五万点宽的一行，面板跟着长出一条横向
  滚动条。可 egui 的 `Label` 只画视口之内的文字（`ui.is_rect_visible`），而那一栏在
  底部面板（300 点高）里排在标题集合与首选变体之后——headless 的一帧里它**根本没被
  画出来**，量帧里最宽的那块文字也就量不到它。试过三条路都够不着：滚轮事件、把视口
  调高到 2000 点、挑一条没认出作品的变体好让上面两节缩成两行。
- **这张票实际做了什么：** 界面这一侧照改（`one_line`：换行折平、超过 60 字用省略号
  收住，**原文一个字没动**，整段挂在悬停里，用 `on_hover_ui` 让那个闭包只在真悬停时
  才跑）；验收拆成两条：`一条顶到闸上的简介收成一行画得下的那一截` 钉在
  `one_line` 这个纯函数上（因此把它改成 `pub`，文档里写明了为什么），
  `库里有一条顶到闸上的简介时列表照样滚得动` 钉表那一侧（内存里仍是一扇窗、
  240 行只读 2 次库）。**没有一条断言真的看着那一行被画出来** —— 这是这条验收的缺口，
  记在这儿。
- **谁来裁：** 拿主意的人（要补的话，得给详情面板那个 `ScrollArea` 开一个像
  `Screen::scroll_to` 那样的「只有量帧率时才设」的偏移口）
- **状态：** closed —— 本票补上了
- **收尾裁决：** **由本票接着做** —— 它就是从这条挂单立起来的。
- **实际怎么够着的：** **没有给界面开任何口子，一行行为都没改。** 缺的是那三条路里
  滚轮那条少的一下：**指针得先停进那一栏**（`egui::Event::PointerMoved`），滚轮归指针
  底下那块滚动区；少了它滚的是别处。同一件事票 `queue-followups/06` 在待确认屏上已经
  解过一遍（挂单 Q169），这一票照抄：`crates/gui/tests/browse.rs` 的 `元数据栏滚一趟`
  把指针停在底下那块编辑面板的**右半栏**（左边 42% 是 `facts_column`），连发 24 次
  `MouseWheel`，每一帧收那一帧真的画出来的字。
