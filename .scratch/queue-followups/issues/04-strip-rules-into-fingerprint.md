# 04 — 剥离规则进变体层与作品层的输入指纹

**What to build:** 改过文件名**剥离规则**之后重跑刮削，**真的重采**。

剥离规则决定从文件名里剥出什么**正题**，正题变了撞出来的中文条目就可能变。可两层的**输入指纹**都没盖住它，缓存一口咬定"输入没变"，整条跳过——用户调完规则重跑，什么都不会重采，而且不报错。

**这与已经做掉的那件事不是同一件。** 另一条线刚把**建索引那一刻的平台折叠表**盖进了指纹（治的是"补一条平台别名重建之后不重采"），那条提交自己写着"规则集的指纹因此不必加"。剥离规则改的是**正题**，那一路照旧漏。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

- [ ] 规则集算得出一个指纹
- [ ] **变体层**与**作品层**的采集记录都盖住它
- [ ] 改过剥离规则重跑，撞上过的锚点**真的重采**而不是被缓存跳过
- [ ] 规则没改时照旧整片跳过——加这道判据不让每一趟刮削都从头来
- [ ] 指纹只认**会改变正题的那部分**：给规则文件加一行注释不触发全库重采
- [ ] 门禁全绿（`--all-features`）

### Q16 — 中文离线源的输入指纹从来没盖住**剥离规则**

- **来自：** 票 `offline-chinese-fields/02`（复审的产出）
- **类别：** 路过发现，不在范围内（票 11 就有的洞）
- **在哪：** `crates/core/src/scrape/zh.rs` 的 `variant_probe` 与 `work_probe`；
  `crates/core/src/filename.rs` 的 `Rules`
- **为什么没停线：** 两个指纹都盖了 dump、这一版取了哪几样字段、匹配参数，唯独没盖
  `naming.rules`。而**剥离规则「是配置不是代码，用户能补充自己遇到的模式」**
  （`CONTEXT.md` 的「剥离规则」词条）——换一份规则会改变**正题**，进而改变撞出来的条目
  与类型，缓存却会一口咬定「输入没变」而整条跳过。这不是这张票引进来的：
  `variant_probe` 那份清单票 11 就是这么写的，`work_probe` 只是照抄了同一份。补它要先给
  `Rules` 加一个 `fingerprint()`，那是 `filename` 那个模块的公开表面，而这张票的风险面
  按规格只该在刮削那一侧。
- **这张票实际做了什么：** 没补，照抄了变体那一层现有的那份清单——两层一致，将来补
  `Rules::fingerprint()` 时两处一起加一行就行。**眼下的出口是 `--refresh`**
  （`Source::probe` 的文档已经把「盖不住这个源自己的解析逻辑」那一条写在那儿了，
  换规则与换解析逻辑是同一类）。
- **谁来裁：** 拿主意的人（该单开一张票：它同时影响识别那一层与刮削这一侧）
- **状态：** open
- **收尾裁决：** **由本票接着做** —— 它就是从这条挂单立起来的。
