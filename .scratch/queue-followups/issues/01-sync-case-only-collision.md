# 01 — 同步执行层认得出只差大小写的落点占用

**What to build:** 排完差量预览之后，维护者自己往卡里拷了一个 `GB/Tetris.zip`；按下同步，工具要写的是 `GB/tetris.zip`——**只差大小写**。这一票要让执行那一层认出这是一次落点占用：**维护者那份文件一个字节都不动**，这一步记成一条没做成的步骤，其余几百步照常走完，报告里说得出是哪个落点被占着。

掌机的卡是 FAT32 或 exFAT，**不区分大小写**。眼下执行层压根不比落点，会在大小写敏感的盘上另写一份、在不敏感的卡上顶掉维护者那份，两种情况都报告"成功"。

**这一票的验收测试已经写好了，而且正红着。** 它排一趟计划、确认计划里有那一步，然后模拟"排完计划之后落点才被占上"，断言 `failures` 里有那一条。做这一票就是把它变绿——判据不必自己想。

**优先做。** 这一批票里只有这一条会**弄丢用户的数据**，其余都是欠账。

**Blocked by:** 无 —— 可立即开工

**Status:** done

- [x] 只差大小写的落点被占着时，那一步记成一条没做成的步骤（`Act::Add` 那一条失败），不是覆盖
      —— `crates/core/tests/sync_run.rs::计划算完之后才出现的落点占用_执行这一层也挡得住`
      从红转绿（改之前它挂在 `outcome.failures` 那句上，`failures` 是空的）。
- [x] **落点上原有的文件一个字节都不动**，修改时间也不动
      —— 同一条测试的 `assert_eq!(fs::read(&维护者那份), 原样)`；`place` 在
      `create_dir_all` 之前就返回 `AlreadyExists`，落点那一枝连目录都没建过。
- [x] 其余步骤照常做完，不因为这一条整趟停住
      —— 新增 `落点被占只挡那一条_其余几步照常做完`：3 步的计划里挡下 1 条，
      `failures.len() == 1`、`manifest.files.len() == 2`、`interrupted`/`gave_up` 都是假，
      另一份 ROM 的字节与主库那份逐字相等。
      另有 `落点被占再多也不算系统性故障_不触发连着失败就停下来`：`GIVE_UP_AFTER` 是 10，
      而新增在计划里是**连在一起**的，占用一旦计进那个计数，卡里拷了十来个只差大小写的
      文件就能让其余几百步一步都不做——`AlreadyExists` 因此不进那个计数（也不清零）。
      12 份里占掉 11 份，`gave_up` 仍是假、`failures.len() == 11`、第 12 份照常落下。
- [x] 报告说得出是哪个落点被占着
      —— `Failure::why` 里印的是**盘上真实那条路径**（「`GB/tetris.zip` 的落点上已经有
      东西了（…/GB/Tetris.zip）」），`sync::report` 的「没做成的」一节逐条印出来；
      `只差大小写的是上一级目录_执行这一层照样挡得住` 断言了 `why` 里有 `Tetris.zip`。
      **报之前一律先问 `occupied_by`**，哪怕逐字那一问已经说「占着了」：`landing` 交回来的
      是 `根 + 键` 拼出来的那条（`real_path` 的快路径），大小写还是我们自己的——在卡上
      （不敏感，正是主场景）照它印，括号里那条与前面一模一样，等于没说出是谁占着。
- [x] 比落点用的是与**排计划那一层同源**的那套折起来的可比形态，两处不各写一套
      —— 两处调的都是 `crate::path::fold`（小写 + NFC）这**同一个函数**：计划那一侧在
      `sync::plan` 的 `strangers` 与 `Desired::screen`，执行这一侧在
      `sync::execute::occupied_by` / `folded_children`。折的都是**整条键**，
      `只差大小写的是上一级目录_执行这一层照样挡得住` 证明上一级目录那一段也折——
      那条测试里卡上 `GB/` 与 `gb/` 并存（敏感盘上并得了），挡路的那份在排在后面的
      `gb/` 底下：每一层折起来一样的候选**全都要跟下去**，只跟排在前面那个会漏。
- [x] 大小写敏感的盘与不敏感的卡上行为一致
      —— **保留一半**：跑门禁这台机器是 ext4（敏感），敏感那一边由上面三条新测试实测；
      不敏感那一边没法在 CI 里造（要一个不敏感的挂载点），走的是 `landing` → `real_path`
      那一问，`大小写不敏感的目标上_清单之外只差大小写的文件不被顶掉` 覆盖它的计划侧。
      两边现在判的是同一个 `path::fold`，结论因此对齐。**真卡上那一半没有票管**，
      记成挂单 `Q135`。
- [x] 门禁全绿（`--all-features`）
      —— `cargo clippy --workspace --all-targets --all-features -j 1` 干净；
      `cargo test --workspace --all-features -j 1 -- --test-threads=2`：

## 挂单裁决（第二轮）

### Q133 — 票说「执行层压根不比落点」，其实闸早就在，缺的只是大小写那一半

- **来自：** 票 `queue-followups/01`
- **类别：** 票写错了
- **在哪：** `crates/core/src/sync/execute.rs` 的 `place` / `landing`（提交 `3fa668c` 加的）
- **为什么没停线：** 判据是那条红测试，票的**归因**写偏了不影响要做的事。
- **这张票实际做了什么：** 照红测试做。实测那道闸在**大小写不敏感**的目标上本来就管用
  ——`real_path` 先拿 `root.join(key)` 试一次，不敏感的文件系统上它开得了别人那份，
  于是 `taken` 为真、新增被挡下（`大小写不敏感的目标上_清单之外只差大小写的文件不被顶掉`
  一直是绿的）。漏的是**敏感的盘**：`real_path` 只折 NFC（ADR-0020），大小写归文件系统
  自己认，ext4 上它答「空的」。所以这一票补的是「同一张卡换台机器插，行为得是同一个」，
  不是从零加一道闸；票里那句「两种情况都报告成功」只对一半。
- **谁来裁：** 收尾
- **状态：** open
- **收尾裁决（第二轮）：** **noted** —— 核对过、不用改，留作记录。

### Q134 — 落点占用这道闸每一条新增都要现列一层目录，没做缓存

- **来自：** 票 `queue-followups/01`
- **类别：** 路过发现，不在范围内
- **在哪：** `crates/core/src/sync/execute.rs` 的 `occupied_by` / `folded_child`
- **为什么没停线：** 代价的**量级没变，常数翻了一倍**——`landing` 走的 `real_path`
  一直就是这样：直接拼那一下打不开就逐段列目录，于是每一条新增本来就要把落点那条路径
  上的每一层列一遍；`real_path` 每次现开一个 `DirCache::default()`，`occupied_by` 又
  不复用它，于是同一层现在被列两遍。
- **这张票实际做了什么：** 走「**不缓存、每次现列**」这条路。另一条路是在一趟 `run` 里
  按目录记一份折起来的 listing（`fs::DirCache` 那种记性），常数能减半；没走，是因为
  这道闸要防的正是「计划算完到真的改名之间，卡还插在机器上」，一份跑到一半就过期的
  listing 会把那道缝重新打开——而这条缺陷是十七张票里唯一会弄丢用户数据的那条。
  真要治代价，该治的是 `real_path` 与它共用一份 listing，那是整条链路的活，不是这一票的。
- **谁来裁：** 收尾（或并进「翻页代价」那张票一起量）
- **状态：** open
- **收尾裁决（第二轮）：** **settled** —— 这条的决定已经落进代码，并有测试钉着。

## 挂单裁决（第三轮）

本票记下的 `Q135`，由票 `parking-3/06`（「落点闸：可注入的目标侧接缝」）落地。

| 挂单 | 它说的 | 裁决 |
|---|---|---|
| `Q135` | 「同一张卡换台机器插，行为得是同一个」只验得了**分大小写**那一半——不敏感的卡（exFAT / FAT32 / Windows / 默认 APFS）在开发机上造不出挂载点，那一半一直靠一句推理撑着 | **settled。** 执行层对外那一个入口上加了一道**可注入的目标侧接缝**：`sync::Sources::target`（`&dyn LibraryFs`，与 `sync::observe` 同一个 trait）。落点闸问目标那三句——`on_target`（盘上真名）、`occupied_by`（折起来占没占）、`settled`（目录段真名）——全从它上面问，**写那一侧一个字节都没经过它**（建目录、`.romcat-part`、`sync_all`、`rename`、写完读回戳照旧是 `std::fs`）。造视图的是 `crate::testing::target::snapshot(root, Folding)`：把卡上真实那棵树照进一个指定折叠语义的 `MemFs`。执行层那四条落点占用测试（`计划算完之后才出现的落点占用…`、`只差大小写的是上一级目录…`、`落点被占只挡那一条…`、`落点被占再多也不算系统性故障…`）现在**在两种折叠语义下各跑一遍**，断言两边都成立——票里说的是「三条」，实际是四条（挂单 `Q246`）。「不注入就是真盘」另有一条钉着：`塞得进一个假目标_不塞就是真盘`。 |

**顺带把本票当年那句推理销掉。** 本票收尾写的「实测那道闸在大小写不敏感的目标上本来
就管用」（`Q133` 的裁决里那段），依据是 `real_path` 先拼一次试开——那是**读代码读出来
的**，不是跑出来的。现在跑出来了：不分大小写那一档上闸挡得住，而且突变检查显示，
把 `occupied_by` 拿掉之后它仍然挡得住、只是**报不出是谁占着**（挂单 `Q248`）。

**接着是 `Q136`**，由票 `parking-3/07`（「列不开的目录那一格 + 落点判据收紧」）落地。

| 挂单 | 它说的 | 裁决 |
|---|---|---|
| `Q136` | 列不开的目录底下，折起来那半边闸整个失效——`folded_children` 的 `read_dir(...).unwrap_or_default()` 把「列不开」折成了「这一层没有挡路的」。后果：大小写敏感的盘上会在维护者那份 `GB/Tetris.zip` 旁边多写一份 `GB/tetris.zip` | **settled。** 照 ADR-0021 把「读不动」立成第三态，一路带到落点判定：`list()` 把 `read_dir` 那一个失败拆成 `Missing` / `NotADir` / `Unreadable` 三种结论，`occupancy()` 交出的不再是 `Option<PathBuf>` 而是 `Occupied` / `NotADir` / `Unreadable` / `Clear`——**列不开就是「答不出来」，答不出来就不写**。两条测试钉着：`列不开的目录底下_落点被占照样挡得住`（`#[cfg(unix)]`，真盘上一个 `0300` 的目录，不注入，走的正是本票当年那条真实路径）与 `列不开的目录底下_假视图上闸照样挡得住`（手捏 `MemFs`：先 `unlistable_dir` 再往底下 `file`，哪台机器都跑得了）。突变检查过：把 `Unreadable` 折回 `Absent`，两条当场红。代价记在挂单 `Q258`——那种目录本来写得进，现在整枝不写。 |
