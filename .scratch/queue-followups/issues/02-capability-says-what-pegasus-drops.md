# 02 — 能力档位说出 Pegasus 丢掉的换行与前导空白

**What to build:** 导出到 Pegasus 之前，**能力档位**就说得出这个格式会丢掉哪两样：简介里的**单个换行**折成空格（只有空行分隔的段落往返得回来），以及简介开头的**前导空白**（含全角空格）被掐掉。

中文离线源产出的简介两样都带——开头两个全角空格是那份数据源的常态。眼下导出再读回来，排版悄悄变了，而用户会以为是刮削出了问题。

**不改 Pegasus 的读写。** 这两样是这个格式自己的天花板：读那一侧把续行折成空格、只有 `.` 是段落分隔；前导空白与续行缩进在这个格式里长得一模一样，分不开。ADR-0003 定的能力档位本来就是"导出前就知道这个格式会丢掉什么"——这一票补的是**它说不说得出**。

**Blocked by:** 无 —— 可立即开工

**Status:** done

### Q26 — Pegasus 存不下单个换行，这件事还没由能力档位说出口

- **来自：** 票 `offline-chinese-fields/03` 的 Q22 裁决（协调者）
- **类别：** 规格没说
- **在哪：** `crates/core/src/adapter/pegasus.rs` 的 `write_attribute` 与 `joined`、
  `crates/core/src/capability.rs`（能力档位那一套）
- **为什么没停线：** Q22 的修复已经让写出来的文件**读得回来**了，这一条是它的残留：
  简介里单个 `\n` 读回来是一个空格，只有空行分隔的段落往返得回来。中文离线源的简介
  两种换行都有，所以真库上会有一批条目的简介往返一趟变了形。
- **这张票实际做了什么：** 只把它记准，没动能力档位。ADR-0003 说的正是「每个适配器
  标着能力档位：导出前就知道这个格式会丢掉什么」——单个换行折成空格该在那张表上有名字，
  而不是让用户自己发现。
- **谁来裁：** 拿主意的人（够单开一张小票；也可以并进票 06「报告说实话」那一趟，
  它本来就在改「这个格式补不上什么」的措辞）
- **状态：** resolved
- **收尾裁决：** **由本票接着做** —— 它就是从这条挂单立起来的。

### Q32 — Pegasus 往返会吃掉简介开头那两个全角空格，`trim_start` 把 U+3000 也当空白

- **来自：** 票 `offline-chinese-fields/04`（`/code-review` 的产出）

- **在哪：** `crates/core/src/adapter/pegasus.rs` 的 `classify`（约 385 行）里那句
