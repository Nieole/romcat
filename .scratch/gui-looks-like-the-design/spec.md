# 界面照设计稿落地

**Status:** ready-for-agent
**Opened:** 2026-09-13
**判据：** 设计稿 `.scratch/gui-looks-like-the-design/prototype.html`（第四稿）与令牌
`.scratch/gui-looks-like-the-design/tokens.toml`；ADR-0023（**自足**的判据）、ADR-0005
（界面只是窗口壳）、ADR-0024（一个判断只有一处实现）、ADR-0016（容量超限只给建议）、
ADR-0017（能力档案与文件系统上限）、ADR-0007（ScreenScraper 配额）
**材料：** 设计稿（六屏 + 开场 + 全部对话框，离线可用）、`before/` 现状截图、
`check_tokens.py`（当前 65 项一致）、2026-09-13 的裁定（设计稿说明区「已裁定」一节）

## Problem Statement

**界面每张票都验收通过了，成品还是难看，而且仍然把人赶回终端。**

维护者打开程序，看见的是与设计稿几乎无关的另一个东西：

- **观感从来没进过验收。** `gui-redesign` 的规格写着「凡是原型与本规格文字冲突的地方，
  以文字为准——原型不是实现的依据」，唯一管版式的那张票的八条验收里没有一条是
  「长得像设计稿」。于是配色是 egui 默认暗色主题，字体只有一份 7.3 MB 的常规体——
  屏上没有粗体、路径与容量不等宽，整屏看不出层次。
- **版式从「一张表当主角」散成了好几块面板抢地方。** 顶栏把导航与四五个动作挤在一排，
  右边还挂着「内存里 26 行、读库 4 次」这种调试数；主区域底下叠三层，作品表只剩十几行。
- **写给开发者看的话漏到了屏上。** 「上下两半之间是『且』……全部下推到中立库」
  「（ADR-0012）」照原样印着，markdown 的 `**` 也原样印了出来。
- **示例数据是理想化的。** 设计稿从前只画干净的作品名，真库里 46,444 个变体有 16,716 个
  没挂上作品，屏上是一串相对路径；实现只好直接印路径。
- **还有一批「就在这台机器上、就现在、就这一份库」的事，界面上没有落点**——按 ADR-0023
  的判据，每一处都是缺陷而不是取舍：数据源优先级、库体检与它的后续动作（平台纠正、
  成型纠正、重复拷贝）、合集、条件组筛选、手动例外、导出撞上外部修改后的「照写」、
  移除根、设置（工作目录、配额、ffmpeg）、导入已有的 Pegasus / ES-DE 元数据。

设计稿第四稿把这些全部画完了，并且只用 egui 画得出来的东西。**现在缺的是把它落地，
并且守住**——不守住的话，下一轮仍旧是每张票都绿、整体还是丑。

## Solution

**把设计稿定为验收基准，分三层把门；照稿把六屏重排一遍，并把稿子里那些新面接到
已有的核心库能力上。**

1. **参数层，机器全查。** 颜色、字号、间距、圆角、版式尺寸写进一份**令牌**数据文件，
   放在 `crates/gui` 里（数据不是代码，同 `platforms.toml` / `profiles.toml` /
   `priorities.toml` 一条纪律）。egui 的两套 `Visuals` 从它取值，设计稿那份
   `check_tokens.py` 也读它——两边没法各改各的。
2. **结构与文案层，机器全查。** 用现有的那条接缝（不开窗跑一帧 + 读这一帧**真画出来的
   字**）钉住：导航在左栏、刮削面板默认收起、工序六行、置信度四档逐字一致、屏上不出现
   `**` 与 `ADR-`、认不出作品的那一行长什么样。
3. **像素层，人批一次、之后机器守。** 用 egui_kittest 的截图比对，每屏一张基线，
   第一版由拿主意的人对着设计稿点头，之后任何像素变化都让门禁红。
4. **照稿重排六屏**（库 / 待确认 / 浏览 / 子库 / 任务 / 设置）与开场、新手引导、
   作品详情页、全部对话框。
5. **把设计稿里的新面接上核心库已有的能力**：规则与维度（`sublibrary::rule`）、
   例外与容量建议（`sublibrary`）、合集（`collection`）、库体检（`report` 的 JSON）、
   成型纠正（`shape` 的 overrides）、优先级（`scrape::priority`）、匹配裁决
   （`scrape::zh`）、能力档案（`capability`）。界面只画和转发，一条领域判断都不新写。

**字体预算（2026-09-13 裁定）：只再打包一份拉丁与数字的粗体与一份拉丁等宽体，中文一律
常规字重。** 中文的层次改由字号、颜色与间距承担；设计稿已经按这个结果画（CJK 强制常规
字重），所以稿子上看到的就是落地后该有的样子。

## User Stories

### 观感与版式

1. 作为库主，我想让界面的配色、字号、圆角与间距与设计稿一致，这样我第一眼就能认出这是同一个工具。
2. 作为库主，我想在浅色与深色两套主题下都得到同样的层次，这样换系统主题不会让某些字变得看不清。
3. 作为库主，我想让导航固定在左栏、六个入口各带一个计数，这样我知道每一屏还有多少事。
4. 作为库主，我想让浏览屏是「左筛选 / 中表格 / 右详情」三栏，这样表格是主角而不是被挤在中间的一条缝。
5. 作为库主，我想把左栏、筛选栏、详情栏和库屏的各个分块折叠起来，这样小屏上也有干活的地方。
6. 作为库主，我想让折叠状态、面板宽度和视图选择下次打开还记得，这样我不用每次重新调。
7. 作为库主，我想让刮削面板默认收起、点了才弹出来，这样它不占着表格的位置。
8. 作为库主，我想让数字（数量、容量、时间）用等宽字体对齐，这样一列数字扫一眼就能比大小。
9. 作为库主，我想让标题只在拉丁字母与数字上加粗、中文靠字号与颜色分层，这样程序不必为一份中文粗体多背 7 MB。
10. 作为库主，我想让置信度既有颜色也有文字，这样色觉障碍下我照样读得出是哪一档。
11. 作为库主，我想让窗口标题写明打开的是哪一份主库、看的是哪一屏，这样多开窗口时我分得清。
12. 作为库主，我想让每一屏在没有内容时给出空态和明确的下一步，而不是一片空白或一堆示例设备。

### 文案

13. 作为库主，我想让按钮上写的是动词（添加主库、打开、在文件系统中打开），这样我知道点下去会发生什么。
14. 作为库主，我不想在界面上看到写给开发者的解释、ADR 编号和 `**`，这样屏上的每一句都是我用得上的。
15. 作为库主，我想让收场的四档在界面与命令行是同一套词（完成 / 已取消 / 部分完成 / 失败），这样两边说的是同一件事。
16. 作为库主，我想让工序叫「整理标题」而不是「折标题」，这样它与文档里的说法一致。
17. 作为库主，我想在跨平台的界面上看到「在文件系统中打开」而不是「在访达中显示」，这样在 Windows 上这句话也成立。

### 库屏与工序

18. 作为库主，我想在库屏看到完整的六行工序（扫描、识别、刮削、整理标题、裁决、导出），这样我知道整条路有多长、我走到哪儿了。
19. 作为库主，我想让每一行工序报出「还差多少」，这样我知道这一步值不值得现在做。
20. 作为库主，我想在顶部看到一行「下一步：……」并直接点按钮跑，这样我不用自己判断先做哪个。
21. 作为库主，我想在根的列表里看到每个根的路径、变体数与上次扫描时间，这样我知道哪块盘还没扫。
22. 作为库主，我想移除一个根，并被明确告知这会从库里去掉多少变体、多少作品会消失、子库会少多少，这样我不会误删。
23. 作为库主，我想知道移除根之后裁决、收藏与合集还在，这样我敢做这件事。
24. 作为库主，我想在数据源那一块看到 DAT 仓库、中文离线源、Switch 数据库的状态与更新时间，并能直接下载或更新。
25. 作为库主，我想在缺少前置条件时（例如还没下数据源就点识别）只看到一句提示和去处，而不是任务历史里多一条失败任务。

### 待确认

26. 作为库主，我想让能整批处理的批排在前面，并写明这一批的共同判定依据，这样我知道自己在为什么背书。
27. 作为库主，我想在一批里按目录、按候选作品或按命名规律下钻，因为坏的那几条往往集中在某一处。
28. 作为库主，我想在任意一层整批通过或整批拒绝，自己决定下钻到多细。
29. 作为库主，我想在处理掉一部分之后，仍能对这一批剩下的部分整批处理，并看到剩多少。
30. 作为库主，我想在每一批上看到随机样本并能换一组，这样我不是闭着眼按。
31. 作为库主，我想在裁决记录里撤销任意一批，被后来的批盖住时给我说清是哪一批盖的。
32. 作为库主，我想在逐条模式下用键盘走完（左右切候选、Y 通过、N 都不对、空格先放着、U 撤销）。
33. 作为库主，我想看到中文离线源同一次匹配带来的全部字段与依据，一次裁决管住全部，这样我不必逐个字段判断。
34. 作为库主，我想知道匹配裁决不在按批撤销那条路上，改主意时再裁一次即可，这样我不会找不到撤销按钮就慌。
35. 作为库主，我想在识别跑完后知道有几条候选来自库里已经问过的模型答案、这一趟一个请求都没发。

### 浏览与筛选

36. 作为库主，我想按平台、中文身份、识别结论、收藏与合集筛选，并看到每个分面的数量。
37. 作为库主，我想用可嵌套的条件组筛（全部满足 / 任一满足 / 都不满足），并用九个运算符里的任意一个。
38. 作为库主，我想在填错时当场看到哪一条子句不成立（年份不是四位数、体积没写单位、平台名不认识），这样我不用等筛完才发现。
39. 作为库主，我想随时看到当前筛选写成规则是什么样子，这样我知道存成子库会得到什么。
40. 作为库主，我想知道「识别结论」这类只用于浏览的分面不会写进规则，这样我不会以为它进了子库。
41. 作为库主，我想按作品名、平台、变体数、容量、年份排序，年份未知的永远排在最后。
42. 作为库主，我想在表格与卡片两种视图之间切换，卡片上看到封面、名称、平台、年份、变体数与中文身份。
43. 作为库主，我想在没有封面时看到一张有平台色和标题的字卡，而不是灰色占位块。
44. 作为库主，我想选择在列表每行开头显示封面缩略图。
45. 作为库主，我想看到认不出作品的那一行如实显示正题与从尾部截断的路径，这样我知道它还没挂上作品。
46. 作为库主，我想右键一行拿到常用动作（打开详情、勾选、收藏、加入合集、加入子库、合并、刮削、在文件系统中打开、复制名称）。
47. 作为库主，我想用键盘走浏览屏（上下选、Enter 打开、空格勾选、⌘/Ctrl+A 全选筛选结果、F 收藏、E 编辑元数据）。
48. 作为库主，我想用 ⌘/Ctrl+1–6 切屏、⌘/Ctrl+F 搜索、⌘/Ctrl+, 打开设置、`?` 看快捷键表。

### 收藏与合集

49. 作为库主，我想把一批作品收进自己起名的合集，并按合集筛选。
50. 作为库主，我想给合集改名、删除合集（就是把成员全部移出），并在作品详情里把一个作品移出某个合集。
51. 作为库主，我想在收藏挂不住内容锚时（无判据那一档）被明确标出来，这样我不会以为改名之后它还在。

### 作品详情与元数据

52. 作为库主，我想在作品详情页看到概览、变体与文件、元数据、标题、媒体、识别依据六个面。
53. 作为库主，我想看到每个字段当前用的是哪个数据源的值，并能一键改用另一个来源的值。
54. 作为库主，我想手动改写任意字段，并知道它记为裁决、重新刮削不会被覆盖。
55. 作为库主，我想管理标题集合（添加名称、隐藏某个名称、恢复），并看到显示标题与排序标题是怎么选出来的。
56. 作为库主，我想在没有 ffmpeg 的机器上照常使用，视频显示为占位图标并说明原因，而不是报错。
57. 作为库主，我想把某个变体设为首选变体，并知道这记为裁决。

### 合并作品与移出

58. 作为库主，我想把被识别成两个作品、其实是同一个游戏的东西合并到一起，选一个保留、其余的名字留作别名。
59. 作为库主，我想在合并前核对每个变体要不要归入，并为每个平台各定一个首选变体。
60. 作为库主，我想在合并前只看有冲突的字段并逐项选值，这样我不用重看全部元数据。
61. 作为库主，我想在合并前看清会发生什么（写几条裁决、前端条目从多少变多少、子库要重新生成差量预览），并能整批撤销。
62. 作为库主，我想在系统认为两个作品可能是同一个时得到提示与理由，也能说「不是同一个」让它以后不再提示。
63. 作为库主，我想把一个变体从作品里移出，放到新建的作品或另一个已有作品，这是合并的反向操作。

### 子库

64. 作为库主，我想新建子库并设置名称、目标路径、前端格式、能力档案与容量上限，路径不合适时当场告诉我原因。
65. 作为库主，我想看到能力档案对这个子库涉及的每个平台各声明了什么（设备直接能用什么、不能用时转成什么），并能按平台覆盖。
66. 作为库主，我想让一个子库的选择集由多条规则取并集组成，按平台分几次加入。
67. 作为库主，我想在加入前看到会新增多少变体、与已有规则重复多少、加入后占多少容量。
68. 作为库主，我想编辑或移除某一条规则，并能撤销。
69. 作为库主，我想管理手动例外（包含与排除），并知道例外优先于规则、永久记住。
70. 作为库主，我想在容量超限时看到一张删减建议表：每项释放多少、累计多少、排除到哪一项就放得下、全排除也还差多少。
71. 作为库主，我想在同步前看到差量预览：新增、删除、保留各多少，以及异常项分类（设备上缺失、被修改过、目标位置被占用、放不进目标）。
72. 作为库主，我想决定要不要补回设备上缺失的文件，默认不补。
73. 作为库主，我想在落点撞车时看到撞的是哪两份，并排除其中一份让另一份正常复制。
74. 作为库主，我想在设备没连上时也能算出已选容量，并知道「清单外文件」是未知而不是零。
75. 作为库主，我想删除一个子库，并知道设备上已同步的文件不会被删除。

### 任务

76. 作为库主，我想看到正在跑的任务、等待中的队列和历史，历史里写明四档收场。
77. 作为库主，我想随时停下一趟任务，并知道停下后保留了什么、下次从哪儿继续。
78. 作为库主，我想在任务跑着的时候照常用其他屏。

### 导出

79. 作为库主，我想在导出撞上「外面有人动过那几份文件」时被逐份点名，并看到它们是什么时候、被怎么改过的。
80. 作为库主，我想在看过之后按一下「我看过了，照写」就重排一趟带覆盖的导出，而不必回终端。
81. 作为库主，我想让那颗「照写」每次都要当场点、不记成偏好，这样我不会哪天顺手覆盖掉自己的手改。
82. 作为库主，我想让停下的那一趟不打「上次导出」的时刻戳，这样工序那一行不会骗我。

### 库体检与纠正

83. 作为库主，我想在库屏看到一份体检报告的概要（重复拷贝、目录与内容平台不符、成型存疑、不可读、未纳入管理的目录、附属文件落单、非游戏资产、疑似同一作品），每一格点进去看明细。
84. 作为库主，我想看到重复拷贝按可腾出的空间排序、每组列出全部路径，并知道工具绝不自动删除。
85. 作为库主，我想把体检明细导出成清单，拿到别处处理。
86. 作为库主，我想处理「目录说的平台和文件内容不符」，按组决定是按内容改还是保持目录的说法，并知道这记为裁决、不移动任何文件。
87. 作为库主，我想纠正成型出错的地方（多碟没合在一起、一个目录被当成一个变体），并知道人工纠正永久保留、可撤销。
88. 作为库主，我想知道未纳入管理的目录有哪些、各有多少文件，作为整理的依据。

### 设置

89. 作为库主，我想在一个设置页里找到主题、启动行为、工作目录与媒体池、数据源与更新、ScreenScraper 账号与配额、刮削与导出的默认值、ffmpeg 路径、快捷键与关于。
90. 作为库主，我想看到 ScreenScraper 的配额用了多少，并被提醒未识别 ROM 配额撞穿会连账号带 IP 一起封禁。
91. 作为库主，我想调整数据源优先级：按字段排，裁决固定第一，手工维护的元数据固定在所有数据源之前，其余可上下移。
92. 作为库主，我想在保存优先级前看到「哪些作品的显示值会变、变成什么」，并知道这不需要重新刮削。
93. 作为库主，我想知道街机的标题另有一套顺序，并能单独编辑它。

### 导入

94. 作为库主，我想把自己多年手工维护的 Pegasus 元数据与 ES-DE 的 gamelist 一次性导进库里。
95. 作为库主，我想在导入前看到会读哪几份文件、按路径对得上多少条、对不上多少条，并知道对不上的不会靠名字猜。
96. 作为库主，我想知道导入的值排在裁决之后、所有数据源之前，之后的刮削不会覆盖它们。
97. 作为库主，我想知道前端里的游玩记录与收藏不会被导入、也不会被覆盖。

### 验收

98. 作为拿主意的人，我想让颜色与尺寸只有一份来源，两边偏离时门禁当场红。
99. 作为拿主意的人，我想让「屏上不许出现 `**` 与 ADR- 编号」这类规矩由测试守着，而不是靠人复查。
100. 作为拿主意的人，我想在第一次对着设计稿点头之后，任何像素变化都要有人显式更新基线，这样观感不会再悄悄漂走。

## Implementation Decisions

### 一、令牌：颜色与尺寸只有一份来源

- **`crates/gui/src/tokens.toml`**（数据不是代码，与 `platforms.toml` / `profiles.toml` /
  `priorities.toml` 同一条纪律，`include_str!` 进二进制）。内容照设计稿目录那一份搬：
  两套主题的颜色、平台色、字号六档、间距档位、圆角三档、版式尺寸（左栏宽、窄条宽、
  筛选栏宽、详情栏宽、行高、色条宽、缩略图、对话框四档宽度）、字体预算。
- **`look` 从它取值装两套 `Visuals`**，装的地方仍旧是现在这一处（开窗与不开窗跑帧走
  同一句）。**界面里不许再出现第二处写死的颜色**：置信度四档的颜色已经收在 `look`，
  平台色、面板底色、描边一起收进来。
- **设计稿那份 `check_tokens.py` 改成读 `crates/gui/src/tokens.toml`**，设计稿目录里
  不再留第二份令牌。
- 令牌里的**字号与圆角**是 egui `Style` 的输入；间距档位是约定（版式里只用这几档），
  由代码走查而不是测试守。

### 二、字体预算

- 现有的 `NotoSansSC-Subset.ttf`（常规体，22,534 个码位）**不动**。
- 新增两份小子集：**拉丁与数字的粗体**、**拉丁等宽体**。两份都只含 ASCII + 常用标点 +
  数字，各自几百 KB 量级；仍旧由 `tools/font-subset.py` 那条路产出，同样的输入产出
  同样的字节。
- **粗体族里只放拉丁粗体**，中文回退到常规体；**关掉字重合成**，否则 egui 会画出假粗体，
  屏上就与设计稿不一致了。
- 等宽只用于路径、哈希、序列号、数量与容量；中文落回常规体（等宽族里同样不放中文）。

### 三、结构与文案

- **六屏 + 开场**：库、待确认、浏览、子库、任务、设置。设置是新的一屏（不是对话框），
  与其他屏同级，走同一套「哪一屏可见」的开关。
- **左栏导航**：六个入口各带计数徽标，底部是新手引导入口、已保存裁决数与收起按钮。
  顶栏不再承载导航与动作。
- **刮削改成对话框**，与添加主库向导同一种写法。
- **通用对话框框架**：一个 `Modal` + 一张「种类 → 画法 / 动作」的分发表，全部弹层
  （子库目标设置、例外、合集、优先级、导出照写、移除根、成型、平台纠正、体检明细、
  导入、快捷键、删除确认、移出此作品）走同一套；宽度只取令牌里的四档。
- **认不出作品的那一行**：主栏显示**正题**（从文件名剥掉汉化组、版本号等标记后的名字）
  并挂一个「未关联作品」标签，副行显示**从尾部截断**的相对路径（测量宽度后从左侧删字
  补「…」）。这条是「原型没画过、实现只好直接印路径」那处缺口的正解。
- **文案清理**：屏上不出现 `**`、`ADR-`、模块名与写给开发者的解释。旧说法逐处改成词表
  的词——认领新主库 → 添加主库；折标题 → 整理标题；按停了 → 已取消；停在半路 →
  部分完成。四档收场的落字处只有一处（`Ending::render`），界面与命令行都读它。
- **工序六行**：扫描、识别、刮削、整理标题、裁决、导出。每行报「还差多少」；算不出的
  那两支（整理标题、导出）退回显示上次跑的时刻，词表**工序**那一条已经写明这条退路。
- **操作被拒不记为失败任务**：前置条件不满足时只给一句提示 + 去处，任务历史只记录
  真正跑过的任务。
- **非游戏资产默认不列出**，浏览屏一个开关可以显示；导出行为不变（永不导出）。

### 四、把设计稿的新面接到已有核心能力上（界面只画和转发）

| 界面上的面 | 吃的核心库能力 | 备注 |
|---|---|---|
| 条件组编辑器 | `sublibrary::rule` 的**维度 / 子句 / 组 / 连接** | 十三个维度、九个运算符、三种连接全部照 `Dimension` / `Op` 摆；**解析与判断不在界面里重写一遍**，界面只组装再交回去 |
| 子库目标设置 | `capability`（预置档案 × 文件系统）、`sublibrary::Sublibrary::at` | 平台矩阵与文件系统上限逐条展示，含来源与核实日期；超过 180 天标成陈旧 |
| 手动例外 | 选择集里的例外那一半 | 例外优先于规则，永久记住 |
| 容量与删减建议 | `sublibrary::over_capacity`、`trim_suggestions`、容量条三段 | 只给建议，绝不自动删减（ADR-0016） |
| 差量预览与异常项 | `sync` 的三方对比结果 | 「放不进目标」一栏含**落点撞车**、超单文件上限、文件名不收的字符（词表已把它们归一栏） |
| 合集与收藏 | `collection`（`add` / `remove` / `standing` / `project`） | 成员锚在内容锚上；挂不住内容锚的要在屏上标出来 |
| 合并作品 / 移出此作品 | 一批**裁决**，每条是「手工指定作品」 | 与待确认里那一种同一种裁决，因此走既有的按批撤销；发行版信息不动 |
| 数据源优先级 | `scrape::priority`（`order` / `rank` / 平台覆盖） | 裁决固定第一，`Pegasus` / `ES-Gamelist` 固定在全部数据源之前；街机的标题另有一份顺序 |
| 库体检 | `report` 的 JSON 形态（它本来就是给界面吃的） | 八格概要 + 明细；重复拷贝走 `DuplicateDetails` |
| 成型纠正 | `shape::reshape` 与它的 overrides | 多碟合成一个变体、目录拆成多个变体；人工纠正是一等公民、永久保留 |
| 同一次匹配 | `scrape::zh::matched_groups` / `judge` | 已接在逐条那一屏；这一轮把**依据**与条目号照设计稿重排，不改行为 |
| 缓存命中报数 | 中立库里已经问过的模型答案折成候选 | 报告里说得出「有几条来自已经问过的答案」，一个请求都不发 |
| 导入 Pegasus / ES-Gamelist | `adapter` 那一侧的导入 | 按路径对应；对不上的进导入报告，不按名字猜；不导入前端里的用户状态 |
| 导出「照写」 | 导出本来就一份一份写、每份存底本 | 「哪几份被动过」是白拿的，不新造比对机制 |
| 移除根 | 根与变体的键（根名 + 相对路径） | 界面负责把「会去掉多少」说清楚 |

**需要核心库新长出来的只有三处**，各自单独一张票，不与观感票混：

1. **「疑似同一作品」的判断**（ADR-0024：只能有一处实现）。判据来自设计稿里已经写出的
   三类线索：不同数据库对同一部作品的命名差异、平台与年份一致、中文离线源里两个名字
   指向同一条条目。**阈值与判据由核心库定，界面只展示理由并发起合并。**
2. **优先级的写回**：`Priorities` 眼下只读得进来（`load` / `builtin_text`），界面上改完
   要写回工作目录的 `priorities.toml`，需要一个「导出成文本」的出口。
3. **平台纠正落成什么**：目录与内容不符的清单已经在扫描的聚合里（`PlatformConflict`），
   缺的是「按内容改」落成一条什么样的裁决、下一趟识别怎么读它。

**明确暂缓（2026-09-13 裁定）**：合并向导里的「以后扫描到的也自动归入」需要在**沉淀库**
新增一条作品级的「A 与 B 是同一作品」记录。这一轮**不做**，界面上那个勾选框画成不可选
并写明原因与眼下的走法（再合并一次）。

### 五、排期形状

- **第一张票先打通整条路**：令牌文件 + 两份小字体 + 三层门的骨架 + **最小的一屏**
  （建议开场或库屏）完整落地，并由拿主意的人批下第一版截图基线。
- 其余每屏一张票，都排在第一张之后。
- **文案清理单开一张，不依赖别的票**，现在就能做。
- 新功能面按「吃哪块核心能力」分票，一票一面；需要核心库新能力的那三处各自先行。

## Testing Decisions

**什么算好测试：断言的是这一帧真画出来的东西与真实交互的结果，不是内部结构。**
这一仓已经有这条纪律的先例，继续照它写：

- **`crates/gui/tests/shared::画出来的字`** ——从 `FullOutput` 里收 `Galley`，一段一行。
  「屏上摆得出来」「屏上写的是同一个词」「屏上没了」这三类断言只认它。
- **`crates/gui/tests/layout.rs`** ——真的按下去、拖过去、松手，再问面板多宽、问工作目录
  里那个数落在哪儿。版式那几条照它写。
- **`crates/gui/tests/queue.rs`** ——一屏摆不下时**真发滚轮事件**滚一趟再断言（挂单
  `Q169`）。新面里凡是内容比一屏长的（体检明细、优先级、平台纠正）都照它办。
- **合成数据照真库的形状**：`demo` 那一份的规模引 `docs/library-facts.md`，认不出作品的
  那一行、BIOS 那几行、一万八千条的待确认队列都要在合成数据里存在——**设计稿这一轮的
  教训之一就是理想化数据**。

三层门各自的测试位置：

1. **参数层（新，一条）**：`look` 里一条单元测试，读 `tokens.toml`，把两套 `Visuals`
   与令牌**逐项**比对（颜色、圆角、字号）。变异实测：改令牌里任意一个颜色，这条当场红。
   设计稿那一侧由 `check_tokens.py` 比对同一份文件（当前 65 项一致）。
2. **结构与文案层（沿用现有接缝，不新开）**：每屏一份测试文件（已有 `browse` / `queue` /
   `table` / `task` / `roots` / `sublibrary` / `layout` / `media`，新增 `stages` /
   `settings` 之类跟着屏走）。至少钉住：导航在左栏且六项齐；刮削面板默认不显示；
   工序六行且每行报得出数；置信度四档在两屏上逐字一致且每处上色都跟着词；
   屏上不出现 `**` 与 `ADR-`；认不出作品的那一行显示正题与截断后的路径；空态那一句在。
3. **像素层（新，一条）**：`crates/gui/tests/snapshot.rs`，egui_kittest 0.36.1 的
   `snapshot` + `wgpu`，以合成数据在固定视口渲染每屏一张 PNG 存成基线。
   - **两件事要先定**：CI 上没有显卡，用软件渲染（lavapipe / llvmpipe）；不同平台渲染
     有细微差别，因此**定一台出基线的机器**并定一个比对阈值。
   - 基线**第一版由拿主意的人对着设计稿点头**；之后更新基线必须显式提交，差异摆在提交里。
4. **核心库那一侧**：新长出来的三处（疑似同一作品的判断、优先级写回、平台纠正的裁决形状）
   各自在核心库里测，界面只测「画出来了、按下去转给了它」。ADR-0005：界面里不许出现
   第二处领域判断——这条本身也用测试钉（新面的测试里断言界面调的是核心库那个函数的结果）。

**门禁**：`cargo clippy --workspace --all-targets --all-features` 与
`cargo test --workspace --all-features`。界面那七个测试目标要 `--features demo` 才编译，
门禁一律带 `--all-features`。截图那条按上面定的机器与阈值跑。

**每张票收尾附对照图**：用 egui MCP 起程序截同一屏，与设计稿对应屏并排放进票里。

## Out of Scope

- **「以后扫描到的也自动归入」**：需要沉淀库新增作品级记录（2026-09-13 裁定暂缓）。
- **换渲染器**（Slint / Tauri）：等 `rom-metadata-automation/23`（Windows 输入法真机验证）
  出结果再谈；这份规格假定留在 egui 上。
- **评分这一维**：写得出规则，眼下没有源，界面只如实说明。
- **前端里的用户状态**（游玩次数、时长、通关、前端自己的收藏）：只搬运，不生成不覆盖，
  这一轮不给任何编辑入口。
- **主库的写操作**：ADR-0004，界面上不提供任何改动 ROM 的入口；库体检发现重复拷贝也
  只报告。
- **联网刮削的新能力**：ScreenScraper 只按现有配置走，设置页不新增登录流程之外的东西。
- **设计稿里的示例数据本身**（作品名、封面、数字）：那是稿子的道具，不进实现。
- **在线分享裁决记录**（设计稿里那颗「导出裁决记录…」只画到「选保存位置」为止）。

## Further Notes

- **排期：不再有前置的闸门。** `rom-metadata-automation/23`（Windows 输入法真机验证）
  **已于 2026-09-13 验过、通过**，界面层留在 egui（ADR-0005 的实机验证结果一节）。

  5.33 TiB、18,241 条待确认），但**不是**用户当前库的实时数据。
