# 24 — 差量预览里的异常项与落点撞车

**What to build:** 维护者在同步前看到**差量预览**：新增、删除、保留各多少，以及处理不了的
那几类分栏列出来——设备上缺失、被修改过、目标位置被占用、**放不进目标**。他能决定要不要
补回缺失的文件，也能在**落点撞车**时排除其中一份让另一份正常复制。

**Blocked by:** 20

**Status:** done

⚠️ **差量预览是同步的前置条件，不是可选功能**（词表）。生成预览只读，不写任何文件。

⚠️ **撞上的一个都不放行**（词表**落点撞车**）：放行其中一个等于由排序决定谁留下，
下一趟排序变了赢家就换人。「放不进目标」一栏同时收超过单文件上限与文件名不收的字符。

- [x] 三方对比的数字齐（新增 / 删除 / **不动** / 异常 / 放不进目标）
  - **照稿一排五个大数字方块**（拿主意的人 2026-09-21 裁，挂单 `Q1020`：「五个大数字 + 底下一行
    小字补齐」）。**第三格屏上写「不动」不写「保留」**（同日裁，挂单 `Q1026`）：「保留」在这个
    仓库里已经被占了两次——[[合并作品]]的「选一个保留」与票 `28` 平台纠正的「保持目录的说法」
    ——三处并着叫，下一个人必然并回去。词表补了**不动**与**异常**两条；前两处一个字没碰。
    证据：`crates/gui/tests/sublibrary.rs::三方对比照稿一排五个大数字_新增删除不动异常与放不进目标`——
    五格逐格断言那个大数字与它底下那行小字都画在屏上（新增 `＋N · 新增 · <多大>`、
    删除 `－N · 删除 · 释放 <多大>`、`不动 · <多大>`、`异常 · 不处理`、放不进目标）；
    再断**加得起来**这条规矩：
    五个栏名后面那几个数，头四个加起来等于「异常」那一格，末一个等于「放不进目标」那一格。
  - **小字那一行把表上才有的两样补齐**，都画在屏上、**不塞进悬停**（截图门看不到悬停，等于没有）：
    - **更新**那一档——「其中 N 个是重传已有的那一份（…），没算进上面的新增」。
      **绝不并进新增那个大数字**：并了的话，屏上那个「新增」就含着一批其实是重传已有那一份的文件，
      而人照它去估这一趟要往卡上写多少全新的东西。`更新那一档不并进新增_小字里单说一句`
      **反向钉住**——屏上有「＋新增」那个数，**没有**「＋(新增+更新)」那个数。
    - **每一类涉及几个变体**——「按变体数：新增 N 个、…」。词表里人认得的单位是变体，
      而五个大数字数的都是文件。
    - **零的那几档不写空话**（照票 `26` 的裁定）：更新是零就不提更新，变体数只写非零的那几档；
      断言钉着这份夹具里删除是零、屏上就没有「删除 0 个」。
  - **「异常」那一格不给容量**：这几条各占各的地方——没了的在卡上一个字节都不占，落点被占那几个
    占着地方的是别人的文件——凑一个总数出来不对应卡上任何一件事（照稿写「异常 · 不处理」）。
  - 变体数与放不进目标那一格的账都由核心答（`Plan::surprise_variants` / `Plan::rejected_tally`）：
    界面自己再数一遍的话，命令行与 `--json` 里永远没有这两个数，只有界面有
    （ADR-0024，收尾审查 Standards 轴 M1 挑出）。
  - 版式照 `.diff` 立成三个令牌（`size-diff-value` 15、`diff-tile-padding` [8,10]、`diff-gap` 8），
    `check_tokens.py` 绿。**小字换行不截断**：卡片在两栏版式里只有半屏宽，一格摊到九十点上下，
    「新增 · 220.72 MiB」一行放不下——稿里 `.diff small` 本来就是会换行的行内文字；
    五格先量一遍取最高的那一个、小字框一律照它，底边才齐。
- [x] 四类异常分栏列出，每一类写明工具**不会**做什么（不覆盖、不删除）
  - 证据：`crates/gui/tests/sublibrary.rs::四类异常分栏列出_每一栏写明工具不会做什么`——五个栏名
    都在（一栏一栏走 `SurpriseKind::all()`），逐栏切过去断言屏上含那一栏的 `refusal()` 原话；
    空着的那一栏写「没有 X 的。」。核心侧
    `crates/core/src/sync.rs::每一类对不上的事都说得出屏上叫什么_以及工具不会做什么` 逐类断各自
    该说的那件事（Gone 含「默认不补」、Changed 含「不覆盖」「不删除」、Occupied 含「一律不碰」、
    Unreadable 含「一律不动」）。
  - **那句话与屏上那一栏的名字都由核心一处答**（`SurpriseKind::shown` / `refusal`，走
    `Exception::shown` 那条成例）；**命令行逐类印的是同一份**（`sync/report.rs` 那个循环）。
  - ⚠️ 摆的是**五**栏，稿与票面写的是四类：多出来的是 `SurpriseKind::Unreadable`（**元数据读不到**，
    ADR-0021 的第三态）。漏掉它的话，屏上那个「异常」总数里含着它们而四栏加起来少一截，
    人对不上账（挂单 `Q1021`）。
- [x] 设备上缺失的可以选择补回，**默认不补**
  - 证据：`crates/gui/tests/sublibrary.rs::设备上缺失的可以选择补回_默认不补_勾上之后那几个才进计划`——
    进场 `restore_missing()` 是 `false`、计划里一条 `step.restore` 都没有；屏上那一格写着
    「同步时补回这 1 个文件」与「只补清单里记录过的文件」；勾上重排之后那一条进计划、路径对得上，
    **照旧留在「设备上缺失」那一栏里**（补回不是把它从异常里抹掉，那才是静默补回）；取消再排又没了。
  - **补回补的是两批**，核心一处答（`Plan::restorable`）：这一趟才发现没了的，与上一趟就记着不补的
    （`Plan::withheld`，刻意不进对不上的那一堆）。落点上有东西挡着的那几个不算——补回不是覆盖
    别人的许可。`同步过一趟之后那几个还缺着_补回那一格照旧摆得出而且数得对` 钉住：同步一趟之后
    那一栏空了，那一格照旧画得出、数是 1，屏上还把「你删过、工具记着不补」那一批说出口。
    （**改之前红**：拿那一栏的条数当「补回会补几个」，数说少了；同步过一趟之后那一格整个不画，
    人在界面上再也补不回来——收尾审查 Standards 轴 H1 挑出。）
- [x] 落点撞车列出撞的是哪两份，排除其中一份后另一份正常复制，排除记为手动例外
  - 证据：`crates/gui/tests/sublibrary.rs::落点撞车列出撞的是哪两份_排除其中一份之后另一份正常复制`——
    两个根造出一处撞车，屏上整行画出 `库/SFC/幻想传说 汉化版.zip` 与
    `另一块盘/SFC/幻想传说 汉化版.zip` 两条**主库侧完整的键**（落点剥掉了根名，不带根名两行长得
    一模一样，挂单 `Q57`），撞上几份就摆几颗「排除这一份」；屏上写着「撞上的一个都不放行」。
    按下去之后库里多一条 `Exception::Exclude`、备注正是「落点撞车，保留另一份」、**卡上目录树逐
    文件一个字节不差**（ADR-0004、ADR-0015），那份差量当场作废；重排一趟之后不撞了，剩下那一份
    进了计划。
  - 归堆在核心一处（`Plan::collisions`，按折起来的落点归、按主库侧那条键排），**命令行与界面配出来
    的对子是同一批**（`sync/report.rs` 也改成按处印）；`Rejected` 新加 `source` 与 `only_folded`
    两格——后者在判出来那一刻记下，不事后从路径文本反推（`align` 之后会翻，收尾审查 Standards 轴
    M4 挑出）。核心侧 `撞在一起的归成一处_每一份带着主库侧那条完整的键`、
    `只差大小写撞上的那一处_说得出是只差大小写`。
  - **前端元数据那一行不摆按钮**：它挂在一个记号名下、不是变体，记不成例外（ADR-0016）——按下去
    会往库里写一条排不掉的脏例外。那一问收成核心 `sync::is_variant`，与裁剪建议那一侧同一处
    （票 20 已经在那条路上挡过一次，ADR-0024；收尾审查 Spec 轴 M1 挑出），
    `前端元数据不是变体_记不成例外` 钉住。
- [x] 放不进目标一栏含撞车、超单文件上限、文件名不收的字符三种
  - 证据：`crates/gui/tests/sublibrary.rs::放不进目标一栏含撞车超单文件上限与文件名不收的字符三种`——
    三个小标题都在（`RejectReason::{Collision,TooBig,BadName}.label()`），整栏那句说明逐字照稿；
    **零也一直摆着**（不说的话，人分不出「查过、没有」与「压根没查」）。
  - 撞车那一段写「**N 份，撞成 M 处**」并断言它与栏上那个数加得起来：只写「M 处」的话，栏上那个
    数按份、栏里那几个数按处，两个数写成同一个形状却加不起来（收尾审查 Spec 轴 H1 挑出）。
  - 每一类**该去哪儿办**由核心答（`RejectReason::advice`），命令行与界面印同一份；
    **一条都没有时不说**——目标本来就是 exFAT 时，在「超过单文件上限 · 0」底下劝人换一张 exFAT
    的卡是句蠢话（Spec 轴 M3 挑出）。核心侧
    `放不进目标那几类都说得出该去哪儿办_撞车那一类不在这儿说`。
- [x] 选择集改动后预览失效；同步按钮在没有有效预览时按不下去
  - 证据：后半截是新的——`crates/gui/tests/sublibrary.rs::没有有效预览时同步按不下去_屏上说清为什么`：
    点屏上正好写着「同步」那一处，**摊开的还是「掌机」**（按得动的话那一下会先把另一台摊开再去
    同步），没留错、没排出同步趟；屏上写着「同步前需要先生成差量预览」；走 `Screen::sync` 同样被拦
    并留一句「还没排过差量预览」；排一趟之后按得动、真跑得起来。
  - 实现是 `actions_ui` 里新加的「手上有没有这一台的一份有效预览」那道闸，加
    `on_disabled_hover_text` 把按不动的理由说出口（票 `07`：拒绝要说清为什么、去哪儿办）。
    **作废预览的每一条路都走 `Screen::invalidate`**，于是这一格跟着当场变灰，不必各处记得去关它。
  - 前半截既有测试钉着，本票没动那条路：`改过选择那份预览当场作废`、`改过例外之后差量预览作废并说明`、
    `保存目标设置之后已有的差量预览作废_提示条写差量预览已失效`、
    `别处改过选择集之后这一屏缓着的差量与容量账当场作废`。
- [x] 「装不装得下」与子库屏说的是同一个数（`one-criterion-per-thing/01` 那个底），两处不许各算一份
  - 证据：`crates/gui/tests/sublibrary.rs::装不装得下与容量条说的是同一个数_两处都照那份计划`——
    `gauge.taken() == plan.after_bytes`、`gauge.strangers == Some(plan.stranger_bytes)`、

    之后就是同底），本票只把它钉住——没有这条钉，哪天有人在这一屏上另算一份，门禁不会红。
