# 24 — 差量预览里的异常项与落点撞车

**What to build:** 维护者在同步前看到**差量预览**：新增、删除、保留各多少，以及处理不了的
那几类分栏列出来——设备上缺失、被修改过、目标位置被占用、**放不进目标**。他能决定要不要
补回缺失的文件，也能在**落点撞车**时排除其中一份让另一份正常复制。

**Blocked by:** 20

**Status:** done

⚠️ **差量预览是同步的前置条件，不是可选功能**（词表）。生成预览只读，不写任何文件。

⚠️ **撞上的一个都不放行**（词表**落点撞车**）：放行其中一个等于由排序决定谁留下，
下一趟排序变了赢家就换人。「放不进目标」一栏同时收超过单文件上限与文件名不收的字符。

- [x] 三方对比的数字齐（新增 / 删除 / **不动** / 异常 / 放不进目标）
  - **照稿一排五个大数字方块**（拿主意的人 2026-09-21 裁，挂单 `Q1020`：「五个大数字 + 底下一行
    小字补齐」）。**第三格屏上写「不动」不写「保留」**（同日裁，挂单 `Q1026`）：「保留」在这个
    仓库里已经被占了两次——[[合并作品]]的「选一个保留」与票 `28` 平台纠正的「保持目录的说法」
    ——三处并着叫，下一个人必然并回去。词表补了**不动**与**异常**两条；前两处一个字没碰。
    证据：`crates/gui/tests/sublibrary.rs::三方对比照稿一排五个大数字_新增删除不动异常与放不进目标`——
    五格逐格断言那个大数字与它底下那行小字都画在屏上（新增 `＋N · 新增 · <多大>`、
    删除 `－N · 删除 · 释放 <多大>`、`不动 · <多大>`、`异常 · 不处理`、放不进目标）；
    再断**加得起来**这条规矩：
    五个栏名后面那几个数，头四个加起来等于「异常」那一格，末一个等于「放不进目标」那一格。
  - **小字那一行把表上才有的两样补齐**，都画在屏上、**不塞进悬停**（截图门看不到悬停，等于没有）：
    - **更新**那一档——「其中 N 个是重传已有的那一份（…），没算进上面的新增」。
      **绝不并进新增那个大数字**：并了的话，屏上那个「新增」就含着一批其实是重传已有那一份的文件，
      而人照它去估这一趟要往卡上写多少全新的东西。`更新那一档不并进新增_小字里单说一句`
      **反向钉住**——屏上有「＋新增」那个数，**没有**「＋(新增+更新)」那个数。
    - **每一类涉及几个变体**——「按变体数：新增 N 个、…」。词表里人认得的单位是变体，
      而五个大数字数的都是文件。
    - **零的那几档不写空话**（照票 `26` 的裁定）：更新是零就不提更新，变体数只写非零的那几档；
      断言钉着这份夹具里删除是零、屏上就没有「删除 0 个」。
  - **「异常」那一格不给容量**：这几条各占各的地方——没了的在卡上一个字节都不占，落点被占那几个
    占着地方的是别人的文件——凑一个总数出来不对应卡上任何一件事（照稿写「异常 · 不处理」）。
  - 变体数与放不进目标那一格的账都由核心答（`Plan::surprise_variants` / `Plan::rejected_tally`）：
    界面自己再数一遍的话，命令行与 `--json` 里永远没有这两个数，只有界面有
    （ADR-0024，收尾审查 Standards 轴 M1 挑出）。
  - 版式照 `.diff` 立成三个令牌（`size-diff-value` 15、`diff-tile-padding` [8,10]、`diff-gap` 8），
    `check_tokens.py` 绿。**五格等宽等高、上下缘齐，而且是构造上的**：一格一个定死的矩形
    （宽由容器五等分、高五格共用一个，都不由内容说了算），`Screen::diff_tiles` 把这几个矩形
    交出去，测试逐格断上缘、下缘、宽三样（拿矩形断，不比像素）。
  - **小字折行只落在字段与字段之间**：一格摊到九十点上下，「新增 · 220.72 MiB」一行放不下，
    而一整串交给 egui 去折，它在中日韩字之间随处都断得下去。小字因此写成几个**不可断的字段**
    （标签、释放、多大），每一行自己 `layout_no_wrap`。**稿上那个「·」要么五格都有、要么
    五格都没有**：只有一格摆得下就它一个带点，一排看着参差。
    断言挂在规矩上：每个字段都得**连在一起**出现在某一行上（折断了就没有哪一行还连着写得出它）。
    - ⚠️ **这一段是打回重做的**（拿主意的人 2026-09-21 看合并向导那几张图时立的新要求：
      「排版也要调整一下，至少要对齐文字」）。头两版的毛病：截断成「新增 · 69…」；
      换行之后折出「新增 · 690」＋「**B**」（数值与单位分了家）与「异常 · 不处」＋「**理**」
      （词被拦腰切断）；五格各随内容伸缩，宽 80–100 点不等，只有一行小字的那一格矮了近二十点。
- [x] 四类异常分栏列出，每一类写明工具**不会**做什么（不覆盖、不删除）
  - 证据：`crates/gui/tests/sublibrary.rs::四类异常分栏列出_每一栏写明工具不会做什么`——五个栏名
    都在（一栏一栏走 `SurpriseKind::all()`），逐栏切过去断言屏上含那一栏的 `refusal()` 原话；
    空着的那一栏写「没有 X 的。」。核心侧
    `crates/core/src/sync.rs::每一类对不上的事都说得出屏上叫什么_以及工具不会做什么` 逐类断各自
    该说的那件事（Gone 含「默认不补」、Changed 含「不覆盖」「不删除」、Occupied 含「一律不碰」、
    Unreadable 含「一律不动」）。
  - **那句话与屏上那一栏的名字都由核心一处答**（`SurpriseKind::shown` / `refusal`，走
    `Exception::shown` 那条成例）；**命令行逐类印的是同一份**（`sync/report.rs` 那个循环）。
  - ⚠️ 摆的是**五**栏，稿与票面写的是四类：多出来的是 `SurpriseKind::Unreadable`（**元数据读不到**，

    **照旧留在「设备上缺失」那一栏里**（补回不是把它从异常里抹掉，那才是静默补回）；取消再排又没了。
  - **补回补的是两批**，核心一处答（`Plan::restorable`）：这一趟才发现没了的，与上一趟就记着不补的

    别人的许可。`同步过一趟之后那几个还缺着_补回那一格照旧摆得出而且数得对` 钉住：同步一趟之后
    那一栏空了，那一格照旧画得出、数是 1，屏上还把「你删过、工具记着不补」那一批说出口。
    （**改之前红**：拿那一栏的条数当「补回会补几个」，数说少了；同步过一趟之后那一格整个不画，
    人在界面上再也补不回来——收尾审查 Standards 轴 H1 挑出。）
- [x] 落点撞车列出撞的是哪两份，排除其中一份后另一份正常复制，排除记为手动例外

- **裁决（第五轮收口，2026-09-23）：** **记** —— 已裁五个大数字并已落地。已落地：票 gui-looks-like-the-design/24（sublibrary.rs tally_ui）

- **在哪：** `crates/gui/src/sublibrary.rs` 的 `tally_ui`。设计稿 `diffHTML` 那一排是 `.diff`：五个格子，
  每格一个大数字加一行小字（`+87 / 新增 · 220.72 MiB`、`−30 / 删除 · 释放 120.00 MiB`、`800 / 保留`、

  这一屏的别处（容量条图例）已经是小字横排，一排大数字会是这一屏上唯一的那种块头。
- **谁来裁：** 拿主意的人
- **状态：** **closed（2026-09-21 裁了）**——原话：「**五个大数字 + 底下一行小字补齐**」。
  落成：五格照稿（新增 / 删除 / 保留 / 异常 / 放不进目标，每格一个**文件数**加一行小字，
  版式、内边距、圆角、字号都照 `.diff` 立成令牌 `size-diff-value` / `diff-tile-padding` / `diff-gap`）；

  「新增 · 220.72 MiB」这类小字在一行里放不下——**照稿让它换行**（稿里 `.diff small` 本来就是
  会换行的行内文字），五格先量一遍取最高的那一个、小字框一律照它，底边才齐。
  头一版没换行、走的截断，出来是「新增 · 69…」，那一格等于什么都没说，自审时打回重做。

### Q1080 — `.rs` 的文档注释里不许写词表那个 `[[词]]`：rustdoc 会读成 intra-doc link，门禁当场红

- **裁决（第五轮收口，2026-09-23）：** **记** —— 已定成规矩并塞进 brief。已落地：编排者 brief（门禁 doc 步 -D warnings 兜底）

- **来自：** 票 `gui-looks-like-the-design/24`（编排者 2026-09-21 另划一个号，从 `Q1029` 拆出来）
- **类别：** 规矩（**已定**）
- **在哪：** 任何 `.rs` 的文档注释（`///` / `//!`）。`[[词]]` 是 `CONTEXT.md` 引词表的写法，
  **只在那份文件里成立**。写进 Rust 文档注释，rustdoc 把它读成 intra-doc link，找不到那个项
  就报「unresolved link to 合并作品」；而门禁 `doc` 那一步带 `RUSTDOCFLAGS="-D warnings"`，
  于是**当场红**。
- **为什么记：** 它是**可复现的规则，不是一次性失误**——谁在 Rust 文档里引词表的词都会撞上。
  本票 2026-09-21 真撞了一次：门禁六步里五步绿、`doc` 一条红（日志
  `/Users/nicoer/dev/game-wt/logs/slot-3-gl24-gate2.log`），白跑了一趟十几分钟的全量门禁。
- **这张票实际做了什么：** 改在提交 `cb01705`——散文里要引词表的词，照旧写「合并作品」就是；
  真要在文档里链到代码，用 Rust 自己那套单方括号的写法（一对方括号里包一个反引号括起的项名）。
- **怎么防：** 门禁 `doc` 那一步本来就拦得住（`-D warnings`），代价只是撞上的人白跑一趟全量门禁。
  真嫌贵的那一天，`xtask` 那一侧加一条只扫 `.rs` 里 `///` / `//!` 有没有 `[[` 的快检，
  排在 `glossary` 旁边——那一步零点几秒，撞上的人不必等到 `doc`。
- **谁来裁：** 编排者
- **状态：** **已定成规矩**（编排者 2026-09-21）：已塞进新派出去的 brief；这一条留给以后翻账的人。
