## 阈值是什么（核心库定的那一句）

**平台得有交集**（硬条件），而且**至少有一条立得了案的线索**：

| 线索 | 立得了案吗 | 为什么 |
|---|---|---|
| 命名撞上（两边各有一个叫法，`zh::key_of` 归一之后是同一串字） | 立得了 | 两个数据库对同一部作品的命名差异，识别因此建成了两个作品 |
| 同一条中文条目（两边的名字在中文离线源里指向同一条） | 立得了 | 那是「这两个名字是同一部作品的两种叫法」的直接证据 |
| 平台与年份一致 | **立不了** | 同一年同一平台的游戏成百上千；只当佐证 |

**名字那一条只认「归一之后一字不差」，不按相似度**：库里现成的 `zh::similarity` 在这一层会把
同系列的两部作品配成一对（`超级机器人大战J` 与 `R` 是 0.88）。中文离线源那一侧撞错了，代价是
人在队列里多看一眼；这一层给的建议**人是要按下去合并的**，撞错就是把两部游戏并成一个。
两边名字确实不一样的那一类（TOSEC 的 `Pocket Monster - Red Version` 与 No-Intro 的
`Pocket Monsters - Aka`）交给中文条目那一条去连——设计稿举的正是这一例。

## 复用而不是另起一套（ADR-0024）

| 要的东西 | 从哪一处取 |
|---|---|
| 名字归一与相似度 | `zh::key_of` / `zh::similarity` / `zh::alnum_of` |
| 这个锚点撞上了哪条中文条目 | `zh::entry_in` + `scrape::zh` 那组源名；新的 `scrape::zh::entry_marks` 只是 `matched_groups` 的全库那一份 |
| 一个作品有哪些叫法（**DAT 条目名本来就在里面**） | `title::work_titles`（`title::fold` 把自动通过的候选那条条目名折成官方名称，源就是那个数据库的名字） |
| 一个作品屏上写着的年份 | `Catalog::work_year_of`；那句 SQL 收进了 `scraped_year` 一处，与主列表那一列、详情面板那一格同一个取法 |
| 屏上那个作品叫什么 | `title::choose`（挑显示标题那一处） |
| 「那个作品还剩几个变体」「怎么合」 | 票 16 的 `triage::merge` 一族，一个字没改 |
