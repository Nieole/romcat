# 05 — 开场照设计稿落地，并立起截图门

**What to build:** 维护者第一次打开程序，看到的开场与设计稿一致：左边一句话讲清工具做
什么加三条承诺，右边只有一个主要操作；添加主库仍是三步向导，点「开始扫描」之前一个
文件都不写。这一屏同时成为**截图门**的第一张基线——之后谁改动了一个像素，门禁就红。

**Blocked by:** 01（令牌）、02（字体）、03（文案）、04（弹层写法）；
目录选择器复用 `gui-answers-all-six/01`；开场那一屏另有三张票在动，见下面的排波约束。

**Status:** ready-for-agent

⚠️ **弹层照票 04 那一套**，向导不自己写一份。

⚠️ **开场这一屏同时有四张票在动，本票排最后**：`no-mute-spots-opening-a-catalog/01`
（`主库标识` / `主库原名` 跨三个 crate 机械改名 59 处，含开场与向导的调用点，它自己写明是
prefactor）→ `/03`（建库变成显式动作，改向导落盘那一段）→ `/04`（列举说得出「为什么用不了」，
改开场空态分支与向导的写入前置告知）→ 本票重排。**先重排再被改名，等于白排一次。**

⚠️ **两句话不许在重排时改写**：`no-mute-spots-opening-a-catalog/04` 的硬约束点名
「结构版本对不上」那句原话不动；空态也不再是「有 / 没有」两态，要照它的**三态**画
（有库 / 空的 / 目录读不动），向导里还多一句「目录写不动」。设计稿的版式套在这三态上，
不是把它们压回一句。

⚠️ **选目录不自己写第二条路**：`gui-answers-all-six/01` 已经把「弹一下、交回可空路径」
收成一层薄封装，并硬约束不许再加第二条处理路径的实现。这两张票动的是**同一处向导代码**，
不许排进同一波——先做 `gui-answers-all-six/01`，本票在它之上重排。

⚠️ **截图门有两件事要先定并写进票里**：CI 上没有显卡，用软件渲染；不同平台渲染有细微
差别，因此定**一台出基线的机器**与一个比对阈值。
