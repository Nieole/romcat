# 22 — 手动例外：包含与排除

**What to build:** 维护者管理一个子库的**例外**：规则没选中也要带上的（包含）、规则选中了
也不带的（排除）。屏上写明例外**优先于规则**、**永久记住**，每一条都能撤销。

**Blocked by:** 20

**Status:** done

⚠️ 容量超限时删减建议里的「排除」、差量预览里**落点撞车**时的「排除这一份」，落的都是
这里的例外——不是第二套机制。

- [x] 包含与排除两栏，逐条显示作品、平台、体积、备注与时间
  - 证据：`crates/gui/tests/sublibrary.rs::手动例外两栏逐条写作品平台体积备注与时间_每条都撤得掉`——卡上例外那一行右边照稿一颗「管理」（**没有例外时也摆**），按下去开出弹层；包含那一栏上表头六列齐（作品 / 平台 / 体积 / 备注 / 时间 / 撤销），逐格读得出作品名、`GBA`、从 fixture 盘上量出来的字节数、那句备注；换到排除那一栏，另一条才在、这一条不串栏。
  - 两栏那一排摆在**标题说明与分隔线之间**（`Dialog::head`，照稿 `DLG.excl` 的 `head`），走共用的 `look::segmented`，栏名后面跟着这一栏几条。
  - **一行是一个变体不是一个作品**：例外落在变体这一层（ADR-0016、F2）。主栏写**屏上叫什么**（`ExceptionDetail::display`：认出作品的是显示标题、认不出的是那个变体的**正题**——两样都由核心一处答，与浏览屏主列表同一支，ADR-0024），副行一律写变体的键。
  - 库里眼下没有那个变体（盘没插、目录改了名）时体积写「—」并在悬停里说清，**不写 0**；那一问由核心答（`ExceptionDetail::missing`）。核心侧 `crates/core/tests/sublibrary.rs::例外那张表逐条写得出作品平台体积与备注_库里没有那个变体的照旧在` 钉住逐格与次序（「时刻倒着排、同一刻按键排」，断言挂在规矩上而不是「第几条是谁」）。
- [x] 搜索作品直接添加为包含或排除；同一个作品从一栏换到另一栏时不会留下两条
  - 证据：`crates/gui/tests/sublibrary.rs::搜作品直接加成包含或排除_同一个作品换一栏不留两条`——搜「传说」找着那个作品，加进包含栏后库里**两条**（它底下两个变体各一条）、备注跟着记上；换到排除栏再加一次，**还是两条、方向全换过去**，不是四条。核心侧 `一个作品整批记成例外_从一栏换到另一栏不留两条` 同形。
  - 整批写在一个事务里（`Catalog::set_exceptions`）；`set_exception` 改成拿一个键调它，于是**全仓只有一条 upsert**——「不留两条」是那条 `ON CONFLICT … DO UPDATE` 的事，不是界面去重出来的。
  - 作用范围靠核心展开（`Catalog::scoped_variants`，与浏览屏批量操作同一处）：屏上那一行写着几个变体，按下去就记几条。
  - 那一行末尾「现在是哪一栏」**按身份认**（`Who`：认出作品比 `work` 表那个名字、认不出比变体的键），不拿屏上那串字比——`work` 表的 `name` 上刻意没有 `UNIQUE`，同名异作是真实存在的。**整份都在一向时才写「现在是「X」」**，只覆盖一部分就如实写「底下已经记着 N 条例外」。
  - 加完把搜索框与备注**清空**（照稿 `st.q=''; st.note=''`）：备注是**这一条**的「为什么」，留着下一次会默默带上上一条那句。
- [x] 每条都能撤销，撤销后合计与容量条跟着变
  - 证据：`crates/gui/tests/sublibrary.rs::撤掉一条例外之后合计与容量条跟着变`——三个变体的子库上记一条排除，`picked` 3→2、`bytes` 少掉那一份，卡上「合计 2 个变体 · …」跟着变；在弹层里按撤销之后库里那一条没了、`picked` 回到 3、`bytes` 回到原数、卡上那一行写回「没有手动例外」。
  - 收尾三样一起办（`Screen::after_exception_changed`）：缓着的差量与容量账作废、当场重排一趟「算一遍容量」、弹层里那张表重读。**盘上的文件一个字节都不动**（ADR-0004、ADR-0015）。
- [x] 屏上写明例外优先于规则并永久记住
  - 证据：`crates/gui/tests/sublibrary.rs::手动例外弹层上写明优先于规则并永久记住`——弹层说明那一句逐字在屏上：「例外优先于规则，并且永久记住。「包含」是规则没选中也要带上的，「排除」是规则选中了也不带的。」ADR-0016 那句话得在屏上，不只在文档里。
- [x] 修改例外后差量预览失效并说明
  - 证据：`crates/gui/tests/sublibrary.rs::改过例外之后差量预览作废并说明`——排过一趟差量，在弹层里加一条例外之后 `prepared` 没了，屏上有「差量预览已失效」；页脚那句「修改例外后，同步前需要重新生成差量预览。」**一直摆着**（`Dialog::footer_note`，照稿摆在页脚左边），不等人真改了才冒。
  - **两条路都走同一支**：删减建议表上的「排除」（`Screen::exclude`）原先自己抄了一遍收尾，于是这条硬要求在两条路上不一样——那一条静静把预览作废、那句话不说。收尾审查 Spec 轴挑出，已改成调 `after_exception_changed`（也是 ADR-0024 意义上的第二份实现）。
- [x] 没有例外时是空态，写明从哪儿加
  - 证据：`crates/gui/tests/sublibrary.rs::没有例外时两栏各是空态并写明从哪儿加`——两栏各自的空态都在，且空着时不画表身（屏上一个「撤销」都没有）。
  - **排除那一栏逐字照稿**（它指的两条路眼下都有）。**包含那一栏这一版不照稿**，理由与何时换回见下面「岔路口的裁决」F3，票 `23` 票面里也留了触发点。

- **在哪：** `crates/gui/src/sublibrary.rs` 的 `exception_table_ui`（一行一颗「撤销」）与 `Screen::undo_exception`（`Catalog::clear_exception`，一次一个变体的键）；加进来那一侧是 `Screen::add_exception` → `Catalog::set_exceptions`（一个作品底下那几个变体**整批**记上）。

- **这张票实际做了什么：** 逐行撤（编排者 2026-09-20 定「先这样」）。例外照旧落在**变体**这一层（ADR-0016、F2 选 (a)）——这一条问的不是存成什么，只是屏上那一下的粒度。

- **建议留：** 另一条路的前者，与票 23「加入子库」对话框一起做——那一屏正是整批加的入口，两处的粒度一起定才不会又错开。

#### 票 `23` 的「加入」那一侧定成了什么样（2026-09-22 回填）

建议里那句「两处的粒度一起定」要的对照在这儿。票 `23` 那一层的**加入侧**是：

- **入口**：表格上方那一条最右那颗「加入子库…」，或右键菜单里同名那一项。
- **粒度**：一次一批，**批是「勾中的那几个作品底下的全部变体」**
  （`Catalog::scoped_variants` 按当前筛选摊开），走
  `Catalog::set_exceptions(..., Exception::Include, None)` —— **一个事务整批落**。
  也就是说加进来的仍旧是**变体**那一层的行（ADR-0016 没动），
  只是一下子记 N 条。
- **回执**：「「X」收入了 N 个变体（手动例外，不随筛选条件变）。」**报的是真落了几条**
  （`set_exceptions` 交回的行数），不是计划数。
- **撤销**：**加入这一侧眼下没有撤销**。票 `23` 做的撤销是**移除一条规则**那一条
  （验收第 7 条，`take_rule` / `restore_rule` ＋ 提示条），与例外无关。
