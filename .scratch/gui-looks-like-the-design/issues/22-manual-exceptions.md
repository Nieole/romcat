# 22 — 手动例外：包含与排除

**What to build:** 维护者管理一个子库的**例外**：规则没选中也要带上的（包含）、规则选中了
也不带的（排除）。屏上写明例外**优先于规则**、**永久记住**，每一条都能撤销。

**Blocked by:** 20

**Status:** done

⚠️ 容量超限时删减建议里的「排除」、差量预览里**落点撞车**时的「排除这一份」，落的都是
这里的例外——不是第二套机制。

- [x] 包含与排除两栏，逐条显示作品、平台、体积、备注与时间
  - 证据：`crates/gui/tests/sublibrary.rs::手动例外两栏逐条写作品平台体积备注与时间_每条都撤得掉`——卡上例外那一行右边照稿一颗「管理」（**没有例外时也摆**），按下去开出弹层；包含那一栏上表头六列齐（作品 / 平台 / 体积 / 备注 / 时间 / 撤销），逐格读得出作品名、`GBA`、从 fixture 盘上量出来的字节数、那句备注；换到排除那一栏，另一条才在、这一条不串栏。
  - 两栏那一排摆在**标题说明与分隔线之间**（`Dialog::head`，照稿 `DLG.excl` 的 `head`），走共用的 `look::segmented`，栏名后面跟着这一栏几条。
  - **一行是一个变体不是一个作品**：例外落在变体这一层（ADR-0016、F2）。主栏写**屏上叫什么**（`ExceptionDetail::display`：认出作品的是显示标题、认不出的是那个变体的**正题**——两样都由核心一处答，与浏览屏主列表同一支，ADR-0024），副行一律写变体的键。
  - 库里眼下没有那个变体（盘没插、目录改了名）时体积写「—」并在悬停里说清，**不写 0**；那一问由核心答（`ExceptionDetail::missing`）。核心侧 `crates/core/tests/sublibrary.rs::例外那张表逐条写得出作品平台体积与备注_库里没有那个变体的照旧在` 钉住逐格与次序（「时刻倒着排、同一刻按键排」，断言挂在规矩上而不是「第几条是谁」）。
- [x] 搜索作品直接添加为包含或排除；同一个作品从一栏换到另一栏时不会留下两条
  - 证据：`crates/gui/tests/sublibrary.rs::搜作品直接加成包含或排除_同一个作品换一栏不留两条`——搜「传说」找着那个作品，加进包含栏后库里**两条**（它底下两个变体各一条）、备注跟着记上；换到排除栏再加一次，**还是两条、方向全换过去**，不是四条。核心侧 `一个作品整批记成例外_从一栏换到另一栏不留两条` 同形。
  - 整批写在一个事务里（`Catalog::set_exceptions`）；`set_exception` 改成拿一个键调它，于是**全仓只有一条 upsert**——「不留两条」是那条 `ON CONFLICT … DO UPDATE` 的事，不是界面去重出来的。
  - 作用范围靠核心展开（`Catalog::scoped_variants`，与浏览屏批量操作同一处）：屏上那一行写着几个变体，按下去就记几条。
  - 那一行末尾「现在是哪一栏」**按身份认**（`Who`：认出作品比 `work` 表那个名字、认不出比变体的键），不拿屏上那串字比——`work` 表的 `name` 上刻意没有 `UNIQUE`，同名异作是真实存在的。**整份都在一向时才写「现在是「X」」**，只覆盖一部分就如实写「底下已经记着 N 条例外」。
  - 加完把搜索框与备注**清空**（照稿 `st.q=''; st.note=''`）：备注是**这一条**的「为什么」，留着下一次会默默带上上一条那句。
- [x] 每条都能撤销，撤销后合计与容量条跟着变
  - 证据：`crates/gui/tests/sublibrary.rs::撤掉一条例外之后合计与容量条跟着变`——三个变体的子库上记一条排除，`picked` 3→2、`bytes` 少掉那一份，卡上「合计 2 个变体 · …」跟着变；在弹层里按撤销之后库里那一条没了、`picked` 回到 3、`bytes` 回到原数、卡上那一行写回「没有手动例外」。
  - 收尾三样一起办（`Screen::after_exception_changed`）：缓着的差量与容量账作废、当场重排一趟「算一遍容量」、弹层里那张表重读。**盘上的文件一个字节都不动**（ADR-0004、ADR-0015）。
- [x] 屏上写明例外优先于规则并永久记住
  - 证据：`crates/gui/tests/sublibrary.rs::手动例外弹层上写明优先于规则并永久记住`——弹层说明那一句逐字在屏上：「例外优先于规则，并且永久记住。「包含」是规则没选中也要带上的，「排除」是规则选中了也不带的。」ADR-0016 那句话得在屏上，不只在文档里。
- [x] 修改例外后差量预览失效并说明
  - 证据：`crates/gui/tests/sublibrary.rs::改过例外之后差量预览作废并说明`——排过一趟差量，在弹层里加一条例外之后 `prepared` 没了，屏上有「差量预览已失效」；页脚那句「修改例外后，同步前需要重新生成差量预览。」**一直摆着**（`Dialog::footer_note`，照稿摆在页脚左边），不等人真改了才冒。
  - **两条路都走同一支**：删减建议表上的「排除」（`Screen::exclude`）原先自己抄了一遍收尾，于是这条硬要求在两条路上不一样——那一条静静把预览作废、那句话不说。收尾审查 Spec 轴挑出，已改成调 `after_exception_changed`（也是 ADR-0024 意义上的第二份实现）。
- [x] 没有例外时是空态，写明从哪儿加
  - 证据：`crates/gui/tests/sublibrary.rs::没有例外时两栏各是空态并写明从哪儿加`——两栏各自的空态都在，且空着时不画表身（屏上一个「撤销」都没有）。
  - **排除那一栏逐字照稿**（它指的两条路眼下都有）。**包含那一栏这一版不照稿**，理由与何时换回见下面「岔路口的裁决」F3，票 `23` 票面里也留了触发点。

收挂单 `Q818`：例外的显示词在子库屏与浏览屏一起定——核心 `Exception::label` 写「收入」，设计稿与本票写「包含」。

## 岔路口的裁决

编排者 2026-09-20 定：

- **F2 例外落在哪一层 —— 选 (a)：变体。** 屏上搜的是**作品**（人记得住的是作品名），按下去把
  它底下**每个变体各记一条**（`Catalog::set_exceptions`，一个事务）。稿上把一次加进来的一个作品
  画成一条（「N 个变体」），我们不那么存——那等于给同一件事造第二套机制，正是票面 ⚠️ 要防的。
  代价：撤销是**逐个变体**撤，不是一下撤掉整个作品（稿上也是逐行撤）。**先这样**，要「整组撤」
  记在挂单 `Q973`。
- **F3 空态那句话 —— 选 (a)：照实写眼下走得通的路，不照稿。**
  稿上写的是「在浏览中勾选作品，『加入子库…』时选『只加入勾选的作品』」，而**那个对话框是票 23，
  眼下还不存在**——照稿写等于在空态上指一条按不着的路，而空态的全部价值就是告诉人下一步去哪儿。
  所以包含那一栏写的是「还没有手动包含的内容。在下面搜作品直接添加；也可以在浏览屏的详情面板里
  对着某一份按『包含它』」。排除那一栏照稿原样（它指的「容量超限时删减建议里的『排除』」已经有了）。
  **什么时候换回去：票 23 的「加入子库…」对话框落地之后**，把包含那一栏的空态换成稿上那句，
  并重出这一对截图基线。
- **`Q950` 不在这张票里做**（那两处在目标设置弹层，是票 21 的面，一并做要重出它刚被点头的六张基线），
  编排者另开票收。
- **`Q812` 在这张票里收**：子库屏改过例外之后，浏览屏手上缓着的那一份跟着重读。照原挂单的「另一条路」
  做，与 `take_touched` 反向同形。

`Q818`（界面写「包含」还是「收入」）与 `Q975`（共用弹层缺「标头那一排」「页脚说明字」两个槽）
编排者去问拿主意的人，眼下按「界面写包含、库里与命令行照旧收入」与「两样挪进内容区」写着。

拿主意的人 2026-09-20 又裁了两处：

- **F1 `Q818` —— 屏上照稿写「包含」，库里存的值与命令行不动。** 落在核心 `Exception::shown()`
  （`label()` 照旧是存进库、命令行印的那个词），界面两屏一起换；词表**例外**条目补了那一段。
- **F4 / F5 `Q975` —— 给共用弹层加那两个槽，照稿摆。** `Dialog::head`（「包含｜排除」那一排进
  标题说明与分隔线之间）与 `Dialog::footer_note`（「修改例外后…」那句进页脚左边，配
  `Footer::dismiss_on_right`）。**加槽不许改已有弹层的默认行为**：没给槽时画出来与从前一字不差，
  由 `crates/gui/tests/dialog.rs::没给那两个槽的弹层一点地方都不多占_给了才画出来` 钉住，
  另由不带更新跑一趟整份截图门验没用这两个槽的弹层基线一张都没动。

**焦点落在哪一格 —— 保留现在这样**（拿主意的人 2026-09-20 裁）。弹层打开时焦点落进这一层里
头一个接得住焦点的控件（`Dialog::show` 的 `move_focus(Next)`），如今那是「包含」那一格；于是
停在排除栏时，**蓝色焦点圈在「包含」，而选中的是「排除」**（`exceptions-empty-*` 那一对上看得见，
暗色更明显）。为什么不改：这是弹层框架那条既有规矩，不是这一层新写的；**键盘走到哪儿必须看得见**，
把焦点圈摘掉或挪走都是拿无障碍换一眼好看。另两条路（打开时焦点落到选中的那一格、或给 `Dialog`
再加一个「焦点先给谁」的槽）都要动共用件，全窗口的弹层都得重验一遍——为这一处不值。

## 收尾两轴审查（只读）

**Standards 轴两处 ADR-0024、Spec 轴一处硬伤，外加编排者转来的一处，全改在 `0d1c9fe`**：

1. **认不出作品的那一行屏上叫什么**，这一层原先自己答「写变体的键」，而 `WorkRow::name` 的文档
   逐字写着「认不出作品的那一行屏上主栏画的不是它，是 `title()` 那个正题」——同一份未识别内容
   在浏览屏与这一层是两个名字。改成两处都走那一支。
2. **「这一行眼下有没有例外」原先拿屏上那串字比**。`work` 表的 `name` 上刻意没有 `UNIQUE`，
   同名异作是真实存在的。改成按身份比（`Who`），并把话说准：整份都在一向才写「现在是「X」」。
   为此 `ExceptionDetail` 拆成 `work`（身份）与 `display`（屏上的字）——原先第二趟把显示标题
   写回 `work`、身份当场丢掉，那正是这一处的根。
3. **删减建议表上的「排除」没走 `after_exception_changed`**，自己抄了一遍收尾，于是「改过例外
   之后差量预览失效**并说明**」这条硬要求在两条路上不一样。改成调同一支。
4. **`open_exceptions` 优先级表读不动时静默退回内置那份**，而 `stages.rs` 逐字写着「不退回内置
   那份」。改成把那句话摆到屏上、这一层不开（剥离规则同理），配测试
   `优先级表读不动时手动例外那一层不开_屏上说清为什么`。

其余照改：加完清空搜索框与备注（照稿）；排除栏空态逐字照稿；体积那一格改问
`ExceptionDetail::missing()`；弹层收尾不再把 `set_exception_search` 内联一遍；
`set_exceptions` 与 `open_exceptions` 两处文档说准。

审查提的「落点撞车的『排除这一份』没实现」：查过票 `24` 清单第 4 条明写归它，**不属本票**，
⚠️ 那条没被违反。
