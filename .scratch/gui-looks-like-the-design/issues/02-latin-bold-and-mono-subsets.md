**What to build:** 维护者在屏上看得出层次：标题里的拉丁字母与数字是粗的，路径、哈希、
容量与数量等宽对齐、一列数字扫一眼能比大小；中文一律常规字重，程序只多几百 KB。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **裁定（2026-09-13）：不打包中文粗体。** 中文的层次靠字号、颜色与间距，设计稿已经
按这个结果画。

⚠️ **字重合成必须关掉**，否则 egui 会给中文画出假粗体——那正是这条裁定要避免的东西。

- [x] 两份小子集由现有那条子集脚本产出，同样的输入产出同样的字节；许可跟着二进制走

### Q460 — 拉丁两份子集只收拉丁字母、数字与 ASCII 标点，不收规格说的「常用标点」

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 裁定：维持现状：不收常用标点（2026-09-23 拿主意的人）。规格那句已就地改成实际口径。

- **来自：** 票 `gui-looks-like-the-design/02`
- **类别：** 两份东西矛盾
- **在哪：** `tools/font-subset.py` 的 `LATIN_RANGES`；规格「二、字体预算」一节「两份都只含 ASCII + 常用标点 + 数字」，对票的验收「粗体族里只有拉丁与数字」与令牌 `bold-coverage = "latin-digits-only"`
- **为什么没停线：** 改字符集是改一张区段表再重跑脚本，测试里同一张表的谓词（`拉丁那张表里有`）跟着改一处
- **这张票实际做了什么：** 两份都收 U+0020–007E，加 U+00C0–017F 里的字母（跳过 `×` `÷`）；不收 U+00A0–00BF 的 `· ° © ¥ « »`，也不收 U+2000–206F 的 `— … “ ”`——它们在粗体族里回退常规体，在等宽族里先落到 egui 内置的 Hack
- **没走的那条：** 照规格字面把常用标点也收进来，英文标题里的破折号、引号与 `©` 跟着变粗
- **建议留：** 现在这条。中文标题里用的正是这几个标点——本仓库的小节标题满是 `根 · 3 个` 这种分隔号——收进粗体，常规字重的一句中文中间会夹一个半粗的点，那正是「中文不加粗」裁定要避免的观感。带变音符的字母要收，否则 `Pokémon` 在词中间换字重（Noto Sans SC 本身缺 `Č Ł Ř Š Ž` 等扩展 A 字母，那几个照样回退常规体）
- **谁来裁：** 拿主意的人
- **状态：** settled（第五轮收口，2026-09-23，见顶上裁决）
