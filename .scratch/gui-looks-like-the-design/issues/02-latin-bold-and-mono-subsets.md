# 02 — 打包拉丁粗体与拉丁等宽两份子集

**What to build:** 维护者在屏上看得出层次：标题里的拉丁字母与数字是粗的，路径、哈希、
容量与数量等宽对齐、一列数字扫一眼能比大小；中文一律常规字重，程序只多几百 KB。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **裁定（2026-09-13）：不打包中文粗体。** 中文的层次靠字号、颜色与间距，设计稿已经
按这个结果画。

⚠️ **字重合成必须关掉**，否则 egui 会给中文画出假粗体——那正是这条裁定要避免的东西。

- [x] 两份小子集由现有那条子集脚本产出，同样的输入产出同样的字节；许可跟着二进制走
  - `tools/font-subset.py` 加 `--face regular|strong|mono`。
    - 粗体：`NotoSansSC[wght].ttf` 固定在 600，产物 `NotoSansSC-SemiBold-Latin.ttf`
      **28,272 字节 / `4ae719a9…`**。
    - 等宽：`JetBrainsMono[wght].ttf`（Version 2.211）固定在 400，产物 `JetBrainsMono-Latin.ttf`
      **53,512 字节 / `2961f709…`**。
  - 确定性实测（fontTools 4.64.0，2026-09-13）：两份各重跑一遍，SHA-256 逐字节相同；常规体用
    改过的脚本重裁，仍是 `066c7a2b…` / 7,670,804 字节。源与产物的哈希、字节补进了脚本文档那张表。
  - 脚本裁完查 cmap：超出字符集就失败，等宽还要数字同宽。反证实测：拿常规体去过 `strong`
    那道核对，报「混进了字符集之外的 22347 个码位」。
  - 许可跟着二进制走：
    - `crates/gui/assets/OFL-JetBrainsMono.txt` 入库，`font::LICENSES` 用 `include_str!` 一家一份
      嵌进二进制。
    - 字体样张里一家一个折叠块；README「许可」一节已改。
    - 测试 `许可跟着二进制走` 钉着两家的版权行都在。
- [x] 粗体族里只有拉丁与数字，中文回退常规体；屏上没有合成出来的假粗体
  - 粗体族 `FontFamily::Name("strong")` 的回退链是：拉丁粗体 → 整条常规链。子集只收 ASCII
    与带变音符的拉丁字母，`· × ° ©` 这类标点与符号不收（中文标题拿 `·` 当分隔号），见 `Q460`。
  - 测试 `粗体族里只有拉丁与数字`：粗体族里 A–Z、a–z、0–9、`éō` 由粗体子集画，粗体子集带的字
    全在拉丁那张表里。
  - 测试 `粗体族里的中文回退常规体`：`REQUIRED`、整张样张与 `·×÷°©¥«»—…“”` 里，拉丁那张表之外的字
    都落到常规体子集。
  - 测试 `屏上没有合成出来的假粗体`：粗体族与常规族排同一串中文（含 `·` `°`），逐字比图集纹理
    `uv_rect` 与步进，完全相同；反过来比 `FinalFantasy1997`，必须不同，免得这条比较分不出
    两份字体。
    - egui 0.36.1 本来就没有字重合成（`FontId` 上只有一句 `TODO(emilk): weight (bold)`），
      这条测试守的是以后也不许有。
  - 屏上：gui 里 65 处粗体都换成了 `font::strong`（62 处 `ui.strong(` 加 3 处
    `RichText::new(..).strong()`），带拉丁与数字的标题现在拉丁是粗的，强调色照旧，见 `Q463`。
- [x] 等宽只用于路径、哈希、序列号、数量与容量；一列数字对得齐（同宽数字）
  - 入口 `font::mono`。
    - 测试 `等宽族里数字同宽中文回退常规体`：A–Z、a–z、0–9、`-_./\:éō` 由等宽子集画；`0–9` 与
      `W` `i` 在 egui 里一样宽；中文回退常规体。
    - 测试 `入口画出来的字落在对应的字族`：看这一帧真画出来的字，`font::mono` 落在等宽族，
      `font::strong` 落在粗体族。
  - 切到等宽的格：根表的路径 / 变体 / 容量、差量账的文件 / 变体 / 容量、浏览主表的变体 / 容量。
    许可全文原来用 `ui.monospace`，改回常规体——等宽只给上面那几样。
  - **保留**：嵌在一句中文里的数（`根 · {} 个` 这类）与变体详情里的序列号仍是常规体。切它们得把
    一个 label 拆成分段排版，那是照稿重排的活，没有哪张票收了它，见 `Q462`。
- [x] 二进制体积增量量出来写进票里
  - **增量 86,183 字节（84 KB）**，量的是资产，这些字节原样进二进制：
    - 两份子集 28,272 + 53,512 = 81,784（`include_bytes!`）；
    - JetBrains Mono 许可 4,399（`include_str!`）。
  - 规格说「程序只多几百 KB」，测试 `拉丁两份子集在几百千字节以内` 钉了 500 KB 的上界。
  - **保留**：没有量 release 二进制构建前后的差。派单认可按资产字节量增量，量 release 二进制
    要额外占一次宽跑。
- [x] 字体检查那条路照旧跑得过，豆腐块没有多出来
  - `font::missing`（`--font-check` 与字体测试都走它）改成常规、粗体、等宽三个族都问，见 `Q461`。
    - `font_check` 两条照旧通过：库里全能画的通过，`𪚥 한글` 报得出来。
    - `必备字符一个豆腐块都没有`、`字体样张整张都画得出来`、`三个字族里都没有豆腐块` 通过。
  - 顺带修掉一个误报：egui `has_glyph` 会把替换字 `◻` 那份字体画的字报成豆腐块（等宽族里 Hack
    画的 `… — → ∀ ♪`、常规族里 NotoEmoji 画的 `🎮`）。`missing` 绕开了它，测试
    `替换字那份字体画的字不算豆腐块` 钉着；反证表里的 `♥` 就建在这个误报上，已拿掉。
    所以豆腐块只少不多。
  - 定向跑过（`TMPDIR` 指向分大小写的盘）：`romcat-gui` 全部测试文件（`browse` 那条修过后重跑）、
    clippy `--all-targets --all-features`、`RUSTDOCFLAGS="-D warnings"` 的 doc。
