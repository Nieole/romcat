# 20 — 子库屏照稿重排

**What to build:** 维护者在子库屏上一台设备一张卡：目标路径、前端格式与**能力档案**写在
卡头，下面是**选择集**里的每一条**规则**（名称、条件、命中多少、多大）与去重后的合计，
再下面是**容量条**。空间不够时只给删减建议。

**Blocked by:** 01、02、03；「装得下吗」那个数由 `one-criterion-per-thing/01` 改成与同步
计划器同底之后才成立。（截图那一条要等 `05`。）

**Status:** ready-for-agent

⚠️ **容量条三段**（词表）：**选中**（只问中立库，卡不在手边也算得出）、**清单之外**
（要设备在位才知道，没排过差量预览时是「未知」而**不是零**）、**上限**。
超没超不在条子这儿算。

⚠️ **「超没超」只由一处说了算，界面只画**（词表**容量条**）。眼下报告那一侧答的是一个
更好听但不成立的问题，`one-criterion-per-thing/01` 正在把它改成与同步计划器同一个底——
本票画的必须是改过之后那个数，别照旧口径画一遍。

⚠️ **超限只给建议，绝不自动删减**（ADR-0016）：删减建议表要说清每项释放多少、累计多少、
排除到哪一项就放得下、全排除也还差多少。

- [x] 一台设备一张卡，卡头写清路径、前端格式、文件系统与能力档案
  - 证据：`crates/gui/tests/sublibrary.rs::一台设备一张卡_卡头写清路径前端格式文件系统与能力档案`——两台设备挑两份档案（没挑过的走「不作声称」，文件系统「无限制」；另一台 `retroarch-fat32`，文件系统 `FAT32`），读这一帧画出来的字，两行卡头各自同时写着目标路径、`Pegasus`、文件系统与档案名。档案与文件系统由核心名册解（`Roster::find_or_unclaimed`），界面不另判；记着的档案名在名册里查不到时卡头点名说出来（`Roster::find`）。
  - 每张卡都画自己的规则与容量条：`没摊开的那一张也画得出自己的容量条`。差量预览一次只摆摊开那一台，别的卡上留一颗「排差量预览」；票 07 的拒绝在这条新路上照旧生效：`没摊开的卡上按排差量预览_卡不在位时照旧只在屏上说_任务历史不多一条`。
  - ⚠️ 保留：令牌里没有卡片两列门槛、容量条高度这几格，借了弹层宽度档与间距档（`Q813`）。
- [x] 规则列表逐条显示名称、条件、命中数与大小；合计写明去掉了多少重复
  - 证据：`规则列表逐条写名称条件命中数与大小_合计写明去掉了几个规则之间重叠的`——一台两条互相重叠的规则、一台一条：逐条画出「规则 N」、规则原文、「N 个 · 大小」（字节从 fixture 盘上量出来）；合计「合计 3 个变体 · …」与「已去除 2 个被多条规则同时选中的变体」，没重叠的那一台写「规则之间没有重叠」。
  - 逐条大小与重叠数由核心 `sublibrary::select` 数（新加 `Selected::rule_bytes` / `Selected::overlaps`，报告里 `RuleLine::bytes` / `SelectionReport::overlaps`），界面只照写。屏上不说「重复」：那是词表**重复拷贝**的词，话照设计稿。
  - ⚠️ 保留：**名称**眼下是「规则 {序号}」——中立库的规则表没有名字那一列，加列要升结构版本（`Q811`，建议随票 23 的加入对话框一起做）；没按「算一遍容量」之前那几个数写「—」（`Q817`）；例外那一行照核心的词写「收入」（`Q818`，已托票 22）。
- [x] 容量条三段照词表画，「未知」画成未知而不是零
  - 证据：`容量条三段照词表画_没看过目标时清单之外画成未知而不是零`——卡拔下来算一遍容量：图例是「选中 …」「清单之外 未知」「上限 …」，并写明「未知不代表为零」，屏上没有「清单之外 0」；插回去再算一遍，清单之外换成卡上那份存档的大小。**改之前红**（旧图例写的是「清单之外 —（…）」）。
  - 条子总量照核心 `Room::after_bytes`（`one-criterion-per-thing/01` 之后的那个底：目标现占 ＋ 净变化）；原有 `容量条三段各自标得出数`、`容量超限时给裁剪建议但一个都不自动砍掉`、`卡不在手边算得出选中多少_装不装得下如实说算不出` 照旧绿。
  - ⚠️ 保留：「未知」那一段的斜纹是画出来的形状，读字的接缝看不见，由第二段的截图基线守。
- [x] 超限时给出删减建议表（四个数齐），排除记为这个子库的手动例外
  - 证据：`超限时删减建议表四个数齐_排除记为这个子库的手动例外_一个文件都不删`——上限取「同步之后 − 最大那一个」：屏上有「超出容量上限 …」、每一项的释放与累计、「排除到这一项就能放下」紧跟在头一项后面；上限 1 B 时写「全部排除也还差 …」、不说放得下；按头一行「排除」之后，中立库里多一条这个子库的排除例外，主库与卡上目录树逐文件一处不差，当场重算后建议表收掉、手动例外那一行写「排除 1 条」。
  - 「放得下」「还差」由核心 `Room::fits_after` / `Room::short_after_all` 判（ADR-0024），界面只画。计划器的裁剪建议不再列前端元数据（它不是变体，排除不掉）：`crates/core/src/sync.rs::裁剪建议不列前端元数据_它不是变体排除不掉_但照旧占着地方`。
  - ⚠️ 保留：累计腾出是计划器口径下的估计，作品共用的媒体记在头一个变体名下（`Q819`）；排除之后自动重算一遍容量（`Q815`）；浏览屏缓着的那份例外不跟着重读（`Q812`）。
