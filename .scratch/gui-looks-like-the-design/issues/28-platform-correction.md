# 28 — 平台纠正：目录说的与内容不符

**What to build:** 维护者处理「目录说这是 GB、文件内容说这是 GBC」这一类：按组看到有多少条、
凭什么这么判、两条样例，然后决定**按内容改**还是**保持目录的说法**。纠正记为**裁决**，
不移动任何文件；导出与同步按纠正后的平台放置。

**Blocked by:** 27；识别按内容记平台由 `one-criterion-per-thing/03` 提供。

**Status:** done

⚠️ **平台由目录给出，是扫描的输入；但目录只是强先验，文件内容可以推翻它**（词表**平台**）。
这张票要新定的是：「按内容改」落成一条什么形状的裁决、下一趟识别怎么读它——那部分在
**核心库**里定，界面只画和转发。

⚠️ **与 `one-criterion-per-thing/03` 物化的那一列分清楚**：那一列记的是**识别按内容判出来
的**平台，本票落的是**人工纠正**。两者是两回事——**都不许回写「目录声明的平台」那一列**，
否则平台冲突报表就失去对照物，下一次体检也认不出这些条目处理过没有。

⚠️ **有一类改不改都行**：GBC 向下兼容 GB，有意放在 GBC 目录也说得通——屏上要说明白，
并且「保持」也要能记下来，免得每次体检都再问一遍。

- **为什么该并：** 两处回答的是**同一句话**——「这个变体的目录声明与它的内容对不对得上」，
  而这句话的答案与它在哪一层被问无关（ADR-0024 那条判据的原话）。眼下两处各给一个数，
  库体检说 N 条、识别报告说 M 条，读报告的人分不出这是两种毛病还是同一种毛病数了两遍。
  ADR-0024「这不是假想的病」那一节里的 `D123` 正是这一对的上半截。
- **GB↔GBC 今天出不来的原因（两处都明说它不算冲突）：**
  - 第 1 处：`platforms.toml` 里 **GB 与 GBC 故意不填 `扩展名`**，原文写着
    「`.gb` 与 `.gbc` 互相串目录是常态，填了只会把报告淹掉」。没有扩展名，就判不出这一组。
  - 第 2 处：`CONFLICT_FROM` 的文档逐字写着「**判据是家族不是那一个平台**：GB 与 GBC
    共用一份卡带头，一份 CGB 卡躺在 `gb/` 目录里**不是**冲突」。
  - 可**设计稿把它摆成头两组**：`GB → GBC 2,946 条`（CGB 标志 `0xC0`，只能在 GBC 上跑，
    放在 GB 目录会被当成 GB 游戏导出）与 `GBC → GB 1,870 条`（CGB 标志 `0x00`），
    票 28 票面那条 ⚠️「有一类改不改都行」举的也正是这一对。
    要让它出得来，得立**第三条判据**：「CGB 标志说这张卡只能在 GBC 上跑」——
    原料已经在 `content_cart` 上，缺的是判据与它该并到哪儿。
- **为什么没停线（编排者 2026-09-21 裁：本票走选项 3）：** 票 28 的正题是
  **「把那一格变成能动手纠正的那一层」，而纠正这一层对判据是中立的**——判据以后并出
  第三组来，屏上自动多一组，纠正的形状一个字不用改。反过来，现在动判据要连带改票 27
  那一格的数与基线，两件事绞在一起。
- **并了之后要一并付的账：**
  - **票 27 那一格的数会变**（真库上多出几千条），`Finding::criterion` / `Finding::hint`
    那两句措辞跟着改；
  - **库屏基线要重出**（`crates/gui/tests/snapshots/library/health-{light,dark}` 那一对，
    格子上的数与小字都在图里）；
  - 识别报告那一栏的数也跟着换出处；
  - 本票的 `PlatformCorrections` 与 `platform_correction` 表**不用动**（按 `(declared, implied)`
    分组，多一组就多一行可定的决定）。
- **顺带记一笔：** 票 28 的票面写「核心库**已有一处**判据（票 27 用的就是它）」——
  实际是两处。收尾时原样报给拿主意的人。
