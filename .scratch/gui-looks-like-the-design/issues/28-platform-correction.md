# 28 — 平台纠正：目录说的与内容不符

**What to build:** 维护者处理「目录说这是 GB、文件内容说这是 GBC」这一类：按组看到有多少条、
凭什么这么判、两条样例，然后决定**按内容改**还是**保持目录的说法**。纠正记为**裁决**，
不移动任何文件；导出与同步按纠正后的平台放置。

**Blocked by:** 27；识别按内容记平台由 `one-criterion-per-thing/03` 提供。

**Status:** done

⚠️ **平台由目录给出，是扫描的输入；但目录只是强先验，文件内容可以推翻它**（词表**平台**）。
这张票要新定的是：「按内容改」落成一条什么形状的裁决、下一趟识别怎么读它——那部分在
**核心库**里定，界面只画和转发。

⚠️ **与 `one-criterion-per-thing/03` 物化的那一列分清楚**：那一列记的是**识别按内容判出来
的**平台，本票落的是**人工纠正**。两者是两回事——**都不许回写「目录声明的平台」那一列**，
否则平台冲突报表就失去对照物，下一次体检也认不出这些条目处理过没有。

⚠️ **有一类改不改都行**：GBC 向下兼容 GB，有意放在 GBC 目录也说得通——屏上要说明白，
并且「保持」也要能记下来，免得每次体检都再问一遍。

- [x] 按组列出（从什么平台 → 到什么平台、多少条、理由、样例）
  - **分组在核心库那一处判据上**（`scan::aggregate::conflicting_platform`，ADR-0024）：
    `ConflictAcc.by_pair` 按那一对平台累计条数、凭据、扩展名与本组样例，折进
    `ConflictSummary.groups`（条数多的在前，一样多时按平台名排——报告次序得是死的）。
  - 理由那一句出自核心库一处：`ConflictGroup::reason()`（哪几个扩展名、凭据各几条）。
  - 样例记的是**中立库的键**，屏上照票 09 写「根名 · 相对路径」（`table::root_and_path`）——
    收尾自审挑出来的：原先记的是展示路径，基线图里会留下某一台机器上那条临时目录。
  - 测试：`crates/core/src/report.rs::平台冲突按从哪个平台到哪个平台分组_条数多的在前_每组带扩展名判据与样例`、
    `crates/core/tests/platform_fix.rs::平台冲突按组列出来_每组说得出从哪到哪几条凭什么两条样例`、
    `crates/gui/tests/health.rs::点目录与内容平台不符那一格_开的是平台纠正那一层_…`。
- [x] 每组两条出路：按内容改、保持目录的说法；两种都记得住
  - 两档都落一行（`PlatformDecision::{ByContent, KeepDeclared}`）。**「保持」不是「什么都不做」**：
    它要压得过内容那一层，否则人定完下一趟识别照旧按内容算。
  - 测试：`crates/core/src/verdict.rs::平台纠正按主库分开_两种决定都记得住_撤掉之后行还在`、
    `crates/core/src/identify.rs::平台纠正说保持目录的说法时内容说的话也压不过它`、
    `crates/core/tests/platform_fix.rs::保持目录的说法压得过内容那一层_而且不再问第二遍`、
    `crates/gui/tests/health.rs::保持目录的说法也记得住_那一组不再问第二遍`。
- [x] 纠正落成裁决（形状在核心库定），可撤销
  - **形状**：沉淀库第 8 条迁移 `platform_correction`，键是**主库标识**加那一对平台，与
    **路径锚**同一个处境（只在本机这一份主库里成立，导出不带）。**撤掉不删行**（`undone_at`，
    同 `title_suppression.lifted_at`）；一对平台上同时只有一条说了算的（局部唯一索引）。
  - **按组落一行，不是几千条各落一行**：那几千条是可再生的（体检每一趟都数得出来），
    人下的那一个决定才是不可再生的那一样。
  - 测试：上面那条 `verdict.rs` 的，加 `crates/core/src/verdict.rs::第七版的老库升上来之后平台纠正那张表就建好了`、
    `crates/core/tests/platform_fix.rs::撤销之后这一组回到还没处理_那一格重新数它`、
    `crates/gui/tests/health.rs::按内容改之后那一组摊着说已改为_那一格的数跟着降_撤销回得去`。
  - **屏上说的是「记为人工纠正」**，不照设计稿那句「记为裁决」（2026-09-21 拿主意的人裁，
    挂单 `Q1032`）：落下来的是 `platform_correction` 那张表，与**成型的人工纠正**同族，
    撤销**不走裁决记录**——说成裁决是对用户说了另一样东西的名字。
    一条**反向断言**钉着（屏上有「记为人工纠正」、**没有**「记为裁决」）。
- [x] 不移动、不改名任何文件
  - **主库只读**（ADR-0004）：按下去只往沉淀库写一条决定。**两条「目标目录整份快照逐字节相同」
    钉着**（照票 26 那条的形状）：`crates/core/tests/platform_fix.rs::纠正一整轮下来盘上的文件一个字节都没动`
    （跑识别 → 定两组 → 再跑识别 → 撤销），`crates/gui/tests/health.rs::纠正一整轮_盘上的文件一个字节都没动`
    （屏上真点四下）。
  - **两条都做过「真的红」**：在两条断言前各插一行真改一个字节，当场都炸——这条守的不是形状。
- [x] 下一趟识别按纠正后的平台重新匹配
  - `identify::platform_of` 改成**一条回退链，三层**：人定过的平台纠正 → 卡带内部头（ADR-0011）
    → 目录声明。形状照**第几版**那一条。**「这个变体撞上哪一组」不在这儿另判**，问的是
    `conflicting_platform` 那一处（ADR-0024）。
  - **界面与命令行两条路都读它**：`gui/src/stages.rs::identify_run`、`cli/src/main.rs::run_identify`
    ——命令行不读的话，人在界面上定完、回终端挂后台跑一趟识别（ADR-0023 的分工）就等于没定。
  - 测试：`crates/core/src/identify.rs` 四条（按内容改 / 保持 / 别的组不受影响 / 容器里那份也算数）、
    `crates/core/tests/platform_fix.rs::按内容改之后下一趟识别按新平台算_目录声明的那一列一个字不动_那一格不再数它`。
  - ⚠️ **不回写「目录声明的平台」那一列**（票面第二条 ⚠️）：那一列是平台冲突报表的对照物。
    同一条测试里钉着（`目录声明的(&现场, "塞尔达传说.fds") == Some("FC")`）。
- [x] 处理过的组在库体检概要里不再计数
  - **报告本身一条不少**：主库只读，盘上的目录名与扩展名永远对不上，下一趟体检照旧数得出来。
    概要那一格画的是 `CorrectionGroups::remaining()`（还没处理的那几组），小字换成
    `handled_note()`（「已处理 N 组」）——**两个数都由核心库交，界面一个都不自己算**。
    两样分开，撤销才回得去；这条道理写在 `report/correction.rs` 的模块文档里。
  - 测试：`crates/core/src/report.rs::处理过的组不再算进库体检那一格_两种决定都算处理过_撤销之后重新算`、
    `crates/gui/tests/health.rs::按内容改之后那一组摊着说已改为_那一格的数跟着降_撤销回得去`。
