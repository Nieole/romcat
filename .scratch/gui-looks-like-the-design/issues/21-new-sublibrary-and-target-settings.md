# 21 — 新建子库与目标设置

**What to build:** 维护者新建一个子库（对应一台设备）：起名、选目标路径、挑前端格式与
**能力档案**、定容量上限；路径不合适时当场告诉他为什么，并让他看到文件会落到设备上的
哪个位置。

**Blocked by:** 20

**Status:** ready-for-agent

⚠️ **能力档案 = 平台矩阵 × 文件系统**（ADR-0017）。屏上要逐平台列出「设备直接能用什么」
与「不能用时转成什么」，并**带上来源与核实日期**——矩阵错误比不转换更糟，超过 180 天的
声明标成陈旧。压缩镜像之间的互转这一版做不到，遇到时如实报出来。

⚠️ **选目标路径走 `gui-answers-all-six/01` 那条薄封装**，不另写第二条处理路径的实现；
输入框照旧留着（远程会话时的退路）。弹层照票 04 那一套。

⚠️ 路径校验至少挡住三种：在**主库的根**之内（主库只读）、属于**工作目录**、已被别的
子库占用。

- [ ] 表单六项齐（名称、目标路径、前端格式、能力档案、容量上限、落点预览）
- [ ] 路径当场校验并说清原因；设备连着时报出文件系统与可用空间，没连着也能建
- [ ] 能力档案逐平台列出吃什么 / 转什么，带来源与核实日期，陈旧的标出来
- [ ] 可以按平台覆盖档案的结论，覆盖只影响这个子库
- [ ] FAT32 那 4 GiB 单文件上限在选择集里有超限变体时当场提醒
- [ ] 目标设置改动后，已有的差量预览失效并在屏上说明

⚠️ **范围变大**（拿主意的人 2026-09-15 看岔路口 F1–F11 时定，四条没选推荐）：

- [ ] 容量上限照稿二选一「按设备容量 / 自定义」：核心库加「按设备容量」一档，上限跟着设备总容量走、换卡跟着变；设备没连着时用上次连上时读到的总容量，没读过就不设上限（这一条回报成岔路口）；自定义那档照 9-14 的规矩（一位小数 GB，去掉 .0，没改字不重存）；词表「容量上限」补这一档（F1）
- [ ] 界面上前端格式统一写「ES-DE」，子库卡头跟着改；核心库适配器标识、命令行旗标、库里存的值不动（F2）
- [ ] 前端格式那句说明照实际布局写，Pegasus、ES 各一句（F3）；落点预览用真实落点：目标设置取头一个变体的真实落点与元数据位置，新建时用示例名、目录照实际规则（F4）
- [ ] 能力档案表每行一小行「核实日期 …」，陈旧时换成警示色「陈旧」，来源去掉记号放悬停（F5）；`profiles.toml` 每条加可选的「说明」，只在来源原文确实说了的地方填，照稿画，解析与校验配测试（F6）；新建时平台表按所选档案的条目列，不带覆盖列（F7）
- [ ] 连接状态行照稿全写：可移动存储、文件系统、容量与可用空间由核心库一个跨平台依赖读（Windows / macOS / Linux，不写 unsafe）；清单外文件数只读遍历目标、排上任务台，数出来之前那半句不画，路径变了或设备重新连上时重数（F8）
- [ ] 核心库加子库改名：一个事务里摘出来按新名放回，规则、目标、按平台覆盖、清单、同步状态跟过去；新名空白或重名当场拒；测试钉住改名后旧名不在、新名东西齐全、差量预览不变（F10）
- [ ] 保存目标设置之后底边提示条写「差量预览已失效」，走共用的 `toast.rs`（F9）；截图三对：目标设置停在弹层顶部、滚到底各一对，新建弹层顶部一对，路径被拦下的样子用断言钉住不拍图（F11）
