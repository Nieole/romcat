本稿更新（第四稿）

  • 子库的目标设置。新建子库和「目标设置…」是一张完整的表单：名称、目标路径（当场校验是否在主库的根内、是否被其他子库占用、是否连接）、前端格式、能力档案（预置档案 + 每个平台的转换覆盖）、容量上限、设备上的落点预览。
  • 手动例外管理。包含与排除两栏，写明例外优先于规则并永久记住；可以搜索作品直接添加，也可以逐条撤销。容量超限时的「排除」和落点撞车时的「排除这一份」都记到这里。
  • 条件组编辑器。浏览屏的筛选器就是一棵组：分面（平台、中文、收藏与合集）加上可嵌套的条件组，三种连接（全部满足 / 任一满足 / 都不满足）、十三个维度、九个运算符。每个子句当场校验（年份四位数、体积带单位、平台名认不认识、合集在不在），下方实时显示存成子库后的规则文字。
  • 收藏与合集。新建、改名、删除（删除就是把成员全部移出）、按合集筛选、在作品详情里移出某个合集。挂不住内容锚的作品（无判据那一档）会明确标出「只能按路径记录」。
  • 待确认的细分下钻。按目录 / 按候选作品 / 按命名规律三种细分，点一项只看这一部分，并在这一层整批通过或拒绝；剩下的仍可整批处理，每一层都进裁决记录、可撤销。
  • 移出此作品。合并的反向操作：把一个变体移到新建的作品或另一个已有作品，同样是一条「手工指定作品」的裁决，可整批撤销。
  • 表格按列排序、平台「更多」、侧边设为首选变体都接上了（作品名按排序标题排，年份未知的永远排在最后）。
  • 数据源优先级。按字段排：裁决固定第一，导入的 Pegasus / ES-Gamelist 固定在所有数据源之前，其余可上下调整；街机的标题另有一份顺序。保存前列出「哪些作品的显示值会变」，保存后立即生效，不需要重新刮削。
  • 导出撞上外部修改。逐份点名哪几个文件在上次导出后被改过、改了什么，给一条「我看过了，照写」；这一趟记为部分完成，不打「上次导出」的时刻戳，按钮不记状态。
  • 移除根。说清会从库里去掉多少变体、多少作品会消失、子库会少多少、裁决为什么不受影响，勾选确认后才能移除。
  • 成型纠正。多碟游戏没合在一起、目录被当成一个变体拆错了，都可以人工纠正；纠正记为裁决，永久保留，可撤销。
  • 容量超限的删减建议（每项释放多少、累计多少、排除到哪一项就放得下）与差量预览的异常项（设备上缺失要不要补回、被修改过、目标位置被占用、放不进目标：落点撞车 / 超上限 / 文件名不收的字符）。
  • 同一次匹配的字段一起确认。逐条裁决时列出中文离线源这一次匹配带来的全部字段和依据，一次裁决管住全部；否定就一起清除。它不进裁决记录的批，改主意时再裁一次覆盖。
  • 识别说明缓存命中（有多少条候选来自已经问过的模型答案，这一趟不发请求）、没有 ffmpeg 时的视频占位、各屏空态（首次启动时子库、合集、体检都是空态加一个明确的下一步）。
  • 库体检与平台纠正。库页面新增体检分块：重复拷贝、目录与内容平台不符、成型存疑、不可读、未纳入管理的目录、附属文件落单、非游戏资产、疑似同一作品，每一格点进去看明细。平台纠正按组处理（GB 目录里的 GBC 游戏等），记为裁决、不移动文件。
  • 统一的设置页（常规、工作目录、数据源与配额、刮削、导出、工具、快捷键、关于）、右键菜单与全局快捷键（Ctrl/⌘+1–6 切页、⌘F 搜索、? 看快捷键、浏览屏上下键与空格、F 收藏、E 编辑）。
  • 导入已有元数据。Pegasus 与 ES-DE 的一次性迁移：在根里找到哪些文件、按路径对得上多少、导入哪些字段、不导入前端里的游玩记录，导入的值排在裁决之后、所有数据源之前。
  • 只给拉丁与数字加粗（裁定 2026-09-13）：中文一律常规字重，层次靠字号、颜色和间距。设计稿已按这个结果画，不再用中文粗体制造层次。

前三稿的内容

  • 首次启动与添加主库。没有主库时只给一个主要操作；三步向导在点击「开始扫描」之前不写入任何文件。
  • 新手引导。第一次进入主窗口时依次介绍各个页面，可以随时从左侧栏底部重新打开。之后由「库」页面的工序负责提示下一步。
  • 卡片视图、可折叠面板、列表封面开关。见下一节。
  • 作品详情页与元数据编辑。概览、变体与文件、元数据、标题、媒体、识别依据六个标签页；每个字段显示当前值和来源，可以选用其他来源或手动填写，保存后记为裁决。
  • 合并作品。三步向导：选择保留的作品 → 核对变体与首选 → 处理字段冲突并确认。合并落成一批裁决，可在裁决记录中整批撤销。
  • 加入子库与挑选模式。一个子库的选择集由多条规则取并集组成；挑选模式下换一个平台、点一下就加一条，随时看到累计数量和容量。
  • 文案统一为常规用语，按钮用动词，不出现实现细节和文档编号。

卡片视图的设计

  • 放在「浏览」页面，作为表格之外的另一种视图。「库」页面管理的是根和数据源，作品内容都在「浏览」里；ADR-0002 也把封面墙定为次要视图。
  • 大多数作品没有封面，所以无封面卡片也要好看。真实库中本地能匹配到的图片只有 647 张（230 个变体），离线刮削也拿不到图片。没有封面时显示「字卡」：平台色底、显示标题大字、平台代号水印，而不是灰色占位块。示例里约一半有封面，是为了同时展示两种样式。
  • 卡片上的信息：右上角平台，左下角中文版本（汉化 / 官中），右下角收藏，底边一条置信度色条，下方文字写明置信度。勾选框在悬停或已有选择时出现。
  • 交互与表格一致：点击卡片在右侧显示详情，勾选用于批量操作（刮削、收藏、保存为子库），键盘可用 Tab 移动、Enter 查看、空格勾选。
  • 「只显示有封面的」是视图开关，不是筛选条件，不会写入子库的选择集规则（维度中没有「封面」）。

已裁定（2026-09-13）

  • 字体预算：只打包一份拉丁与数字的粗体，中文一律常规字重。程序体积基本不变。中文的层次改由字号、颜色和间距承担，本稿已照这个结果画；egui 那边要关掉字重合成，避免画出假粗体。
  • 工序按六行落地（扫描、识别、刮削、整理标题、裁决、导出），补齐代码里缺的扫描、刮削、裁决三行，各自报「还差多少」。
  • 两处行为变化各开一张票：非游戏资产默认不列出；操作被拒只弹提示，不再记为失败任务。
  • 「疑似同一作品」的判断放核心库（ADR-0024：一个判断只有一处实现），界面只展示和发起合并。
  • 「以后扫描到的也自动归入」暂缓。它需要在沉淀库新增一条作品级的「A 与 B 是同一作品」记录；本稿把这个选项标为还不能选，并写明眼下的走法是再合并一次。
  • 「合并作品」进词表（CONTEXT.md），并在「收敛」那一条注明要回避的是导出时的合并。
  • 界面用语已确认并写入词表：添加主库、整理标题、部分完成、已取消、裁决记录、新手引导。代码里的旧说法（任务历史的「按停了」「停在半路」、工序的「折标题」）另开票跟进。
  • 折叠状态与视图选择与面板宽度一起存在工作目录的界面偏好文件里。

在 egui 中的实现方式

本稿只使用 egui 可以绘制的元素：纯色填充、1 像素描边、圆角和打包的字体，没有模糊和 CSS 专属动效。卡片上的封面是程序生成的占位图，实际界面中显示媒体池里的图片。

验收方式

  • 颜色令牌：自动检查。令牌文件已经在同目录的 tokens.toml 里（两套主题、平台色、字号、间距、圆角、版式尺寸）。check_tokens.py 现在就能核对本稿的 CSS 变量与它是否一致（当前 65 项一致）；egui 那边照它填 Visuals，门禁里用同样的一条测试比对。
  • 结构与文案：自动检查。利用现有测试工具读取界面文字和元素位置，例如导航在左侧、刮削对话框默认不显示、界面上不出现 ** 或 ADR-。
  • 画面：首次人工确认，之后自动守护。用 egui_kittest 以示例数据渲染每个页面作为基准图，第一次由你对照本稿确认，之后任何像素变化都会让门禁失败。
  • 开发过程中对照检查。实现时用 egui MCP 启动程序截图，与本稿对应页面并排比较，并在工单收尾时附上对照图。

这是设计稿，不是实现。确认后按「界面观感落地」进行讨论、写规格和拆工单；当前界面截图在同目录的 before/ 中。
