# 04 — 刮削进工序那一段，成为第四行

**What to build:** 维护者在库屏工序那一段看见**刮削**这一行——它是主干六步之一，此前屏上没有它。
那一行说得出「还差多少」，按一下就排一趟刮削上**任务台**，跟其余几步在台上长得一样
（报得出跑到哪儿、按得下停下、跑完在历史里留一条）。

收挂单 `Q447`：刮削那三处——文案算在内、按钮不算，两半的判据不一样。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

⚠️ **「还差多少」的口径已裁定：数「一条刮削结论都没有的变体」。** 一句 SQL（拿现成的
「有刮削结论的锚点各有几个」反减）。**这个口径必须写在屏上**：「这一行数的是一条刮削结论
都没有的变体，**不是**按当前那套旋钮还差多少」。

⚠️ **别回去重开这个岔路口。** 不按旋钮算，是因为真判据是逐（锚点 × 源）比**输入指纹**，
而指纹把「这一趟要哪些字段」折进去了——**同一个变体在窄字段那一趟算「刮过」、宽字段那一趟
算「没刮过」**。按旋钮算的那个数是刮削面板那本估算账的事，**两本账别混**。

⚠️ 工序那个枚举**加一支要改五处，其中两处不在核心库**——清单逐条写在那个枚举上方的文档里，
照它走，别漏。排活走工序那一段**排一趟活的那个唯一入口**，不另写一份实现。

- [ ] 库屏工序那一段有**四行**，第四行是刮削
- [ ] 那一行报得出一个数，而那个数是「一条刮削结论都没有的变体」有多少
- [ ] 那一行旁边（或悬停里）**明写口径**，说清它不是按当前旋钮算的
- [ ] 按那一行的按钮排得出一趟刮削上任务台，跑完那一行的数跟着变
- [ ] 那一趟在任务台上四档**收场**照旧分得开，与其余几步同一套看法
- [ ] 这一趟正在跑的时候那一行的按钮按不下去（照其余几行的先例）
- [ ] 核心库那份工序测试里，第四支的措辞照前三支同一形状钉住
