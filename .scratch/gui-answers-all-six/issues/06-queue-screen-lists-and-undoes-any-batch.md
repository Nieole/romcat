# 06 — 待确认队列屏：列得出每一批裁决、撤得掉任意一批，屏头那个数不过期

**What to build:** 维护者在**待确认队列**屏上看得见自己落过的每一**批裁决**——什么时候落的、
多少条、撤过没有——并且撤得掉**其中任意一批**，不只是最后一批。撤一批被「后来还在册的批盖住」
时当场被拦下并说清是哪一批盖的。另外：扫完一个新根之后切到这一屏，屏头那个「还没识别 N 个」
是**扫描之后**的数。

收挂单 `Q448` ①（界面撤不掉更早的那一批裁决）与 `Q419`（扫描完不重列，屏头那个数会过期）。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **核心库不改。** 撤一批那个入口本来就吃任意批号，沉淀库里每条裁决连它盖掉的那条一起存着，
撤一批**不删行、只打一个「已撤」的时刻**；那条「被后来还在册的批盖住就整份拒」的守卫也已经在了。
这张票要建的只有**界面这一侧**：队列屏眼下只记得「本次进程里刚落下的那一批」（一个可空的位置，
不是一串），要改成**从沉淀库列批**。

⚠️ **命名陷阱，动手前先读词表**。词表**批**这一条已经把两个意思分开了：「**一批变体**」是这一屏
一级分批的那一批（还没落任何库），「**一批裁决**」是撤销的粒度。而代码里那两层**各有一个同名的
方法**分别指这两样。这张票动的是后者——**不许再加第三个同名的东西**，屏上那两处措辞必须分得开。

⚠️ 屏头那个数**取现成的那一处**：「还没跑过的有几条」已经是一句 SQL，而且这一屏、命令行的队列
报告、工序那一段三处共用同一处。**不许另造一份数。** 而且这次只重算那个数，**不重列整份队列**
——扫描不改变队列本身（那些变体连结论都还没有，进不了队列）。

- **类别：** 规格没说
- **在哪：** `crates/gui/src/queue.rs` `Screen::undo_last`（读 `applied` 那一格）；对照 `crates/cli/src/main.rs` `pick_batch`（`triage undo --last` 取沉淀库里最新一批在册的）
