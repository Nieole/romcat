# 06 — 待确认队列屏：列得出每一批裁决、撤得掉任意一批，屏头那个数不过期

**What to build:** 维护者在**待确认队列**屏上看得见自己落过的每一**批裁决**——什么时候落的、
多少条、撤过没有——并且撤得掉**其中任意一批**，不只是最后一批。撤一批被「后来还在册的批盖住」
时当场被拦下并说清是哪一批盖的。另外：扫完一个新根之后切到这一屏，屏头那个「还没识别 N 个」
是**扫描之后**的数。

收挂单 `Q448` ①（界面撤不掉更早的那一批裁决）与 `Q419`（扫描完不重列，屏头那个数会过期）。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **核心库不改。** 撤一批那个入口本来就吃任意批号，沉淀库里每条裁决连它盖掉的那条一起存着，
撤一批**不删行、只打一个「已撤」的时刻**；那条「被后来还在册的批盖住就整份拒」的守卫也已经在了。
这张票要建的只有**界面这一侧**：队列屏眼下只记得「本次进程里刚落下的那一批」（一个可空的位置，
不是一串），要改成**从沉淀库列批**。

⚠️ **命名陷阱，动手前先读词表**。词表**批**这一条已经把两个意思分开了：「**一批变体**」是这一屏
一级分批的那一批（还没落任何库），「**一批裁决**」是撤销的粒度。而代码里那两层**各有一个同名的
方法**分别指这两样。这张票动的是后者——**不许再加第三个同名的东西**，屏上那两处措辞必须分得开。

⚠️ 屏头那个数**取现成的那一处**：「还没跑过的有几条」已经是一句 SQL，而且这一屏、命令行的队列
报告、工序那一段三处共用同一处。**不许另造一份数。** 而且这次只重算那个数，**不重列整份队列**
——扫描不改变队列本身（那些变体连结论都还没有，进不了队列）。

- [x] 屏上列得出落过的每一批裁决：什么时候落的、多少条、撤过没有
  —— `crates/gui/tests/queue.rs` 的 `裁决记录从沉淀库列出落过的每一批裁决_连这个窗口开之前落下的`：
  一批在窗口开之前经核心库落下（上一趟会话 / 命令行），一批在界面上按 `N` 落下；点开顶栏那颗
  「裁决记录」，两行逐字是「第 N 批裁决 · 时刻 · 1 条 · 在册」，新的在前。列的是
  `verdict::Store::batches`（`queue::Screen::refresh_records`，落下、撤销、放回、重新列队列时各重列一次），
  不再靠本进程记住的那一格 `applied`。
- [x] 撤得掉**任意一批**，不只是最后一批；撤完当场看得见那些变体回到队列里
  —— `撤得掉任意一批裁决不只是最后一批_撤完那些变体当场回到队列里`：落甲、丙、乙三批（最后落下的是乙），
  撤中间丙那一批，下一帧逐条那张表就画出丙，待裁决 0 → 1，甲、乙不回来，乙那一批照旧在册。
  入口是 `queue::Screen::undo(site, 批)`：裁决记录每一行的「撤销」走它，`undo_last`（`U` 与落下之后那颗按钮）也改走它。
  按钮本身的接线由 `裁决记录里那颗撤销与放回按下去就是撤销与放回` 钉着：真的点那一颗「撤销」、再点「放回」，
  那一批在沉淀库里跟着撤、跟着回，丙跟着回到队列、再退出。
  顺带收掉挂单 `Q448` ① 那句话：`U` 无可撤时从「更早落下的那些在命令行上撤」改指「裁决记录」
  （`逐条流按_u_无可撤时说清楚而不是一声不吭` 改断言：含「裁决记录」、不含 `romcat`）。
- [x] 撤一批被后来还在册的批盖住时**当场拒**，那句话说清是哪一批盖的
  —— `撤一批被后来还在册的一批盖住时当场拒并说清是哪一批盖的_撤过的仍在记录上标着已撤`：甲、乙是两份
  **重复拷贝**（同一条内容锚），乙那一批盖住甲那一批；撤甲那一批被核心库 `TriageError::CoveredBy` 整份拒下，
  那句话（含「第 {乙那一批} 批」）原样画在屏上——裁决记录那一块顶上也画一份，就在按下去的地方
  （那一块只画它自己那两颗按钮的回话，整屏别处的错不跑进去）；
  甲那一批那一行仍是「在册」，甲不回队列。**保留**：那句话是核心库写的，里面带着一句命令行指路
  （`romcat triage undo --batch`），界面照规格原样画——见挂单 `Q622`。
- [x] 撤过的那一批在列表上**仍然看得见**，标着已撤
  —— 同一条：照那句话先撤乙那一批、再撤甲那一批，两行都还在，写「已撤（时刻）」，旁边是「放回」不是「撤销」；
  两份拷贝都回到队列。放回任意一批走 `queue::Screen::redo`（命令行 `triage redo --batch` 吃任意一批，
  界面做不到的话撤错了更早那一批就得回终端——ADR-0023 修订段的判据）。
- [x] 屏上「一批变体」与「一批裁决」两处措辞分得开，读的人不会混
  —— `屏上一批变体与一批裁决两处措辞分得开`：一级分批那一句是「一级 · 按依据形状分成 N 批变体」、不含「裁决」；
  落下之后那颗按钮是「撤回第 N 批裁决」；那一帧屏上凡是提到「第 N 批」的一句都说「批裁决」。
  **保留**：被后来的一批盖住时原样画出来的那句是核心库写的（「第 1 批里有 1 条被第 3 批盖住了……」），
  那里是裸「第 N 批」、还带着命令行指路，这一条测试不画被拒的那一帧——见挂单 `Q622`。同一趟改的还有
  「前 N 批变体盖住…」「另有 N 批变体没列」「只看这一批变体：」「第 N 批裁决已撤回…」「放回第 N 批裁决」。
  代码里**没加第三个叫 `batches` / `batch` 的东西**（`records`、`refresh_records`、`undo`、`redo`），
  `verdict::Batch` 在界面里一律带着模块名写。
- [x] 扫完一个根再看这一屏，屏头那个「还没识别 N 个」是**扫描之后**的数
  —— `crates/gui/tests/roots.rs` 的 `扫完一个根再看待确认队列屏_屏头那个数是扫描之后的_而且没有把整份队列重列一遍`：
  扫甲、跑识别、再加乙扫一趟，**一次「重新列队列」都不点**，队列屏屏头画「另有 2 个变体连识别都还没跑过」，
  与工序段识别那一行 `Behind::Left(2)` 是同一个数。取数只有 `Catalog::not_run_count` 一处：
  `App::poll_tasks` 认领完非工序的那一趟之后调 `queue::Screen::recount_not_run`。
  **保留**：这一条落在库屏那份界面测试里、不在待确认队列那份——见挂单 `Q623`。
- [x] 同一条里反向断言：那一次重算**没有把整份队列重列一遍**
  —— 同一条：扫之前人把展开的头一批收起来，扫完之后屏上仍然没有「随机样本」；整份重列
  （`queue::Screen::reload`）会把头一批重新展开。前提也断了（队列里有东西、列完头一批确实是展开的），不是空转。
  **保留**：这个反证靠的是「整份重列会重新展开头一批」这件事；哪天重列改成保留人展开到哪儿，这一条要换一个反证。
  另：扫完之后 `Queue::not_run()` 那一份照旧是列队列时的数，屏上画的是这一屏缓着的那一份（`queue::Screen::not_run`）。
