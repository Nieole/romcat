# 02 — 界面上的识别用上库里已经付过钱的答案

**What to build:** 维护者在界面上跑一趟识别，中立库里**已经问过、已经付过钱**的那些模型答案
照旧折成候选——与他在终端里跑同一趟得到的候选一样多。这一趟**一个网络请求都不发**。
跑完那份报告说得出「有几条候选来自已经问过的答案」。

收挂单 `Q418`：界面上的识别整层关掉模型推断，连库里已经付过钱的答案也不用。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

⚠️ **核心库一个字都不改。** 那个装配用的结构体字段全部公开，命令行本来就是字面量构造的，
界面照它办即可——**不要加「只用缓存」那种新构造器**。

⚠️ **上一轮否掉这一条的理由在这条路上不成立，别照抄。** 挂单原文写的是「价钱要从价目表里查，
而界面上没有那几个旋钮；0 价算出来的计划会印出花费 0.00 美元」。命令行那条拒绝拦的是
**印一份计划**；界面这一路**既不排计划、也不装那个把计划念出来的回调**，于是零价永远不会
被人看见。**价目表不装，价钱一律传零。**

三样必须一起钉死：不给凭据、不排计划、不装念计划那个回调。三样缺一样，这张票就没做对。

- [ ] 预先往中立库里放几条已经问过的答案，在界面上跑一趟识别，那些答案**折成了候选**
- [ ] 同一趟里**一个网络请求都没发**（不给凭据这一条在测试里断得出来）
- [ ] 屏上或报告里说得出「有几条候选来自已经问过的答案」
- [ ] 同一份库上，界面这一趟与命令行那一趟给出的候选**一样多**
- [ ] 核心库的公开面一个字没动（不新增构造器、不改那个装配结构体）
- [ ] 价目表在界面这条路上一处都没读；零价不会被印到任何人眼前
