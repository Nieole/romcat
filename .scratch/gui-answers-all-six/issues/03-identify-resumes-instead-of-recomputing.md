# 03 — 识别按停之后，下一趟不重算已经算完的

**What to build:** 维护者按停一趟识别，再跑一趟时**只算还没算过的那些**，不是从头再算一遍。
按停那一趟在**收场**那条轴上照旧如实落**停在半路**——它清过库、动过东西，那一档本来就该落它。

收挂单 `Q420`：识别没有断点，按停之后下一趟从头再算一遍。——**做掉了**（见下面第一、二条的证据）。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **收场四档的词以票 `gui-looks-like-the-design/03` 为准**（完成 / 已取消 / 部分完成 /
失败）：本票正文里若还写着「按停了」「停在半路」，实现与断言一律用新词；那张票没有阻塞、
可立即开工，两张不排同一波。

⚠️ **只做这一件，不做通用续跑。** 识别眼下起手把结论整份清掉，改成**只清这一趟要重算的那些**。
**不落断点文件**——扫描那一套的**断点**与同步那一套的**清单**都是更重的机制，这张票一样都不引进来。

⚠️ **新加的按停测试不许再添一处挂钟窗口。** 界面那份测试里已经有四处「三千步、每步睡两毫秒」

把那一下钉在一个信号上，或者拿一个**一开始就停着的把手**来验。收拾存量那四种写法是另一批的事
（`machine-checks-premises`），这张票只管**不再变多**。

### Q631 — 识别接着算时不看两趟之间输入变没变

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `gui-answers-all-six/03`
- **类别：** 规格没说
- **在哪：** `crates/core/src/identify.rs` 的 `start_or_continue`（起手那一步：`Catalog::identify_unfinished` 为真就接着算）；记号是中立库 `meta` 表上的 `MetaKey::IdentifyUnfinished`，只有「没走完 / 走完了」两态
- **为什么没停线：** 票与规格只要「下一趟不重算已经算完的」，没说两趟之间 DAT 库、沉淀库、主库变了怎么办；验收里的「完全一样」在输入不变时成立，有测试钉着。
- **这张票实际做了什么：** 记号不带任何输入的摘要。按停 → 换了 DAT 库（或者重扫改了某个目录下有谁、换了 `--no-read-library`）→ 再跑，接着算的那一趟里上一趟算完的那部分还是旧输入的结论；这一趟跑完记号摘掉，**再下一趟**从头算才全换新。重扫改过字节或挪过位置的变体不受影响：它们的结论随重扫收掉，落回还没识别，接着算的那一趟会算到。两趟之间在待确认屏上裁决、撤销或重做一批也会写结论（`triage` 里两处 `write_identifications`、两处 `restore_conclusions`），但它们只动得了**有结论的**变体（队列与快照都只收有结论的），写下的是裁决的投影或识别算过的那份快照，与重跑一遍照沉淀库重放得到的一样——平台那一列的差别是 `Q602` / `Q603` 的事，不是这一条的。
- **没走的那条：** 记号里带一份输入摘要（DAT 库各份的指纹、沉淀库的裁决条数、读不读主库那个选项），起手对不上就从头算；或者给命令行加一个「从头算」的开关，界面上配一颗按钮。
- **建议留：** 这条。输入摘要就是一份**输入指纹**，票明写不引进扫描的断点、同步的清单那类更重的机制；而且 DAT 库、沉淀库、中文离线源、TitleID 索引、模型答案缓存五样都得折进去，漏一样就是一个安静的错。代价如实说：按停之后改了弹药的人，要多跑一趟才全换新。真要做，开关比摘要便宜。
- **谁来裁：** 拿主意的人

### Q632 — 模型推断那一层有事可做时，上一趟算完、一条候选都没有的那些照旧重算

- **裁决（第五轮收口，2026-09-23）：** **岔** —— 实现走的就是条目建议的那条；追认：维持现状（2026-09-23 拿主意的人整批追认）。

- **来自：** 票 `gui-answers-all-six/03`
- **类别：** 规格没说
- **在哪：** `crates/core/src/identify.rs` 的 `start_or_continue`（`guessing.wants(candidates)` 那一句）；判据本身在 `crates/core/src/identify/model.rs` 的 `Guessing::wants`；`Catalog::identified_candidates`
- **为什么没停线：** 两条路都站得住，差在「接着算」省多少与「完全一样」盖多宽；不改表、不改口径。
- **这张票实际做了什么：** 那一层跑在主循环之后、被按停的那一趟整个不跑，要问谁是主循环逐个攒出来的。接着算的那一趟起手时，把有结论但一条候选都没有、而这一层这一趟有事可做的变体放回这一趟要算的那一批；判据与主循环里「交不交给它」收成了同一处（`Guessing::wants`）。测试：`crates/core/tests/identify.rs` 的 `按停之后接着算_模型推断那一层要问的一个不少`（只算计划，一个请求都不发；计划上要问几个、结论全貌都与一趟不停跑到底比）。于是「部分完成」那句话写的是「下一趟接着算剩下的，不从头来」，没写「算完的一个都不再算」。代价：重算的那几个在 `identification.read_bytes` 上记 0（哈希取回来不读盘），与一趟不停跑到底记的不一样——那一列是这一趟的账，从头再跑一趟也是 0，测试把它从「结论全貌」里拿出来单独比。
- **没走的那条：** 模型推断那一层有事可做时（命令行开 `--model` / `--model-plan`，或者库里存着问过的答案）干脆整趟从头算，不接着算——判据更简单，那句话能说死「算完的一个都不再算」，读盘的账也与一趟不停跑到底一样。
- **建议留：** 这条。重算的只有一条候选都没有的那几个，它们的哈希、光盘与卡带头都缓存在中立库里，不读盘；界面这一路眼下（`Guessing::off()`）一个都不重算。整趟从头算那条在库里存着问过的答案时接着算整个不生效，而存着答案是会越来越常见的状态（`Q418` 要让界面也用上它们）。
- **谁来裁：** 收尾
- **状态：** settled（第五轮收口，2026-09-23，见顶上裁决）
### Q633 — 接着算的那一趟，进度的分母是这一趟要算的，不是全部变体

- **裁决（第五轮收口，2026-09-23）：** **记** —— 另一条会让剩余时间外推失真。记下，无事可做

- **来自：** 票 `gui-answers-all-six/03`
- **类别：** 规格没说
- **在哪：** `crates/core/src/identify.rs` 的 `run`（`Progress::total` 取 `todo.len()`）
- **为什么没停线：** 两种报法都说得通，只影响任务台的进度条与命令行那行「已算 N / M」。
- **这张票实际做了什么：** 分母是这一趟要算的那几个、从 0 数起。测试：`按停之后再跑一趟_已经算完的那些不再重算` 断的就是 `(done, total)`。命令行跑完另说一句「上一趟已经算完的 K 个变体这一趟没再算」。
- **没走的那条：** 分母照旧是全部变体，`done` 从上一趟算完的那个数接着往上报——进度条一开跑就停在上一趟停下的地方，看起来更像「接着」。
- **建议留：** 这条。任务台照「走了几成」线性外推剩余时间（`task::Progress::remaining`），从上一趟的数起报的话，开跑那一刻就是几成，剩余时间短得离谱。整份库还差多少，工序段上识别那一行本来就在报。
- **谁来裁：** 收尾
- **状态：** settled（第五轮收口，2026-09-23，见顶上裁决）
