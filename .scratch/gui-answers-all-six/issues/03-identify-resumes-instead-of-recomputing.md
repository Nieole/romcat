# 03 — 识别按停之后，下一趟不重算已经算完的

**What to build:** 维护者按停一趟识别，再跑一趟时**只算还没算过的那些**，不是从头再算一遍。
按停那一趟在**收场**那条轴上照旧如实落**停在半路**——它清过库、动过东西，那一档本来就该落它。

收挂单 `Q420`：识别没有断点，按停之后下一趟从头再算一遍。——**做掉了**（见下面第一、二条的证据）。

**Blocked by:** 无 —— 可立即开工

**Status:** done

⚠️ **收场四档的词以票 `gui-looks-like-the-design/03` 为准**（完成 / 已取消 / 部分完成 /
失败）：本票正文里若还写着「按停了」「停在半路」，实现与断言一律用新词；那张票没有阻塞、
可立即开工，两张不排同一波。

⚠️ **只做这一件，不做通用续跑。** 识别眼下起手把结论整份清掉，改成**只清这一趟要重算的那些**。
**不落断点文件**——扫描那一套的**断点**与同步那一套的**清单**都是更重的机制，这张票一样都不引进来。

⚠️ **新加的按停测试不许再添一处挂钟窗口。** 界面那份测试里已经有四处「三千步、每步睡两毫秒」
的六秒窗口，而这个写法**真的咬过一次**（早先一份两秒的版本，机器一忙就自己先结束、测试假失败）。
把那一下钉在一个信号上，或者拿一个**一开始就停着的把手**来验。收拾存量那四种写法是另一批的事
（`machine-checks-premises`），这张票只管**不再变多**。

- [x] 按停一趟识别，再跑一趟，**已经算完的那些没有被重算**（数得出来）
  - 证据：`crates/core/tests/identify.rs` 的 `按停之后再跑一趟_已经算完的那些不再重算`。8 个变体，算完第 6 个按停；再跑一趟进度报 `(done, total) = (2, 2)`（改之前红在 `(8, 8)`），从中立库取回的哈希 0 份——对照：跑完之后再从头来一趟，同一份裸文件的哈希取得回来（>0）。`Outcome::carried_over` 数的就是「上一趟算完、这一趟没再算」的那几个。
  - 做法：中立库 `meta` 表加一个键 `MetaKey::IdentifyUnfinished`（「上一趟识别没走完」，具名读写 `Catalog::identify_unfinished` / `set_identify_unfinished`），起手从头算、清完结论时记上，跑完一整趟摘掉；记着的话起手不清，只算还没识别的（`identify::start_or_continue`）。不落断点文件。
- [x] 再跑那一趟把剩下的算完，最终结论与「一趟不停跑到底」得到的**完全一样**
  - 证据：`crates/core/tests/identify.rs` 的 `按停之后接着跑完_结论与一趟不停跑到底一模一样`。两份一样的库，一份一口气跑完，一份按停在两对该共用一条发行版的变体中间（一对撞同一条 DAT 条目，一对钉同一条裁决）再接着跑完；逐行比状态（`State::of`）、理由、识别判定的平台（`identified_platforms`）、候选、作品与发行版（按说的东西比，不比行号）、报告全文，外加读盘的账。改之前红在「发行版 3 行 vs 2 行」——续跑那一趟不认领上一趟建的发行版（修法：`Projector::adopting`）。
  - 证据：同文件 `按停之后接着算_模型推断那一层要问的一个不少`（只算计划，一个请求都不发）：计划上要问几个变体与结论全貌都与一趟不停跑到底一样（改之前红在 `None` vs `Some(1)`）。
  - **保留**：开着模型推断接着算时，重算的那几个 `identification.read_bytes` 记 0，与一趟不停跑到底记的不同——那一列是这一趟的账（挂单 `Q632`）。两趟之间换了弹药（DAT 库、`--no-read-library`……）时不保证一样（挂单 `Q631`）。
- [x] 按停那一趟在收场那条轴上落的是**停在半路**，那句话说得出「识别没有断点」这件事今天变了没变
  - 按票 `gui-looks-like-the-design/03` 的说法，这一档叫**部分完成**。
  - 证据：`crates/core/tests/task.rs` 的 `识别按停之后在台上记成部分完成而且说得出下一趟接着算剩下的`（一开始就停着的把手）：`Ending::render` 以「部分完成：」起头、不带 `**` 与 `ADR-`，含「下一趟接着算剩下的」、不含「从头再算」（改之前红在那句还说「识别没有断点，下一趟从头再算一遍」）。界面那条 `crates/gui/tests/roots.rs` 的 `识别跑到一半按停在任务台历史上记成部分完成` 断同一句。
  - 那句话只写在一处：`identify::Outcome::left_behind`，任务台（`run_task`）与命令行收场都从它取。
- [x] 那条按停测试**不靠挂钟**（新增零处睡两毫秒式的占位活）
  - 证据：新加的按停测试（core `tests/identify.rs` 三条、cli `tests/identify.rs` 一条）都在进度回调里 `cancel()`，一个变体一批，停在第几个是定死的；台上那条用一开始就停着的把手。`git diff 24f16a3 | grep '^+' | grep 'sleep\|from_millis'` 为空。
- [x] 命令行那条路跟着白拿同一个行为（两条路共用同一份实现，不许分成两份）
  - 证据：`crates/cli/tests/identify.rs` 的 `按停过的识别命令行接着算剩下的`：按停一趟之后跑 `romcat identify`，只算了没轮到的那一个（回盘读 1 份内容），库里一个「还没识别」都不剩，stderr 说「上一趟已经算完的 1 个变体这一趟没再算」（改之前红在没有这句）。续跑写在 `identify::run` 里，界面 `identify::run_task` 与命令行 `run_identify` 都经它。
  - **保留**：命令行被 Ctrl-C 的那一趟印的收场句（`crates/cli/src/main.rs`：`Outcome::left_behind` 再补一句「下面这份报告只是半份」）没有断言——要断就得真给进程发 Ctrl-C，离不开挂钟窗口；前半句由上面 core 任务台那条测试钉着。
