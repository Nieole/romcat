## 它建什么

这个仓库眼下**没有任何机器在核前提**：词表挡不住票与规格、门禁的回执会静默交出一份截断的
日志、README 里会随票涨的数没有一个东西盯着。全靠人念一遍，而实测命中率是 **1/3**
——本轮撞了三次词表 `_Avoid_`（`job_of`、「输出目录」、`Step`），只有第三次是动手前避开的，
靠的是派活时那一句「动手前把你要用的词在词表里过一遍」，不是任何自动的东西。

**根在仓库之外，仓库里只做得了防法那一半**（挂单 `Q365`）：`/code-review`、`/to-spec`、
`/to-tickets`、`/wayfinder` 全住在 `~/.claude/plugins/cache/…/mattpocock-skills/`，
这个仓库改不掉它们。

**这一批分两件活**（2026-09-09 裁定），判据一句话：
**一条规矩若说不出「哪条命令会因为违反它而变红」，就不进门禁，只进 `docs/agents/`。**

### 存量读数：我原先的前提错了三个数量级

我写这份简报时以为词表门禁的存量是「`enum Job` 与 `job_of` 两处」。实测（2026-09-10）：

- 词表 **100 行 `_Avoid_`、去重 236 个禁词**
- 扫 212 个 `.rs` 文件（注释用词法器剔除）：**标识符命中 2,581 处声明点**（按出现处算 10,852）、
  **字面量命中 4,842 处**，各分布在 188 / 189 个文件里
- 假阳占大头（标识符约七成、字面量约四分之三），**但真违规仍有约 2,000 处**

**而真违规里最大的几户动不了**：`--workspace`（54 处声明 ＋ 80 处字面量，**用户天天敲的旗标**）、
`evidence`（126 处，含 SQL 列名）、`key`（499 处，拿它指锚点）、`Game` / `GameRecord`
（DAT 的 `<game>` 元素）、`--dry-run`。假阳则是结构性的四族：禁词是正名的一截（1,071 处）、
词本身是别处的正名（206 处）、**散文式中文测试名 669 处**、外部格式与硬件专名。

**「命中即红、不加豁免清单、全量扫」在这个数上完全不可行。**

### 这一批真正的产出：词表读得通了

**`_Avoid_` 原先读起来是「这个词元禁止出现」**，而按那个读法这个仓库有约两千处违规，
包括一个公开旗标。于是词表开头新增两节（**已落笔**）：

| 落在哪 | 一句话 |
|---|---|
| `CONTEXT.md` **`_Avoid_` 是什么意思** | 它列的是**近义词**：别拿那些词去**指这个概念**。**三类豁免**：① 外部格式与硬件的专名 ② 已经公开的旗标名、库列名与协议字段 ③ 那个词恰好是另一条正名的一截（散文里当普通词用也算）。拿不准就问一句：**我是在给这个概念起名吗？** |
| `CONTEXT.md` **`_Gate_` 是词表对门禁的授权** | `_Avoid_` 的**子集**，意思是「这几个词严到可以让门禁当场报红」。进它要同时满足三条：不是任何正名的一截、不是外部格式或硬件专名、在散文里不当普通词用。**12 个词条各有一行 `_Gate_`**，逐条核过是自己那条 `_Avoid_` 的真子集 |

### 逐条

| # | 裁定 |
|---|---|
| **不接 CI** | `.github/workflows/gate.yml` 早写好了（调的就是同一个 xtask），但它**从没被任何 CI 跑过**——这个仓库没有 remote。**接受「只咬跑 `cargo xtask gate` 的 agent」**：这个仓库 90 张票几乎全是 agent 做的。否掉 pre-commit hook——它把每次提交拖到 8–11 分钟，而「跑得慢的检查被 `--no-verify` 绕过」是有名的失败模式。接 remote ＋ runner 是维护者的决定，不是一张票 |

| **件一 · 形状** | 递归 `cargo xtask words`，检查本体是 xtask 里带单元测试的函数——保住「门禁每一步都是 cargo」那条形状 |
| **件一 · 价值（诚实版）** | ⚠️ **这道机器一次也没能「重放」本轮的三次事故**：`job_of` 拦不住（一条正则分不开它与 `default_jobs`，后者指并发度、按新写的豁免第 1 类不算违规）、「输出目录」写在票与规格里而那侧不扫、`Step` **压根不在 `_Avoid_` 里**（词表禁的是中文「步骤」）。**它拦的是将来那些多字中文近义词。** 拿主意的人看完这条代价后仍选了做（而不是「只留词表那句限定」） |
| **件二 · 怎么钉** | **生成 ＋ 核对**：带标记的区段由一条命令写进去，门禁那一步只 `--check`。README 那句「以门禁自己的输出为准」已经写着却照样漂了三次（`Q198`/`Q268`/`Q380`）——**光靠免责声明不管用**。否掉「把数删掉」：读者会失去量级感，而那正是那几个数存在的理由 |
| **件二 · 标记形状** | **单行标记、值紧跟其后**（`<!-- 数:测试条数 -->1,815`；TOML 注释里同形）。成对区段标记要处理「区段里被人手改过」，而单行标记的替换与核对是同一条正则。`--check` 的报错里**要带上对的那个数** |
| **件二 · 范围** | 只管**算得出来的四样**：测试条数、测试目标数、票数、ADR 份数。真库那些数不进这个机制（判据说它们不可核），改成一律**带日期与出处**，且**不许在第二处复述**（`docs/scale-reference.md` 与 `library-facts.md` 打架就是复述出来的） |
| **「门禁五条」那个数** | **措辞里不写它**（「门禁五条」→「门禁那几条」）。三条理由：那个数对读者没有信息量（要知道跑哪几条就 `--list`）；**真正的钉子已经在了**（`xtask/tests/gate.rs` 硬断言那五个名字的完整列表）；门禁打印的汇总表**本来就是算出来的**，只有散文里那个数是手抄的。否掉「把它也纳进生成机制」——那要把生成机制铺进一个 GitHub Actions 的 job 名，是拿大锤敲图钉 |
| `Q426③` **基准** | **`#[ignore]` 的普通测试，不引 criterion。** 那两趟量的是**数量级**（1.7 秒对 16 毫秒，差两个数量级），不是看 5% 的回归——criterion 那套统计是为后者准备的。仓库眼下 bench 0、criterion 0、`#[ignore]` **0 处**，这是第一条，房规一起定：`cargo test -- --ignored` 跑，**不进门禁** |
| `Q427` **占位活** | **只收占位活那四种**，做成等一个信号的共享 helper（放现成的共享夹具里）。**轮询那一族（六个文件）与等图那八处不动**——它们等的是「后台线程真的跑完了」「图真的下下来了」，那个不确定性是**真的**；占位活不一样，它假装在干活，而「干多久」本来就该由测试说了算 |
| `Q365①` `Q373` **两份规程** | **合成一份新文件**放 `docs/agents/`。两条都是「怎么在这个仓库里跑一件长活、并拿到一份可信的回执」，同一个主题；拆成两份会让 `docs/agents/` 变成一堆小纸片。内容：worktree 里怎么派审查（判据是「它报的审查范围里得出现你改过的那十几个文件」）、怎么跑门禁（`setsid nohup` 脱出会话、前台分段 `tail --pid` 阻塞、**日志写到自己的文件里**），以及那句判据——**回执里那份输出不是完整日志，不能拿它的短小当「没跑过」的证据** |

## 件一：门禁加一步扫词表 `_Avoid_`

**范围已裁定（2026-09-09，两次裁定，后一次收窄）：只扫 `crates/**/*.rs` 的
代码标识符（fn／类型／字段／枚举支名）；`.scratch/**/*.md` 不扫；命中即红；不加豁免清单。**

这一栏先定的是「扫票与规格＋代码」，落地时撞上一个绕不开的问题**当场收窄了**：
`_Avoid_` 里的词**合法地大量出现在正文里**——挂单整份、文档注释、本轮三条撞 `_Avoid_`
的条目自己，全都在**正确地谈论**那个禁词（`crates/core/src/catalog/title.rs` 的文档注释
就写着「名字不叫 `job_of`，词表那条 `_Avoid_` 列着它」）。照「命中即红、不加豁免清单」
去扫正文，门禁开第一天就红一片，而红的全是对的句子。

**收窄的代价说清：本轮三次撞里这道门禁只拦得住两次。**
`job_of`（`Q424`）与 `Step`（`Q415`）是代码标识符，拦得住；
**「输出目录」（`Q439`）拦不住**——它写在票与规格里，而那侧不扫了。
`Q365` 当初点的正是「没有任何东西在票与规格上跑一遍词表」这一半，**这一半仍然没有机器**，
留给派活时那句「动手前把你要用的词在词表里过一遍」。

**前置活：先修 `Q424` 那两处旧账**——`crates/gui/src/roots.rs` 的 `enum Job` 与
`Screen::job_of`（词表**任务**条 `_Avoid_` 逐字列着 `job`）。门禁一开它们立即变红，
所以它们排在门禁前面。

**形状已裁定：新步仍然是 cargo，走 `cargo xtask words`（递归 xtask 调用）**，检查本体是

## 件二：机器可核的数字

**判据已裁定：一条命令算得出来的数，才准写成断言。**

- **可核** —— 测试条数、测试目标数、票数、ADR 份数。进门禁。
- **不可核** —— 真库那些数、工具链版本、耗时秒数。机器碰不到，一律要求**带日期与出处**
  （`docs/library-facts.md` 已经是这个形状），**并且不许在第二处复述**。

⚠️ **「不许复述」是有案底的**：`docs/scale-reference.md:40`–`41` 与
`docs/library-facts.md:16` **并存着一批打架的数**，后者把前者标成了「判断作废」。

已知规模（sub-agent 2026-09-09 核过，四族）：

1. **随票变的 6 处** —— `README.md:97`（票数、测试条数、目标数）、`README.md:207`、
   `crates/gui/Cargo.toml:16`–`18`/`:29`、`README.md:119`（ADR 份数）。
   `crates/gui/Cargo.toml:19`–`23` 的注释自己写着「**没有任何东西盯着这两处同步**」。
   **这一族已经第三次被记进挂单**：`Q198`、`Q268`、`Q380`。
2. **xtask 注释里的实测数** —— rustdoc 告警 **67** 条同时钉在三处（`gate.rs:36`–`38`、
   `README.md:215`），而挂单里还留着 **68** 的旧版。
3. **根 `Cargo.toml` 里的真库数 7 处** —— `:56` `2.50 TiB`、`:70` `21,901 条`、`:84` `342 张`…
4. **`docs/library-facts.md` 全篇**加 `docs/platforms.md`。

2026-09-09 已就地改掉的：`README.md` 三处（1,815 / 70 目标、1,692 / 63 目标、少跑 123；
票数 `87/90`）、`README.md:119`（22→23 份 ADR）、`crates/gui/Cargo.toml:18`、
根 `Cargo.toml` 两处「门禁四条」。**改掉不等于钉住**——这一件要建的正是钉住它的东西。
