# 06 — 两条量级基准留在树里

**What to build:** 维护者跑一条命令就能复核折标题与导出的**量级**——它们还是不是差着两个
数量级。此前那两趟量完就删了，复核要照挂单里那段重新搭一遍。

收挂单 `Q426③`。

**Blocked by:** **05 — `docs/agents/` 多一份跑长活的规程**

**Status:** ready-for-agent

⚠️ **新开一份量级测量的测试文件**，两条都放它，都挂 `#[ignore]`。三条理由：
① 它们不是回归测试、是**量级测量**，混进主题测试文件会让读者以为它们在验行为；
② 两条共用「造一份 N 个变体的合成库」那套夹具，放一处才不重复搭；
③ `cargo test -- --ignored` 的产物因此是**一份读得懂的量级报告**。

⚠️ **不引 criterion、不建 `benches/`。** 那两趟量的是**数量级**（折算真库 1.7 秒与 2.0 秒，
对着一帧 16 毫秒的预算差两个数量级），不是要看 5% 的回归——criterion 那套统计是为后者准备的。

⚠️ **这是仓库第一条 `#[ignore]`，房规同时定，写进票 `05` 那份规程**：
`#[ignore]` 只用于**要人主动跑、且跑起来很贵**的东西；**不用于「暂时挂起的失败测试」**
——那种要么修要么删。

⚠️ **不进门禁。**

- [ ] 那份新文件里两条基准都挂着 `#[ignore]`，平常一条都不跑
- [ ] `cargo test -- --ignored` 跑得起来，两条都报得出耗时与折算到真库的量级
- [ ] 两条共用同一套合成库夹具，没有第二份
- [ ] 全仓没有 criterion、没有 `benches/`
- [ ] `#[ignore]` 的房规写进了票 `05` 那份规程
