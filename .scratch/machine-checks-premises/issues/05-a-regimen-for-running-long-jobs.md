# 05 — `docs/agents/` 多一份跑长活的规程

**What to build:** 接票的 agent 读得到一份规程，告诉它**怎么在这个仓库里跑一件长活、
并拿到一份可信的回执**——在 worktree 里怎么派审查、怎么跑门禁、以及怎么判断手上那份回执
是不是骗人的。

收挂单 `Q365①`（worktree 里怎么派审查）与 `Q373`（门禁的回执会静默截断）。

**Blocked by:** 无 —— 可立即开工

**Status:** ready-for-agent

⚠️ **合成一份新文件，不拆两份。** 两条都是同一个主题；拆开会让 `docs/agents/` 变成
一堆小纸片，而 `CLAUDE.md` 那一节要逐个指过去。

⚠️ **要写进去的两条判据（这是这份文件的核心，别写成流水账）**：
- **派审查**：`它报的审查范围里得出现你改过的那十几个文件`。根改不掉（那几个技能住在仓库外的
  plugin cache 里，本轮至少咬了两次，交回一份看起来正常、其实审的是主工作区的回执），
  这里写的是防法。
- **跑门禁**：`回执里那份输出不是完整日志，不能拿它的短小当「没跑过」的证据`。
  附实测：同一趟门禁，回执 **42 行 / 3.7 KB**、零个 `Running`、零个 `Compiling`；
  自己写的日志 **2,233 行 / 145 KB**。据前者判定「它压根没跑过」，白重跑了一趟、约十一分钟。
  办法：脱出会话、在前台分段阻塞着等、**日志写到自己的文件里**。

⚠️ 照 `docs/agents/` 现有那三份的房规写：`# 标题` ＋ 空行 ＋ 一行说明，`##` 小节。
写完在 `CLAUDE.md` 的 Agent skills 那一节加一个指向。

⚠️ **这份文件后面还会被两张票各补一段**（票 `02` 补门禁在 `main` 上的退化行为、
票 `06` 补 `#[ignore]` 的房规）——留好位置，别写成不给人加节的形状。
