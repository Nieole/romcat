# 02 — 门禁多一步扫词表

**What to build:** 接票的 agent 新写的标识符或屏上文案撞上词表 `_Gate_` 里的词，
**门禁当场报红**，并说清三样：**哪一行、命中哪个词、该用哪个正名**。它只看**新写的代码**，
所以两千处存量一处都不报。

收挂单 `Q365`（防法那一半）与 `Q424`（没有任何东西在新代码上跑一遍词表）。

**Blocked by:** **01 —（prefactor）「门禁几条」那个数从措辞里消失**、
**05 — `docs/agents/` 多一份跑长活的规程**

**Status:** ready-for-agent

⚠️ **范围：相对 `main` 的 merge base 以来的全部改动，含未提交的。** 接票的 agent 跑门禁时
改动一半已提交一半没有（它跑门禁正是为了决定要不要提交），只看一半都会漏。
**在 `main` 上直接干活时 merge base 就是 `HEAD`，于是退化成「只看未提交的」——这是对的，
但要往票 `05` 那份规程里补一段说明**，否则有人会以为门禁在 `main` 上失效了。

⚠️ **扫标识符与字符串字面量；不扫注释与文档注释**（那里是在**谈论**禁词）、
**不扫 `.scratch/`**、**不扫词表自己**。

⚠️ **词表从 `CONTEXT.md` 读，不在门禁里另抄一份。** 抄一份就是当场犯这一批要治的病；
而「哪些词严到可以报红」是领域判断，ADR-0024 说它只许有一处实现。

⚠️ **形状：新那条仍然是 cargo**（递归的 xtask 子命令），保住「门禁每一条都是 cargo 子进程」
那条形状。检查本体是纯函数：**（`_Gate_` 词表 × 改动的行）→ 命中**，单元测试直接打它。

⚠️ **加这一条会撞三条现成测试**：硬断言五条名字的那条、断言「不带 `--all-features` 的
只有一条」的那条、断言完整命令字面量的那条。三条都要跟着改。

⚠️ **把这道机器的价值如实写进它自己的文档**：它**一次也没能「重放」本轮三次事故**——
`job_of` 拦不住（一条正则分不开它与 `default_jobs`，后者指并发度、按词表豁免第 1 类不算违规）、
「输出目录」写在票与规格里而那侧不扫、`Step` 压根不在 `_Avoid_` 里（词表禁的是中文「步骤」）。
**它拦的是将来那些多字中文近义词。** 不写这一句，下一个人会以为它比实际强。
