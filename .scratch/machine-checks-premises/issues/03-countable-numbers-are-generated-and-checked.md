**What to build:** 维护者不必再手抄那几个会随票变的数。**测试条数、测试目标数、票数、
ADR 份数**由一条命令写进带标记的位置；它们过期时**门禁报红，并告诉他对的那个数**。

⚠️ **判据：一条命令算得出来的数，才准写成断言。** 只管那四样。
**真库那些数不进这个机制**（机器碰不到）——它们归票 `04`。

- **在哪：** `.cargo/config.toml` 那条别名 `xtask = "run --quiet --package xtask --"`
  ＋ `xtask/src/gate.rs` 的 `Step::command_in`（门禁每一步都是 xtask 进程起的 cargo 子进程）
- **实测（2026-09-22，slot-3，同一份树、中间一个字节都没改）：**

  | 这一趟 | 怎么跑的 | 用时 | `Compiling` |
  |---|---|---|---|
  | 1 | 裸跑 `cargo test --workspace --all-features -- --list` | **91 秒** | 一片 |
  | 2 | 同上，再跑一遍 | 3.2 秒 | 0 |
  | 3 | `cargo xtask numbers --check`（内层同一条 `-- --list`） | **104 秒** | **7** |
  | 4 | 同上，再跑一遍 | 3.4 秒 | 0 |

  **交替跑就交替重编**，稳定复现。重编的只有工作区那几个 crate（7 个），依赖树没动。
- **后果：** **「跑完 `cargo test` 再跑 `cargo xtask gate`」会白付一趟重编**——而这一轮
  几乎每个 agent 都是这么跑的（先窄跑几条 `cargo test -p …` 自查，再跑全量门禁）。
  它同时解释了「同一棵树上门禁一趟比一趟慢」那几处怪事。
- **为什么没停线：** 与这张票要做的事无关；而且它两边都只是**慢**，不出错、不改结论。
- **这张票实际做了什么：** **只量、只记，没追根因。** 追它要把两边的环境逐个变量 diff 出来
  （大概率在 `RUSTFLAGS`／`CARGO_ENCODED_RUSTFLAGS`／feature 组合／rustc 解析到哪一个
  二进制这一族里——本机 `which cargo` 是 `/opt/homebrew/bin/cargo`、**`rustup` 不在 PATH 上**，
  所以 `rust-toolchain.toml` 那一钉在本机是不是真钉着，也在这条线里），那是一条独立的线，
  塞进这张票会把它从「一个数一处算法」变成「查 cargo 指纹」。
- **另一条路：** 当场追下去，或者退一步让门禁把内层那趟 cargo 的环境显式对齐
  （`Command::env_remove` 掉 `cargo run` 注进来的那几个）——两条都要先知道是哪个变量。
- **建议留：** 记着、交 `/settle` 排一条独立的线去追。真追出来，省下的是**每个 agent 每一轮
  一到两趟约 100 秒**，而且它还牵着「本机到底用的是哪一版工具链」这个更要紧的问题。
