# 机器替人核前提

**Status:** ready-for-agent
**Opened:** 2026-09-10
**规矩：** 词表 `CONTEXT.md` 的 `_Avoid_` 与 `_Gate_` 两节（这一批的前置产出，已落笔）
**材料：** `.scratch/machine-checks-premises/grill.md`（五轮十三条裁定 ＋ 存量实测读数）

## Problem Statement

**这个仓库没有任何机器在替人核前提，而"靠人念一遍"的实测命中率是三分之一。**

维护者与接票的 agent 撞得到的那一面：

- **词表挡不住任何东西。** 第四轮九张票撞了三次词表 `_Avoid_`——`job_of`、「输出目录」、
  `Step`——**只有第三次是动手前避开的**，靠的是派活时那一句"动手前把你要用的词在词表里过一遍"，
  不是任何自动的东西。三分之一。
- **门禁的回执会静默交出一份截断的日志。** 同一趟门禁：回执里那份输出 42 行 / 3.7 KB、
  零个 `Running`、零个 `Compiling`，而自己写的日志 2,233 行 / 145 KB。据前者判定"它压根没跑过"，
  **白重跑了一趟门禁、约十一分钟**。
- **README 与注释里那些会随票变的数，没有一个东西盯着。** 那一族**第三次**被记进挂单
  （`Q198`、`Q268`、`Q380`）；而写完 ADR-0024 那天，README 里 ADR 份数**一小时内错了两次**
  ——改成 23、加一份 ADR、当场又错。
- **`docs/agents/` 里缺两份规程**：在 worktree 里怎么派审查（那个根改不掉——它住在仓库外的
  plugin cache 里，本轮至少咬了两次，交回一份看起来正常、其实审的是主工作区的回执），
  以及怎么跑门禁。
- **两趟量过的一次性基准没留在树里**，复核要照条目里那段重搭。仓库眼下 `benches/` 0 个、
  criterion 0 处、`#[ignore]` **0 处**。
- **按停那类测试还靠挂钟抢时间**：四种"占位活"写法散在五个文件，而这个写法**真的咬过一次**
  （早先一份两秒的版本，机器一忙就自己先结束、测试假失败）。

**这些都不是这一轮新长出来的。** 它们全是"靠人念一遍"这条唯一防线漏掉的地方。

## Solution

**在仓库里加两道机器，写下两份规程，并把两类靠挂钟的测试改成不靠挂钟。**

判据一句话（第三轮已裁）：**一条规矩若说不出"哪条命令会因为违反它而变红"，就不进门禁，
只进 `docs/agents/`。**

⚠️ **这一批最值钱的产出已经落笔了，不在待办里：词表变得读得通。**
实测把原本的计划推翻过一次——`_Avoid_` 原先读起来是"这个词元禁止出现"，而按那个读法这个
仓库有约**两千处**违规，其中包括一个用户天天敲的旗标。于是词表新增两节：
`_Avoid_` 列的是**近义词**（别拿它们去**指这个概念**）并带三类豁免；
`_Gate_` 是它的**子集**，是**词表对门禁的授权**。**12 个词条各有一行 `_Gate_`。**

剩下五件：

1. **门禁多一步扫词表** —— 只扫**新写的代码**、只用 `_Gate_` 那份缩小词表。
2. **算得出来的数由一条命令写，门禁核对** —— 测试条数、测试目标数、票数、ADR 份数。
3. **`docs/agents/` 多一份规程** —— 怎么跑长活、怎么拿到一份可信的回执。
4. **两条量级基准留在树里** —— `#[ignore]`，人主动跑。
5. **占位活那四种写法收成一种** —— 等一个信号，不等挂钟。

## User Stories

1. 作为接票的 agent，我想在新写的标识符撞上词表 `_Gate_` 里的词时**被门禁当场拦下**，这样我不必靠记性去念一遍词表。
2. 作为接票的 agent，我想让这道检查**只看我这张票改动的行**，这样我不会被两千处存量淹掉。
3. 作为接票的 agent，我想让它**同时看已提交与未提交的改动**，这样我跑门禁时拿到的答案是"我这张票到此为止干净吗"。
4. 作为接票的 agent，我想让它**不扫注释与文档注释**，这样我在注释里**谈论**一个禁词不会被误报。
5. 作为接票的 agent，我想让它也扫**字符串字面量**，这样屏上真说出去的话也守着词表。
6. 作为维护者，我想让"哪些词严到可以报红"**写在词表里而不是门禁的代码里**，这样改它的是我而不是实现者。
7. 作为维护者，我想让 `_Gate_` **永远是它那条 `_Avoid_` 的子集**，这样不会冒出第二份禁词表。
8. 作为接票的 agent，我想在报红时**看见是哪一行、哪个词、该用哪个正名**，这样我当场改得掉。
9. 作为维护者，我想让 README 与注释里那几个会随票变的数**由一条命令写进去**，这样它们不再漂。
10. 作为维护者，我想让门禁在那些数过期时**报红并告诉我对的那个数**，这样我不必自己去数。
11. 作为维护者，我想让**真库那些数不进这个机制**，一律带日期与出处，这样机器碰不到的东西不会被假装核过。
12. 作为维护者，我想让真库那些数**不许在第二处复述**，这样不会再出现两份文件各写一个、互相打架。
13. 作为维护者，我想让"门禁几条"这种数**在措辞里消失**，这样加一步不必去改十五处散文。
14. 作为接票的 agent，我想有一份规程告诉我**在 worktree 里怎么派审查、怎么判断它审的是我这份工作区**，这样我不会拿到一份看起来正常、其实审错了地方的回执。
15. 作为接票的 agent，我想有一份规程告诉我**怎么跑门禁**（怎么脱出会话、怎么在前台阻塞着等、日志写哪儿），这样我不必每次自己摸索。
16. 作为接票的 agent，我想在那份规程里读到**"回执里那份输出不是完整日志"**这句判据，这样我不会拿它的短小当"没跑过"的证据，白重跑一趟。
17. 作为维护者，我想让那两趟量级基准**留在树里**，这样下一个人复核不必照条目里那段重新搭一遍。
18. 作为维护者，我想让它们**默认不跑**、要人主动跑，这样它们不拖慢门禁。
19. 作为维护者，我想让 `cargo test -- --ignored` 的产物是**一份读得懂的量级报告**，这样我一眼看出还是不是差两个数量级。
20. 作为维护者，我想让 `#[ignore]` 在这个仓库有一条**明写的房规**，这样它不会变成"暂时挂起的失败测试"的垃圾桶。
21. 作为接票的 agent，我想让按停那类测试**等一个信号而不是等挂钟**，这样它不会在机器忙的时候假失败。
22. 作为接票的 agent，我想让那个占位活是**一处共享的东西**，这样我不必在第五个文件里再抄一遍。
23. 作为维护者，我想让**等后台线程跑完、等图下下来**那两族轮询**保持不动**，这样我不会为了整齐把真实的不确定性也换掉。
24. 作为维护者，我想让这一批**一个字节都不动我的主库**，这样它照旧敢在 10 TB 的真库上用。
25. 作为维护者，我想让这一批**不改任何交付出去的行为**（门禁跑手不进那两个二进制），这样它对用户是零风险的。

## Implementation Decisions

### 零、前置：词表那两节（已落笔，实现者只需读）

- **`_Avoid_` 是什么意思**：它列的是**近义词**——别拿那些词去**指这个概念**；不是"这个词元禁止
  出现"。三类豁免：① 外部格式与硬件的专名 ② 已经公开的旗标名、库列名与协议字段
  ③ 那个词恰好是另一条正名的一截（散文里当普通词用也算）。
- **`_Gate_` 是词表对门禁的授权**：`_Avoid_` 的**子集**，"这几个词严到可以报红"。
  进它要同时满足三条：不是任何正名的一截、不是外部格式或硬件专名、在散文里不当普通词用。
  **12 个词条各有一行**，没进的连理由一起记在词表里。

### 一、门禁多一步扫词表

- **形状**：新步仍然是 cargo，走**递归的 xtask 子命令**——保住"门禁每一步都是 cargo 子进程"
  那条形状。检查本体是 xtask 里的函数。
- **范围**：**相对 `main` 的 merge base 以来的全部改动，含未提交的**。理由：接票的 agent 跑门禁时
  改动一半已提交一半没有（它跑门禁正是为了决定要不要提交），只看一半都会漏。
  ⚠️ **在 `main` 上直接干活时 merge base 就是 `HEAD`，于是退化成"只看未提交的"**——
  这是对的，但要在规程里写明，否则有人会以为门禁在 `main` 上失效了。
- **扫什么**：`crates/**/*.rs` 的**标识符**与**字符串字面量**。
  **不扫注释与文档注释**（那里是在**谈论**禁词）、**不扫 `.scratch/`**、**不扫词表自己**。
- **用哪份词表**：只用 `_Gate_` 那些行，**从词表里读**，不在门禁里另抄一份
  （抄一份就是当场犯这一批要治的病；而"哪些词严到可以报红"是领域判断，ADR-0024 说它只许有一处）。
- **`_Gate_` ⊆ `_Avoid_` 要有机器守着**：读词表时校验每一行 `_Gate_` 都是它那条 `_Avoid_` 的
  子集，越界就报错。写这份规格时人手核过一遍，发现过一处放错条的（`线程池` 本属**任务台**、
  被写到了**任务**上）——所以这道校验不是多余的。
- **报红时说三样**：哪一行、命中哪个词、**该用哪个正名**（词条名就在 `_Gate_` 行上面）。
- **加这一步会撞三条现成测试**：那份集成测试硬断言那五条的名字、断言"不带 `--all-features`
  的步恰好只有 `check`"、断言五行完整命令的字面量。三条都要跟着改。
- ⚠️ **CI 上的浅克隆会让这一步算不出 diff。** `actions/checkout@v4` 没给 `fetch-depth`，
默认只取 1 层历史，于是**「相对 `main` 的 merge base」在 CI 上求不出来**。两条路：给 checkout
加 `fetch-depth: 0`，或者这一步在**拿不到历史时如实跳过并说明**（别假装扫过了）。
本地跑 `cargo xtask gate` 不受影响——那儿历史是全的。

⚠️ **这道机器的价值要如实写进它自己的文档**：它**一次也没能"重放"本轮三次事故**——
  `job_of` 拦不住（一条正则分不开它与 `default_jobs`，后者指并发度、按豁免第 1 类不算违规）、
  「输出目录」写在票与规格里而那侧不扫、`Step` 压根不在 `_Avoid_` 里（词表禁的是中文「步骤」）。
  **它拦的是将来那些多字中文近义词。** 不写这一句，下一个人会以为它比实际强。

### 二、算得出来的数由一条命令写，门禁核对

- **判据**：**一条命令算得出来的数，才准写成断言。**
- **管四样**：测试条数、测试目标数、票数、ADR 份数。**真库那些数不管**——机器碰不到，
  改成一律**带日期与出处**，并且**不许在第二处复述**（两份文件并存着一批打架的数，就是复述出来的）。
- **标记形状**：**单行标记、值紧跟其后**（Markdown 用 HTML 注释、TOML 用 `#` 注释，同一形状）。
  成对区段标记要处理"区段里被人手改过"，而单行标记的替换与核对是**同一条正则**。
- **两个动作**：`--write` 改写，`--check` 核对。**`--check` 的报错里要带上对的那个数**，
  这样人不必自己去数。门禁跑的是 `--check`。
- ⚠️ **`--check` 得自己跑一趟"列出全部测试"**：门禁那几步走的是继承 stdio 的方式、
  **不捕获子进程输出**，没法从测试那一趟里顺手把数捞出来。这一步排在测试之后，编译缓存是热的。
- **计数规则要写死**：票数按"文件靠前处那行 `Status:`"数，行首锚定——松一点的匹配会把票末尾
  正文里出现的 `done` 也算进去（写这份规格时实测撞过：松匹配数出 88，锚定数出 87）。
- **"门禁几条"那个数从措辞里消失**（"门禁五条" → "门禁那几条"）。三条理由：那个数对读者
  没有信息量（要知道跑哪几条就 `--list`）；**真正的钉子已经在了**（那条硬断言五条名字的测试）；
  门禁打印的汇总表**本来就是算出来的**，只有散文里那个数是手抄的。
  ⚠️ 存量至少十五处，且**其中一处已经漂成了"四条"**（xtask 那个 crate 的模块文档）。

### 三、`docs/agents/` 多一份规程

- **合成一份新文件**，不拆两份：两条都是"怎么在这个仓库里跑一件长活、并拿到一份可信的回执"，
  同一个主题；拆开会让 `docs/agents/` 变成一堆小纸片，而 `CLAUDE.md` 那一节要逐个指过去。
- **内容**：
  - **在 worktree 里怎么派审查**，判据是「**它报的审查范围里得出现你改过的那十几个文件**」。
    根改不掉（那几个技能住在仓库外的 plugin cache 里），这里写的是防法。
  - **怎么跑门禁**：脱出会话、在前台分段阻塞着等、**日志写到自己的文件里**。
  - 判据一句话：**回执里那份输出不是完整日志，不能拿它的短小当"没跑过"的证据。**
    附实测：同一趟门禁，回执 42 行 / 3.7 KB，自己的日志 2,233 行 / 145 KB。
  - **门禁在 `main` 上的退化行为**（见上）。
  - **`#[ignore]` 的房规**（见下）。
- 照 `docs/agents/` 现有那三份的房规写：`# 标题` ＋ 空行 ＋ 一行说明，`##` 小节。
  写完在 `CLAUDE.md` 的 Agent skills 那一节加一个指向。

### 四、两条量级基准留在树里

- **新开一份"量级测量"的测试文件**，两条都放它，都挂 `#[ignore]`。
  理由：① 它们不是回归测试、是**量级测量**，混进主题测试文件会让读者以为它们在验行为；
  ② 两条共用"造一份 N 个变体的合成库"那套夹具，放一处才不重复搭；
  ③ `cargo test -- --ignored` 的产物因此是**一份读得懂的量级报告**。
- **不引 criterion、不建 `benches/`**：那两趟量的是**数量级**（折算真库 1.7 秒与 2.0 秒，
  对着一帧 16 毫秒的预算差两个数量级），不是要看 5% 的回归——criterion 那套统计是为后者准备的。
- **房规写进规程**：`#[ignore]` 只用于**要人主动跑、且跑起来很贵**的东西；
  **不用于"暂时挂起的失败测试"**（那种要么修要么删）。这是仓库第一条 `#[ignore]`，房规同时定。
- **不进门禁。**

### 五、占位活那四种写法收成一种

- **一处共享的 helper**，放 GUI 那几份界面测试**现成的共享夹具**里
  （三个文件已经在用它，第四个加一行引用即可）。
- **形状：等一个信号。** 测试想让那趟活停就发信号，不再"三千步、每步睡两毫秒"地耗六秒挂钟。
- **只收占位活那四种。轮询那一族（六个文件）与等图那八处不动**——它们等的是"后台线程真的
  跑完了""图真的下下来了"，那个不确定性是**真的**，换成信号要改任务台的公开面，那是另一件事。
  占位活不一样：它假装在干活，而"干多久"本来就该由测试说了算。

## Testing Decisions

**什么算一条好测试**：只验**外面看得见的行为**——那条命令红了还是绿了、报错里说了什么、
文件被改成了什么样。不验内部状态。**这一批自己的测试尤其不许靠挂钟**（它有一件正是在治这个）。

**跨 crate 的新接缝一个都不加。** 两个纯函数是在 xtask **内部**划的，而那个 crate 本来就有
库入口、本来就有一份集成测试。

| 件 | 接缝 | 验什么 |
|---|---|---|
| 门禁扫词表 | **纯函数**（`_Gate_` 词表 × 改动的行 → 命中）在 xtask 里单元测试；采集那层（拿 diff、读词表）由那份现成的集成测试验一次 | 命中／不命中；**注释里的禁词不报**；三类豁免不误报；`_Gate_` 越界时报错 |
| 数字生成核对 | 同形的纯函数（文档内容 × 算出来的数 → 改写后的内容／不一致清单） | `--write` 改对；**`--check` 的报错带上对的那个数**；真库那些数一处没动 |
| 规程 | **无测试** —— 纯文档，诚实说出来 | — |
| 量级基准 | 那份新开的测量文件自己 | 挂了 `#[ignore]`（默认不跑）；`-- --ignored` 跑得起来、报得出量级 |
| 占位活 | GUI 那几份界面测试现成的共享夹具 | 四处改完之后**新增零处睡毫秒式的占位活**；那几条按停测试照旧绿 |

**先例照抄这几处**：门禁那份集成测试已经在造临时 crate 验那几条，新那条采集测试照它办；
纯函数的单元测试照 xtask 里已有的写法。占位活那个 helper 的调用形状照现成那四处
（它们逐字相同的那一种）。

⚠️ **门禁那一步的测试要连"存量不报"一起验**：拿一份**没改动过**的文件、里头有已知的存量命中，
断言它**不报红**。只验"改动的行报红"会让下一个人以为它是全量扫的。

## Out of Scope

- **接 CI —— 不用做，它已经在跑。** `.github/workflows/gate.yml` 调的就是同一个门禁跑手，
  而它**从 2026-09-08 起就在 GitHub Actions 上真跑**（实测 32 次运行、28 次绿、3 次被并发组
  取消）。于是这一批加的两道机器**咬得住每一次 push**，不只是跑门禁的 agent。
  这一批要做的只有一处与 CI 有关：见下面那条 `fetch-depth`。
- **pre-commit hook。** 否掉了：它把每次提交拖到门禁那个量级（8–11 分钟），而"跑得慢的检查
  被绕过"是有名的失败模式。
- **清那两千处存量。** 门禁只扫新写的代码。存量里绝大多数按新写的那三类豁免**压根不是违规**；
  真该改的那些没有票在催。
- **改 `--workspace`／`--dry-run`／`evidence` 那几列。** 词表新增的豁免第 2 类明写：
  `_Avoid_` 是命名指导，**不是破坏性变更的授权**。
- **扫 `.scratch/**/*.md`（票与规格）。** 上一轮定的：那里的正文大量**合法地引用**禁词。
  于是"没有任何东西在票与规格上跑一遍词表"这一半**仍然没有机器**，留给派活时那一句话。
- **收拾轮询那一族与等图那八处。** 它们等的不确定性是真的。
- **引 criterion、建 `benches/`。**
- **`docs/library-facts.md` 那些真库数进生成机制。** 机器碰不到。

## Further Notes

**这一批有一条与别处相反的性格：它的成果是"以后少一类事故"，而不是"现在多一个功能"。**
所以它最容易被排到最后，也最容易在排到时被砍。判据留在这儿：**"靠人念一遍"这条唯一防线，
实测命中率三分之一。**

**两处实测推翻了原计划，别照旧账干活：**

- **词表门禁的存量不是两处，是约两千处真违规**（含一个公开旗标）。原本的"命中即红、
  不加豁免清单、全量扫"完全不可行——这才是词表那两节被写出来的原因。
- **那道门禁一次也没能"重放"本轮三次事故**（见 Implementation Decisions 一）。
  拿主意的人看完这条代价后**仍然选了做**，而不是"只留词表那句限定"。这一句要留在票面上，
  免得下一个人以为是没想清楚。

错了两次**；而写这份规格时又撞见第 N 处——xtask 那个 crate 的模块文档写着"那四条命令"，
而门禁早就是五步、这一批还要加成六步。
