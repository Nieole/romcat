# 人写下的留得住，写到卡上的前端读得到

**Status:** ready-for-agent
**Opened:** 2026-09-24（`/settle` 第五轮收口 → `/grill-with-docs` → `/to-spec`）
**来源：** 挂单 23 件；已裁定的形状与逐件核查（文件行号）见同目录 `grill.md`

## Problem Statement

**一、人拍过的板，删库重扫就丢。** ADR-0001 修订写着「不可再生的东西不住在中立库里」，可今天还有好几样人亲手定的东西住在中立库：

- 作品详情页上改过的字段、亲手加的叫法、定过的首选变体——删库重扫就没了。删库前那句提示还说「沉淀库里的裁决一条不丢」，对详情页的字段修改是一句假话。
- 待确认屏上「已经就地裁掉了哪一组」只活在这个进程里：窗口关掉再开，那几项不再标「已通过」，细分方式也不再锁着，屏上的数当场变成假话。
- 合并作品落成的裁决把 DAT 的**修订**丢了，详情页「版本」那一格合并之后退回「—」。
- 裁决钉的内容锚「谁代表这个变体」可能挑中捎带的 BIOS，一条裁决于是管到所有带同一份 BIOS 的变体。
- 标题那一侧（中文叫法）没有能一条条裁的队列，只有报告里一个数加十个例子；ADR-0002 与词表的原话还按置信度分档，而两侧队列的判据早已不看置信度。
- 子库的手动例外一次加几十上百条，撤的时候只能一条一条撤。
- 差量预览里「设备上被修改过」的那几份每趟都报，人没有办法让工具接管它们。
- 子库例外那两张截图基线靠挂钟排序，机器一忙就红。

**二、写到卡上的，前端读不到或缺一样。**

- ES-DE 2.0 起默认只读自己数据目录里的 `gamelists/`，子库写在各平台目录旁的 `gamelist.xml` 可能根本不被读。
- 多碟变体合成之后没有 `.m3u`，前端里换碟要手动。
- 在界面上连着纠正几处成型结果，每按一下都全库重新成型一趟（分钟级）。
- 差量预览上勾一下「补回」，台上那一趟白跑、不停；「放不进目标」那一行的容量把撞车的几份各算一遍；撞车明细不在 `--json` 里。
- `romcat export` 不开 `--media` 时按不停；同步连着失败、自己收了手时任务台记成「完成」。

**三、设置屏上画着的几样，核心库没有能力。**

- ScreenScraper 账号只认环境变量，从 Finder 启动的界面读不到，在线档实际上用不了。
- ffmpeg 只在进程 PATH 里找，macOS 上从 Finder 启动的界面基本永远报「没找到」。
- 工作目录与媒体池占了多大算不出来，屏上只好报条数；老库里入过池的媒体那三格（宽、高、时长）永远空着。
- 稿上有两颗「每周自动检查更新」开关，核心库没有这条路。

## Solution

**一、沉淀库收下人手写的东西。**

- 详情页的字段修改、亲手加的叫法、首选变体搬进**沉淀库**，锚在**路径锚**上（与人工纠正同族：熬得过删库重扫、熬不过改名挪目录，默认不导出）。
  开现场时照沉淀库回放进中立库的投影。删库前那句提示逐项写实话。
- 沉淀库的批表记下「就地落下的那一批」的**作用范围**（形状、轴、组名），结构化存；待确认屏开窗时照它折回，锁细分方式、标「已通过」。
- 裁决带上 DAT **修订**：沉淀库多一格，合并与一切「定成这个发行版」的裁决都写它，导出格式升一版。
- 卡带头里读出来的版本号**不接**「第几版」那条链，只作为修订的证据写进依据与详情（词表**第几版**条已补）。
- 识别挑「代表这个变体的那一份」时先跳过**非游戏资产**；已有裁决不迁（真库 0 条）。
- **待确认队列**加一档「标题」：一条 = 一串还没人裁过的中文叫法，肯定或否定的是那一整串字（词表已放宽）。ADR-0002 补一段修订：进不进队列看有没有自动通过、有没有人裁过，不看置信度。
- 手动例外按**作品**折一层：同作品同方向并一行，行尾一颗撤整组，可展开看逐份。分组判断在核心库，不动表结构。
- 差量预览「被修改过」那一栏加**收回清单**（词表新词）：按下之前先说清是哪几份，确认后记回清单，此后工具有权更新或删除它；审计（谁、何时、哪几份）住沉淀库。
- 例外带显式时刻的写入口，截图夹具钉互不相同的定值，基线不再随挂钟变。
- Switch 补丁判据维持只认票据（不拿 titledb 反查）——不做。

**二、同步落点。**

- ES-DE：**先由拿主意的人在真掌机上核实**默认读哪、`LegacyGamelistFileLocation` 开没开；核实之后，设备档案记一项「ES-DE 数据目录」（相对卡根），元数据写到那里，清单照管。
- `.m3u`：多碟变体**只在同步时**生成到卡上，清单照管；导出到主库那一侧不生成（不碰 ADR-0004 的边）。
- 成型纠正**攒着**：纠正先落沉淀库，屏上累计「N 处待生效」，人按一下跑一趟全库；到跑之前屏上说清看到的是旧结构。
- 差量预览：勾「补回」先停掉台上那一趟再重排；「放不进目标」的容量撞车那几份只算一次并写明口径；撞车明细进 `--json`。
- 收场说实话：`romcat export` 不开 `--media` 也接 Ctrl-C；同步连着失败自己收手、而且留下了东西时报**部分完成**。

**三、设置屏背后的核心能力。**

- ScreenScraper 账号：设置屏可填，存工作目录里一份**只本机可读（0600）**的文件，只一套；命令行也读它，环境变量照旧优先。「测试连接」扣不扣配额另议，不在这一批。
- ffmpeg：核心库除 PATH 外再找几处常见位置（Homebrew 两处、Windows 常见安装目录），不落盘。
- 核心库立「量工作目录与媒体池各件多大」一面，设置屏改报字节；同一趟遍历顺手把老媒体缺的宽、高、时长补上——排在任务台上，不放在开库路上。
- 「每周自动检查更新」不做：把设置屏稿上那两颗开关划掉，屏上那句现话留着。

## User Stories

1. 作为在详情页改过字段的人，我想删库重扫之后我改的值还在，这样我的手工活不会白做。
2. 作为亲手给作品加过叫法的人，我想删库重扫之后那个叫法还在。
3. 作为定过首选变体的人，我想删库重扫之后前端默认启动的还是我定的那一个。
4. 作为挪过目录或改过名的人，我想被告知这几样手工定的东西熬不过改名挪目录，因为它们钉在路径上。
5. 作为删库前看提示的人，我想那句提示逐项说实话：哪些留得住、哪些会丢。
6. 作为导出沉淀库分享给别人的人，我想路径锚的这几样默认不导出，因为它们只对本机成立。
7. 作为在待确认屏就地裁了一组的人，我想关掉窗口再开，那几项仍标「已通过」、细分方式仍锁着。
8. 作为在命令行看裁决记录的人，我想就地落下的那一批带着作用范围，与界面同一份。
9. 作为合并作品的人，我想合并之后详情页「版本」那一格照旧写着 DAT 的修订。
10. 作为导出沉淀库的人，我想新版导出格式带着修订，旧版导出照旧读得回来。
11. 作为看详情的人，我想卡带头里读出来的版本号出现在依据里，作为修订的一份证据，而不是冒充「第几版」。
12. 作为裁决过变体的人，我想裁决钉在游戏本身的内容上，不钉在捎带的 BIOS 上，这样一条裁决不会管到一大片无关的变体。
13. 作为整理中文叫法的人，我想在待确认屏上有一档「标题」，一条条看还没人裁过的叫法。
14. 作为整理中文叫法的人，我想肯定或否定的是那一整串字，被几个变体共用的叫法只出一条。
15. 作为整理中文叫法的人，我想裁过的叫法从队列里消失，撤销后回来。
16. 作为读 ADR 与词表的人，我想它们说的「进不进队列」与代码一致：看有没有自动通过、有没有人裁过，不看置信度。
17. 作为管子库的人，我想手动例外按作品折起来，一颗按钮撤掉整个作品的那几份。
18. 作为管子库的人，我想展开一个作品看得到逐份的例外。
19. 作为管子库的人，我想在「被修改过」那一栏把那几份**收回清单**，这样它们不再每趟都报，工具重新接管它们。
20. 作为管子库的人，我想收回之前先被告知是哪几份、收回意味着什么（工具此后可能更新或删掉它们）。
21. 作为事后查账的人，我想每一次收回清单都留一笔审计：谁、何时、哪几份。
22. 作为不收回的人，我想那几份照旧每趟报出来、工具照旧不碰。
23. 作为改截图基线的人，我想子库例外那两张基线在忙闲不同的机器上画得一样。
24. 作为用 ES-DE 的人，我想子库写到卡上的元数据落在 ES-DE 真读的地方。
25. 作为设备档案的维护者，我想 ES-DE 数据目录是档案里一项，默认值照 ES-DE 2.x，卡上布局不同可以改。
26. 作为 ES-DE 数据目录在内置存储上的人，我想被告知同步目标够不着那里，而不是写了一个没人读的文件。
27. 作为玩多碟游戏的人，我想同步到卡上的多碟变体带一份 `.m3u`，前端里换碟不用手动。
28. 作为维护主库的人，我想导出到主库时不生成 `.m3u`，主库里不多出非元数据文件。
29. 作为把子库移出设备的人，我想那份 `.m3u` 跟着清单一起清掉。
30. 作为连着纠正成型的人，我想每一处纠正先记下、屏上累计「N 处待生效」，按一下才跑一趟全库。
31. 作为连着纠正成型的人，我想在跑之前屏上说清眼下看到的还是旧结构。
32. 作为连着纠正成型的人，我想那几处纠正落在沉淀库，窗口关了也不丢。
33. 作为排差量预览的人，我想勾「补回」时台上那一趟先停掉，不白跑。
34. 作为看「放不进目标」的人，我想撞车的几份只算一次容量，屏上写明口径。
35. 作为用 `--json` 的人，我想撞车明细也在 JSON 里。
36. 作为在命令行导出的人，我想不开 `--media` 时 Ctrl-C 照样停得下，收场说清停在哪。
37. 作为看任务台的人，我想同步连着失败、自己收了手的那一趟记成部分完成，不记完成。
38. 作为从 Finder 启动界面的人，我想在设置屏填一次 ScreenScraper 账号，下次开窗还在。
39. 作为在命令行刮削的人，我想命令行也读那份账号文件；设了环境变量时环境变量优先。
40. 作为在意隐私的人，我想账号文件只有本机本人读得了（0600），而且只有一套。
41. 作为用 Homebrew 装 ffmpeg 的人，我想从 Finder 启动的界面也找得到它。
42. 作为 ffmpeg 装在怪位置的人，我想被如实告知没找到，以及找过哪几处。
43. 作为看设置屏的人，我想工作目录与媒体池写的是占了多少字节，不是条数。
44. 作为老库的主人，我想任务台上有一趟活把老媒体缺的宽、高、时长补上，而不是开库时卡住。
45. 作为看设置屏的人，我想不再看到两颗按不出效果的「自动检查更新」开关。
46. 作为维护主库的人，我想这一批一样不碰主库一个字节（ADR-0004）。

## Implementation Decisions

**第一组 · 沉淀库**

- 沉淀库新增（顺序迁移，照已有先例）：字段裁决值、亲手加的叫法、首选变体（三样都锚路径锚：主库标识 + 位置）；批表的作用范围格；裁决的修订格；收回清单的审计表；成型纠正的待生效记录（第二组用）。
  中立库里原来那几张表降为**投影**，开现场时照沉淀库重建，与合集、收藏同一个做法（ADR-0001 修订）。旧中立库里已有的这几样，开现场时救进沉淀库一次、记下「搬过了」（照人工纠正那一次的先例，`Q721` `Q726`）。
- 导出格式升一版：带修订；路径锚的三样默认不导出。旧版导出照旧能导入。
- 删库提示逐项列：留得住的（沉淀库里的）、会丢的（只有可再生的）。
- 识别里「代表这个变体」的挑法先跳过非游戏资产；不写迁移。
- 标题待确认：核心库立一问「列出还没人裁过的中文叫法」（按叫法一行，与标题否定表同粒度），界面待确认屏加一档；肯定/否定走已有的标题裁决与撤销。
  ADR-0002 补一段修订。
- 手动例外按作品分组的判断在核心库（交出「作品 → 这一组例外」）；界面一行一组、行尾撤整组、可展开。
- **收回清单**：核心库立一个带审计的操作（给子库 + 哪几份），写清单、写审计；界面「被修改过」那一栏加按钮、先确认一层。
- 例外写入加一个带显式时刻的入口（照「标记已导出」那个带时刻入口的先例），截图夹具改用它。

**第二组 · 同步落点**

- ES-DE 那张票分两段：头一段是**人做的核实**（`ready-for-human`），把结论写回设备档案的说明；第二段是按结论加「ES-DE 数据目录」一项并改落点。
- `.m3u`：同步的计划里对多碟变体多一项生成文件，适配器能力里声明「支持播放列表」；清单记它。
- 成型纠正：纠正落沉淀库的待生效记录；界面累计、给一颗「重新成型」；跑完清掉待生效记录。
- 差量预览：界面「补回」先停台上那一趟；核心库放不进目标的容量按路径去重；撞车明细作为字段进报告的序列化。
- 收场：命令行导出无论开不开媒体都挂取消；同步「放弃」且留下东西时报部分完成。

**第三组 · 设置屏**

- 程序级那份账号文件住工作目录，权限 0600（Windows 上照该平台的只本人可读）；读取顺序：环境变量 → 文件。核心库一处读写，界面与命令行都走它。
- ffmpeg 查找：PATH 之后按固定顺序试几处常见位置；找不到时交出找过的清单。
- 核心库立「量工作目录与媒体池」一面（各件多大、几份）；设置屏读它。老媒体补宽高时长作为一趟任务台上的活，复用同一次遍历。
- 设置屏删掉「自动检查更新」两颗开关（与设计稿一起改），屏上现话保留。

## Testing Decisions

- 好测试只看外部行为：做一件事、换一种方式把库重建、再问库。不断言表结构与 SQL。每一件先写一条在今天 `main` 上红的测试再修。
- **沉淀库组**：一条共用的核心库接缝——「做一件人手写的事 → 删掉中立库重扫 → 那件事还在」，照「改名之后路径锚一个字节没动、沉淀库里的裁决照旧对得上」那条测试的写法。逐一覆盖：字段修改、亲手加的叫法、首选变体、就地裁一组的作用范围、合并带修订、成型待生效。
  另：挪目录之后路径锚的三样对不上（如实）；BIOS 与游戏同在的变体，裁决钉在游戏那一份上；导出新格式带修订、旧格式导入得回。
  界面各加一条：待确认屏「标题」一档列得出、裁得掉、撤得回；子库屏「被修改过」收回清单先确认、之后那几份不再出现；例外按作品折、撤整组。
- **同步落点组**：接在现有同步计划与真盘同步那两份测试上：多碟变体同步后卡上有 `.m3u` 且进了清单、移出后清掉；导出到主库不生成；同步连着失败收手报部分完成；放不进目标撞车只算一次；`--json` 有撞车明细。
  命令行：导出不开 `--media` 时发取消信号，收场说部分完成。界面：成型连着纠正两处，屏上「2 处待生效」，按一下才起一趟任务。
  ES-DE 落点在核实之后写，测试照设备档案的新项断言落点。
- **设置屏组**：核心库测账号文件写出来是 0600、读取顺序环境变量优先；ffmpeg 查找对一个注入的候选位置命中、全不中时交出找过的清单；量尺对一个造出来的工作目录报对字节数、补得上宽高时长。界面测设置屏那几格与截图基线（开关已划掉）。
- 门禁全绿；本机 `sync_run` 那五条已知红（`Q479`）不算这一批的回归。

## Out of Scope

- 「测试连接」扣不扣 ScreenScraper 配额——另问。
- 每周自动检查更新（`Q1062`）、titledb 反查判补丁（`Q703`）——已裁不做。
- 卡带头版本号接进「第几版」——已裁不接。
- 首选变体、叫法、字段修改熬过改名挪目录（内容锚）——已裁路径锚。
- 手动例外按「哪一次加进来的」撤——已裁按作品，不动表结构。
- 落点平台按纠正（`Q1033`）——在 `core-answers-once/03`。

## Further Notes

- 沉淀库那一组共用一串顺序迁移，几张票动同一份迁移清单，**不宜并行**，按编号串着做。
- ES-DE 那一段在拿主意的人核实之前不动代码。
- 第三组的账号文件是工作目录里第一份「程序级、跨主库」的设置；ffmpeg 已裁不落盘，所以眼下它是唯一一份，不为它立通用的设置框架。
