# 开一份库这条路上不留哑口

**Status:** 待 `/to-spec`
**Opened:** 2026-09-09（`/settle` 第四轮收口 → `/grill-with-docs`）

## 它建什么

从零开一份库这条路上，**每一步都说得出话**。眼下四处是哑口：目录写不动不说、
「版本对不上」与「文件坏了」分不开、建库走了哪条入口看不出、已有的库改不了名。
另外三件是同一带上的搭车活。

## 这一批最该先读的一句

`Q370`（→ 票 `08`）、`Q371`（→ 票 `05`）、`Q393`（→ 票 `05`）、`Q388`（→ 票 `05`）四条
当初都写着「谁来裁：票 `NN`」，而**那几张票后来真的来了、真的动了那一带、没收它**。
`Q371` 更狠：票 `05` 自己在同一处另问了一句 `catalog_path(..).exists()`（那就是挂单
`Q411`），完全不知道有人把一条挂单托给了它。

根因不在那几张票：**那条处置把义务记在挂单上，而干活的人只读票。**
`PARKING-LOT.md` 的条目格式已于 2026-09-09 **禁掉「谁来裁：票 `NN`」这个选项**，规矩写进
`docs/agents/issue-tracker.md`。**这一批开票时，每一条都要在票正文里写清 `收挂单 Qn`。**

## 七件

### 1. 目录读不动与它压根不在，交出来是同一样东西 —— 挂单 `Q388`

`crates/core/src/workspace.rs::catalogs` 里
`let Ok(dir) = std::fs::read_dir(..) else { return Vec::new() }`——两种情况屏上都说
「还没有库，认领一个主库开始」。票 `05` 已经在那一屏上**认领新主库**了（要往那个目录
**写**），而「这个目录写不动」到今天仍然说不出来。

### 2. 「版本对不上」与「文件坏了」分不开 —— 挂单 `Q393`

`CatalogEntry::facts: Result<CatalogFacts, String>`，`entry_of` 里一句
`Err(format!("{error}"))` 把 `CatalogError` 压成了一句话。票 `05` 只问了 `exists()`，
于是「这个名字撞上一份**版本对不上**的旧库」与「撞上一份**坏文件**」到今天仍然分不开
——而那正是条目当初托给 `05` 的那件事。`openable` 只答了「按不按得下打开」。

### 3. 建库入口收成一处 —— 挂单 `Q371`

`Catalog::open` 仍是「打开即创建」。今天漏不了（`Site::open` / `Site::open_file` 都先
`catalog.exists()`），但**建得出中立库的地方已经有两个**（命令行 `open_catalog` 与向导），
而只有前者走 `open_named`。

**形状：把「折中立库的路径」与「带着原名开它」收成一个函数**
（`catalog_path(ws, slug)` 与 `open_named(&path, &slug.display_name())` 永远成对），
让「建库时不记名字」**在类型上就写不出来**。

### 4. 元数据表那一族键怎么读写 —— 挂单 `Q370`

`Catalog::open_named` 是唯一的写入口，`meta_set` 仍是私有，于是**已有的库改不了名**。
条目当初说「等票 `08` 要往同一张表写导出配置时一起想清楚这一族键怎么读写」——
`08` 来了、往同一张表写了两个键（`exported_at`、`export_out_dir`）、**没收这一条**。
那一族键现在已经长齐四个（`library_name` / `titles_folded_at` / `exported_at` /
`export_out_dir`），这一问到期了。「已有的库改不了名」是它的第一个用例。

### 5. `Site::library` 名不副实 —— 挂单 `Q372`

公开面上并存两个「主库名」：`Site::library`（＝`Slug::text()`，中立库的主文件名，也是
**路径锚**里那个键）与 `Catalog::library_name()`（人起的那个原名）。名不副实的是前者
——**它根本不是「名字」，是文件名**。票 `01` 只在两处文档里互相指了一下。

**形状已裁定（2026-09-09）：只改名，不动锚。**
`Site::library` → `Site::slug`；**路径锚里存的键一个字节不动**（它存的就是这个 slug，
语义没变、只是叫法对上了）。真要动锚是另一件事，而且那件事至今没有理由。

### 6. 删掉那份没人用的 `impl eframe::App for App` —— 挂单 `Q382`（并 `Q390`）

`crates/gui/src/app.rs:533` 与 `crates/gui/src/program.rs` 末尾**两份逐字相同**的实现，
`App` 那份从票 `02` 起就没有调用方。当初挡着它的是票 `02` / `03` 各自「`App` 与五屏的
公开接口一处不动」的硬约束——**那两张票都已 `done`，挡的人没了**。

### 7. 开场那几行按上次扫描时刻倒着排 —— 挂单 `Q389`

眼下按主库名的**码位**排（`workspace.rs::catalogs` 末尾那句 `sort_by`），于是「乙库」排在
「甲库」前面。**裁定（2026-09-09）：按上次扫描时刻倒着排**，最近动过的那份在最上面。
用户机器上是三份库（ADR-0023），三行里「哪份是我刚在弄的」比「哪份名字码位小」有用得多。
拼音排否掉——要一张汉字读音表，这个仓库一份都没有。
⚠️ `crates/core/tests/catalog_list.rs::列出这个工作目录里的中立库` 把「按码位排」写在断言
旁边了，跟着改。
